对象和类

7.1 对象介绍

在Java中，对象是理解整个面向对象编程（OOP）的核心。简单来说，对象是现实中某个事物的抽象表示，它包含了属性（数据）和行为（方法）

通俗理解：类与对象的关系

在Java中，类是对象的蓝图或模板，而对象是根据这个模板创建出来的具体实例。

  • 类：就像一张建造房子的设计图。它规定了房子必须有门、窗户、墙（属性），以及可以开门、开灯（行为），但它本身不是实体。
  • 对象：根据这张设计图建造出来的实际房子。小区里每一栋具体的房子（101室、102室）都是对象。它们都遵循同一个设计图，但拥有独立的门牌号（属性值可以不同）。

对象的两个核心特征

当你创建一个对象时，它主要包含两样东西：

  1. 状态（属性/成员变量）：对象拥有什么？
    • 比如一个“狗”对象，它有：品种、颜色、年龄。
  2. 行为（方法）：对象能做什么？
    • 比如一个“狗”对象，它可以：叫、跑、吃。

7.2 使用类

类 是 Java 面向对象编程（OOP，Object-Oriented Programming）的基石。它是一种 引用数据类型，是创建对象的模板，它定义了对象将拥有什么样的数据（属性）以及可以执行什么样的操作（方法）。

类的构成

在 Java 中，一个类通常包含两种最重要的成员：

  1. 属性/字段：也称为成员变量。它描述了类应该拥有什么样的 数据 或 状态。
    • 例如：人的姓名、年龄；汽车的品牌、颜色。
  2. 方法：它描述了类能够做什么样的 行为 或 操作。
    • 例如：人可以走路、说话；汽车可以加速、刹车。

为什么需要类

  • 封装性：将数据（属性）和操作数据的方法绑定在一起，对外部隐藏内部细节。
  • 复用性：写一次类，就可以创建无数个对象，不用重复写代码。
  • 模块化：把复杂的问题拆分成不同的类，每个类负责自己的事情，便于管理和维护。

7.4 修改器、访问器和私有辅助方法

在Java中，Mutators（修改器）、Accessors（访问器）和Private Helpers（私有辅助方法）是面向对象编程中用于封装和管理数据的三个重要概念。它们共同协作，确保类的内部数据安全、可控且易于维护。

简单来说：

  • Accessors：用于安全地获取数据（读）。
  • Mutators：用于安全地修改数据（写）。
  • Private Helpers：是类内部的“隐形助手”，用于代码复用和逻辑拆分。

7.4.1 Accessors（访问器）

访问器的主要作用是获取（读取）类中私有字段的值，最常见的形式就是 getter 方法。

  • 命名规范：通常以 get 开头，后跟字段名（首字母大写）。如果返回值是 boolean 类型，有时也用 is 开头。
  • 核心作用：
    • 封装：外界不需要知道数据是如何存储的，只需要通过方法来获取。
    • 控制访问：你可以决定是否返回原始数据，还是返回一份拷贝（对于像数组、列表这样的可变对象尤其重要）。
    • 派生数据：可以在方法中加入计算逻辑，而不是直接返回一个字段。

7.4.2 Mutators（修改器）

修改器的主要作用是修改（设置）类中私有字段的值，最常见的形式就是 setter 方法。

  • 命名规范：以 set 开头，后跟字段名，并接受一个同类型的参数。
  • 核心作用：
    • 数据验证：在修改数据前进行检查，确保新值符合业务规则（例如年龄不能为负数）。
    • 触发内部更新：修改一个字段后，可能自动触发其他相关字段的重新计算。
    • 维护对象状态：确保对象的内部状态始终是有效的。

7.4.3 Private Helpers（私有辅助方法）

私有辅助方法是声明为 private 的方法，它们只能在类的内部被调用，外界无法访问。

  • 核心作用：

    • 代码复用：当多个方法（如不同的 mutators）需要执行相同的复杂逻辑时，可以提取成一个私有方法，避免代码重复。
    • 提高可读性：将复杂算法或步骤拆分成多个小方法，让主方法的逻辑更清晰。
    • 隐藏实现细节：一些内部工作不需要也不应该暴露给外部用户。

7.5 初始化和构造函数

7.5.1 类的初始化

类的初始化是指在程序运行过程中，为类或对象分配内存并设置初始值的过程。主要分为两个阶段：

1. 类初始化（Class Initialization）

  • 在类首次主动使用时执行
  • 执行静态变量的赋值和静态代码块
  • 只执行一次

2. 对象初始化（Object Initialization）

  • 每次创建对象时执行
  • 执行顺序：实例变量初始化 → 实例代码块 → 构造函数

7.5.2 构造函数初始化

1. 基本特点

  • 方法名与类名相同
  • 没有返回类型（包括void）
  • 可以重载
  • 自动执行

7.6 将程序分解为类

将程序分解为类是面向对象设计的核心。Java作为一种强制使用类的语言，合理的类分解直接影响代码的可维护性、可扩展性和可重用性。

7.6.1 面向真实世界的建模（名词分析法）

这是最直观的思路，适用于业务逻辑系统。找名词，定类别。

  • 核心方法：分析需求文档或问题描述，圈出其中的名词，这些通常就是候选类。
  • 例子（电商系统）：
    • 名词：用户、商品、购物车、订单、支付方式。
    • 对应类：User、Product、ShoppingCart、Order、Payment。
  • 作用：这些类主要负责数据的持有和管理（属性：getter/setter，以及基本的数据校验）。

7.6.2 单一职责原则

这是最核心的设计原则。任何一个类，最好只有一个引起它变化的原因。

  • 核心方法：如果一个类看起来“既当爹又当妈”，什么都做，就需要拆开。

反例（上帝类）：

  • 正例（拆分）：
    • DataFetcher：负责查询数据库。
    • Calculator：负责业务逻辑计算。
    • ReportGenerator：负责生成Excel/PDF。
    • EmailSender：负责发送邮件。

7.6.3 设计模式视角

根据对象在系统中的角色来分解，这是分层架构的基础。

  • 实体类：对应现实中的事物，通常对应数据库表（如 User.java）。
  • 控制类：负责处理业务流程和逻辑，通常对应Service层（如 UserService.java）。
  • 边界类：负责与外部系统或用户交互，通常对应Controller层或UI层（如 UserController.java）。

7.6.4 关注点分离

将不同技术层面的代码放到不同的类中。

  • 表现层：处理HTTP请求、参数校验（XxxController）。
  • 业务层：处理具体的业务逻辑（XxxService）。
  • 持久层：操作数据库（XxxRepository 或 XxxDAO）。
  • 工具类：提供通用的、与业务无关的功能（如日期处理、字符串处理）。
  • 配置类：专门管理Bean和配置（@Configuration）。

7.6.5 抽象类与接口（面向抽象编程）

当多个类有共同的属性和行为，但行为的具体实现方式不同时，可以提取出父类或接口。

  • 提取基类/超类：
    • 例如：Cat 和 Dog 都属于 Animal（抽象类）。Animal负责定义共有的属性（年龄、名字）和抽象行为（makeSound()）。
  • 定义能力（接口）：
    • 例如：并不是所有动物都会飞，但 Sparrow 和 Airplane 都能飞。这时可以定义一个 Flyable 接口，包含 fly() 方法。

在实际开发中如何思考？

  1. 找概念（名词）：先找出有哪些业务实体（如：学生、课程、老师）。
  2. 定边界（分层）：决定哪些类负责展示（Controller），哪些负责逻辑（Service），哪些负责存数据（DAO）。
  3. 找共性（继承/接口）：看看这些实体是否有共同行为可以提取。
  4. 看职责（单一职责）：写完一个类后，回头看看它是否超过200行，是否做了太多不相关的事情。
  5. 分离变化：把容易变化的部分（如算法、外部依赖）封装起来，避免影响核心类。

7.7 类中的main()方法

在Java类中，main方法是Java应用程序的入口点。当您运行一个Java程序时，Java虚拟机（JVM，Java Virtual Machine）首先会寻找并调用这个特定的方法。

main方法的作用

  1. 程序起点：它是程序的第一个执行点。
  2. 程序控制：它通常负责创建其他对象、调用其他方法，从而启动整个应用程序的逻辑流程。
  3. 命令行交互：通过String[] args接收外部参数。

标准的main方法签名

  • public：访问修饰符。
    • 必须为public（公共的）。因为JVM需要从类的外部调用这个方法，如果设为private，JVM将无权访问，也就无法启动程序。
  • static：静态修饰符。
    • 必须为static（静态的）。这样JVM在启动时不需要创建该类的对象实例，就可以直接通过类名调用这个方法。
  • void：返回值类型。
    • 必须为void（无返回值）。当main方法执行完毕，就意味着程序结束了。一旦将值返回给JVM，JVM没有地方可以接收，所以不需要返回值。
  • main：方法名。
    • 这是JVM的固定识别名称。JVM只会寻找名为“main”的方法作为入口，写错字母（如 mian）会导致程序找不到入口。
  • String[] args：参数。
    • 这是一个字符串数组类型的参数，通常命名为args（可以改名，但约定俗成用args）。
    • 作用：用于接收用户在命令行启动程序时传入的参数。

7.8 单元测试（类）

在Java中，类的单元测试是指针对软件中最小的可测试单元——通常是一个类——所编写的自动化测试代码。

它的核心目的是独立地验证这个类（尤其是它的公共方法）在给定特定输入时，是否能产生正确的输出或行为。

核心思想

  • 最小单元：测试的范围通常限定在一个类之内，不跨类，尤其不跨外部系统（如数据库、网络、文件系统）。
  • 自动化：测试代码可以一键运行，无需人工干预。
  • 可重复：每次运行的结果都应该是稳定的。
  • 即时代价：开发者在修改代码后运行单元测试，能立即知道是否破坏了原有的功能。

为什么需要单元测试？

  • 保证代码质量：验证代码逻辑是否符合预期。
  • 防止回归：当修改或重构代码时，运行已有的单元测试可以确保旧功能没有因为新代码而损坏。
  • 简化调试：当测试失败时，范围很小，很容易定位到是哪一个类的哪一行代码出了问题。
  • 作为活的文档：好的单元测试代码本身就是一份如何调用该类及其方法的示例文档。

单元测试的基本结构

通常遵循 Given-When-Then 模式（即 准备-执行-断言 模式）：

  1. Given（准备）：初始化测试环境，创建被测类的实例，准备测试数据。
  2. When（执行）：调用被测类的方法。
  3. Then（断言）：验证执行结果是否与预期一致。

常用的单元测试框架与工具

在Java生态中，最核心的是以下两个框架：

  • JUnit 5：Java中最主流的单元测试框架。它提供了运行测试的引擎以及断言方法。
  • TestNG：另一个流行的测试框架，功能与JUnit类似，但在某些配置上更灵活。

除了框架本身，为了应对复杂场景，通常会配合使用模拟框架：

  • Mockito：最常用的模拟框架。当被测类依赖了其他类（如数据库访问层）时，可以使用Mockito来模拟那些依赖，从而隔离被测类，只测试这个类本身的逻辑。
  • PowerMock / Mockito 的内联模拟器：用于模拟静态方法、私有方法等更复杂的情况。

好的单元测试特性

  • FIRST原则：
    • Fast（快速）：执行速度要快，这样才能经常运行。
    • Isolated（隔离）：不能依赖外部环境（如时间、网络），且测试之间不应相互影响。
    • Repeatable（可重复）：每次运行结果都一样。
    • Self-validating（自验证）：测试结果只有通过或失败，不需要人工查看日志来判断。
    • Timely（及时）：通常是在写生产代码之前或同时编写。

7.10 对象和引用

引用可以理解为指向对象的"指针"或"地址"。当你创建对象时，实际上是在堆内存中分配空间，而引用则存储这个对象的内存地址。

引用的基本概念

7.10.1 Java中的四种引用类型

Java提供了四种不同程度的引用，主要用于垃圾回收的控制：

1. 强引用（Strong Reference）

最常见的引用类型，只要引用存在，垃圾回收器就不会回收。

2. 软引用（Soft Reference）

内存充足时不会被回收，内存不足时会被回收。适合实现缓存。

3. 弱引用（Weak Reference）

下一次垃圾回收时，无论内存是否充足，都会被回收。

4. 虚引用（Phantom Reference）

最弱的引用，无法通过它获取对象实例。主要用于跟踪对象被垃圾回收的状态。

  1. 引用是访问对象的"钥匙"，存储对象的内存地址
  2. Java提供了四种引用类型，用于不同场景的内存管理
  3. 方法参数传递的是引用的副本，而不是对象本身
  4. 理解引用对避免内存泄漏和优化程序性能很重要

7.16 ArrayList ADT

7.16.1 什么是 ADT？

ADT 是 Abstract Data Type（抽象数据类型） 的缩写。

核心思想

ADT 是一种 数学模型 以及定义在该模型上的一组操作。它只关心“做什么”（即对外提供的功能），而不关心“怎么做”（即具体的实现细节）。

通俗理解

可以把 ADT 想象成一个 黑盒子：

  • 外部（用户）：只知道这个黑盒子能干什么（比如能存数据、能取数据）。
  • 内部（实现者）：可以使用数组、链表或其他数据结构来实现这些功能。

常见例子

  • 整数：就是一个 ADT。我们知道可以对整数进行加、减、乘、除运算，但整数在计算机底层是用二进制补码实现的，我们并不需要关心这个细节。
  • 栈（Stack）：是一个 ADT。它定义了 push（压入）、pop（弹出）等操作，遵循后进先出（LIFO）的原则。它可以由数组实现，也可以由链表实现。

总结：ADT = 数据 + 操作，封装了实现细节。

7.16.2 ArrayList 中常见的 ADT 方法

  1. 增加元素：

    • add(E e)：在列表末尾添加一个元素。

    • add(int index, E element)：在指定位置插入一个元素。

  2. 删除元素：

    • remove(int index)：删除指定位置的元素，并返回它。
    • remove(Object o)：删除列表中第一个出现的指定元素。

  3. 修改元素：

    • set(int index, E element)：用指定元素替换列表中指定位置的元素。

  4. 查询元素：

    • get(int index)：返回列表中指定位置的元素。
    • size()：返回列表中的元素个数。
    • isEmpty()：判断列表是否为空。
    • contains(Object o)：判断列表是否包含指定元素。
    • indexOf(Object o)：返回指定元素在列表中第一次出现的位置。

  5. 其他辅助方法：

    • clear()：移除列表中的所有元素。
    • toArray()：将列表转换为数组。
