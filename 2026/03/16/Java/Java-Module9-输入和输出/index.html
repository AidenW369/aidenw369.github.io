9.1 输入流和输出流

输入流和输出流是Java程序对外进行数据读写的通道。

9.1.1 PrintStream 类

PrintStream 是 Java 标准库中的一个类，位于 java.io 包中。它是一个字节输出流，提供了方便的打印方法，可以将各种数据类型的数据格式化为字符串并输出。

主要特点：

  • 自动刷新：某些构造方法创建的PrintStream可以自动刷新

  • 格式化输出：提供print()、println()和printf()等便捷方法

9.2.6 flush() 输出

flush() 是输出流（OutputStream/Writer）中的一个方法，强制将缓冲区中的数据立即写入到目的地。简单来说，就是”清空缓冲区”。

为什么需要flush()？

为了提高效率，Java的IO流使用了**缓冲区（Buffer）**机制：

  • 数据先写入内存缓冲区
  • 缓冲区满了才真正输出到目标设备
  • 这样可以减少实际的IO操作次数

哪些流需要flush()？

需要手动flush的流：
  • BufferedOutputStream
  • BufferedWriter
  • PrintStream/PrintWriter
  • 网络Socket输出流
  • 数据库输出流
自动flush的情况：
  • 缓冲区满了自动写入
  • 流关闭时自动flush
  • PrintStream/PrintWriter 遇到换行符（某些构造器参数）

flush()的实际应用场景

场景1：控制台输出
场景2：文件写入

flush() vs close()

特性 flush() close()
作用 清空缓冲区 关闭流并释放资源
后续使用 可以继续写入 不能再写入
自动行为 不会自动调用 自动调用flush
调用次数 可以多次调用 只能调用一次

总结

什么时候必须使用flush()？

  1. 实时交互：需要立即看到结果时（进度条、提示信息）
  2. 关键数据：确保数据不丢失，即使程序崩溃
  3. 网络通信：确保数据立即发送
  4. 调试信息：需要准确定位问题发生的位置

9.4 文件读取输入流

9.4.1 FileInputStream

FileInputStream 是Java中用于从文件中读取字节数据的输入流类。它位于 java.io 包中，是 InputStream 抽象类的子类。

主要特点

  1. 字节流：以字节为单位读取文件内容
  2. 文件输入：专门用于从文件系统中读取数据
  3. 原始数据：适合读取二进制文件（如图片、音频、视频等）

常用构造方法

核心方法

方法 说明
int read() 读取一个字节，返回字节值（0-255），到达文件末尾返回-1
int read(byte[] b) 读取字节到数组中，返回实际读取的字节数
int read(byte[] b, int off, int len) 读取指定长度的字节到数组的指定位置
void close() 关闭流并释放资源
int available() 返回可以读取的字节数
long skip(long n) 跳过指定数量的字节

使用示例

1. 单个字节读取（不推荐用于大文件）
2. 使用缓冲区读取（推荐）

注意事项

  1. 资源管理：使用完必须关闭流，推荐使用 try-with-resources 自动关闭
  2. 字符编码：FileInputStream 是字节流，读取文本文件时可能出现乱码，应使用 InputStreamReader 包装
  3. 性能优化：使用缓冲区（byte数组）批量读取比单个字节读取性能更好
  4. 异常处理：必须处理 FileNotFoundException 和 IOException

9.4.2 hasNextInt() 和 hasNext()

1. hasNext() 方法

检查输入源中是否还有下一个 token（默认以空白符分隔的字符串），不关心token的具体类型。

特点

  • 返回 boolean 值
  • 只检查是否存在下一个token
  • 不验证token的类型
  • 遇到空格、制表符、换行符时会分隔token

2. hasNextInt() 方法

检查输入源中的下一个token是否可以解释为int类型的整数。

特点

  • 返回 boolean 值
  • 验证下一个token是否为有效的整数
  • 不会消耗（读取）该token
  • 支持负数和正数
  • 只检查整数类型，不检查小数

9.4.3 其他类似的类型检查方法

方法 检查内容 示例
hasNextInt() 是否为整数 “123” → true, “12.3” → false
hasNextLong() 是否为长整数 “12345678901” → true
hasNextDouble() 是否为双精度浮点数 “12.3” → true, “abc” → false
hasNextBoolean() 是否为布尔值 “true”/“false” → true
hasNextLine() 是否还有下一行 按行检查
hasNextBigInteger() 是否为超大整数 任意大小的整数

9.4.4 实际应用场景

场景1：验证用户输入

场景2：混合类型数据处理

场景3：读取文件中的数字

注意事项

  1. 不消耗输入：这两个方法都只检查，不读取输入
  2. 配合使用：通常先用 hasNextInt() 检查，再用 nextInt() 读取
  3. 阻塞问题：从键盘读入时，hasNext() 会阻塞等待输入
  4. 异常安全：使用 hasNextInt() 可以避免 InputMismatchException

9.5 文件写入输出流

在Java中，文件写入输出流通常指的是用于将数据写入到文件中的输出流（OutputStream），最典型的就是 FileOutputStream 类。

字节流

FileOutputStream 是 OutputStream 的子类，它属于字节流。

  • 处理单位：它以 字节（Byte） 为单位进行写入。这意味着它可以处理任何类型的文件，包括文本文件（.txt）、图片（.jpg）、音频（.mp3）等。
  • 工作原理：你把一个字节数组（byte[]）交给它，它就把这些字节原封不动地写到文件中。

9.5.1 FileOutputStream

FileOutputStream以字节为单位向文件写入数据的，适合写入所有类型的文件（文本、图片、视频等）。

写入模式

模式 构造方法 行为
覆盖模式 new FileOutputStream("file.txt") 每次运行都会删除原文件内容，重新写入
追加模式 new FileOutputStream("file.txt", true) 在文件末尾继续添加内容，保留原有数据

使用流程

  1. 创建流对象：打开通往文件的数据通道。
  2. 写入数据：通过通道发送数据。
  3. 关闭流：通道使用完毕，必须关闭以释放系统资源（这一步非常关键）。

基本使用示例

1. 写入字节数据（覆盖模式）
2. 追加模式写入
3. 使用 try-with-resources（推荐）

9.5.2 实际应用场景

1. 文件复制（经典案例）

2. 写入日志文件

注意事项

  1. 自动创建文件：如果输出的文件不存在，FileOutputStream 会自动创建（但目录必须存在）
  2. 覆盖风险：默认模式会清空原文件，小心数据丢失
  3. 编码问题：写入文本时，getBytes() 使用平台默认编码，可能导致乱码
  4. 必须关闭流：否则文件可能被锁定，或数据丢失
  5. flush() 的作用：强制将缓冲区数据写入磁盘，确保数据不丢失
