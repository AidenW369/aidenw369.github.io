内存管理

8.1 内存管理简介

Java内存管理是Java虚拟机（JVM）自动管理内存的机制，主要包括内存分配和内存回收两个核心部分。

8.1.1 Java内存区域划分

1. 堆（Heap）

  • 所有线程共享，存放对象实例和数组
  • 垃圾回收的主要区域（GC堆）
  • 可分为：新生代（Eden、Survivor0、Survivor1）和老年代

2. 栈（Stack）

  • 线程私有，生命周期与线程相同
  • 存储：局部变量表、操作数栈、方法出口等
  • 每个方法执行时都会创建一个栈帧

3. 方法区（Method Area）

  • 线程共享，存储类信息、常量、静态变量等
  • 包含运行时常量池
  • JDK 8以后：元空间（Metaspace）永久替代

4. 程序计数器（Program Counter Register）

  • 线程私有，记录当前线程执行的字节码地址
  • 较小的内存空间

5. 本地方法栈（Native Method Stack）

  • 线程私有，为本地方法（Native方法）服务

8.1.2 垃圾回收机制（GC）

1. 判断对象是否可回收

  • 引用计数法（简单但无法解决循环引用）
  • 可达性分析（主流方式，从GC Roots开始搜索）

2. 垃圾回收算法

  • 标记-清除：标记可回收对象，统一清除
  • 标记-复制：将内存分为两块，只使用一块
  • 标记-整理：移动存活对象，解决碎片问题
  • 分代收集：新生代用复制算法，老年代用标记-整理

3. 常见的垃圾收集器

  • Serial、Parallel（并行收集）
  • CMS（并发标记清除）
  • G1（分区式收集）
  • ZGC（低延迟）

内存分配策略

常见内存问题

  1. 内存泄漏：对象不再使用但无法被回收
  2. 内存溢出：堆内存不足（OutOfMemoryError）
  3. 栈溢出：递归过深（StackOverflowError）

8.3 堆内存和栈内存

堆内存（Heap）和栈内存（Stack）是程序运行时用于存储数据的两种主要内存区域。 它们的管理方式、存储内容和生命周期都有很大的不同。

8.3.1 栈内存 (Stack)

栈内存的特点是 后进先出 ，就像一摞盘子，后放上去的，先用完先拿走。

  • 存储什么：
    • 基本数据类型：例如整数、浮点数、布尔值、字符等，它们直接存储值。
    • 对象引用/指针：当你在方法内创建一个对象（例如 Person p = new Person()），变量 p 本身（也就是指向对象的地址）是存储在栈上的。对象本体则存储在堆上。
    • 方法调用的上下文：每次调用一个方法，Java 虚拟机会在栈上为这个方法创建一个“栈帧”，用来存放方法的局部变量、中间计算结果以及方法的返回地址。方法调用结束，这个栈帧就会被销毁。
  • 如何管理：由程序 自动管理 。方法被调用时，内存自动分配；方法执行完毕，内存自动释放。
  • 优点：分配和释放速度非常快，仅次于 CPU 寄存器。
  • 缺点：灵活性差。内存大小在编译时基本确定，且空间通常较小。如果存放数据过多（比如无限制的递归调用），会导致 栈溢出 错误。

8.3.2 堆内存 (Heap)

堆内存是一个 运行时数据区 ，用来存放程序中所有通过 new 关键字创建的对象和数组。

  • 存储什么：
    • 对象实例：所有通过 new 创建的对象（例如 new Person(), new String()）都存储在堆上。
    • 数组：数组也是对象，所以数组实例也存储在堆上。
  • 如何管理：由 垃圾回收器 自动管理。程序员创建对象，但不需要显式地销毁对象。垃圾回收器会周期性地检查哪些对象不再被任何引用指向，然后回收它们占用的内存。
  • 优点：灵活性高，可以在运行时动态地分配内存大小，只要还有空间，就可以创建新对象。
  • 缺点：分配和访问速度比栈慢，因为堆是更复杂的内存区域。如果创建了太多对象而没有及时回收，会导致 堆溢出 错误。

8.3.3 核心区别总结

特性 栈 (Stack) 堆 (Heap)
存储内容 基本数据类型、对象引用（指针）、方法调用上下文 对象实例、数组
管理方式 自动管理 （方法调用结束即释放） 垃圾回收器管理 （自动回收无用对象）
生命周期 与方法调用同步，生命周期短 从对象创建到不再被引用，生命周期长
存取速度 快 （仅次于寄存器） 相对较慢
内存大小 通常较小（由 JVM 参数控制） 通常较大（由 JVM 参数控制）
数据共享 不支持多线程间共享 多线程可以共享堆上的对象
主要问题 栈溢出 （如无限递归） 堆溢出 （如创建过多对象）

8.4 垃圾回收机制

垃圾回收（Garbage Collection, GC）是Java虚拟机（JVM）自动管理内存的一种机制，它负责：

  • 自动检测并释放不再被程序使用的对象所占用的内存
  • 无需程序员手动释放内存（对比C/C++的malloc/free）

8.4.1 如何判断对象是否可回收

1. 引用计数法（早期方法，已不常用）

  • 每个对象维护一个引用计数器
  • 有引用时+1，引用失效时-1
  • 计数器为0时回收
  • 缺点：无法解决循环引用问题

2. 可达性分析（主流方法）

从GC Roots对象出发，通过引用链无法到达的对象即为可回收对象

8.4.2 垃圾回收算法

算法 原理 优点 缺点
标记-清除 先标记可回收对象，然后统一清除 实现简单 产生内存碎片
标记-复制 将内存分为两块，只使用一块，存活对象复制到另一块 无碎片 内存利用率低
标记-整理 标记后让存活对象向一端移动 无碎片，内存利用率高 移动对象开销大
分代收集 结合多种算法，不同代使用不同算法 综合性能好 实现复杂

最佳实践总结

  1. 最小化变量作用域：在需要的地方定义变量
  2. 及时清理不再使用的引用：特别是大对象
  3. 避免在静态集合中缓存过多数据
  4. 注意内部类和闭包导致的对象逃逸
