Data Structure Module1

数据结构与算法简介

1.1 数据结构

数据结构是计算机存储、组织数据的方式。它不仅指数据在内存中的存储方式，还包括了数据之间的相互关系以及对数据的一系列操作（如增删改查）。

可以把它理解为数据的容器和排列规则。选择合适的数据结构，可以显著提高算法的效率和资源的利用率。

1.1.1 记录（Record） / 结构体（Struct）

  • 定义：记录是一种用于存储不同类型数据项的复合数据结构。在面向对象编程的语言中，它类似于一个没有复杂方法的简单类。在数据库中，它通常指代表中的一行数据。
  • 特点：将逻辑上相关的多个属性（字段）组合成一个单一的单元。
  • 应用场景：
    • 数据库表：如学生表中的一行（包含学号、姓名、年龄）。
    • 文件存储：如读取CSV文件时，每一行数据被解析成一个记录。
    • 网络协议：定义数据包的结构，包含固定的头部和数据负载。

1.1.2 数组（Array）

  • 定义：数组是一种线性数据结构，它在内存中占用一块连续的空间，用于存储相同类型的多个元素。
  • 特点：支持通过索引（下标）进行随机访问，时间复杂度为O（1）。但插入和删除操作（特别是中间位置）较慢，因为需要移动其他元素。
  • 应用场景：
    • 图像处理：图像通常被表示为像素值的二维数组。
    • 矩阵运算：科学计算、机器学习中的矩阵和张量。
    • 查找表：如存储一个月的天数 int days[12] = {31， 28， ...}。
    • 缓存友好：由于数据连续存储，CPU缓存命中率高，适合高性能计算。

1.1.3 链表（Linked List）

  • 定义：链表是一种线性数据结构，元素（节点）在内存中是离散存储的。每个节点包含数据和指向下一个节点的指针。
  • 特点：插入和删除非常快（只需修改指针），但查找元素需要从头遍历（顺序访问），时间复杂度为O（n）。
  • 应用场景：
    • 操作系统：文件系统的FAT表（文件分配表）。
    • 内存管理：空闲内存块通常用链表管理（空闲链表）。
    • 实现复杂数据结构：如栈、队列、图的邻接表通常使用链表实现。
    • 音乐播放器播放列表：可以轻松地插入、删除和切换上一首/下一首歌曲。

1.1.4 二叉树（Binary Tree）

  • 定义：一种树形结构，每个节点最多有两个子节点（左子树和右子树）。最常用的是**二叉搜索树（BST）**及其变种。
  • 特点：结合了有序数组的查找优势（通过二分思想）和链表的插入优势。在理想情况下，查找、插入、删除的时间复杂度都是O（log n）。
  • 应用场景：
    • 数据库索引：许多非关系型数据库使用B-树（B树，一种自平衡树结构）作为索引结构。
    • 文件系统目录：操作系统的目录结构本身就是树形结构。
    • 编译器设计：解析源代码时生成抽象语法树（AST，Abstract Syntax Tree）。
    • 哈夫曼编码：使用二叉树实现数据压缩算法。

1.1.5 哈希表（Hash Table） / 散列表

  • 定义：哈希表根据键（Key）直接访问在内存存储位置的数据结构。它通过哈希函数将键映射到表中的一个位置以加快查找速度。
  • 特点：插入、删除、查找的平均时间复杂度都是O（1）（常数时间），这是非常高效的。但它是无序的，且需要考虑哈希冲突。
  • 应用场景：
    • 数据库索引：某些数据库引擎也使用哈希索引进行等值查询。
    • 缓存系统：如Redis（一种内存数据库）、Memcached（一种分布式内存对象缓存系统）本质上是一个巨大的哈希表。
    • 编译器/解释器：用于维护符号表（变量名 -> 变量信息的映射）。
    • 对象属性存储：JavaScript中的对象、Python中的字典（Dict）都是哈希表的实现。

1.1.6 堆（Heap）

  • 定义：堆是一种特殊的完全二叉树。最大堆的每个节点都大于等于它的子节点，根节点是最大值；最小堆则相反。
  • 特点：专门用于快速获取最大或最小元素。
  • 应用场景：
    • 优先队列：操作系统调度进程时，优先级高的进程先执行。
    • 堆排序：一种时间复杂度为O（n log n）的高效排序算法。
    • 求Top K问题：例如从1亿个数中找出最大的100个数（使用大小为100的最小堆）。
    • 任务调度：定时任务执行器中，最近需要执行的任务排在堆顶。

1.1.7 图（Graph）

  • 定义：图由顶点和连接顶点的边组成。它比树更复杂，可以有环路。
  • 特点：表达多对多的复杂关系。
  • 应用场景：
    • 社交网络：用户是顶点，关注/好友关系是边，用于好友推荐。
    • 地图导航：地点是顶点，道路是边，使用Dijkstra（一种最短路径算法）、A*（一种启发式搜索算法）算法计算最短路径。
    • 推荐系统：如“买了这个商品的用户也买了”。
    • 计算机网络：互联网的路由器构成了巨大的图，使用路由协议寻找最佳路径。
    • 知识图谱：搜索引擎（如Google）使用知识图谱来理解实体之间的关系（如：姚明 与 叶莉 是 夫妻）。

总结

数据结构 核心特点 常用场景
记录 组合不同类型数据 数据库行、对象属性
数组 连续内存、随机访问 矩阵、缓冲区、查找表
链表 离散内存、动态增删 内存管理、实现队列/栈
二叉树 层级结构、快速查找 文件系统、表达式解析
哈希表 键值映射、极速查找 缓存、字典、索引
堆 极值获取 优先队列、Top K问题、定时器
图 复杂关系网络 社交网络、导航、推荐系统

1.2 算法简介

NP问题的全称与核心概念

NP 的全称是 Nondeterministic Polynomial time，即 非确定性多项式时间。

这个概念的核心，并非在于问题是否难解，而在于验证一个解的正确性是否容易。

P 类问题 (Polynomial time)：

这是指那些可以在多项式时间内找到解的问题。简单来说，就是计算机能够“快速”解决的问题。

  • 例子： 对一组数字进行排序、在数据库中搜索一个条目。这些任务都很容易。

NP 类问题 (Nondeterministic Polynomial time)：

这是指那些可以在多项式时间内验证一个解是否正确的问题。

  • 关键点： 对于NP问题，找到答案可能很慢（甚至非常非常慢），但如果你给我一个候选答案，我可以快速地检查它是不是对的。
  • 经典例子： 数独游戏。
    • 找到一个解可能很慢： 一个空白的数独盘，你要尝试很多种数字组合才能填满它。
    • 验证一个解非常快： 如果我给你一个填满的数字盘，你可以很快地检查每一行、每一列、每一个小九宫格是否都包含了1-9且不重复。你不需要知道这个解是怎么来的，只需要验证它是否正确。

NP完全问题与NP难问题

NP完全问题：

这是NP问题中最难的一类。它们有一个神奇的特性：如果我们能够找到一个“快速”（多项式时间）的算法来解决任意一个NP完全问题，那么所有NP问题就都能被“快速”解决。 换句话说，NP完全问题是NP问题复杂性的“标杆”。上面提到的旅行商问题、数独、布尔可满足性问题都属于NP完全问题。

NP难问题：

这类问题不比任何一个NP问题简单，但它们本身可能不属于NP问题（即，可能连验证一个解是否正确都无法在多项式时间内完成）。

P 是否等于 NP？

  • 如果 P = NP：这意味着所有能快速验证的问题，也都能被快速解决。这将带来巨大的变革：现在的许多难题（如药物分子设计、最优路线规划、数学定理自动证明）都将迎刃而解。当然，这也意味着现有的很多加密体系（如RSA加密）将会失效，因为黑客也能快速破解密码了。
  • 如果 P ≠ NP：这意味着有些问题（至少是NP完全问题）天生就是难解的，我们永远无法为它们找到一个高效的通用算法。我们只能退而求其次，寻找近似解、或针对特定情况的有效算法。

目前，绝大多数科学家都倾向于相信 P ≠ NP，但这一点至今未能被严格证明。

总结

特性 P 问题 NP 问题 NP 完全问题 NP 难问题
找解的速度 快速 可能很慢 很慢（目前已知） 很慢
验证的速度 快速 快速 快速 可能很慢
核心比喻 容易做，也容易检查 不容易做，但容易检查 NP里最难的一批 至少和NP一样难，甚至更离谱

1.3 数据结构与算法的关系

1.3.1 相互依存的关系

数据结构是算法的操作对象和载体。

  • 算法在运行过程中，必然需要处理数据。这些数据如何组织、存储在哪里，就是数据结构要考虑的问题。
  • 没有数据结构，算法就没有了操作的“原材料”和“工作台”。一个算法的设计和选择，很大程度上依赖于数据是如何组织的。

算法是数据结构的“使用方法”和“行为逻辑”。

  • 数据结构只是静态地存储数据，而算法定义了如何对这些数据进行操作，比如插入、删除、查找、排序、遍历等。
  • 一个数据结构是否有用、是否高效，是通过在其上运行的算法来体现的。如果没有算法，数据结构就只是一堆杂乱无章的数据。
  • 例子： 你设计了一个“图”这种数据结构，用来表示城市间的航线。如果没有“最短路径算法”（如Dijkstra算法），这个图就只是一个静态的模型，无法帮你找到从北京到上海最便宜的航班。

1.3.2 选择决定了效率：程序 = 数据结构 + 算法

计算机科学家尼古拉斯·沃斯（Niklaus Wirth）曾提出一个著名的公式：程序 = 数据结构 + 算法。这个公式精准地概括了它们的核心地位。

  • 对于一个特定的问题，选择什么样的数据结构，会直接影响到解决问题的算法的效率。
  • 数据结构的选择会影响算法的时间复杂度和空间复杂度。
  • 例子： 实现一个“撤销”功能
    • 方法一： 使用数组来存储操作历史。要撤销时，你需要找到最后一个操作（需要知道数组的长度），然后把它移除。如果数组长度是n，找到最后一个元素的时间是O(1)，但移除后可能需要移动其他元素，最坏情况是O(n)。
    • 方法二： 使用栈（Stack） 这种数据结构。栈的特性就是“后进先出”（LIFO），完美匹配撤销功能。入栈和出栈（撤销）操作的时间复杂度都是O(1)，显然比用数组更简单、更高效。

1.3.3 抽象与实现的关系

  • 抽象数据类型（ADT，Abstract Data Type） 是站在用户角度，描述了一类数据结构的逻辑行为和操作，它定义了“做什么”。比如，字典ADT，你只需要知道它可以插入、删除、查找键值对。
  • 数据结构 则是ADT的具体实现方式，它定义了“如何做”。同一个ADT可以有多种不同的数据结构来实现。
  • 算法 则是实现这些操作的具体步骤。
    • 例子： “字典”这个ADT，可以使用哈希表这种数据结构来实现，其插入和查找算法的平均时间复杂度是O(1)；也可以使用二叉搜索树这种数据结构来实现，其插入和查找算法的平均时间复杂度是O(log n)。选择哪种数据结构，取决于你对算法效率（是查找快更重要，还是有序遍历更重要）的具体需求。

1.4 抽象数据类型（ADT）

  • ADT（抽象数据类型）： 定义了一组操作和行为的逻辑规范，它只关心“能做什么”（如：插入、删除、查找），而不关心“怎么做”。
  • 数据结构： 是ADT的具体实现方式，它关心“怎么做”（如：用数组还是链表来存储数据）。

1.4.1 列表 ADT

这是最基础、最常用的 ADT。它代表一个有序的元素序列。你可以访问、添加或删除其中的元素。

  • 定义的操作：
    • insert(pos, element)：在指定位置插入元素
    • remove(pos)：移除指定位置的元素
    • get(pos)：获取指定位置的元素
    • size()：获取列表长度
  • 常见底层实现：
    • 数组（或动态数组）：
      • 原理： 在内存中开辟一块连续的空间。
      • 优点： 按下标访问非常快（O(1)）。
      • 缺点： 在中间插入或删除元素比较慢，因为需要移动后续所有元素（O(n)）。动态数组（如 Java 的 ArrayList，Python 的 list）在扩容时也会有性能开销。
    • 链表：
      • 原理： 元素在内存中是分散的，每个元素（节点）里存着下一个（或上一个）元素的地址。
      • 优点： 在已知位置的插入和删除非常快（只需修改指针，O(1)）。
      • 缺点： 查找某个位置的元素比较慢，需要从头开始遍历（O(n)）。

1.4.2 栈 ADT

这是一种受限制的列表。它的操作遵循 后进先出 的原则。就像一叠盘子，你总是用最上面的，洗完的新盘子也总是放在最上面。

  • 定义的操作：
    • push(element)：把元素压入栈顶
    • pop()：弹出（移除并返回）栈顶元素
    • peek()/top()：查看栈顶元素但不移除
    • isEmpty()：检查是否为空
  • 常见底层实现：
    • 动态数组： 因为总是在“末尾”进行 push 和 pop，正好利用数组末尾操作快的特性。
    • 链表： 总是在“头部”进行 push 和 pop，也很方便。

1.4.3 队列 ADT

这也是一种受限制的列表。它的操作遵循 先进先出 的原则。就像在电影院排队买票，先来的人先买到票离开。

  • 定义的操作：
    • enqueue(element)：把元素加入队尾
    • dequeue()：从队首移除并返回元素
    • front()：查看队首元素但不移除
  • 常见底层实现：
    • 循环数组： 为了高效利用空间，使用一个固定大小的数组，并用两个指针（头指针和尾指针）来标记队首和队尾。
    • 链表： 在头部进行出队（dequeue），在尾部进行入队（enqueue），也很合适。

1.4.4 优先队列 ADT

这是一种特殊的队列。它不再遵守“先进先出”，而是 谁优先级高，谁先出。

  • 定义的操作：
    • insert(element, priority)：插入一个带有优先级的元素
    • deleteMin() / deleteMax()：移除并返回优先级最高（或最低）的元素
  • 常见底层实现：
    • 堆（Heap）： 这是最经典、最高效的实现方式。堆通常是一个完全二叉树，通常用数组来存储（因为完全二叉树很适合用数组连续存储，父节点和子节点的索引有固定的数学关系，不需要用指针）。比如 Java 的 PriorityQueue，Python 的 heapq。

1.4.5 映射/字典 ADT

这是一个非常重要的 ADT。它存储的是 键值对，通过“键”来快速查找、添加或删除对应的“值”。

  • 定义的操作：
    • put(key, value)：存入键值对
    • get(key)：根据键获取值
    • remove(key)：根据键移除键值对
  • 常见底层实现：
    • 哈希表：
      • 原理： 通过一个哈希函数计算出 key 应该存放的位置（数组下标），然后直接访问。
      • 优点： 平均情况下，查找、插入、删除都非常快（O(1)）。
      • 缺点： 需要处理哈希冲突，且元素是无序的。例如 Python 的 dict，Java 的 HashMap。
    • 平衡二叉搜索树：
      • 原理： 用树的结构来组织数据，保证树的大致平衡。
      • 优点： 元素是有序的。可以方便地找到最大、最小或某个范围内的所有键。
      • 缺点： 基本操作的时间复杂度是 O(log n)，通常比哈希表慢一点。例如 Java 的 TreeMap，C++ 的 map。

1.4.6 集合 ADT

它就像一个数学上的集合。里面是不重复的元素。

  • 定义的操作：
    • add(element)：添加元素（如果已存在则不添加）
    • contains(element)：检查元素是否在集合中
    • remove(element)：移除元素
  • 常见底层实现：
    • 集合的实现通常直接基于字典。可以理解为把字典的“键”拿出来，忽略“值”。或者用“值”来表示元素是否存在。
    • 哈希表 实现的集合（如 Python 的 set，Java 的 HashSet）是无序的。
    • 树 实现的集合（如 Java 的 TreeSet）是有序的。

1.4.7 Deque ADT（双端队列）

发音：通常读作 “Deck”（像”甲板”一样），是 Double-ended queue 的缩写。

顾名思义，它允许你在两端进行插入和删除操作。你可以把它想象成一个管道，两头都是通的。

核心操作

相比于只能在栈顶操作的 Stack（栈）和只能在队首/队尾操作的 Queue（队列），Deque 更加灵活：

  • addFront(element)：在队首插入元素
  • addBack(element)：在队尾插入元素（相当于队列的 enqueue）
  • removeFront()：移除并返回队首元素（相当于队列的 dequeue 和栈的 pop）
  • removeBack()：移除并返回队尾元素
  • getFront() / getBack()：查看两端元素

和 Stack、Queue 的关系

  • 如果禁用 addFront 和 removeFront，Deque 就变成了 Queue（只能从一端进，另一端出）。
  • 如果禁用 addFront 和 removeBack（即只操作同一端），Deque 就变成了 Stack。

1.4.8 Bag ADT（包 / 多重集合）

这是一个在很多教科书里单独讲解，但在实际编程语言中较少作为独立接口出现的 ADT。它的另一个名字更能说明其本质：Multiset（多重集合）。

如果说 Set 是”装了各种球的袋子，每种颜色的球只能有一个”，那么 Bag 就是一个普通的袋子，你可以往里面随便扔东西，不在乎顺序，也允许重复。

核心操作

Bag 强调收集和计数：

  • add(element)：添加一个元素（允许重复）
  • remove(element)：移除一个元素（通常只移除一个匹配项）
  • count(element)：返回该元素在 Bag 中出现的次数（这是 Bag 区别于 List 的关键）
  • size()：返回袋子中所有元素的总个数（包含重复计数）

底层实现

通常用哈希表来实现，只是表的 Key 是元素，Value 是出现次数（计数器）。

举个例子帮你区分 Bag 和 Set

假设你数桌子上硬币的个数：

  • 如果你关心的是有哪些面值（比如有1元、5角、1角），你在用的是 Set。
  • 如果你关心的是总共有多少钱（比如2个1元，3个5角，5个1角），你在用的是 Bag。

底层实现

通常用双向链表（每个节点有前后指针）或者循环数组来实现，因为这两种结构都能高效地在两端进行操作。

总结

ADT 核心特点 常见的底层数据结构（怎么做）
列表 线性序列，按位置访问 动态数组、链表
栈 后进先出 动态数组、链表
队列 先进先出 循环数组、链表
优先队列 按优先级出队 堆（本质是一个数组）
字典/映射 键值对，通过键访问 哈希表、平衡二叉搜索树
集合 不重复的元素 哈希表、平衡二叉搜索树

1.5.2 核心ADT及其适用场景

1. List（列表）

适用场景：需要有序集合，可以通过索引访问元素

  • ArrayList

    • ✅ 适合：频繁随机访问、较少插入删除、主要在末尾添加元素
    • ❌ 不适合：频繁在中间插入/删除元素
    • 典型应用：配置数据列表、缓存数据、大多数查询为主的场景

  • LinkedList

    • ✅ 适合：频繁在任意位置插入/删除、需要实现队列/双端队列
    • ❌ 不适合：频繁随机访问
    • 典型应用：LRU缓存实现、消息队列、撤销操作记录

2. Set（集合）

适用场景：需要元素唯一性，不需要重复元素

  • HashSet

    • ✅ 适合：不需要有序、快速查找去重
    • 典型应用：用户权限集合、已处理ID记录、数据去重

  • LinkedHashSet

    • ✅ 适合：需要保持插入顺序的唯一集合
    • 典型应用：最近访问记录、按添加顺序的去重列表

  • TreeSet

    • ✅ 适合：需要自动排序的唯一集合

    • 典型应用：排行榜、自动排序的配置项、范围查询

3. Map（映射）

适用场景：需要键值对存储，通过键快速查找值

  • HashMap

    • ✅ 适合：大多数键值对场景，无顺序要求
    • 典型应用：缓存系统、配置属性、对象映射关系

  • LinkedHashMap

    • ✅ 适合：需要保持插入顺序或访问顺序的Map
    • 典型应用：LRU缓存实现、有序配置加载

  • TreeMap

    • ✅ 适合：需要按键排序的Map
    • 典型应用：范围查询、字典排序、按时间戳的日志

  • ConcurrentHashMap

    • ✅ 适合：多线程环境下的键值对存储

    • 典型应用：共享缓存、计数器、会话管理

4. Queue/Deque（队列/双端队列）

适用场景：需要按特定顺序处理元素

  • ArrayDeque
    • ✅ 适合：作为栈或队列使用，比Stack和LinkedList性能更好
    • 典型应用：任务调度、表达式求值、撤销操作
  • PriorityQueue
    • ✅ 适合：需要按优先级处理元素的场景
    • 典型应用：任务优先级调度、Dijkstra算法、霍夫曼编码
  • BlockingQueue（及其实现）
    • ✅ 适合：生产者-消费者模式，需要线程安全的队列
    • 典型应用：线程池任务队列、消息中间件

特殊场景建议

  1. 大数据量处理：考虑使用EnumMap（键为枚举类型）或EnumSet，性能更好
  2. 需要统计频率：使用HashMap配合AtomicInteger或LongAdder
  3. 不可变集合：Java 9+的List.of()、Set.of()、Map.of()
  4. 需要空值安全：考虑使用Optional包装或Collections.emptyXXX()
