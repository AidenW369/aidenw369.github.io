搜索与算法分析

2.1 算法效率

算法效率，简单来说，就是衡量一个算法在解决问题时对计算机资源（主要是时间和内存）的消耗程度。

评价算法效率主要看两个核心指标：

  • 时间复杂度：算法运行需要的时间，随输入数据量的增长如何变化。
  • 空间复杂度：算法运行额外占用的内存，随输入数据量的增长如何变化。

2.1.1 时间复杂度

指算法运行时间随输入规模 n 增长的变化趋势。它是对算法效率的抽象描述，通常用大O表示法来刻画。

  1. O(1) —— 常数时间

    • 描述：无论数据量多大，执行时间都恒定。

    • 例子：在数组里通过下标直接取数 arr[500]；判断一个数是奇数还是偶数。

    • 比喻：直接翻到第500页，一秒钟搞定。无论电话簿是100页还是1万页，都是一瞬间。

  2. O(log⁡n) —— 对数时间

    • 描述：数据量翻倍，时间只增加一个常数步。

    • 例子：二分查找。每次查找都排除一半的数据。

    • 比喻：你翻开电话簿的中间，发现“L”在右边，于是丢掉左边一半；再翻剩余部分的中间……直到找到目标。1000页的电话簿，最多只需要翻10次（210≈1000210≈1000）。

  3. O(n) —— 线性时间

    • 描述：时间随数据量线性增长。数据量变成10倍，时间也变成10倍。
    • 例子：遍历一个数组找出最大值；简单的循环。
    • 比喻：从第一页开始，一页一页地找名字。如果电话簿厚了10倍，找的时间也长了10倍。

  4. O(nlog⁡n) —— 线性对数时间

    • 描述：这是比较高效的排序算法能达到的效率。
    • 例子：归并排序、快速排序（平均情况）。
    • 比喻：这类似于将电话簿拆分成小份分别整理，再合并。这是处理大规模数据时比较理想的时间复杂度。

  5. O(n^2) —— 平方时间

    • 描述：数据量翻倍，时间变成4倍。
    • 例子：冒泡排序、选择排序；双层嵌套循环。
    • 比喻：你拿着电话簿里的每一个名字，去跟电话簿里的其他所有名字比对一遍。当页数翻倍时，比对次数变成了4倍。

  6. O(2^n) —— 指数/阶乘时间

    • 描述：数据量稍微增加一点，时间就爆炸性增长。
    • 例子：递归计算斐波那契数列（未经优化）、旅行商问题的暴力解法。
    • 比喻：尝试所有可能的排列组合。当名字从10个变成20个时，可能全宇宙的计算机算到宇宙毁灭也算不完。
情况 含义 快速排序示例 实际意义
最佳情况 输入最有利时，算法达到的最优表现 数组已完全排好序（且使用三数取中法）→ O(nlog⁡n) 意义不大，因为不总能遇到最优输入
最坏情况 输入最不利时，算法的最差表现 数组已排好序，且每次选第一个元素作基准 → O(n2) 最重要，因为它决定了算法的上界和稳定性
平均情况 对所有可能输入的概率加权平均 随机排列的数组 → O(nlog⁡n) 最接近真实使用场景，但计算复杂

为什么最坏情况最重要？

在工程和面试中，最坏情况复杂度往往是第一关注点。原因很简单：

  • 保证性：知道最坏情况，就知道算法“再差也不会差过这个底线”。对于实时系统（比如自动驾驶、手术设备），不能接受某个输入让程序突然卡死。
  • 防御性：如果用户或攻击者可以构造恶意输入（比如让排序退化成 O(n2) 的输入），你不希望系统被轻易拖垮。

因此，当我们说一个算法“时间复杂度是 O(nlog⁡n) 时，通常是指最坏情况，除非特别说明是平均情况。

运行时复杂度的完整表达

在严谨的算法分析中，我们通常会这样表述：

算法 A 的时间复杂度：

  • 最坏情况：O(f(n))
  • 平均情况：O(g(n))
  • 最佳情况：O(h(n))

比如快速排序的完整描述就是：

  • 最坏：O(n2)
  • 平均：O(nlog⁡n)
  • 最佳：O(nlog⁡n)

2.1.2 空间复杂度

算法的空间复杂度是衡量算法在运行过程中临时占用存储空间大小的量度。

它不仅关注算法本身代码所占的空间（通常是固定的），更关注输入数据所占的空间以及算法运行时额外申请的临时空间。

空间复杂度通常用大 O 符号（Big O notation）来表示，反映了空间需求与数据规模 n 之间的增长关系。

常见的空间复杂度量级

O(1) —— 常数空间

  • 含义：无论输入数据量 n 有多大，算法所需要的额外内存空间都是固定的，不随 n 变化。
  • 例子：冒泡排序、插入排序、交换两个变量的值。

O(n) —— 线性空间

  • 含义：算法需要的额外空间与输入规模 n 成正比。
  • 例子：归并排序（临时数组）、深度优先搜索（DFS）中的递归栈、复制一个数组。

O(n^2) —— 平方空间

  • 含义：空间需求与 n 的平方成正比。
  • 例子：存储一个 n×n 的二维矩阵（如动态规划中的二维DP表，当无法状态压缩时）。

2.1.3 空间复杂度 vs 时间复杂度

在算法分析中，通常需要在空间和时间之间做权衡（即时空权衡）：

  • 拿空间换时间：比如动态规划中的记忆化搜索，通过存储中间结果（消耗更多内存），避免重复计算（节省时间）。
  • 拿时间换空间：比如递归，虽然代码简洁，但递归调用会占用大量的栈空间（每次递归都要保存现场），且函数调用本身有一定时间开销。

2.2 搜索和算法（线性查找）

线性搜索的时间复杂度用大O表示法表示：

  • 最好情况 O(1)：目标元素在第一个位置

  • 最坏情况 O(n)：目标元素在最后一个位置或不存在

  • 平均情况 O(n)：目标元素在中间某个位置

2.3 二分查找

二分查找（Binary Search）是一种在有序数组中查找特定元素的高效算法。它的核心思想是分而治之，每次将查找范围缩小一半。

核心原理

  1. 每次比较数组中间元素与目标值
  2. 如果相等，返回索引
  3. 如果中间元素大于目标值，在左半部分继续查找
  4. 如果中间元素小于目标值，在右半部分继续查找
  5. 重复直到找到目标或范围为空

使用Java标准库实现二分查找

确定索引值-向下取整原则

  • 在Java的二分查找实现中，通常通过计算中间索引来确定第一个要比较的元素。
  • 中间索引 mid = (low + high) / 2
  • 整数除法会自动舍弃小数部分（即向下取整）

例如数组 [0, 1, 2, 3, 4, 5]，中间索引 = (0 + 5) / 2 = 2.5，向下取整为2，通常为左边数值。

向下取整：|3.8| = 3 |-2.4| = -3

2.4 常量时间运算

在算法分析中，常量时间运算指的是：无论输入数据的规模（n）有多大，该运算所花费的时间都保持固定，不会随着 n 的增长而增加。用大 O 符号表示，就是 O(1)。

核心特征

  1. 与输入规模无关
    操作的执行步数不依赖于输入大小 n。例如：
    • 访问数组中的某个元素：arr[i]
    • 执行基本的算术运算：a + b、x * y
    • 比较两个数的大小：if (a > b)
    • 给变量赋值：int x = 5
  2. 不代表“一秒钟”
    “常量”指的是增长阶数，而不是绝对时间。一个 O(1) 的操作可能执行了 100 条指令，但只要它不随 n 增长，就仍是常量时间。

2.4.3 不同编程语言之间的执行绝对时间

同样逻辑的代码在不同编程语言中，常量时间运算的实际耗时可能不一致，但它们在算法分析中的大O复杂度分类仍然是 O(1)。

示例：整数加法

语言 相对耗时 原因
C/C++ 极快（1-2 CPU指令） 直接编译为机器码，操作CPU寄存器
Java 较快 JIT编译后接近C，但仍有JVM开销
Python 较慢 整数是对象，需要解引用、类型检查、内存管理
JavaScript 中等 JIT优化后较快，但动态类型有额外检查

总结

维度 是否一致 说明

实际执行时间 ❌ 不一致 解释型 vs 编译型，动态类型 vs 静态类型，对象开销等

关键结论：常量时间运算是理论概念（大O分析），在不同语言中这个标签是一致的。但实际性能会因语言实现、运行时环境、硬件等差异很大。优秀的程序员既要知道理论上的复杂度，也要了解具体语言在实际执行时的表现。

2.5 算法的复杂性增长

复杂性的增长是指随着输入规模 n 变大，算法所消耗的资源（通常是时间或内存）会如何变化。

例如：

  • 一个排序算法的功能是把一组无序数排成有序。
  • 它的复杂度增长可能表现为：当 n 翻倍时，运行时间也大致翻倍（线性），或者变成原来的4倍（平方）。

这种增长我们用增长率来描述，目的是为了在不同算法之间进行比较，并预测算法在大输入下的表现。

2.5.1 上界和下界

上界 O(⋅)
表示算法在最坏情况下的复杂度不会超过**某个增长速度。
例如 T*(n)=O(*n^2) 意味着当 n 足够大时，算法运行时间至多与 n^2 成正比（忽略常数与低阶项）。
通常我们通过分析算法的逻辑结构得到上界。

下界 Ω(⋅)
表示在最坏情况下，算法的复杂度至少是某个增长速度。
例如 T(n)=Ω(nlog⁡n) 说明在最坏情况下，算法所需时间至少与 nlog⁡n 成正比。
有时下界是对某个问题而言的（即任何解决该问题的算法都必须满足这个下界），这称为问题的下界。

紧确界 Θ(⋅)
当上界和下界相同时，我们说算法的复杂度是 Θ(f(n))，即增长率精确为 f(n) 的量级。

2.5.2 增长率与渐近符号

增长率是比较算法效率的核心，指的是当 n→∞时，函数的行为趋势。
渐近符号就是用来数学化描述增长率的工具。

  • O（大O）：渐近上界。
    f(n) = O(g(n)) 表示存在常数 c > 0,n0​，使 0 ≤ f(n) ≤ cg(n) 对所有 n ≥ n0​ 成立。

  • Ω（大Omega）：渐近下界。
    f(n) = Ω(g(n)) 表示存在 c > 0,n0​，使 0 ≤ cg(n) ≤ f(n)对所有 n ≥ n0​ 成立。

  • Θ（大Theta）：渐近紧界。
    f(n) = Θ(g(n))表示 f(n) = O(g(n))且 f(n) = Ω(g(n))，即增长率与 g(n) 同阶。

它们之间的关系

  • 功能决定算法是什么，而复杂性增长决定算法在规模变大时的可行性。
  • 我们通过上界（算法保证不超过）与下界（问题本身或算法至少需要）来刻画复杂性。
  • 渐近符号用来精确比较增长率，忽略常数和低阶项，让我们能聚焦在核心增长趋势上。

2.6 大O表示法

算法的大O表示法（Big O notation）是用于描述算法效率（时间复杂度或空间复杂度）随着输入规模增长时，其变化趋势的数学表示方法。它关注的是“当输入规模足够大时，算法的运行时间或内存占用如何增长”。

大O表示法忽略常数因子和低阶项，只关注主要增长趋势。

2.6.1 常见的大O复杂度

大O表示法 名称 说明 示例
O(1) 常数时间 无论输入多大，执行时间不变 数组按索引访问、哈希表查找
O(log n) 对数时间 每次操作将规模减半 二分查找、平衡二叉搜索树操作
O(n) 线性时间 与输入规模成正比 简单循环遍历数组
O(n log n) 线性对数时间 常见于高效排序算法 归并排序、快速排序（平均情况）
O(n²) 平方时间 嵌套循环遍历二维数据 冒泡排序、选择排序
O(2ⁿ) 指数时间 每增加一个元素，时间翻倍 递归求解斐波那契数列（未优化）
O(n!) 阶乘时间 极慢，仅适用于极小输入 旅行商问题的暴力解法

关键点

  1. 最坏情况：大O通常描述最坏情况下的增长趋势（但也可用于平均情况）。
  2. 丢弃低阶项和常数。
  3. 空间复杂度：同样可以用大O表示内存占用，如 O(n) 表示额外空间与输入规模成线性关系。

注意事项

  • 大O是渐近分析，对于小规模数据，常数较大的 O(n) 可能比常数小的 O(n2) 慢。
  • 实际应用中需要结合常数因子、硬件环境和输入特征综合评估。

2.6.2 计算规则

1. 只考虑最高阶项

当 n 趋向无穷大时，低阶项和常数系数对增长趋势的影响可以忽略不计。

  • 忽略低阶项：T(n)=n2+n 的复杂度为 O(n2)。
  • 忽略常数系数：T(n)=3n 的复杂度为 O(n)；T(n)=2n^2的复杂度为 O(n^2)。
  • 常数时间：无论输入大小，执行时间固定，均为 O(1)。

2. 加法规则

如果算法由顺序执行的两部分组成，总复杂度取增长更快的那个：

O(f(n)) + O(g(n)) = O(max⁡(f(n), g(n)))

3. 乘法规则

嵌套循环/复合操作时，复杂度相乘：

O(f(n)) × O(g(n)) = O(f(n)⋅g(n))

4. 常见递归复杂度

递归形式 示例 复杂度
T(n) = 2T(n/2) + O(1) 二叉树遍历 O(n)
T(n) = 2T(n/2) + O(n) 归并排序 O(n log n)
T(n) = T(n−1) + O(1) 递归求和 O(n)
T(n) = T(n−1) + O(n) 快速排序最坏情况 O(n²)
T(n) = 2T(n−1) + O(1) 斐波那契递归 O(2ⁿ)

2.7 算法分析

分析算法的最坏时间复杂度，核心在于确定输入规模与基本操作执行次数之间的函数关系，并取其增长最快的项作为渐进上界。

2.7.1 明确分析目标

最坏时间复杂度关注的是：对于任意规模为 n 的输入，算法所需执行的基本操作次数的最大值。

它通常用大 O 表示法描述，即 T(n)=O(f(n))，表示存在常数 c 和 n0，使得当 n≥n0时，T(n)≤c⋅f(n)。

2.7.2 具体分析步骤

1. 确定输入规模

明确哪个参数代表问题规模，如：

  • 数组长度 n
  • 矩阵维度 n×n
  • 图的顶点数 V 和边数 E

2. 识别基本操作

基本操作是算法中耗时最多的“原子操作”，通常是：

  • 比较（如 if (a[i] > a[j])）
  • 赋值（如 temp = a[i]）
  • 算术运算（如 sum += a[i]）

在循环或递归中，最内层循环体中的操作往往成为主导。

3. 分析执行次数

根据算法结构，统计基本操作执行的最坏情况次数：

  • 顺序结构：直接相加。
  • 分支结构：取分支中最大执行次数。
  • 循环结构：
    • 单层循环：执行次数为循环次数。
    • 多层循环：通常为各层循环次数的乘积（注意循环变量是否依赖外层）。
  • 递归结构：建立递推关系式并求解。

4. 构造最坏情况输入

思考哪种输入会导致基本操作次数最大。例如：

  • 排序算法：输入完全逆序（对于冒泡排序）或已排序（对于快速排序的某些枢轴选择）。

  • 查找算法：目标元素在末尾或不存在。

5. 用大 O表示

忽略低阶项和常数系数，只保留增长最快的项。

2.7.3 常见误区与注意事项

  1. 不要将平均情况与最坏情况混淆
    例如快速排序平均为 O(nlog⁡n)，但最坏为 O(n^2)。

  2. 注意递归深度与每层工作量的平衡
    如归并排序每层 O(n)，深度 log⁡n，总复杂度 O(nlog⁡n)。

  3. 区分“输入规模”与“输入值”
    例如判断一个数是否为质数，输入规模是数的位数 d，而非数值本身，此时 O(n)实际上是关于 n 的指数级（因为 n 是 2^d 量级）。

  4. 大 O 是上界，不一定是紧确界
    如果分析得到 O(n^2)，但实际是 O(n)，说明上界放得太宽，应寻找更紧的界。
