11.1 异常处理

异常处理是Java编程中用于管理程序运行时出现的异常情况（错误）的机制。它允许程序在遇到问题时能够优雅地处理，而不是直接崩溃。

异常是程序执行过程中出现的打断正常流程的事件。在Java中，异常被表示为对象，这些对象描述了错误的类型、发生位置等信息。

11.1.1 异常的分类

  • Error：严重问题，如内存溢出(OutOfMemoryError)，程序通常无法处理
  • 受检异常(Checked Exception)：编译时强制处理的异常，如IOException、SQLException
  • 非受检异常(Unchecked Exception/RuntimeException)：运行时可能出现的异常，如NullPointerException、ArrayIndexOutOfBoundsException

11.1.2 异常处理的关键字

关键字 作用
try 监控可能抛出异常的代码块
catch 捕获并处理特定类型的异常
finally 无论是否发生异常都会执行的代码块（如资源清理）
throw 手动抛出异常
throws 在方法声明中声明可能抛出的异常

11.1.3 捕获异常

捕获异常是指使用try-catch语句块来拦截和处理程序运行时出现的异常情况。

11.1.4 常见异常类型

1. 运行时异常（RuntimeException）

这些异常通常由程序逻辑错误引起，编译器不强制处理。

异常类型 描述 示例场景
NullPointerException 空指针异常，调用null对象的方法或属性 String str = null; str.length();
ArrayIndexOutOfBoundsException 数组索引越界 int[] arr = new int[3]; arr[5] = 10;
ArithmeticException 算术异常，如除零 int result = 10 / 0;
ClassCastException 类型转换异常 Object obj = "String"; Integer num = (Integer)obj;
NumberFormatException 数字格式异常 Integer.parseInt("abc");
IllegalArgumentException 非法参数异常 方法接收到不合法参数时
IndexOutOfBoundsException 索引越界异常 String str = "abc"; str.charAt(5);
ConcurrentModificationException 并发修改异常 遍历集合时修改集合

2. 受检异常（Checked Exception）

编译器强制要求处理的异常，要么try-catch，要么throws声明。

异常类型 描述 示例场景
IOException IO操作异常 文件读写、网络操作失败
FileNotFoundException 文件未找到 new FileInputStream("不存在.txt");
SQLException 数据库操作异常 数据库连接失败、SQL语法错误
ClassNotFoundException 类未找到 Class.forName("com.xxx.XXX");
InterruptedException 线程中断异常 Thread.sleep(1000); 被中断
NoSuchMethodException 方法未找到 反射调用不存在的方法
ParseException 解析异常 日期字符串解析失败

3. 错误（Error）

严重的系统级问题，程序通常无法处理。

错误类型 描述 发生场景
OutOfMemoryError 内存溢出 创建过多对象，内存不足
StackOverflowError 栈溢出 递归调用过深
NoClassDefFoundError 类定义未找到 类文件存在但无法加载
VirtualMachineError 虚拟机错误 JVM内部错误

捕获异常的最佳实践

  1. 精确捕获：尽量捕获具体的异常类型，而不是通用的Exception
  2. 合理处理：不要只是打印异常，要根据业务做适当处理
  3. 资源清理：使用finally或try-with-resources确保资源释放
  4. 异常包装：可以将低层异常包装成业务异常抛出
  5. 日志记录：使用日志框架记录异常信息，而不是e.printStackTrace()

在Java中，抛出异常是指当程序运行过程中遇到错误或意外情况时，创建一个异常对象并将其传递给运行时系统的过程。这个过程使用throw关键字来完成。

  • 继承自Exception（除了RuntimeException）

2. 非检查型异常（Unchecked Exception）

  • 可以不显式处理
  • 继承自RuntimeException

11.3 方法抛出异常

在Java中，方法抛出异常是指在方法执行过程中，遇到异常情况时，通过throw关键字主动创建一个异常对象并交给JVM处理，或者在方法声明中使用throws关键字告知调用者该方法可能抛出某些异常。

使用throw和throws可以让代码更清晰地表达异常处理逻辑，提高代码的可读性和健壮性。

11.4 用户自定义异常

用户自定义异常是开发者根据应用程序特定需求创建的异常类，用于处理业务逻辑中的特殊错误情况。

继承自Exception（受检异常）或RuntimeException（非受检异常）的类，用于表示应用程序特有的错误条件。

用户自定义异常让代码更具可读性和可维护性，通过封装特定的错误信息和业务逻辑，使异常处理更加精确和有意义。

11.4.3 最佳实践

✅ 适合使用自定义异常的场景：

  • 业务规则违反（如余额不足、年龄无效）
  • 特定于应用程序的错误条件
  • 需要传递额外的错误信息（错误码、错误字段等）
  • 区分不同类型的业务错误

❌ 不适合使用自定义异常的场景：

  • 已存在标准异常可以表达的情况（如IllegalArgumentException）

  • 系统级错误（IO错误、SQL错误等）

11.5 文件异常

在Java中，文件异常是指在进行文件输入/输出操作时，由于各种原因导致操作失败而抛出的异常。这些异常通常继承自IOException类或其子类。

11.5.1 常见的文件异常类型

1. FileNotFoundException

最常见的文件异常，当文件不存在或无法访问时抛出。

2. IOException

IO操作失败时的通用异常，是所有文件异常的父类。

3. SecurityException

当没有足够权限访问文件时抛出。

4. EOFException

在读取文件时意外到达文件末尾抛出。

11.5.2 文件异常的常见原因

  1. 文件不存在
  2. 路径错误
  3. 权限不足（只读文件尝试写入）
  4. 磁盘空间已满
  5. 文件正在被其他程序占用
  6. 文件损坏

11.5.3 异常处理方式

1. try-catch 处理

2. throws 声明异常

3. try-with-resources (自动关闭资源)

最佳实践

  1. 始终处理异常：不要忽略文件异常
  2. 提供有用的错误信息：让用户知道出了什么问题
  3. 使用finally或try-with-resources：确保文件资源被正确关闭
  4. 验证文件状态：操作前检查文件是否存在、是否可读等

11.5.4 finally代码块

finally代码块是Java异常处理机制中的重要组成部分，无论是否发生异常，finally块中的代码都会被执行。

主要作用

1. 释放资源

最常见的用途是释放系统资源，防止资源泄漏。

2. 清理操作

执行必要的清理工作，如关闭数据库连接、网络连接等。

finally的执行特性

  1. 无论如何都会执行

  2. 在return之前执行

  3. 异常情况也会执行

总结

  • finally保证清理代码的执行，无论是否发生异常
  • 主要用于释放资源（文件流、数据库连接等）
  • 避免在finally中改变返回值或抛出异常
  • 现代Java开发优先使用try-with-resources替代finally的资源释放

try-with-resources 是 Java 7 引入的特性，可以自动关闭实现了 AutoCloseable 接口的资源，让代码更简洁、更安全。
