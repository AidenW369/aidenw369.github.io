继承

10.1 派生类（子类）

继承是Java面向对象编程的核心特性之一，它允许一个类（子类）基于另一个类（父类）来创建，从而复用父类的属性和方法。

在Java中，派生类（Derived Class）是指通过继承（extends）从另一个类创建而来的类。

简单来说：

  • 被继承的类叫做基类（Base Class）、父类（Super Class）或超类。
  • 继承得来的类就叫做派生类（Derived Class）、子类（Sub Class）。

核心概念：复用与扩展

派生类会自动拥有父类的非私有成员（属性和方法），同时开发者可以在派生类中添加新的成员或修改（重写）继承来的方法。这体现了面向对象编程的复用性和扩展性。

语法结构

派生类的特点

当 Dog 类继承了 Animal 类后：

  1. 拥有父类的成员：虽然 Dog 类里没有写 name 属性和 eat() 方法，但它可以直接使用它们（前提是访问权限允许，如 public 或 protected）。
  2. 可以定义新成员：Dog 类独有的 bark() 方法。
  3. 可以重写方法：Dog 类重新定义了 eat() 方法，覆盖了父类的行为。

继承的优点

  1. 代码复用：避免重复编写相同的代码
  2. 逻辑清晰：体现is-a关系（Dog is an Animal）
  3. 易于维护：修改父类代码，所有子类自动生效
  4. 多态基础：是实现多态的前提条件

  • public成员在任何地方可访问

  • final类不能被继承
  • final方法不能被重写

10.2 派生类的成员访问

在Java中，派生类（子类）对成员的访问权限主要取决于访问修饰符（private、default、protected、public）以及成员是否被隐藏或重写。

10.2.1 访问修饰符的影响

修饰符 类内部 同包子类 异包子类 全局
private ✅ 可以 ❌ 不能 ❌ 不能 ❌ 不能
default （或不写） ✅ 可以 ✅ 可以 ❌ 不能 ❌ 不能
protected ✅ 可以 ✅ 可以 ✅ 可以 ❌ 不能
public ✅ 可以 ✅ 可以 ✅ 可以 ✅ 可以

关键点：

  • private：完全私有，子类不能直接访问。如果需要访问，必须通过父类提供的 public 或 protected 的 getter/setter 方法。
  • protected：最常用于继承。它允许子类访问，即使子类在不同的包中，也阻止了不相关的类访问。
  • default（包级私有）：只有在同一个包中的子类才能访问。

10.2.2 成员变量：隐藏与访问

如果子类定义了与父类同名的成员变量（实例变量或静态变量），这称为隐藏（Hiding），而不是重写。

  • 现象：子类拥有两个同名的变量（一个来自父类，一个来自子类）。
  • 访问规则：
    • 在子类内部直接使用变量名，默认访问的是子类自己的变量。
    • 如果子类方法中想访问父类被隐藏的变量，需要使用关键字 super。

10.2.3 成员方法：重写与访问

如果子类定义了与父类相同签名的方法（非静态），这称为重写（Overriding）。

  • 现象：父类的方法在子类中被覆盖。
  • 访问规则：
    • 在子类内部直接调用方法名，默认调用的是子类重写后的方法。
    • 如果想在子类内部调用父类中被重写的原始方法，需要使用 super。
    • 注意：静态方法不存在重写，只有隐藏，调用方式取决于引用类型。

10.2.4 构造器的特殊之处

构造器不能被继承，但子类构造器必须（直接或间接）调用父类构造器。

  • 隐式调用：如果子类构造器第一行没有显式写 super(...)，编译器会自动添加 super()（调用父类的无参构造器）。如果父类没有无参构造器，编译会报错。
  • 显式调用：可以在子类构造器第一行使用 super(参数) 来指定调用父类的哪个构造器。

总结

在派生类中访问成员，遵循以下原则：

  1. 先看修饰符：private 直接不能动，default 看包，protected 放心用。
  2. 变量看声明类型：直接写变量名 -> 当前类；想拿父类的 -> 用 super。
  3. 方法看对象类型：直接写方法名 -> 调用当前对象（this）的重写方法；想调被覆盖的父类原版 -> 用 super。
  4. 构造器必须调：子类构造器必须通过 super(...) 链式调用父类构造器。

10.3 重写成员方法

在Java继承中，重写（也被称为覆盖，英文是 Override）是指子类定义一个与父类中完全相同的方法（方法名、参数列表、返回值类型都相同），以取代或修改从父类继承而来的方法行为。

当父类的某个方法不能满足子类的特定需求时，子类可以通过重写，提供自己特有的实现逻辑，同时保留方法的名称和形式，以便于统一调用。

方法重写是子类根据自身需求，对继承自父类的方法进行改造或替换的一种机制。它是实现Java多态性的基础。

10.3.1 重写的核心规则

在Java中，方法重写必须遵循以下规则（主要是为了保持多态性）：

  1. 方法签名必须相同：子类重写的方法必须和父类被重写的方法具有相同的方法名和参数列表。
  2. 返回值类型：子类重写方法的返回值类型可以是父类方法返回值类型的子类型（这被称为协变返回类型，Java 5之后支持）。但通常情况下，为了清晰，建议保持一致。
  3. 访问权限：子类重写方法的访问修饰符不能比父类的更严格（即权限可以相同或更宽）。
    • 例如：父类方法是 protected，子类可以是 protected 或 public，但不能是 private。
  4. 不能重写静态方法：只有实例方法可以被重写。静态方法属于类，如果子类定义了与父类相同的静态方法，那叫做隐藏，而不是重写。
  5. final 和 private 方法不能重写：
    • 被 final 修饰的方法不能被重写。
    • private 方法是子类不可见的，所以不能重写。
  6. 注解 @Override：虽然不是语法强制要求，但强烈建议在重写的方法上加上 @Override 注解。这可以让编译器帮你检查是否正确地进行了重写（例如，如果父类没有这个方法，编译器会报错）。

关键点：动态绑定

当你通过父类引用（如 Animal myAnimal = new Dog()）调用一个被重写的方法时，Java 虚拟机会根据实际创建的对象类型（这里是 Dog）来决定运行哪个版本的方法，而不是根据引用的类型（Animal）。

这被称为动态绑定或运行时多态，是Java面向对象编程的核心特性之一。

调用父类被重写的方法

如果在子类中重写了父类的方法，但仍然想调用父类原来的实现，可以在子类的方法体内使用 super 关键字。

10.5 多态 Polymorphism

多态是Java面向对象编程的三大特性之一（封装、继承、多态），指同一个行为具有多个不同表现形式或形态的能力。父类引用指向子类对象，调用方法时表现出子类的行为。

多态是Java面向对象编程的核心特性，它通过"父类引用指向子类对象"的方式，让我们可以面向抽象编程，而不是面向具体实现编程，大大提高了代码的灵活性和可扩展性。

10.5.1 多态的两种形式

1. 编译时多态（方法重载）

在同一个类中，方法名相同但参数列表不同。

2. 运行时多态（方法重写）

子类重写父类的方法，通过父类引用调用时执行子类的方法。

多态的实现条件

  1. 继承（或实现接口）
  2. 方法重写（Override）
  3. 父类引用指向子类对象

10.6 ArrayList对象

ArrayList 是Java集合框架中的一个类，位于 java.util 包中。它实现了 List 接口，是一个动态数组，可以根据需要自动调整大小。

是Java中最常用的集合类之一，它提供了灵活性和丰富的功能，适合大多数需要动态数组的场景。

10.6.1 核心特点

1. 动态大小

  • 传统数组的大小是固定的，而ArrayList可以动态增长和缩小
  • 初始容量默认是10，当元素数量超过容量时，会自动增长50%

2. 有序集合

  • 维护元素的插入顺序
  • 可以通过索引访问元素（从0开始）

3. 允许重复元素

  • 可以存储重复的对象
  • 允许存储null值

特性 ArrayList 普通数组

使用场景

  • 需要频繁添加/删除元素
  • 不确定数据量大小
  • 需要集合框架提供的方法（如排序、查找等）

❌ 不适合使用ArrayList的情况：

  • 需要处理基本数据类型（考虑使用原始数组或对应的包装类）
  • 对性能要求极高且大小固定
  • 需要多维数据结构（虽然可以创建ArrayList的ArrayList）

注意事项

  1. 线程不安全：ArrayList线程不是安全的，多线程环境下需要使用 Collections.synchronizedList() 或 CopyOnWriteArrayList
  2. 性能考虑：
    • 添加元素到末尾：O(1)
    • 在指定位置插入/删除：O(n)
    • 随机访问：O(1)
  3. 遍历时删除：使用迭代器的 remove() 方法，而不是ArrayList的 remove() 方法，避免 ConcurrentModificationException

10.7 抽象类介绍

抽象类是Java中一种特殊的类，它不能被实例化，只能被继承。抽象类使用abstract关键字修饰，可以包含抽象方法和具体方法。

抽象类是Java面向对象编程中实现抽象化的重要机制，它提供了一种介于普通类和接口之间的折中方案。

10.7.2 抽象类的特点

  • 不能实例化：不能使用new关键字创建抽象类的对象
  • 可以包含抽象方法：用abstract修饰，没有方法体
  • 可以包含普通方法：有具体实现的方法
  • 可以有构造方法：用于子类实例化时调用
  • 可以有成员变量：包括静态常量、普通变量等

10.7.3 抽象方法规则

  • 抽象方法只能在抽象类中定义
  • 抽象方法不能有方法体
  • 子类必须实现所有抽象方法（除非子类也是抽象类）
  • 抽象方法不能是private、static或final

抽象类主要用于：

  1. 代码复用：提取子类的公共属性和方法
  2. 定义规范：规定子类必须实现的方法
  3. 模板方法模式：定义算法骨架，具体步骤由子类实现

10.8 抽象类与具体类

抽象类 (Abstract Class)

抽象类是使用 abstract 关键字修饰的类，具有以下特点：

  1. 不能被实例化：不能直接创建抽象类的对象
  2. 可以包含抽象方法：使用 abstract 修饰的方法，只有声明，没有实现
  3. 可以包含具体方法：也可以有普通的方法实现
  4. 可以有构造方法：虽然不能实例化，但可以有构造器（供子类调用）
  5. 可以有成员变量：与普通类一样

具体类 (Concrete Class)

具体类就是普通的、可以实例化的类，特点：

  1. 可以直接实例化：使用 new 关键字创建对象
  2. 所有方法都有实现：不能包含抽象方法
  3. 可以继承抽象类：必须实现所有继承的抽象方法
  4. 可以是 final 的：防止被继承

主要区别

特性 抽象类 具体类
实例化 ❌ 不能 ✅ 能
抽象方法 ✅ 可以有 ❌ 不能有
继承 只能单继承 只能单继承
接口实现 ✅ 可以 ✅ 可以
构造方法 ✅ 可以有 ✅ 可以有

使用场景

抽象类适用场景：

  • 需要定义模板方法模式
  • 多个相关的类有共同的代码需要复用
  • 需要声明抽象方法让子类实现
  • 需要控制访问权限（protected等）

具体类适用场景：

  • 创建可以直接使用的对象
  • 工具类（如 Math、Arrays）
  • 数据封装（如 DTO、Entity）

10.9 Is-a 与 has-a

在Java面向对象编程中，Is-a 和 Has-a 是描述类与类之间两种基本关系的核心概念。它们帮助我们设计清晰、可维护的代码结构。

10.9.1 Is-a 关系（继承）

表示类与类之间的继承关系。它描述的是一种“是一种”的关系，体现了面向对象编程中的特殊性。

  • 关键字：extends（对于类）和 implements（对于接口）。
  • 本质：子类是父类的一种具体化或特殊化。子类会继承父类的属性和方法（除了私有的和构造方法）。
  • 代码体现：
  • Is-a 成立条件：如果 B 类 extends A 类，那么 B 就是 A。在上述例子中，Dog is an Animal 逻辑上是成立的。反之，Animal is a Dog 则不成立。

10.9.2 Has-a 关系（组合/聚合）

定义：表示类与类之间的关联关系。它描述的是一种“有一个”或“包含”的关系，体现了面向对象编程中的复用性。

  • 实现方式：通过在一个类中**定义另一个类的引用（成员变量）**来实现。
  • 分类：
    • 组合：强依赖关系，生命周期一致。如果整体消失了，部分也随之消失。
    • 聚合：弱依赖关系，生命周期可以不同。
  • 代码体现：
  • Has-a 成立条件：如果 Car 类中有一个成员变量是 Engine 类型，那么 Car has an Engine。

核心区别总结

特征 Is-a Has-a
关系名称 继承、泛化 关联、组合、聚合
关键字 extends， implements 成员变量
逻辑描述 A 是 B 的一种 A 包含/拥有 B
代码耦合度 高耦合 (父类改变影响子类) 低耦合 (通过接口或类引用交互)
方向性 单向 (子类 -> 父类) 通常双向或单向
复用方式 白盒复用 (继承实现细节) 黑盒复用 (通过接口调用)

设计原则：优先使用 Has-a 而不是 Is-a

在面向对象设计中，有一条著名的原则：组合优于继承。

  • 为什么？
    1. 破坏封装：继承会打破封装性，子类依赖父类的实现细节。如果父类修改，子类可能出问题。
    2. 灵活性差：继承关系是静态的，在编译时就决定了，运行时无法改变。而Has-a关系（组合）可以在运行时动态绑定不同的实现。
    3. 耦合度高：强耦合关系不利于代码的维护和扩展。
  • 举例对比：
    • 错误的设计 (Is-a)：鸟 继承了 飞机 的 fly() 方法。但如果突然要设计一只 企鹅 (不会飞)，继承体系就出问题了。
    • 正确的设计 (Has-a)：定义一个 可飞行 接口，飞机 和 鸟 分别实现它。或者定义一个 翅膀 类，鸟 拥有 翅膀 (Has-a)，然后调用翅膀的 拍打() 方法。

10.11 接口

接口是Java中的一种引用类型，类似于类，但专门用于定义规范或契约。它主要包含抽象方法（Java 8之后也可以包含默认方法和静态方法）。

可以把接口理解为一种完全抽象的类，它只规定"做什么"，而不规定"怎么做"。

接口是Java实现多态和低耦合设计的核心机制，在实际开发中应用非常广泛。

接口的主要特点

  1. 完全抽象：传统接口中的方法都是抽象方法，没有方法体
  2. 多继承：一个类可以实现多个接口
  3. 解耦合：将"定义"和"实现"分离
  4. 定义规范：规定了实现类必须完成的功能
