堆和树堆

10.1 堆

在数据结构中，堆是一种特殊的完全二叉树。

要理解堆，可以抓住两个核心特点：

  1. 结构上，它是一棵完全二叉树。
  2. 数值上，每个节点与其子节点间有严格的大小关系。

10.1.1 核心特点详解

1. 完全二叉树结构

这意味着，堆在构建时，节点会从上到下、从左到右依次填满每一层，中间不能有空缺。这决定了堆通常用数组来高效存储，通过索引就能找到父子关系：

  • 假设节点的索引是 i（通常从 0 开始）：
    • 父节点：(i - 1) // 2
    • 左子节点：2 * i + 1
    • 右子节点：2 * i + 2

2. 堆序性质

根据数值关系，堆分为两类：

  • 最大堆：任一节点的值，都大于或等于其子节点的值。堆顶元素就是全局最大值。
  • 最小堆：任一节点的值，都小于或等于其子节点的值。堆顶元素就是全局最小值。

核心特点：堆只保证从根到叶子的每条路径上是有序的，但不保证整个数组是完全排序的，也不保证同一层节点间的大小关系。

10.1.2 堆的核心操作

主要是两个操作，它们保证了堆的特性在数据变动后仍能维持。以最小堆为例：

1. 插入与上浮

  • 操作：将新元素加在数组最末尾，也就是完全二叉树的最后一个位置。然后让它不断与父节点比较，如果比父节点小就交换，直到堆序恢复。
  • 时间复杂度：O(log⁡n)。

2. 删除堆顶与下沉

  • 操作：堆的删除通常只移除堆顶。做法是：把最后一个元素移到堆顶位置，然后从根节点开始，不断与两个子节点中较小的那个交换，直到堆序恢复。
  • 时间复杂度：O(log⁡n)。

上浮与下沉

为了维持各自的规矩，它们在调整时用的比较逻辑是相反的：

操作 最小堆的目的 最大堆的目的
上浮 如果当前节点 < 父节点，就交换 如果当前节点 > 父节点，就交换
下沉 如果当前节点 > 较小的子节点，就交换 如果当前节点 < 较大的子节点，就交换

没有全局排序

堆只保证父子之间的顺序，不保证同级之间或全局顺序。

  • 最小堆的反例：[1, 3, 6] 中，3 和 6 在同一层，但 6 比 3 大，这完全合法。最小堆只保证顶上的 1 最小。
  • 最大堆的反例：[9, 5, 8] 中，5 和 8 在同一层，8 比 5 大，完全合法。

所以，堆是一个“半有序”结构，它只为快速拿最值而生。

用途上的直接对应关系

场景 用什么堆 为什么
找出最小的K个数 最大堆 堆顶是K个数里最大的，新来的数只要比堆顶小，就替换掉堆顶。这样能顺利淘汰大数，留住小数。
找出最大的K个数 最小堆 堆顶是K个数里最小的，新来的数只要比堆顶大，就替换掉堆顶。这样能顺利淘汰小数，留住大数。
任务优先级 (数值越小越优先) 最小堆 快速取出优先级最高（数值最小）的任务。
堆排序 (升序) 最大堆 反复取出堆顶最大值，放到数组末尾，就能形成升序序列。

10.1.4 实现与应用

基本实现思路

在 Python 中，heapq 模块就是一个标准的最小堆实现。当然，你也可以用数组手写一个，其核心就是控制元素的上浮和下沉。

典型应用场景

堆擅长快速获取最值，典型应用有：

  • 优先队列：自然就是由堆实现的，可以快速取出优先级最高的任务。
  • 堆排序：反复从最大堆中取出堆顶，就能得到一个降序序列。
  • Top K 问题：比如要在一亿个数字中找出最大的 10 个，用最小堆，在 log⁡klogk 的代价下维护前 10 名即可。
  • 图算法：Dijkstra 最短路径和 Prim 最小生成树算法，都常借助最小堆高效获取下一个最近节点。

除了普通的二叉堆，还有斐波那契堆、二项堆等变种，它们在某些操作的性能上做了优化，能实现更低的均摊时间界。

10.2 使用数组实现堆

在数据结构中，堆是一种特殊的完全二叉树。而使用数组实现堆，正是利用了完全二叉树的特性，用连续的数组空间来紧凑地存储树中的节点，从而避免使用指针。

它的核心在于节点索引的数学关系：

假设根节点在数组中的索引为 0，那么对于索引为 i 的节点：

  • 父节点索引：(i - 1) / 2（向下取整）
  • 左子节点索引：2 * i + 1
  • 右子节点索引：2 * i + 2

用数组存储就是：[100, 50, 60, 10, 20, 30]

  • 50 (索引1) 的父节点是 100 (索引 (1-1)/2 = 0)
  • 50 的左子是 10 (索引 2*1+1 = 3)，右子是 20 (索引 2*1+2 = 4)

数组实现的优缺点

优点：

  • 内存紧凑：无需存储子节点指针，空间效率高。
  • 缓存友好：元素连续存储，访问局部性好，效率高。
  • 操作简单：索引计算极快，实现很简洁。

缺点：

  • 大小限制：静态数组有固定容量（不过用动态数组如 Python 的 list 可以自动扩容）。
  • 不适合合并：合并两个堆不像左偏树等结构那样高效。

10.2.1 堆存储

这指的是堆在计算机内存中的具体存储方式。虽然堆是一棵逻辑上的树，但最经典的存储方式是用数组（顺序存储）。

  • 原理：利用完全二叉树节点位置连续的特性，将节点按层放入数组。
  • 优势：不用存指针，内存紧凑，访问速度快。
  • 场景：这就是你之前看到的那个数组 [100, 50, 60, 10, 20, 30]。

10.2.2 父子索引

这是连接“树”和“数组”两套逻辑的桥梁。为了让数组能像树一样遍历，我们必须能通过数组下标，迅速找到任一节点的父子关系。

假设根节点在索引 0，对任意索引 i 的节点：

  • 父节点索引: (i - 1) // 2
  • 左子节点索引: 2 * i + 1
  • 右子节点索引: 2 * i + 2

这套公式是后面所有“上浮”、“下沉”操作的基础。

这是把堆封装成了一个对象，让你可以像使用一个独立的数据结构一样操作它，内部自动维护堆的性质。它把数据（数组）和操作（插入、删除）绑定在一起。

10.2.4 渗透算法

这其实就是“上浮”和“下沉”操作的学术化统称。它描述的是元素在堆中“渗透”到正确位置，以维持堆的性质的过程。因此，它包括两个方向：

  • 向上渗透，又称“上浮”：
    当一个新元素被插入到数组末尾（堆的底部）时，它可能比父节点大，从而破坏最大堆性质。这时就需要：
    • 过程：反复比较新节点与其父节点，如果它更大，就与父节点交换位置，一步步向上移动。
    • 应用：push 插入操作。
  • 向下渗透，又称“下沉”：
    当堆顶元素被移除，我们用数组最后一个元素填补堆顶时，它可能比子节点小。这时需要：
    • 过程：反复比较该节点与它的最大子节点，如果它更小，就和那个最大的子节点交换，一步步向下移动。
    • 应用：pop 删除堆顶操作。

它们如何协同工作？

让我用一颗大顶堆来串一下这些概念：

  1. 存储与索引：这是根基。我们的大脑里有一棵树，但计算机的 MaxHeap 对象里只有一个数组。我们靠“父子索引”来让数组表现得像树。
  2. 构建类：我们把数组、索引公式、渗透方法都封装在 MaxHeap 类里，对外提供简单干净的接口。
  3. 执行操作与渗透：
    • 当你调用 push(110) 时，110 先被放到数组末尾。然后，向上渗透算法启动。它通过 (i-1)//2 找到父节点 50，发现 110 > 50，于是两者交换。然后继续向上比较，直到将 110 渗透到它应有的位置。
    • 当你调用 pop() 时，顶部的 110 被取走，数组末尾的元素被放到堆顶。然后，向下渗透算法启动。它通过 2*i+1 和 2*i+2 找到两个子节点，并与其中较大的那个比较交换，直到该元素渗透到正确位置。

简单说，堆存储是物理基础，父子索引是逻辑规则，最大堆类是完整封装，而渗透算法是维持规则的核心动作。 这四个概念组合在一起，就构成了数组实现堆的完整图景。

10.3 堆排序

堆排序是一种利用堆这种数据结构设计的比较排序算法，兼具了归并排序和插入排序的部分优点。

堆排序通常使用最大堆来实现升序排列。

10.3.1 堆排序的两大步骤

堆排序的核心思想是：先将待排序的数组构建成一个堆，然后反复从堆顶取出最值，再调整剩余部分，直到有序。

第一步：建堆

将无序的输入数组，原地调整成一个最大堆。这个过程就像在一棵完全二叉树里，从最后一个非叶子节点开始，自下而上、从右到左，不断调整子树使其满足最大堆的性质。

第二步：排序

这是最巧妙的地方。重复以下操作，直到堆的大小变为1：

  1. 交换：将堆顶元素（当前最大值）与当前堆的最后一个元素交换。于是，最大元素就跑到了数组的末尾。
  2. 脱离：将堆的大小减1，相当于把刚才放到末尾的最大值排除在堆外，它已经处于最终的有序位置了。
  3. 调整：交换到堆顶的新元素很可能破坏了最大堆的性质，这时需要对堆顶元素执行一次“下沉”操作，把它调整到合适的位置，使剩余部分重新成为最大堆。

这样不断把次大值“沉”到数组末端，最终就得到了一个升序的数组。

假设我们对数组 [4, 10, 3, 5, 1] 进行堆排序：

算法特点

  • 原地排序：除了几个临时变量，不需要额外开辟大量空间。
  • 时间复杂度：无论最好、最坏还是平均情况，都是 O(n log n)。建堆是O(n)，每次调整是O(log n)，需要调整n-1次。
  • 不稳定排序：在交换和调整过程中，相等元素的相对前后位置可能会改变。
  • 不如快速排序常用：虽然理论性能稳定，但由于堆排序的数据访问跳跃（父子节点在数组中的索引不连续），对CPU缓存不友好，实际速度通常慢于快排。

10.3.3 堆化操作

堆化（Heapify）就是堆排序中反复提到的“调整”过程，它的核心任务是：当一个堆因为某个节点的值改变而违反堆的性质时，通过一系列交换，把这个节点“下沉”或“上浮”到正确的位置，使整个结构重新成为合法的堆。

堆化主要分两种，作用不同：

1. 自顶向下的堆化（Sift Down）

这是堆排序中最关键的操作，用于“建堆”和“交换后的调整”。

  • 场景：当一个父节点的值小于它的子节点（在最大堆中）时，它就不配待在上面了。
  • 过程：让这个“不称职”的父节点，和它较大的子节点交换位置。交换后，它可能仍然小于新的子节点，那就不断重复这个过程，直到它比所有子节点都大，或者沉到了堆底。

2. 自底向上的堆化（Sift Up）

  • 场景：相反地，当堆尾插入新元素，或某个子节点的值大于它的父节点（在最大堆中）时使用。
  • 过程：让这个“过于优秀”的子节点，不断和它的父节点交换，一路向上攀爬，直到父节点比它大，或到达堆顶。

在堆排序中，核心用的是 Sift Down。因为建堆时，我们从后往前对每个非叶子节点执行一次 Sift Down；排序时，每次交换堆顶元素后，也是对新堆顶执行一次 Sift Down。

简单说，堆化就是维护堆性质的核心手段，确保堆的根节点永远是当前的最值。

10.4 优先级队列抽象数据类型（ADT）

数据结构里的优先级队列，是一种特殊的抽象数据类型。它与普通队列“先进先出”不同，核心规则是：优先级最高的元素最先出队。

什么是ADT

ADT只定义行为“做什么”，不关心“怎么做”。优先级队列的抽象定义就是：

  • 数据：一组元素的集合，每个元素都关联一个可比较的优先级。
  • 核心操作：
    • insert(element, priority)：入队，添加一个带优先级的元素。
    • removeMax() 或 removeMin()：出队，移除并返回优先级最高（或最低）的元素。
    • getMax() 或 getMin()：查看优先级最高（或最低）的元素，不移除。
    • 通常还有 isEmpty() 和 size() 等辅助操作。

它的关键特征在于：
元素出队的顺序只取决于优先级，与入队顺序无关。如果优先级相同，具体顺序则由实现决定，ADT本身不作严格规定。

如何实现

实现方式决定了操作的效率，各有优劣。

  • 无序数组/链表
    插入时直接放到末尾，O(1)；取出时需遍历查找最大/最小优先级，O(n)。
  • 有序数组/链表
    插入时找到合适位置以保持有序，O(n)；取出时直接取端点，O(1)。
  • 二叉堆
    这是最常见、最经典的实现方式。插入和取出操作都能在 O(log n) 时间内完成，性能非常均衡。它是堆排序和高效任务调度的基础。
  • 平衡二叉搜索树（如AVL树）
    插入和取出也都是 O(log n)。功能更强大，能支持查找任意优先级等操作，但实现复杂，单纯用于优先级队列有些“大材小用”。

与普通队列的区别

特性 普通队列 优先级队列
核心规则 先进先出 (FIFO) 按优先级出队
出队元素 最早入队的元素 优先级最高的元素
类比 排队结账 急诊室分诊：重症优先
典型应用 广度优先搜索 (BFS)、缓冲区 任务调度、Dijkstra算法、哈夫曼编码

常见实现方式

实现方式决定了操作的时间复杂度，这是选择时的关键考量：

实现结构 插入 删除最值 特点
无序数组/链表 O(1) O(n) 插入快，但需要扫描找最值
有序数组/链表 O(n) O(1) 删除快，但插入要找位置
二叉堆 O(log n) O(log n) 最常用，插入和删除都均衡高效

二叉堆凭借对数级别的稳定性能，成为实际应用中最主流的实现方式。

核心应用场景

优先级队列在算法和系统中无处不在：

  • 任务调度：操作系统根据进程优先级分配CPU时间
  • 图论算法：Dijkstra最短路径、Prim最小生成树，用来高效选择当前最短/最小的边
  • 数据压缩：哈夫曼编码中反复合并频率最低的两个节点
  • 事件模拟：按时间顺序处理未来事件，时间越早优先级越高

简单来说，只要遇到“每次都处理当前最重要的那个任务”的需求，背后很可能就是一个优先级队列。

10.5 树堆（Treaps）

Treap（树堆）是二叉搜索树（BST）和堆（Heap）的结合体，其名字也来源于 Tree + Heap。

它的核心思想很简单：每个节点除了存储数据键值 Key 外，还被分配一个随机生成的优先级 Priority。Treap 同时维护两个约束：

  • 键值按二叉搜索树排列：左子树所有节点的 Key < 根的 Key < 右子树所有节点的 Key。
  • 优先级按堆排列：通常是大顶堆，即父节点的 Priority ≥ 子节点的 Priority。

可以这样理解：键值决定了节点“水平方向”的位置，而随机优先级决定了它“垂直方向”的高度。正是这种随机性，让树在期望下趋于平衡，从而避免普通二叉搜索树在顺序插入时退化成链表的问题。其插入、删除、查找操作的平均时间复杂度都是 O(log n)。

10.5.1 如何维护Treap的平衡？

Treap 不依赖复杂的平衡因子或颜色标记，只靠旋转来修正优先级冲突，保持堆的性质。

主要有两种旋转操作：

  • 右旋 (Right Rotation)
    当左子节点的优先级高于父节点时，将左子节点“提上来”，父节点向右下方旋转成为其右子节点。
  • 左旋 (Left Rotation)
    当右子节点的优先级高于父节点时，将右子节点“提上来”，父节点向左下方旋转成为其左子节点。

10.5.2 基本操作详解

插入 (Insert)

  1. 像普通BST一样，根据Key找到位置并插入新节点，赋予随机Priority。
  2. 从插入点向上回溯，如果新节点的Priority比父节点高，就通过旋转把它向上调整，直到满足堆的性质。

比如，你按Key顺序 A < B < C 依次插入，如果插入 C 时赋予它的优先级最高，最终 C 会通过左旋一路升到根节点，树也变得更平衡。

删除 (Delete)

核心思路是把待删节点通过旋转沉到叶子节点再移除。有两种策略：

  • 策略一：旋转下沉
    1. 找到待删节点。
    2. 如果它只有一边的子节点（或没有），直接删除，用子节点接替即可。
    3. 如果它有两个子节点，比较左右子节点的优先级：
      • 左子优先级高 → 右旋，把待删节点旋到右边。
      • 右子优先级高 → 左旋，把待删节点旋到左边。
    4. 重复这个过程，直到待删节点变成叶子，然后直接删掉。
  • 策略二：优先赋值为 -∞
    先将待删节点的Priority设为负无穷，然后通过旋转把它沉到最底层，最后删掉叶子。

为什么随机优先级能保证平衡？

这源于 Treap 和随机化二叉搜索树在数学结构上的等价性。

如果每次插入前，所有Key都已知，你随机打乱插入顺序，建出的树的期望高度就是 O(log n)。Treap 的精妙之处在于，给每个Key赋予随机优先级，恰好等价于生成了一种随机的插入顺序，因为优先级的大小关系决定了节点加入树的先后关系。所以，即使按顺序插入1到n，只要优先级随机，树在期望下依然是平衡的。

与其他数据结构的比较

  • 对比普通BST：Treap解决了BST在数据有序时退化成链表的问题。
  • 对比AVL/红黑树：AVL和红黑树用复杂规则保证严格的平衡，实现繁琐。Treap用随机化和简洁的旋转达到了概率平衡，实现代码量更少，更不易出错。
  • 对比跳表：两者都是随机化数据结构的代表，都提供概率平衡和期望对数时间。

10.5.3 Treap 的常见变种

  • 无旋 Treap (FHQ Treap)
    由范浩强提出，它彻底抛弃了旋转操作，改用 split（按值分裂）和 merge（合并）两个核心操作来实现所有功能。这种持久化、代码简洁、支持区间操作的特点，使它成为算法竞赛中的热门选择。
  • 笛卡尔树
    从概念上说，Treap 其实就是一种随机的笛卡尔树。当笛卡尔树的键值和优先级都确定时，树的形态唯一；而Treap的优先级是随机的。

总而言之，Treap 是一种优雅的概率平衡二叉搜索树，它用随机优先级和旋转，巧妙又简单地在期望上实现了 O(log n) 的高效操作。
