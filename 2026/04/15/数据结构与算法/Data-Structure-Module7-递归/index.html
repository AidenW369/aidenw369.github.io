递归

7.1 什么是递归

数据结构中的递归，是指一个函数（或过程）在其定义中直接或间接地调用自身的方法。

它本质上是一种将复杂问题“大事化小”的求解策略。其核心思想在于两点：

  1. 子问题必须与原始问题性质相同，但规模更小。
  2. 必须有一个不再递归调用的终止条件（边界条件）。

7.1.1 一个标准的递归程序

  • 递归边界（终止条件）：明确什么时候停止调用自身，直接返回确定值。没有它，程序会无限循环导致栈溢出。
  • 递归逻辑（递推关系）：将问题分解，并调用自身去解决更小的子问题。

7.1.2 递归在内存中是如何运行的

理解递归的关键在于调用栈（Call Stack）。每次函数调用，系统都会在栈顶分配一块内存（栈帧），用于存储局部变量和返回地址。

递归的执行分为两个阶段：

  1. 递推（前进）：问题规模不断递减，栈帧不断压入，直到达到边界条件。
  2. 回归（返回）：从边界条件开始，栈帧依次弹出，逐层返回计算结果。

7.1.3 递归的优缺点

  • 优点：代码清晰简洁，与数学定义高度一致，尤其适合处理树、图这种递归定义的数据结构。
  • 缺点：
    • 性能开销大：频繁的函数调用有额外时间开销。
    • 空间消耗大：调用栈深度受内存限制，可能导致栈溢出（Stack Overflow），尤其是处理大规模数据时。
    • 重复计算：如计算斐波那契数列时，存在大量重复，导致效率很低（可用记忆化搜索优化）。

7.1.4 递归的适用场景

递归思想与某些数据结构的设计不谋而合。当你遇到以下情况，递归往往是首选思路：

  • 树：树的遍历（前序、中序、后序）是其最直观的应用。
  • 图：深度优先搜索（DFS）天然就是递归过程。
  • 链表：链表的反转、节点删除等操作，用递归实现往往比迭代更易懂。
  • 分治算法：归并排序、快速排序，都是将问题不断二分的思想。

简单来说，递归就是把“怎么用同样的方法解决一个更小的自己”描述清楚，并为最小的情况设定一个直接答案。理解它，是掌握更复杂数据结构和算法的基础。

7.2 递归方法

核心思想：函数直接或间接地调用自身，把一个大问题分解成一个或多个与原问题相似但规模更小的子问题。

关键要素：

  1. 边界条件：终止递归的出口，防止无限循环。
  2. 递归体：调用自身并向边界条件逼近的步骤。

适合递归的场景

  • 树和图的遍历：如先序、中序、后序遍历。代码非常简洁自然。
  • 分治算法：如快速排序、归并排序。
  • 动态规划问题的自顶向下求解。
  • 回溯算法：如八皇后、迷宫问题。

优缺点

  • ✅ 代码简洁、逻辑清晰，贴近问题的数学定义。
  • ❌ 效率与空间开销：每次调用都有额外开销（函数栈）；可能栈溢出；可能包含重复计算（如斐波那契数列的朴素递归）。

7.2.1 非递归方法

核心思想：不靠函数自身调用，而是使用 循环 和 显式的辅助数据结构（如栈、队列） 来模拟递归过程，或直接迭代求解。

  • ✅ 效率高：无函数调用开销；无栈溢出风险；易于优化。
  • ❌ 代码可能复杂：需要手动管理执行状态，不如递归直观，尤其是在复杂的树/图操作中。

适用限制 受系统栈大小限制，可能溢出 无此限制

决策指南

  1. 首选递归：当问题本身具有天然的递归结构（如树的遍历），且深度可控（不会栈溢出），优先考虑递归，代码清晰可维护。
  2. 转为非递归：
    • 递归深度太大，可能导致栈溢出。
    • 对性能要求很高的核心代码。
    • 一些能用简单循环直接解决的问题（如线性迭代、简单计算）。
    • 所有递归理论上都能转为非递归，只是复杂度不同。

扩展：尾递归优化

有些编译器/解释器支持尾递归优化。如果递归调用是函数的最后一条语句，可被优化为类似循环的形式，避免栈增长，兼具两者优点。但需注意，Python、Java 等许多语言默认不支持尾递归优化。

7.3 递归搜索算法

数据结构中的递归搜索算法，本质上就是一个函数通过不断调用自身，在某种数据结构中寻找目标元素的方法。

要理解它，我们得先抓住它的两个核心：

  • 递归
    就是一个大问题能被分解成若干个规模更小、解法相同的子问题。函数会一直调用自己，直到问题小到可以直接解决（这叫基线条件），从而避免无限循环。
  • 搜索
    就是在数据集合里，找到一个满足特定条件的元素。

把两者结合，递归搜索算法就是在一个数据结构上，用递归的方式查找目标。

这是递归搜索最完美的体现。二叉搜索树有天然递归结构：一个节点，左边所有节点值都比它小，右边所有节点值都比它大。

从上面两个例子，我们可以总结出递归搜索的通用模板：

  1. 基线条件
    用于终止递归，通常是找到了或搜索范围为空。
  2. 递归条件
    将问题分解。通常包含处理当前元素、并对结构的一部分（如左/右子树、子文件夹、子数组）发起新的搜索调用。
  3. 状态传递
    每次递归调用，搜索范围（如传入的节点）都在缩小，必须朝着基线条件迈进。

7.3.4 常见应用场景

除了上面两种，递归搜索还常用于：

  • 广义表/嵌套列表：如搜索 [1， [2， [3， 4]]， 5] 这种任意嵌套的结构。
  • 图的遍历：深度优先搜索本质上也是递归搜索在节点和边构成的图上的应用。
  • 分治搜索：如二分查找，虽然常用循环实现，但其“将数组一分为二”的思想同样是递归，可以很方便地写成递归形式。

7.3.5 递归搜索已排序列表

“递归搜索已排序列表”，就是把我们刚才聊的递归思想，应用到一个有序的一维数组或列表上。最经典的实现，就是二分查找的递归版本。

它的逻辑很直观：利用列表已排序的特性，每次把搜索范围折半。

  • 基线条件（何时停）：找到目标元素，或者搜索区间已经无效（即左边界超过了右边界）。
  • 递归条件（如何缩小问题）：将列表从中间切开，根据中间元素与目标值的大小比较，决定是继续搜左半边还是右半边。

具体过程演示

假设目标 target = 7，在一个升序列表 arr = [1, 3, 4, 7, 9, 11, 15] 中搜索。

  1. 第一层递归
    列表中间位置的值是 7。恰好，7 == 7，命中基线条件，搜索成功。

再换一个更波折的例子，搜索 target = 4：

  1. 第一层递归
    搜索范围是整个列表，中间值是 7。因为 4 < 7，所以问题缩小为：在 7 的左半边 [1, 3, 4] 中继续搜索。
  2. 第二层递归（在左半边）
    范围是 [1, 3, 4]，中间值是 3。因为 4 > 3，问题缩小为：在 3 的右半边 [4] 中继续搜索。
  3. 第三层递归（在子区间的右半边）
    范围是 [4]，中间值就是 4。4 == 4，命中基线条件，搜索成功。

与循环实现的对比

这个功能也可以用 while 循环实现，两者的核心区别在于：

  • 循环实现
    通过不断更新 left， right 这两个边界指针来缩小范围。
  • 递归实现
    不修改变量，而是通过函数参数传递新的、缩小后的边界。它的特点是状态不可变、逻辑更贴近数学定义。

优缺点与适用场景

  • 优点：代码清晰，函数式风格强，没有副作用（每次调用都使用新的 left 和 right），容易在数学上验证其正确性。
  • 缺点：效率较低。递归调用会带来函数调用栈的开销，有栈溢出风险。比如在Python中，列表过长时，递归版可能导致 RecursionError。而循环版只消耗常量级别的额外内存。
  • 常见场景：除了教学演示，它很适合函数式编程语言，或在处理本身就是递归定义的链表结构时。在一些分治算法（如快速排序的划分）中，这种递归二分的思想也是核心组成部分。

7.5 创建递归方法

在数据结构中，创建递归方法指的是设计一个通过调用自身来解决问题的函数。在 Java 里，递归方法通常包含两个核心部分：

  1. 基准情形：停止递归的条件，防止无限循环。
  2. 递归步骤：方法调用自身，但问题规模缩小，逐步向基准情形逼近。

7.5.1 链表的递归：反转链表

这是理解递归的绝佳例子。递归反转链表的核心思想是：先假设后面部分已反转好，再处理当前节点。

执行逻辑图示（对于 1 -> 2 -> 3 -> null）：

  1. 递归到底：head = 3，3.next==null返回3。
  2. 回溯一层：head = 2，此时newHead是3。
    • 2.next.next = 2 → 3.next = 2
    • 2.next = null
    • 当前链表变为 3 -> 2 -> null
  3. 回溯到顶：head = 1，newHead是3。
    • 1.next.next = 1 → 2.next = 1
    • 1.next = null
    • 最终链表：3 -> 2 -> 1 -> null

7.5.2 创建递归方法的通用步骤

无论哪种数据结构，设计时都可以遵循这个流程：

  1. 定义方法语义
    明确方法要做什么。比如 maxDepth 是“返回以 root 为根的树的高度”。
  2. 确定基准情形
    找出最小规模、无需递归就能直接求解的情况。这防止了无限递归。
  3. 分解问题并递归调用
    将原问题拆分成一个或多个规模更小但结构相同的子问题，调用自身去解决。
  4. 合并子问题的结果
    将递归调用的返回结果，处理成当前问题需要返回的结果。

关键点提醒

  • 栈溢出风险：Java 的调用栈深度有限。递归过深（如处理长度十万级的链表）会导致 StackOverflowError。此时需改用迭代。
  • 避免重复计算：像斐波那契数列求值那样直接递归会产生大量重复计算，此时可引入备忘录优化。例如，数据结构中遍历通常不存在此问题。

7.6 递归的数学方法

在数据结构与算法中，递归的数学方法主要建立在数学归纳法和递推关系的基础上。

递归的数学方法本质就是：识别出问题规模和子问题规模之间的递推关系，然后用代码表达这种关系。掌握这些数学思想，你就能更好地设计递归算法。

7.6.1 数学归纳法与递归的关系

递归本质上就是数学归纳法在编程中的实现：

  • 数学归纳法：证明基本情况成立 → 假设 n 时成立 → 证明 n+1 时成立
  • 递归：定义基本情况 → 假设子问题已解决 → 组合子问题得到最终解

递归的数学核心是递推关系，它描述了问题规模之间的关系。

7.6.2 最大公约数（欧几里得算法）

数学原理

定理：gcd(a, b) = gcd(b, a mod b)

证明：
设 d = gcd(a, b)，则 d|a 且 d|b
设 a = bq + r (0 ≤ r < b)，即 r = a mod b

  • 因为 d|b，所以 d|bq
  • 因为 d|a 且 d|bq，所以 d|(a - bq) = d|r
  • 因此 d 也是 b 和 r 的公因数

反过来，如果 d|b 且 d|r，则 d|(bq + r) = d|a
因此 d 也是 a 和 b 的公因数

所以 {a,b的公因数} = {b,r的公因数}
因此 gcd(a,b) = gcd(b,r) ✓

7.7 使用递归探索所有可能性（回溯算法）

“使用递归探索所有可能性”是数据结构与算法中的一种核心思维模式，官方常称之为回溯算法或深度优先搜索。

它的本质是：面对一个有多步选择的问题，通过递归函数，在每一步尝试所有合法选项，自动形成一棵“决策树”，从而系统地遍历所有可能的解。

可以这样理解它和普通递归的区别：

特性 普通递归 探索所有可能性（回溯）
目标 解决一个确定的问题，如计算阶乘 生成所有可能的组合或路径
选择 每层通常只有一种处理方式 每层有多个选项需逐一尝试
关键操作 单向递归调用 选择 → 探索 → 撤销选择（回溯）

典型应用场景

这个思想能解决一大类问题，它们的共同点是要求“所有组合/排列/子集”等。

  • 组合与子集问题：生成数组 [1,2,3] 的所有子集。每步选择是“选或不选”当前元素。
  • 排列问题：求 [1,2,3] 的全排列。每步选择是“选一个没用过的数字”。
  • 棋盘问题：八皇后、解数独。每步选择是“在合法位置放置皇后/数字”。
  • 图路径问题：找到从起点到终点的所有路径。每步选择是“访问一个未被访问的相邻节点”。

一个具体例子：生成所有子集

以集合 {1, 2, 3} 为例，递归生成的决策树如下：

  • 第一层：决定“1”这个元素选不选。
  • 第二层：决定“2”选不选。
  • 第三层：决定“3”选不选。
    最终所有叶子节点就是全部 2³ = 8 个子集。

关键技巧与注意事项

  • 循环与递归的关系：递归表示“纵向深入”，而函数内部的 for 循环表示“横向遍历同一层的不同选择”。
  • 回溯的精髓是“撤销”：在递归返回后，必须将状态恢复，以免影响同一层后续循环的其他分支。
  • 避免重复：对于组合问题，通常通过 start 索引传递来保证选择是单向的，避免生成 [2,1] 这样的重复组合。对于排列问题，则用 visited 数组标记。
  • 耗时本质：这种方法常用来处理 NP 难问题，时间复杂度通常是指数级，因为它确实在遍历所有可能性。剪枝是优化它的重要手段。

这个思想将一个大问题，分解为“当前步所有尝试”和“基于该尝试后，对剩下所有可能性的探索”，是解决很多复杂问题的基础。

7.8 栈溢出

在数据结构中，堆栈溢出通常指调用栈溢出，即程序运行时，函数调用所需的内存超出了系统分配的栈空间大小。

要理解它，需要先知道“栈”在此处的两个相关含义：

  • 数据结构中的栈：一种“后进先出”的线性表，操作受限。
  • 内存中的调用栈：操作系统为程序分配的一块连续内存，专门用来存放函数调用时的局部变量、返回地址等。它本质上就是用数据结构“栈”的方式管理的。

堆栈溢出通常由两种原因引起：

无限递归

最常见的原因。递归函数如果没有正确的终止条件，或终止条件永远无法满足，就会无限调用自身。每次调用都会在调用栈中分配一块栈帧，空间很快就被耗尽了。

栈帧过大

即使调用次数不多，如果函数内定义了巨大的局部变量，也可能直接撑爆栈空间。

发生时会怎样？

程序会触发段错误或抛出特定异常：

  • Python：RecursionError
  • Java/C#：StackOverflowError / StackOverflowException
  • C/C++：程序崩溃，通常显示 segmentation fault（栈帧过大时）或无响应（递归过深时）。

如何避免栈溢出

  • 确保递归有可达的终止条件，或改用循环来避免过深的递归。
  • 避免在函数内创建过大的局部变量，大数据改用堆内存（如 malloc、new）。
  • 检查递归逻辑，确保参数一定会收敛到终止条件。
