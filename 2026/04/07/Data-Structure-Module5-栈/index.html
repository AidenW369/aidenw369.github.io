栈

5.1 栈的抽象数据类型

在数据结构中，栈（Stack） 的抽象数据类型（ADT） 定义了一个逻辑结构（后进先出，LIFO）以及一组相关的操作，而不涉及具体实现方式（如数组或链表）

逻辑特性

遵循后进先出（LIFO, Last In First Out）：即最后插入的元素最先被删除。

核心方法

操作名 描述
push(x) 将元素 x 压入栈顶。
pop() 删除并返回栈顶元素。
top() 或 peek() 返回栈顶元素，但不删除。
isEmpty() 判断栈是否为空。
size() 返回栈中元素的个数。

栈的典型应用

  • 函数调用与返回（系统栈）
  • 表达式求值与括号匹配
  • 撤销操作（Undo）
  • 浏览器的后退/前进

5.2 链表栈

使用链表构造栈结构 是数据结构中的一种经典实现方式。

栈（Stack）是一种“后进先出”（LIFO, Last In First Out）的线性结构，只允许在一端（称为栈顶）进行插入（压栈，push）和删除（弹栈，pop）操作。

用链表来实现栈，就是利用链表的节点动态存储数据，并维护一个指向栈顶节点的指针。

5.2.1 链表栈的基本结构

  • 节点：每个节点包含数据域（存储元素值）和指针域（指向下一个节点）。
  • 栈顶指针：通常命名为 top，指向链表的第一个节点（即栈顶元素）。当栈为空时，top = NULL。

5.2.2 核心操作

1. 压栈（push）

  • 创建一个新节点，存入数据。
  • 将新节点的 next 指针指向当前的 top。
  • 更新 top 指向新节点。
  • 时间复杂度：O(1)

2. 弹栈（pop）

  • 如果栈为空（top == NULL），则报下溢错误。
  • 保存 top 节点的数据。
  • 将 top 移动到 top->next。
  • 释放原栈顶节点的内存（若需要）。
  • 返回保存的数据。
  • 时间复杂度：O(1)

3. 获取栈顶元素（peek / top）

  • 若栈非空，返回 top->data，否则报错。
  • 时间复杂度：O(1)

4. 判断是否为空（isEmpty）

  • 返回 top == NULL。
  • 时间复杂度：O(1)

5.2.3 链表栈 vs 数组栈

特性 链表栈 数组栈
大小 动态增长，仅受内存限制 固定大小或需要扩容
内存使用 每个节点多一个指针开销 连续内存，无额外指针
缓存友好性 较差（节点分散） 较好（连续内存）
操作复杂度 push/pop 均为 O(1) push/pop 均为 O(1)（均摊）
实现难度 需要手动管理节点内存 相对简单

总结

用链表构造栈充分利用了链表的动态特性，避免了数组栈可能出现的“栈满”问题，适合在元素个数不确定或频繁动态变化的场景中使用。虽然每个节点多占用一个指针空间，但换来的是灵活的内存使用和无需预估容量的便利。

5.3 数组栈

数组栈是使用数组作为底层存储结构的栈实现。栈是一种遵循 后进先出（LIFO，Last In First Out） 原则的数据结构，即最后放入的元素最先被取出。

数组栈就是用数组模拟栈的行为，是栈最经典、最常用的实现方式之一。它简单高效，适用于绝大多数需要后进先出逻辑的场景（如函数调用、括号匹配、撤销操作等）。但需要注意容量管理问题。

核心原理

  • 用一个固定大小（或可动态扩容）的数组来存储数据。
  • 用一个整型变量 top 表示栈顶元素的索引。初始时 top = -1 表示空栈。
  • 元素入栈时，top 加 1，然后将元素存入 array[top]。
  • 元素出栈时，返回 array[top]，然后将 top 减 1（逻辑删除）。

基本操作及时间复杂度

操作 描述 时间复杂度
push(x) 将元素 x 压入栈顶 O(1)
pop() 移除并返回栈顶元素 O(1)
peek() / top() 返回栈顶元素但不移除 O(1)
isEmpty() 判断栈是否为空 O(1)
isFull() 判断栈是否已满（仅针对固定大小数组） O(1)

优点与缺点

优点
  • 实现简单，代码容易理解。
  • 访问速度快，所有操作都是 O(1) 时间。
  • 内存连续，CPU 缓存友好。
缺点
  • 固定容量（若使用静态数组）可能导致栈溢出或空间浪费。

  • 动态扩容（如加倍策略）虽然可以解决容量问题，但扩容时需要复制整个数组，耗时 O(n)。

  • 插入/删除仅在栈顶，灵活性不如链表栈（但这也是栈本身的特点）。

动态扩容数组栈（可选）

为了避免固定容量带来的溢出问题，可以在 push 时检查是否已满，若满则创建一个更大的新数组（通常是原容量的 2 倍），并将原数组元素复制过去。这样扩容的均摊时间复杂度仍为 O(1)。

5.3.1 有界栈

  • 定义：容量上限固定，最多能存储 N 个元素。当栈已满时，继续 push 会失败（抛出溢出异常或返回错误）。
  • 实现方式：通常使用固定大小的数组实现。
  • 特点：
    • 内存占用确定，不会动态增长。
    • 操作效率高（无扩容开销）。
    • 存在“栈满”状态，需要调用者检查。
  • 适用场景：
    • 已知最大元素个数（如操作系统内核栈、嵌入式系统）。
    • 对实时性要求高、不允许动态内存分配的系统。
    • 需要防止无限制占用的安全场景。

5.3.2 无界栈（Unbounded Stack）

  • 定义：逻辑上没有固定容量上限，理论上可以无限增长（直到耗尽所有可用内存）。永远不会出现“栈满”错误。
  • 实现方式：
    • 动态数组：当数组容量不足时自动扩容（如翻倍）。
    • 链表：每个元素动态分配节点，节点之间通过指针链接。
  • 特点：
    • 使用灵活，调用者无需关心容量。
    • 可能有均摊 O(1) 的 push 开销（扩容时 O(n)）。
    • 存在内存耗尽的风险（OutOfMemoryError）。
  • 适用场景：
    • 无法预估栈的最大深度（如函数调用栈、回溯算法、表达式求值）。
    • 希望简化代码逻辑，不处理“栈满”异常。

对比总结

特性 有界栈 无界栈
容量上限 固定，构造时指定 仅受可用内存限制
底层结构 通常为静态数组 动态数组 或 链表
push 失败情况 栈满 → 溢出异常/错误码 内存不足 → OutOfMemoryError
内存占用 预先分配，确定 动态增长，可能占用更多
时间复杂度（均摊） 严格 O(1) 扩容时 O(n)，均摊 O(1)
典型使用场景 实时系统、嵌入式、有界缓冲 通用编程、算法竞赛、JVM 栈

注意

  • “有界/无界”描述的是栈的容量模型，与具体实现（数组或链表）没有绝对绑定。
    例如：用链表也可以实现有界栈（达到节点数上限后禁止插入）。
    用数组也可以实现无界栈（动态扩容）。
  • 在实际工程中，大多数高级语言的标准栈容器（如 C++ std::stack、Java ArrayDeque、Python list）都是无界栈，因为开发者通常不希望手动管理容量。但在底层或受约束环境中（如实时操作系统），有界栈更常见。
