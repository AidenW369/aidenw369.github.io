队列

6.1 队列抽象数据类型（ADT）

在数据结构中，队列（Queue） 是一种重要的抽象数据类型（ADT）。它的核心特点是 “先进先出”。就像现实生活中的排队：先到的人先接受服务，后来的人只能排在队尾。

什么是抽象数据类型（ADT）

ADT 是一个数学模型和定义在该模型上的一组操作。它只关注“能做什么”和“有什么特性”，而不关心具体如何实现（例如用数组还是链表实现）。

队列 ADT 正是这样一个抽象模型，它定义了一种线性的数据集合，并规定了数据只能从一端进入，从另一端离开。

队列遵循 FIFO (First In, First Out，先进先出) 原则：

  • 入队的元素总是被添加到队尾。
  • 出队的元素总是从队头移除。

队列 ADT 的基本操作

操作 描述 通常的别名
enqueue(e) 将元素 e 添加到队列的队尾。 add, offer, push
dequeue() 移除并返回队头的元素。如果队列为空，则发生错误。 remove, poll, pop
front() 返回队头元素，但不移除它。 peek, element
isEmpty() 检查队列是否为空。
size() 返回队列中元素的个数。 length
peek() 返回队列的头部元素，但不移除。
isEmpty() 检查队列是否为空。

队列的常见变体

  • 双端队列 (Deque)：两端都可以进行插入和删除操作。
  • 优先队列 (Priority Queue)：元素带有优先级，出队时优先级最高的元素先出队，而不是严格按FIFO顺序。
  • 循环队列 (Circular Queue)：用数组实现时，让队尾和队头在数组末尾连接起来，有效利用空间。
  • 阻塞队列 (Blocking Queue)：在多线程环境下，当队列为空时，获取元素的线程会被阻塞等待；当队列满时，添加元素的线程会被阻塞。

6.2 链表实现队列

在数据结构中，使用链表的队列是指用链表作为底层存储结构来实现的队列。队列是一种先进先出（FIFO, First In First Out）的线性表，只允许在一端（队尾）插入元素，在另一端（队头）删除元素。

使用链表的队列是一种用链表节点串联、通过头尾指针实现高效 FIFO 操作的动态数据结构，适合无法预估最大容量或频繁入队/出队的场景，但会牺牲一定的内存和缓存性能。

核心思想

  • 使用单链表存储元素，每个节点包含数据域和指向下一个节点的指针。
  • 维护两个指针：front（头指针）指向队头节点，rear（尾指针）指向队尾节点。
  • 入队（enqueue）在链表尾部添加新节点，出队（dequeue）从链表头部删除节点。

基本操作及时间复杂度

操作 描述 时间复杂度
enqueue(x) 将元素 x 插入队尾 O(1)
dequeue() 删除并返回队头元素 O(1)
peek() / front() 返回队头元素但不删除 O(1)
isEmpty() 判断队列是否为空 O(1)

结构示意图

  • 入队时：rear.next = newNode，然后 rear = newNode
  • 出队时：front = front.next（若原队头节点需要释放内存）

链表实现队列的优点

  1. 动态大小：无需预先分配固定容量，可根据需要动态增减节点，不会出现“队列满”的问题（除非内存耗尽）。
  2. 避免数据搬移：数组实现队列时，出队可能导致“假溢出”或需要移动大量元素（循环队列可缓解，但仍有容量限制）。链表实现只需修改指针，无需移动数据。
  3. 内存利用率高：按需分配节点，不会像数组那样可能预留过多空间。

与数组实现队列的对比

特性 链表队列 数组队列（含循环队列）
容量 无上限（受内存限制） 固定或需动态扩容
入队/出队时间 严格 O(1) O(1)（均摊，扩容时可能 O(n)）
内存开销 每个节点额外存储指针（4或8字节） 仅存储数据，无指针开销
缓存友好性 较差（节点分散在堆中） 好（连续内存）

6.3 数组实现队列

数组实现队列是指使用一段连续的存储空间（即数组）来模拟队列的“先进先出”（FIFO, First In First Out）特性。队列的两个基本操作是：

  • 入队（enqueue）：在队尾添加元素。
  • 出队（dequeue）：从队头删除/取出元素。

数组实现队列是一种利用数组和两个下标（front/rear）模拟 FIFO 行为的数据结构，通常采用循环方式避免假溢出，具有固定容量、高效存取的特点。

基本实现方式

最简单的数组队列使用两个整数指针（或下标）：

  • front：指向队头元素的位置。
  • rear：指向队尾元素的下一个可用位置（或当前队尾位置，视具体实现而定）。

初始时，front = rear = 0，表示队列为空。

操作逻辑（非循环数组）

  1. 入队：将元素放入 arr[rear]，然后 rear++。
  2. 出队：取出 arr[front]，然后 front++。

这种简单实现会导致假溢出：当 rear 到达数组末尾时，即使数组前面有空闲位置（因为出队释放了前面的空间），也无法再入队。

循环队列（常用解决方案）

为了解决假溢出，通常采用循环队列，逻辑上将数组首尾相连。

  • 判断队空：front == rear
  • 判断队满：(rear + 1) % capacity == front （牺牲一个单元来区分空和满）
  • 入队：arr[rear] = item; rear = (rear + 1) % capacity;
  • 出队：item = arr[front]; front = (front + 1) % capacity;

另一种避免牺牲空间的做法是维护一个单独的大小计数器 size。

优缺点

优点 缺点
内存连续，缓存友好 容量固定，需预先知道最大长度
操作简单，时间复杂度 O(1) 动态扩容代价较高（需拷贝数据）
无指针开销，适合嵌入式或高性能场景 循环队列需要处理边界取模

适用场景

  • 任务调度、消息队列、缓冲池等固定大小的队列场景。
  • 对内存分配效率要求高、不希望频繁 malloc 的环境。

6.3.1 有界队列与无界队列

有界队列（Bounded Queue） 和 无界队列（Unbounded Queue） 是队列在容量限制上的两种设计理念，常见于多线程环境、消息中间件及各类缓冲区实现中。

1. 有界队列

  • 定义：队列拥有固定的最大容量（记为 capacity），同时存储的元素个数不能超过该上限。
  • 行为：
    • 当队列已满时，再尝试入队（put/enqueue） 的操作会被阻塞、拒绝（抛出异常）或返回失败（取决于具体实现）。
    • 出队操作不受容量影响。
  • 实现方式：通常基于数组（如 ArrayBlockingQueue）或指定上限的链表。
  • 优点：
    • 防止内存无限增长，资源可控。
    • 强制生产-消费速率匹配，避免生产者过快导致系统崩溃。
    • 便于设计有界缓冲区和流控策略。
  • 缺点：需要权衡容量大小设置，过小可能导致性能瓶颈或死锁，过大则浪费内存。

2. 无界队列

  • 定义：逻辑上不设置固定容量上限，理论上可以存储任意多个元素。
  • 行为：
    • 入队操作永远不会被阻塞（只要内存足够）。
    • 实际容量受限于 JVM 堆内存、操作系统内存等物理资源，因此“无界”并非真正无限，只是没有人为设定的固定边界。
  • 实现方式：通常基于动态链表（如 LinkedBlockingQueue 不指定容量时默认为 Integer.MAX_VALUE）或可动态扩容的数组。
  • 优点：
    • 简化设计，无需担心队列满的情况。
    • 适合生产速率远大于消费速率、且能容忍暂时堆积的场景（如日志收集、异步任务处理）。
  • 缺点：
    • 若生产者持续快于消费者，队列会无限制膨胀，最终导致 OutOfMemoryError。
    • 缺乏背压（backpressure）机制，可能掩盖系统问题。

3. 主要区别对比

特性 有界队列 无界队列
容量限制 固定最大值 无固定上限（受物理内存限制）
满时入队行为 阻塞/抛异常/返回 false 永远成功（除非内存耗尽）
内存风险 可控 可能 OOM
典型使用场景 线程池任务队列、缓冲区、流量控制 事件驱动、异步日志、消息中间件（谨慎）
实现复杂度 需处理边界和阻塞逻辑 相对简单（无需检查满状态）

4. 与“数组实现队列”的关系

  • 数组实现的有界队列：数组大小固定，天然是有界队列。之前介绍的循环队列就是典型的有界队列。
  • 数组实现的无界队列：可以通过动态扩容（如 ArrayList 内部机制）模拟无界队列。但扩容需要复制数据，可能导致延迟峰值，通常不如链表实现自然。

总结

  • 有界队列：容量固定，资源安全，适合需要流量控制和背压的场景。
  • 无界队列：无固定上限，实现简单，但需警惕内存溢出，适合生产-消费速率相对稳定或可容忍堆积的场合。

6.4 双端队列的抽象数据类型（ADT）

双端队列（Deque，Double-Ended Queue 的缩写）是一种线性数据结构，它允许在两端（头部和尾部）进行插入和删除操作。

双端队列的 ADT 定义了一个允许在两端高效插入、删除元素的线性集合，它兼具栈和队列的功能，是一个非常灵活的基础数据结构。

行为特性

  • 双端访问：核心特征，在两端操作的时间复杂度通常为 O(1)（常数时间）。
  • 可选容量限制：可以是无界的（理论上无限大），也可以是有界的（容量固定）。
  • 不支持下标的随机访问：与数组不同，通常不能直接通过索引（如 deque[3]）访问元素。访问必须通过两端的操作进行。
  • 不保证线程安全：标准的 Deque ADT 不包含同步机制。

核心操作

操作 描述 通常的命名
在头部插入 在双端队列的最前面添加一个元素 addFirst(e), pushFront(e), offerFirst(e)
在尾部插入 在双端队列的最后面添加一个元素 addLast(e), pushBack(e), offerLast(e)
从头部删除 移除并返回双端队列最前面的元素 removeFirst(), popFront(), pollFirst()
从尾部删除 移除并返回双端队列最后面的元素 removeLast(), popBack(), pollLast()
查看头部元素 返回头部的元素，但不移除它 getFirst(), peekFirst()
查看尾部元素 返回尾部的元素，但不移除它 getLast(), peekLast()

辅助操作

  • size()：返回双端队列中元素的数量。
  • isEmpty()：检查双端队列是否为空。
  • clear()：移除双端队列中的所有元素。
  • contains(e)：检查元素 e 是否在双端队列中。

与栈和队列的关系

双端队列 ADT 非常强大，它可以模拟栈和队列的行为：

  • 作为栈使用（LIFO）：只使用同一端（例如头部）的 addFirst(e) 和 removeFirst()。Java 官方文档建议优先使用 Deque 而非遗留的 Stack 类。
  • 作为队列使用（FIFO）：在一端插入（例如尾部 addLast(e)），在另一端删除（例如头部 removeFirst()）。

常见实现方式

  1. 双向链表：每个节点有指向前驱和后继的指针，实现两端 O(1) 的插入和删除最自然。
  2. 循环数组：使用数组和头尾两个指针。当数组满时可能需要动态扩容。在大多数编程语言的库实现中性能更好，因为内存更连续。
