链表高级

4.1 双链表

双链表（Doubly Linked List） 是链表的一种。与单链表相比，它的每个节点不仅包含指向下一个节点的指针，还包含一个指向上一个节点的指针。

双链表本质上是一种以空间（多存一个指针）换时间（更灵活的插入、删除和双向遍历）的数据结构。 当需要频繁在列表中任意位置进行插入和删除操作，或者需要从两个方向遍历数据时，双链表是一个很好的选择。

4.1.1 双链表的节点结构

一个典型的双链表节点通常包含三个部分：

  • 数据域：存储实际的数据。
  • 前驱指针（prev）：指向列表中前一个节点。
  • 后继指针（next）：指向列表中后一个节点。

4.1.2 双链表与单链表的主要区别

特性 单链表 双链表
指针数量 只有 next 指针 有 prev 和 next 两个指针
内存占用 较小（每个节点少存一个指针） 较大（每个节点多存一个指针）
遍历方向 只能单向（从头到尾） 可以双向（从头到尾或从尾到头）
删除节点 需要知道前驱节点，通常要遍历 有节点本身即可直接删除（借助 prev）
插入节点 需要遍历到目标位置的前一个节点 更方便，可双向查找或直接操作

4.1.3 双链表的优缺点

优点：

  • 双向遍历：可以从任意节点向前或向后遍历，灵活性高。
  • 删除/插入更高效：如果已经定位到某个节点，删除或在其前面插入新节点时，不需要再从头遍历寻找前驱节点，时间复杂度为 O(1)（单链表在这种情况下是 O(n)）。
  • 支持反向操作：适合需要从尾部向前处理的场景（如浏览器的后退功能）。

缺点：

  • 内存占用更大：每个节点需要额外存储一个指针。
  • 操作更复杂：插入和删除节点时，需要同时维护 prev 和 next 两个指针的指向，更容易出错。

4.1.4 常见应用场景

  • 浏览器的前进后退功能：每访问一个新页面，就添加到链表末尾；后退时，利用 prev 指针回到前一页。
  • LRU（最近最少使用）缓存淘汰算法：通常使用“双链表 + 哈希表”的结构实现，双链表用于维护数据的访问顺序。
  • 操作系统的任务调度：某些需要双向遍历任务队列的场景。
  • 编辑器的撤销/重做（Undo/Redo）功能。

4.2 双链表：搜索和插入

4.2.1 双链表搜索

目标：在双链表中查找一个包含特定值的节点。

步骤（通常从头节点开始）：

  1. 设置一个当前指针 current 指向头节点（head）。
  2. 遍历链表：只要 current != NULL，就检查 current.data 是否等于目标值。
  3. 如果找到，返回该节点（或位置，或 true）。
  4. 如果遍历到末尾（current == NULL）都没找到，返回不存在。

时间复杂度：

  • 最坏情况（目标在尾节点或不存在）：O(n)，其中 n 是节点数。

特点：

  • 双链表可以从头向后搜索，也可以从尾向前搜索（如果有尾指针），但在无序链表中搜索仍需线性扫描。

4.2.2 双链表插入

在头部插入（前插）

  1. 创建新节点 new_node。
  2. 将 new_node.next 指向当前头节点 head。
  3. 如果链表非空（head != NULL），将 head.prev 指向 new_node。
  4. 将 head 更新为 new_node。

在尾部插入

  1. 创建新节点 new_node。
  2. 如果链表为空，直接让 head = new_node。
  3. 否则，遍历到尾节点 tail（或维护尾指针）。
  4. 将 tail.next 指向 new_node，new_node.prev 指向 tail。
  5. 更新尾指针（若有）。

在指定节点 p 之后插入

  1. 创建新节点 new_node。
  2. 将 new_node.next = p.next
  3. 将 new_node.prev = p
  4. 如果 p.next != NULL，则 p.next.prev = new_node
  5. 将 p.next = new_node
时间复杂度：
  • 在已知节点位置的前/后插入：O(1)（只需修改指针）。
  • 如果不知道位置，需要先搜索到该位置：O(n) + O(1) = O(n)。

双链表的优势与注意点

  • 优势：相比单链表，双链表可以双向遍历，删除给定节点时不需要知道前驱节点（因为可以直接通过 prev 找到）。
  • 注意：每个节点多一个指针，占用更多内存；插入/删除时要小心更新两个方向的指针（容易出错）。

4.3 双链表：删除

在数据结构中，双链表的删除操作是指删除链表中某个指定的节点。由于双链表每个节点都包含前驱指针（prev） 和后继指针（next），删除时比单链表更灵活，但需要维护更多的指针连接。

删除头节点（第一个节点）

步骤：

  • 将 head 指向第二个节点。
  • 如果新头节点不为空，将其 prev 指针设为 NULL。
  • 释放原头节点的内存。

删除尾节点（最后一个节点）

步骤：

  • 找到最后一个节点（node->next == NULL）。
  • 将其前一个节点的 next 指针设为 NULL。
  • 释放尾节点。

删除中间节点（已知节点指针）

步骤：

  • 设要删除的节点为 curr。
  • 将 curr->prev->next 指向 curr->next。
  • 将 curr->next->prev 指向 curr->prev。
  • 释放 curr。

与单链表删除的对比

特性 单链表删除 双链表删除
已知节点删除 需要从头遍历找到前驱 直接通过 prev 指针完成
时间复杂度 O(n)（需查找前驱） O(1)（已知节点指针）
维护的指针 1个（next） 2个（prev 和 next）
空间开销 较小 较大（多一个指针）

边界条件

  • 空链表：head == NULL
  • 删除唯一节点：头尾指针需同时更新
  • 删除节点为 NULL

4.4 链表遍历

链表遍历是指按顺序访问链表中每个节点的数据，直到链表末尾。这是链表操作中最基础的操作之一。

常见应用场景

  1. 查找元素 - 遍历链表找到目标值
  2. 计算长度 - 遍历统计节点个数
  3. 修改节点 - 遍历更新符合条件的节点
  4. 删除节点 - 遍历找到待删除节点的前驱

时间复杂度与空间复杂度

  • 时间复杂度: O(n) - 需要访问每个节点一次
  • 空间复杂度:
    • 迭代遍历: O(1)
    • 递归遍历: O(n) - 递归调用栈占用

注意事项

  1. 防止空指针 - 遍历前检查 current != null
  2. 保存头节点 - 如果后续还需要链表，不要丢失头节点引用
  3. 不要修改原链表 - 除非是有意修改，否则使用临时变量遍历

4.5 链表排序

在数据结构中，链表的排序指的是对链表中的节点按照某种顺序（如升序或降序）进行重新排列。

由于链表的内存结构不是连续的，且通常只能顺序访问，因此不能直接套用数组的排序算法（如快速排序的随机访问）。对链表排序需要采用适合链表特性的算法。

核心价值在于将头节点视为普通节点，避免大量的 if-else 边界判断，让代码更加统一、健壮和易读。在 LeetCode 等平台的链表题目中，这是一个非常推荐的编码习惯。

4.5.1 常用链表排序算法

  1. 归并排序（Merge Sort） —— 最推荐、最常用

    • 原理：利用分治法。先找到链表的中点（使用快慢指针），将链表分成两半，分别对两半递归排序，再将两个有序子链表合并成一个有序链表。
    • 时间复杂度：O(n log n)
    • 空间复杂度：O(log n)（递归栈）或 O(1)（迭代实现）
    • 优点：稳定、不需要随机访问、性能稳定，是链表排序的首选。

  2. 快速排序（Quick Sort）

    • 原理：选取一个基准节点，将比基准小的节点放到一个子链表，大的放到另一个子链表，然后递归排序，最后拼接。
    • 问题：链表中实现分区需要遍历并重新链接节点，效率不如数组；且通常不稳定。
    • 时间复杂度：平均 O(n log n)，最坏 O(n²)
    • 使用场景：较少用于链表，不如归并排序。

  3. 插入排序（Insertion Sort）

    • 原理：维护一个已排序的部分，每次从原链表中取出一个节点，插入到已排序链表的正确位置。
    • 时间复杂度：O(n²)
    • 优点：实现简单，稳定，适合小规模或近乎有序的链表。
    • 缺点：效率低，不适用于大数据量。

  4. 冒泡排序（Bubble Sort）

    • 原理：重复遍历链表，比较相邻节点并交换值（或交换节点）。
    • 时间复杂度：O(n²)
    • 缺点：效率极低，实际中很少使用，仅教学意义。

关键注意事项

  • 不能直接使用数组排序方法：如二分查找、基于索引的交换等。
  • 操作的是指针/引用：排序时通常改变节点的 next 指向，而不是移动节点内的数据（虽然交换数据也允许，但改变链接更符合链表操作习惯）。
  • 稳定性：归并排序和插入排序可以保持相等元素的相对顺序；快速排序通常不稳定。

总结

  • 最优选：归并排序（O(n log n)，O(1) 空间迭代版本也可实现）。
  • 简单场景：插入排序（数据量小时）。
  • 避免使用：冒泡排序、选择排序等 O(n²) 且不适合链表的算法。

4.6 链表的虚拟节点

在数据结构（尤其是单链表）中，虚拟节点是一个不存储实际有效数据的额外节点。

主要用来简化边界条件的处理，特别是涉及链表头节点可能被增删的场景。

核心概念

  • 本质：一个占位用的节点，通常 val 属性设为一个无意义的值（如 0 或 -1）。
  • 位置：固定在链表头部之前，作为新的固定头节点。
  • 指针：dummy.next 指向原链表的真正头节点（若原链表为空，则指向 null）。

主要作用

  1. 消除对空链表的特殊处理
    • 普通链表插入/删除头节点时需要单独判断 if (head == null)。
    • 使用虚拟节点后，dummy.next 始终代表当前有效头节点。
  2. 统一插入/删除逻辑
    • 不需要区分操作位置是头节点还是中间节点，代码更简洁、更少出错。
  3. 便于返回新链表
    • 最终只需返回 dummy.next 作为新链表头。

4.6.1 典型使用场景

删除链表中所有值为某个值的节点

合并两个有序链表

注意事项

  1. 内存泄漏：虚拟节点本身不会被自动回收，但通常影响很小，因为只有极少量额外内存。
  2. 返回值：永远返回 dummy.next，而不是 dummy 或原 head。
  3. 不是必须的：对于简单的“仅在尾部插入”等不涉及头节点变化的操作，可以不用。
  4. 尾节点虚拟：有时也会使用尾虚拟节点（Tail Sentinel），但不如头虚拟节点常见。

4.7 列表的数据结构

在 Java 中，列表（List） 是一种有序、可重复的集合数据结构，属于 Java 集合框架（Java Collections Framework）的一部分。它允许你存储多个元素，并能通过索引（从 0 开始）来访问、插入或删除元素。

核心特点

  1. 有序性：元素按照插入的顺序存储，每个元素都有一个确定的位置（索引）
  2. 允许重复：可以存储多个相同的元素（包括 null）
  3. 基于索引：通过索引（0, 1, 2…）快速访问元素

4.7.1 主要实现类

ArrayList（最常用）

  • 底层基于动态数组实现
  • 特点：查询快（O(1)）、增删慢（尤其是中间位置，O(n)）
  • 适用场景：频繁读取、遍历，较少插入/删除

LinkedList

  • 底层基于双向链表实现
  • 特点：增删快（头尾O(1)，中间需遍历）、查询慢（O(n)）
  • 适用场景：频繁在头尾插入/删除元素

与其他数据结构的区别

特性 List Set Map
顺序 有序 无序（或有序） 键值对
重复 允许 不允许 键唯一，值可重复
索引访问 支持 不支持 通过键访问

4.8 循环链表

循环链表是一种特殊的链表，它的最后一个节点不是指向 null（空），而是指回第一个节点（头节点），从而形成一个闭环。

  • 空表处理：空表通常用 head == NULL 表示。
  • 尾指针作用：实际应用中常维护一个 尾指针，这样在头部和尾部插入都能达到 O(1) 的时间复杂度。

根据链表的类型，循环链表主要有两种：

  1. 单向循环链表：最后一个节点的 next 指针指向头节点。
  2. 双向循环链表：最后一个节点的 next 指向头节点，头节点的 prev 指向最后一个节点。

核心特点

  • 无尾节点：从任何节点出发，沿着 next 指针走，最终都会回到起点。
  • 遍历条件改变：遍历的终止条件不再是 p == null，而是 p == 头节点。
  • 插入/删除灵活：在任意位置（包括头部）进行插入和删除操作时，代码逻辑比普通链表更统一，因为不需要单独处理 null 指针。

优缺点

  • 优点：
    • 支持从任意节点开始遍历整个链表，非常适合需要循环访问的场景。
    • 在头部和尾部进行插入、删除操作效率很高（尤其配合尾指针时）。
  • 缺点：
    • 如果不小心处理遍历条件，容易造成死循环。
    • 实现和调试的复杂度略高于普通链表。

与普通链表的区别

特性 普通链表 循环链表
尾节点指向 null 头节点
遍历终止条件 cur == null cur == 头节点
首尾操作 需额外处理 null 逻辑更统一
内存使用 少一个指针 多一个尾指向头
