8.2 递归算法

数据结构中的递归算法，简单说就是一个函数在其定义中直接或间接调用自身。

你可以把它理解为一种“层层递进，再逐层返回”的思考方式。它不是直接解决整个大问题，而是把大问题不断分解成规模更小、结构相同的子问题，直到子问题简单到可以直接解决，然后把结果逐层合并回去。

两大核心要素

一个正确的递归必须包含两部分，缺一不可：

  • 基准情形（Base Case）
    这是递归的“出口”。问题简化到最基本情况，无需再递归，直接返回结果。没有它，函数会无限调用下去，导致栈溢出。
  • 递归步骤（Recursive Step）
    把问题分解为更小的同类子问题，并调用函数自身去解决。它必须保证每次调用都向基准情形靠近。

递归 vs. 迭代

很多递归算法都能用循环（迭代）重写。

对比项 递归 迭代
核心思想 函数自调用，分解问题 循环结构，重复执行代码
代码清晰度 对树、图等递归结构，代码极简自然 线性逻辑更直观
性能开销 每次调用都有额外开销，可能栈溢出 通常效率更高，无栈溢出风险
适用场景 树和图的遍历、分治算法（如快排） 简单重复计算（如阶乘、累加）

8.2.1 使用递归实现二分查找算法

关键要点

  1. 递归终止条件：当 left > right 时，表示搜索区间为空
  2. 避免整数溢出：使用 left + (right - left) / 2 而不是 (left + right) / 2
  3. 时间复杂度：O(log n)
  4. 空间复杂度：O(log n)（递归调用栈）
  5. 前提条件：数组必须是有序的

8.3 递归算法的时间复杂度

计算递归算法的时间复杂度，核心是找出递归关系式，然后求解。主要方法有三种：递归树法、主定理法和代入法。

核心思路

先建立描述时间开销的递归方程：

8.3.1 主定理法（最快，适合分治算法）

当递归式形式为 T(n) = a·T(n/b) + f(n) 时直接套用：

  • Case 1：若 f(n) = O(n^(log_b(a) - ε))，则 T(n) = Θ(n^(log_b(a)))
  • Case 2：若 f(n) = Θ(n^(log_b(a)))，则 T(n) = Θ(n^(log_b(a)) · log n)
  • Case 3：若 f(n) = Ω(n^(log_b(a) + ε)) 且满足正则条件，则 T(n) = Θ(f(n))

经典例子：

归并排序 T(n) = 2T(n/2) + O(n)
a=2，b=2，log_b(a)=1，f(n)=O(n) 正好是 n¹ → Case 2
结果：O(n log n)

二分查找 T(n) = T(n/2) + O(1)
a=1，b=2，log_b(a)=0，f(n)=O(1)=n⁰ → Case 2
结果：O(log n)

8.3.2 递归树法（最直观）

什么是递归树

假如公司里有一条规则：
“第1排的人直接告诉老板一句话，后面每个人把前面人的话加上自己的工号，再告诉下一个人。”

这时候，如果想知道一句话从第1排传到第N排会变成什么样，你会怎么分析？

你可能会画一棵“倒着长的树”：

  • 根节点是第1排的原始话；
  • 每一条边代表“传给下一个人的一次处理”；
  • 每个节点代表某一排人听到的内容。

这颗“描述层层调用过程”的树，就非常接近递归树的概念。

递归树就是把递归算法“横向铺开”的一棵树，目的是为了直观理解和数学分析递归的时间复杂度，尤其在分治算法中至关重要。

递归树的正式定义

在数据结构与算法分析中，递归树是用来直观描述递归算法执行过程的一种树形结构：

  • 根节点：表示第一次递归调用的问题规模与代价；
  • 每个节点：表示一次递归调用要处理的问题，通常标注该次调用的代价或数据规模；
  • 边：表示调用关系，从父问题指向子问题；
  • 叶节点：表示递归终止条件，即不再继续递归的 base case。

一句话总结：

递归树 = 把递归的调用关系画成一棵树，用来直观地看问题如何被分解，以及总工作量如何累加。

它和“递归调用栈”有什么区别？

  • 递归调用栈：是程序运行时真实发生的栈帧压入/弹出，是一维的、纵向的时间线；
  • 递归树：是空间展开、静态分析模型，把每一次递归调用都画成一个节点，以便分析总代价。

你可以这样理解：
递归调用栈是“演电影”，一步步发生；递归树是“分镜头剧本”，一次性铺开看清所有分支。

递归树的通用绘制思路

如果你需要手画递归树来分析一道题，可按以下步骤：

  1. 确定递归关系，比如 T(n)=aT(n/b)+f(n)T(n)=a**T(n/b)+f(n)；
  2. 根 - 规模 nn，非递归代价 f(n)f(n)；
  3. 逐层展开：
    • 第 i 层有 aia**i 个节点；
    • 每个节点规模 n/bin/b**i；
    • 每个节点代价 f(n/bi)f(n/b**i)；
  4. 当子问题规模到达 base case 时停止；
  5. 分层相加 → 总代价。

8.3.3 代入法（先猜后证）

猜一个复杂度，然后用数学归纳法证明。

比如 T(n) = 2T(n/2) + n，猜测是 O(n log n)：
假设 T(k) ≤ c·k log k 对 k < n 成立，
T(n) ≤ 2c·(n/2)log(n/2) + n = cn·log n − cn + n ≤ cn·log n（当 c ≥ 1 时），归纳成立。

8.3.4 常见递归模式速查

递归式 对应算法 时间复杂度
T(n) = T(n-1) + O(1) 线性递归（链表遍历） O(n)
T(n) = T(n-1) + O(n) 选择排序 O(n²)
T(n) = 2T(n-1) + O(1) 汉诺塔 O(2ⁿ)
T(n) = T(n/2) + O(1) 二分查找 O(log n)
T(n) = 2T(n/2) + O(n) 归并排序 O(n log n)
T(n) = T(n/2) + O(n) 快速选择（平均） O(n)

8.4 链表：递归

在数据结构中，链表：递归是指利用递归的思想来操作或定义链表。它的核心是把一个链表问题，分解成一个规模更小的同类子问题。

简单来说，就是把一个长链表想象成由 “头节点” 和 “剩余部分” 组成，而“剩余部分”本身又是一个链表。这正是递归的用武之地。

递归定义链表

可以从定义上把链表看成一个递归结构：
一个链表，要么是空的（空链表），要么是一个节点，该节点包含数据，并指向另一个链表（子链表）。

这个定义本身就是递归的，它为递归算法提供了基础。

递归操作的核心思想

处理链表递归时，通常遵循两步：

  1. 处理当前节点（头节点）
  2. 递归处理剩余链表

这就形成了一个链条，直到遇到终止条件（通常是空链表）。

经典例子：递归反转链表

反转链表是理解链表递归的绝佳例子。

思路拆解：
假设链表是 1 -> 2 -> 3 -> 4 -> null，我们要反转它。

  • 递归假设：先假设 head.next 及之后的部分已经反转好了，变成 4 -> 3 -> 2 -> null。
  • 处理当前节点：现在 head 是 1，它仍然指向 2。我们需要让 2 指向 1，并让 1 指向 null。
    • 关键操作是 head.next.next = head; head.next = null;
  • 终止条件：当链表为空或只有一个节点时，直接返回，它就是反转后的头节点。

常见递归应用场景

  • 正向/反向打印链表
  • 合并两个有序链表
  • 回文链表判断（借助递归的“后序遍历”特性）
  • 删除链表中指定值的节点

优缺点与注意事项

优点：

  • 代码简洁：对于反转、回文判断等复杂操作，代码量很少。
  • 思想优雅：符合链表天然的递归结构，能自然实现从后往前的操作。

缺点：

  • 空间开销大：递归会使用系统调用栈，链表很长时可能导致栈溢出。
  • 性能略低：函数调用的开销比迭代循环大。

注意事项：

  • 必须设定终止条件，避免无限递归。
  • 警惕栈溢出：在线编程平台（如力扣、牛客网）对长链表可能直接限制递归深度。工业级代码长链表通常考虑迭代。

总的来说，链表递归把大问题化小，用层层分解的方式处理链表，代码往往非常简洁。理解它，对掌握树、图等更复杂的递归结构也很有帮助。
