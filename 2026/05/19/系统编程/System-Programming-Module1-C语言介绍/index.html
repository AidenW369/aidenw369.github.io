C语言简介

1.1 什么是C语言

C语言是一种通用的、过程式编程语言，由Dennis Ritchie于1972年在贝尔实验室开发，最初用于编写Unix操作系统。以下是C语言的核心特点：

主要特性

  • 高效性：C语言生成的程序运行速度快，接近硬件底层，效率高。
  • 可移植性：用C写的程序可以在不同平台和操作系统上编译运行。
  • 低级操作能力：支持直接操作内存（指针），可以进行位运算等底层操作。
  • 结构化编程：支持函数、循环、条件判断等结构化编程方式。
  • 简洁的语法：关键字少，语法相对简单，但功能强大。

应用领域

  • 操作系统：Linux、Windows内核等大量使用C语言
  • 嵌入式系统：单片机、微控制器编程
  • 系统软件：编译器、数据库（如MySQL）
  • 游戏引擎：底层图形和性能密集型模块
  • 网络编程：高性能服务器、协议实现

C语言的地位

C语言被称为**“编程语言之母”**，因为许多现代语言（如C++、Java、Python、Go）都受到C语言的深刻影响。学习C语言有助于深入理解计算机底层原理，是学习系统编程的重要基础。

1.1.1 C语言与Linux的关系

一、历史渊源

时间 事件
1969年 Unix操作系统在贝尔实验室诞生，最初用汇编语言编写
1972年 Dennis Ritchie发明C语言，Unix随即用C重写
1991年 Linus Torvalds用C语言编写了Linux内核的第一个版本
至今 Linux内核仍以C语言为主要开发语言（约95%以上）

Linux的诞生本身就是C语言的产物。

二、技术层面的紧密关系

1. Linux内核主要由C语言编写

  • Linux内核源码（可在 kernel.org 查看）绝大部分是C语言
  • 少量对性能极度敏感的部分（如启动引导、中断处理）使用汇编语言

2. Linux系统调用接口基于C

  • Linux的所有系统调用（如 read()、write()、fork()）都是以C语言接口形式暴露的
  • 应用程序通过C标准库（glibc）与内核交互

3. 标准C库（glibc）

  • GNU C Library（glibc）是Linux上最核心的运行时库
  • 几乎所有程序（无论用什么语言编写）最终都依赖glibc与系统交互

4. 开发工具链

  • Linux上的默认编译器 GCC（GNU Compiler Collection）最初就是为编译C语言而设计的
  • Makefile、gdb调试器等工具链都与C语言深度绑定

三、相互成就

  • C语言成就了Linux：没有C语言的高效与可移植性，Linux内核无法在如此多的硬件架构上运行（x86、ARM、RISC-V等）
  • Linux成就了C语言：Linux的广泛传播让C语言在服务器、嵌入式、云计算领域保持长久生命力

总结

C语言是Linux的"母语"，Linux是C语言最重要的舞台。两者共同构成了现代计算机系统软件的基石，学习其中一个，往往会加深对另一个的理解。

1.3 注释和缩进

1.3.1 C语言的注释

注释（Comments）

注释是代码中不会被编译器执行的说明文字，用于解释代码逻辑，提高可读性。

C语言有两种注释方式

块注释（多行注释）/* ... */

行注释（单行注释）//

注意：// 风格注释是 C99 标准引入的，早期 C89 只支持 /* */。

1.3.2 C语言的缩进

缩进（Indentation）

缩进是指在代码块前添加空格或制表符，用来体现代码的层次结构。C语言本身不强制缩进，但良好的缩进是编程规范的重要部分。

总计

特性 说明
/* */ 块注释，可多行，C89起支持
// 行注释，单行，C99起支持
缩进单位 通常为2或4个空格，或1个Tab
缩进作用 提高可读性，体现代码层次

1.4 错误和警告

在C语言编程中，**错误（Error）和警告（Warning）**是编译器在分析代码时给出的两种不同的反馈。简单来说，错误会阻止程序生成，而警告不会，但两者都值得认真对待。

1.4.1 C语言错误

错误是代码中违反 C 语言语法规则或编译限制的问题，是致命的。只要存在错误，编译器就无法将代码转换成可执行文件。

常见错误类型：

  • 语法错误：漏掉分号、括号不匹配、关键字拼写错误等。
  • 类型错误：将不兼容的类型赋值给变量。
  • 未声明标识符：使用未定义的变量或函数。
  • 重复定义：同一个变量或函数被定义了多次。
  • 致命链接错误：发生在链接阶段，比如调用了已声明但未定义的函数。

1.4.2 C语言警告

警告是编译器认为代码在语法上合法，但可能存在逻辑风险或可移植性问题。编译过程可以完成，也能生成可执行文件，但运行结果可能不如预期。

千万不能忽视警告。很多运行时崩溃或安全漏洞的根源，正是被忽略的警告。

常见警告类型：

  • 未初始化变量：使用未被赋初值的局部变量。
  • 隐式类型转换：不显式转换就赋值不同类型的数据，可能导致数据丢失。
  • 有符号/无符号数比较：混合比较会产生非直观的转换结果。
  • 控制流问题：无返回值的函数，或 switch 漏掉 break。
  • 未使用的变量/参数：声明了但从未使用。

两者的关键区别

特性 错误（Error） 警告（Warning）
是否阻止编译 是 否
严重程度 高，必须修复 中低，建议修复
程序能否运行 不能 可以，但可能有隐患

1.5 计算机和程序

1.5.1 机器语言（Machine Language）

机器语言是计算机能直接识别和执行的语言，由二进制代码（0和1）组成。每条指令对应CPU的一个具体操作，比如 10110000 01100001 可能表示"将一个数值放入某个寄存器"。它的优点是执行效率最高，无需翻译；缺点是极难阅读、编写和调试，而且不同CPU架构的机器语言互不兼容。

1.5.2 汇编语言（Assembly Language）

汇编语言用简短的助记符来代替二进制指令，比如用 MOV、ADD、JMP 等符号表示操作。它与机器语言基本上是一一对应的关系，只是用人类更容易理解的符号代替了0和1。汇编程序需要通过"汇编器"（Assembler）翻译成机器语言才能执行。汇编语言仍然与硬件架构紧密相关，可移植性差，但比机器语言更易读写，常用于对性能要求极高的场景，如操作系统内核、嵌入式系统和驱动程序开发。

1.5.3 高级语言（High-Level Language）

高级语言更接近人类自然语言和数学表达，如 C、Python、Java 等。程序员可以用 if、while、function 等直观的语法来编写程序，无需关心底层硬件细节。高级语言需要通过"编译器"（Compiler）或"解释器"（Interpreter）翻译成机器语言才能运行。它的优点是易学、易读、开发效率高、可移植性强；缺点是相比汇编语言，运行效率可能略低。

三者的关系可以简单概括为：

机器语言 ← 汇编器翻译 ← 汇编语言 ← （抽象层次提升） ← 高级语言 → 编译器/解释器翻译 → 机器语言

层次越高，离人越近、离机器越远；

层次越低，离机器越近、执行效率越高，但编写难度也越大。
