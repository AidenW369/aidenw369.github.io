算法分析

1.1 算法分析简介

1.1.1 核心概念：可扩展性与算法/数据结构

  • 科学中的尺度：科学家处理从微观到天文级别的物理尺度差异。
  • 计算中的尺度：计算机科学家处理数据量的规模差异。
  • 可扩展性：系统在输入规模或工作负载显著增长时，仍能优雅地保持性能的能力。这是技术方案能否在市场中成功的关键。
  • 核心研究对象
    • 算法：在有限时间内完成特定任务的分步操作流程。
    • 数据结构：组织和访问数据的系统性方法。
  • 学习目标：设计正确且高效（可扩展）的数据结构与算法。

1.1.2 算法分析框架

分析算法的目的是精确衡量其可扩展性。主要衡量指标是运行时间，其次是空间占用，因为时间是稀缺且昂贵的资源。

分析框架的构成：

  1. 描述语言：用于清晰表达算法的语言。
  2. 计算模型：算法运行所基于的抽象计算机模型。
  3. 计数要素：决定运行时统计哪些基本操作。
  4. 递归分析：简要介绍分析递归算法的方法。

主要理论工具：渐近记号（大O记号等），用于刻画运行时间的增长趋势。

1.1.3 分析工具：运行时间（Running Time）

  • 首要分析工具 = 刻画算法或数据结构操作的运行时间
  • 次要关注：空间使用（Space Usage）

为什么运行时间最重要？

  1. 时间是宝贵资源（Precious Resource）
  2. 在经济和科学应用中，所有人都希望程序运行得尽可能快
  3. 运行时间是衡量可扩展性的天然指标

1.2 分析算法

1.2.1 通用分析方法

1. 实验研究方法

核心思路

通过在不同规模的测试输入上运行算法，记录每次运行的实际耗时，以研究运行时间与输入规模 n 的关系。

可视化方式

将实验结果绘制成散点图：

  • x 轴：输入规模 n
  • y 轴：运行时间 t（单位：毫秒 ms）

2. 影响运行时间的因素

因素类别 具体内容
输入规模 规模越大，时间通常越长
输入内容 相同规模下，输入内容不同也可能导致时间差异
硬件环境 处理器速度、时钟频率、内存、磁盘等
软件环境 操作系统、编程语言、编译器/解释器等

💡 补充：这也是为什么算法分析中常区分最好情况 / 平均情况 / 最坏情况复杂度。

3. 实验研究的局限性

  1. 实验只能覆盖有限的测试输入，需保证代表性
  2. 不同硬件/软件环境下，结果难以横向比较
  3. 必须先实现算法才能实验，成本较高

4. 通用分析方法的要求

为了克服实验局限，需要一种更通用的分析框架，满足：

  • ✅ 考虑所有可能的输入
  • ✅ 独立于硬件与软件环境，评估算法相对效率
  • ✅ 仅通过算法的高级描述进行分析，无需实际实现

这正是渐进复杂度分析（Big-O 分析） 的动机所在。

5. 函数增长率与算法比较

将每个算法与一个函数 $ f(n) $ 关联，用来表征其运行时间随输入规模的变化。

常见的 $ f(n)$ 类型

增长类型 表示 特点
常数时间 O(1) 与输入规模无关
对数时间 O(log⁡n) 极慢增长，如二分查找
线性时间 O(n) 与输入成正比
线性对数 O(nlog⁡n) 如归并排序
平方时间 O(n2) 如冒泡排序
指数时间 $O(2^n) $ 增长极快，通常不可接受

1.2.2 伪代码（Pseudocode）

1. 什么是伪代码？

伪代码是程序员用来描述算法的一种介于自然语言和编程语言之间的描述方式：

  • 专供人类阅读，而非计算机执行
  • 比普通文字更有结构性
  • 有助于对数据结构或算法进行高层次分析

核心原则：传达高层思想，而非底层实现细节；既不过于简略，也不过于繁琐。

2. 伪代码的语法构成

构成要素 说明
表达式 用数学符号表示；← 为赋值，= 为等值判断
方法声明 Algorithm name(param1, param2, ...)
条件结构 if 条件 then 真操作 [else 假操作]
While循环 while 条件 do 操作
Repeat循环 repeat 操作 until 条件
For循环 for 变量定义 do 操作
数组索引 A[i] 表示数组第 i 个元素，下标从 0 或 1 开始
方法调用 object.method(args)
方法返回 return 值
注释 // 符号后跟注释内容

3. 示例：arrayMax 算法

问题： 求数组 A（含 n 个整数）中的最大值

4. 算法正确性验证（以 arrayMax 为例）

采用循环不变量思路逐步推导：

  1. 初始：currentMax = A[0]（第 1 个元素的最大值）
  2. 第 i 次迭代开始时：currentMax = 前 i 个元素的最大值
  3. 比较 currentMax 与 A[i]，若成立则更新
  4. 因此第 i+1 次迭代前仍然成立
  5. 经过 n−1 次迭代后，currentMax = 整个数组的最大值 ✓

好的伪代码应足够详细以验证算法正确性，同时足够简洁以便人类理解。

1.2.3 原始操作计数与RAM模型

1. 为什么需要分析方法？

实验分析有其局限性。为此，我们采用分析方法：直接对高层代码或伪代码进行分析，无需实际运行程序。

2. RAM模型（随机访问机器模型）

定义

RAM（Random Access Machine）是一种计算模型，将计算机抽象为：

概念 说明
内存单元 每个单元存储一个"字"（数字、字符串或地址）
随机访问 CPU 可用一次原始操作访问任意内存单元
数字大小 模型中不限制存储数字的大小（简化假设）
执行时间 CPU 执行任何原始操作均视为常数步骤，与输入规模无关

3. 原始操作（Primitive Operations）

原始操作是独立于编程语言、可在伪代码中识别的高层基本操作，每个操作对应一条常数时间的底层指令。

七类原始操作

# 操作类型 示例
1 变量赋值 x = 5
2 调用方法 arrayMax(A)
3 算术运算 a + b
4 比较两个数 i < n
5 数组索引 A[i]
6 对象引用跟随 node.next
7 方法返回 return value
核心思想
  • 不测量每个操作的具体时间，只计算操作总数 t(n)
  • 操作数与实际运行时间成正比（因为每个原始操作都是常数时间）

4. 案例分析：arrayMax 算法

各步骤原始操作计数

步骤 操作说明 操作数
初始化 currentMax = A[0] 数组索引 + 赋值 2（执行1次）
for 循环初始化 i = 1 赋值 1（执行1次）
条件判断 i < n 比较 n（执行n次）
循环体（每次迭代） 索引+比较，[可能]索引+赋值，加法+赋值 4 或 6（执行 n−1 次）
返回 currentMax 返回操作 1（执行1次）

总操作数

​ t(n)≥2+1+n+4(n−1)+1=5n （最好情况）

​ t(n)≤2+1+n+6(n−1)+1=7n−2 （最坏情况）

最好 vs 最坏情况
情况 t(n) 触发条件
最好情况 5n A[0] 是最大值，currentMax 从不被重新赋值
最坏情况 7n−2 数组升序排列，currentMax 每次迭代都被更新

5. 平均情况 vs 最坏情况分析

分析类型 难度 说明
最坏情况分析 ✅ 较简单 无需概率论，只需找到最差输入；本书主要使用此方法
平均情况分析 ❌ 较复杂 需定义输入的概率分布，数学要求高

为什么偏爱最坏情况？

  1. 简单：不需要概率论
  2. 强健：为最坏情况设计意味着对每个输入都表现良好
  3. 类比：就像田径运动员总是在上坡练习，能建立更强的"算法肌肉"

1.2.4 递归

1. 递归概念

递归（Recursion） 是一种重要的算法设计技术，核心思想是：

定义一个过程 P，允许它将自身作为子程序调用，但每次调用必须针对规模更小的子问题。

要素 说明
递归调用 过程对自身的调用，每次处理更小规模的输入
基础情形（Base Case） 问题规模足够小，可以直接求解，无需继续递归
递推关系 如何将大问题分解为小问题

2. 示例：递归求数组最大值

recursiveMax(A, n)

执行逻辑

先递归求前 n-1 个元素的最大值

再与第 n 个元素比较，取较大值返回

3. 递归算法的时间分析

递推方程（Recurrence Equation）

分析递归算法运行时间，需要建立 递推方程，定义函数 T(n) 表示规模为 n 时的运行时间。

对 recursiveMax 算法（每次比较、数组访问、递归调用、max计算、return 均计为1次原始操作）：

T(n)={3if n=1T(n−1)+7otherwise

为什么基础情形是 3？ n=1 时执行：① 比较 n=1，② 访问 A[0]，③ return → 共 3次操作

为什么递推情形是 +7？ 每层执行：① 比较 n=1?，② 递归调用，③ 访问 A[n-1]，④ max 计算，⑤ return等 → 约 7次操作

4. 封闭形式（Closed Form）

封闭形式：将递推方程转化为不含 T 自身引用的显式表达式。

推导过程

T(n)=T(n−1)+7

=T(n−2)+7+7

=T(n−k)+7k

(k=n−1) T(1)+7(n−1)=3+7n−7

T(n)=7n−4

结论

形式 表达式
递推形式 T(n) = T(n−1)+7，T(1) = 3
封闭形式 T(n) = 7n−4
渐近复杂度 O(n) — 线性时间

5. 补充：递归 vs 迭代

对比维度 递归 迭代
代码风格 更简洁优雅 较为直接
时间分析 需建立递推方程 直接计数循环次数
空间开销 有调用栈开销 O(n) 通常 O(1)
适用场景 分治、树/图遍历等 简单循环计算

1.2.5 渐进符号（Asymptotic Notation）

1. 背景与动机

对于简单算法（如 arrayMax、recursiveMax），逐步计算原始操作数过于繁琐。实际上，伪代码中每一步对应的原始操作数不依赖于输入规模，因此可以做简化分析——估计到常数倍数级别即可。渐进符号正是为此而生。

2. 大O符号（Big-Oh Notation）

定义： 设 f(n)和 g(n)是从非负整数到实数的函数。若存在：

  • 实常数 c > 0
  • 整数常数 n0 ≥ 1

使得对所有 n ≥ n0，都有：

​ f(n)≤c⋅g(n)

则称 f(n)是 O(g(n))，读作 “f(n) 是 big-Oh of g(n)” 或 “f(n) 是 order g(n)”。

图形理解（Figure 1.2.3）

从 n0 开始，cg(n) 永远在 f(n) 上方，即 f(n) 被 cg(n) 从上方"压住"。

语义解读

  • “≤”：f 小于等于 g（上界）
  • 常数 c：允许忽略常数倍数差异
  • n≥n0：渐进意义，只关心 $n→∞ $ 时的趋势

典型例题

例题 结论 证明思路
7n−2 O(n) 取c=7,n0=1，则7n−2≤7n
20n3+10n2+5 O(n3) 取c=35,n0=1，则原式≤35n3
3logn+loglogn O(logn) 取c=4,n0=2，因为log⁡log⁡n<log⁡n（n≥2）
$2^{100} $ O(1) 取c=2100,n0=1，常数函数，n不出现
5nlogn+2n $O(n\log n) $ 取c=7,n0=2，则原式≤7nlog⁡n

**规律：**任意多项式 $$a_k n^k + a_{k-1} n^{k-1} + \cdots + a_0 = O(n^k)$$

使用建议

  • 应使用尽可能简单且紧致的 g(n)来描述 f(n)
  • 精确分析运行时间往往困难，而用大O刻画通常更简便
  • 实践中可用简化规则（下一节内容）来快速得出大O表达式，无需每次回到定义

3. 为什么使用 Big-O表示？

我们关心算法的运行时间或空间占用，用函数 f(n)描述

精确描述往往困难，Big-Oh 提供渐近上界，更简洁易用

原则：用尽可能简单的函数 g(n)来刻画 f(n)

  • 例： f(n)=4n3+3n4/3，说它是O(n3)比说O(n5)更有信息量

Theorem 1.2.2：Big-Oh 运算法则

设 $ d(n), e(n), f(n), g(n)$ 均为非负整数到非负实数的映射：

# 法则 说明
1 d(n)是O(f(n))⇒a⋅d(n)是O(f(n)) 常数倍可吸收
2 d(n)是O(f(n))，e(n)是O(g(n))⇒d+e是O(f+g) 加法合并
3 d(n)是O(f(n))，e(n)是O(g(n))⇒d⋅ed是O(f⋅g) 乘法合并
4 d(n)是O(f(n))，f(n)是O(g(n))⇒d(n)是O(g(n)) 传递性
5 f(n)=a0+a1n+⋯+adnd（d次多项式）⇒f(n)是O(nd) 多项式取最高次
6 $n^x是O(a^n)，对任意固定常数 x>0, a>1 $ 指数增长快于多项式
7 lognx是O(log⁡n)，对任意固定常数x>0 指数提到系数后可忽略
8 logxn是O(ny)，对任意固定常数x>0,y>0 对数增长慢于多项式

函数类别术语

术语 表示
对数级 logarithmic O(log⁡n)
线性级 linear O(n)
平方级 quadratic O(n2)
多项式级 polynomial O(nk)，k≥1
指数级 exponential O(an)，a>1

Big-Oh 的正确用法

写法 是否正确
f(n)≤O(g(n)) ❌ 冗余（Big-Oh 本身已含"小于等于"之意）
f(n)=O(g(n)) ⚠️ 常见但不严格
f(n)≥O(g(n))或f(n)>O(g(n)) ❌ 错误
f(n) is O(g(n)) ✅ 推荐写法
f(n)∈O(g(n)) ✅ 严格数学写法（Big-Oh 是函数的集合）

渐近精确表达（扩展）

当需要给出精确首项时，可以写：

​ f(n) is g(n)+O(h(n))

即存在常数c>0,n0≥1，使得对n≥n0，有：

​ f(n)≤g(n)+c⋅h(n)

$例：2n \log n + 4n + 10\sqrt{n} 可表达为 2n\log n + O(n) $
