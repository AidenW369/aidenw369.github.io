基本数据结构

2.1 基本数据结构简介

2.1.1 核心概念梳理

  • 电路交换 vs. 分组交换

    • 传统电话网采用电路交换，通信前需建立一条专用物理通路，资源独占，效率低。
    • 互联网采用分组交换。数据被切分成小包，每个包独立选路，共享网络资源，效率高，但会引入延迟和抖动。

  • 数据包（Packet）与 MTU

    • 数据包是网络传输的基本单元，包含头部（源/目的地址等控制信息）和有效载荷。
    • MTU（最大传输单元）：链路层规定的最大有效载荷。以太网的1500字节是事实标准，但并非绝对（如巨型帧可达9000字节）。

  • TCP 如何保证可靠有序？

    • 确认与重传：接收方收到包后发确认消息，发送方在超时未收到确认时会重传。
    • 序列号：每个字节都有编号，接收方以此按序重组，丢弃重复包。
    • 流量控制与拥塞控制：防止发送方“淹没”接收方或网络，这也是延迟抖动的一大来源。

  • 缓冲区的生产者-消费者模型与流量整形

    • 生产者：网络进程，以变速率将数据包放入队列。多亏了TCP，放入时已是正确顺序。
    • 消费者：播放器进程，以固定码率从队列取出数据解码播放。
    • 缓冲区（队列）：吸收速率波动。作用是流量整形，好比水库——进水忽大忽小，出水则平稳恒定。
    • 初始缓冲：播放前需先蓄积足够数据，以应对后续的网络抖动。

  • 互联网数据包传输

  • 互联网以离散数据包（packets） 传输信息

  • 以太网标准下，单个数据包最大 1500 字节（即MTU）

  • 视频等大文件必须拆分为多个包，各自独立路由，再在目的地重组

2.1.2 为什么不都用 TCP？——实时视频的取舍

教材提到“存储的视频文件”用TCP，这个限制条件非常关键。对于实时视频（如视频会议、直播），情况完全不同：

特性 TCP（适用于点播） UDP（适用于实时通信）
可靠性 绝对可靠，保证送达 尽最大努力交付，不保证可靠
有序性 严格按序 不保证，应用层自己处理
延迟 重传机制引入不可预测的延迟 无连接、无重传，延迟低
控制机制 有复杂的拥塞控制 无，应用层可按需控制发送速率
应用场景 文件传输、网页、点播视频 视频会议、直播、在线游戏、DNS

原因：在实时通话中，一个丢失的音频包已无重传必要，因为它的“时效”已过，强行重传只会造成卡顿。所以宁可短暂花屏/卡音，也要保证低延迟的流畅感。

TCP — Transmission Control Protocol（传输控制协议）

TCP 是一种面向连接、可靠的传输协议。在发送数据之前，需要先通过三次握手建立连接，然后才开始传输。

核心特性：

  • ✅ 可靠交付：确保每个数据包都到达目的地
  • ✅ 有序传输：保证数据按发送顺序重组
  • ✅ 错误检测与重传：丢包会自动重传
  • ✅ 流量控制 & 拥塞控制：防止网络过载
  • ❌ 代价：延迟较高，开销较大

典型应用： 网页浏览（HTTP/HTTPS）、邮件、文件下载、点播视频（YouTube、Netflix）

UDP — User Datagram Protocol（用户数据报协议）

UDP 是一种无连接、不可靠的传输协议。发送方直接把数据"扔出去"，不管对方有没有收到。

核心特性：

  • ✅ 低延迟：无握手，无等待，直接发送
  • ✅ 轻量：头部开销小（8字节 vs TCP的20字节）
  • ❌ 不保证到达：包可能丢失
  • ❌ 不保证顺序：包可能乱序到达
  • ❌ 无重传机制

典型应用： 视频通话（Zoom、FaceTime）、网络直播、在线游戏、DNS查询

对比总结

特性 TCP UDP
全称 传输控制协议 用户数据报协议
连接方式 面向连接（三次握手） 无连接
可靠性 高（保证到达） 低（尽力而为）
顺序保证 ✅ ❌
速度/延迟 较慢 很快
头部开销 20 字节 8 字节
适用场景 准确性优先 速度优先

💡 一个直觉类比

  • TCP 像挂号信——你知道信一定会送到，还能确认签收，但慢一些。
  • UDP 像广播——说出去就算了，不管听众有没有听见，但快。

2.1.3 抖动（Jitter）问题

  • 数据包到达时间不均匀的现象称为网络抖动（Jitter）
  • 原因：网络拥塞、路由路径不同、错误重传等
  • 这是需要缓冲区的根本原因

2.1.4 缓冲区（Buffer）机制

生产者：TCP网络进程，以可变速率向缓冲区写入数据包

消费者：视频播放进程，以固定速率从缓冲区读取数据包

缓冲区起到**“削峰填谷”** 的作用，只要均值速率足够，就能流畅播放

2.1.5 FIFO（先进先出）

  • 缓冲区遵循 FIFO 原则——最早进入的包最先被消费
  • 这保证了视频帧按正确时间顺序播放
  • FIFO 的典型数据结构实现：队列（Queue）

2.2 栈和队列

2.2.1 栈的基本概念

栈是一种遵循**后进先出（LIFO, Last-In First-Out）**原则的容器数据结构。

生活类比：就像自助餐厅里弹簧托盘架上的一叠盘子——最后放上去的盘子，最先被取走。

2.2.2 栈的基本操作

方法 描述
push(o) 将对象 o 插入栈顶
pop() 移除并返回栈顶元素（若栈为空则报错）

2.2.3 基于数组的实现

核心思路

用一个容量为 N 的数组 S 存储元素，同时维护一个整数变量 t 表示栈顶元素的下标。

  • 初始状态（空栈）：t = -1
  • 栈中元素个数：t + 1
  • 栈满条件：t + 1 = N

优点 缺点

push/pop 均为 O(1) 容量不足时会崩溃

替代方案：

  • 使用链表实现（无固定大小限制，空间随元素数量动态变化）
  • 使用可扩展数组（Extendable Array），随栈增长自动扩容

2.2.4 栈的重要应用

方法调用与递归（Method Stack）

在 C、C++、Java、Python 等语言的运行时环境中，每个线程都维护一个私有的方法栈（Method Stack），用于：

  • 追踪局部变量
  • 保存方法调用信息
关键概念
概念 说明
帧（Frame） 描述当前活跃方法调用的数据单元，存储局部变量、参数及返回信息
程序计数器（Program Counter） 记录当前执行语句的地址，方法调用时保存返回地址
运行中方法 位于方法栈顶部的帧所对应的方法
挂起方法 栈中其余帧对应的方法，等待被调用的方法返回

方法调用流程

参数传递：值传递（Call-by-Value）
  • C、Java 等语言使用值传递
  • 传递的是变量当前的值，而非变量本身
  • 被调用方法修改局部副本，不影响调用方的原始变量

递归（Recursion）

栈天然支持递归：每次递归调用都会在方法栈中创建一个独立的帧，拥有各自的局部变量副本。

⚠️ 注意： 若递归设计不当（无终止条件），方法栈会不断增长，最终耗尽内存，引发 StackOverflow 错误。

正确设计递归的要点：

  1. 确保递归调用处理的是"更小"的子问题
  2. 对"最小"情形进行非递归的特殊处理（Base Case）

2.2.5 队列（Queue）

队列的基本概念

队列是一种遵循**先进先出（FIFO, First-In First-Out）**原则的容器数据结构。

生活类比：就像排队买票——先来的人先被服务，后来的人只能在队尾等待。

  • 元素从队尾（rear） 插入
  • 元素从队头（front） 删除
  • 只有在队列中待得最久的元素才能被取出

队列的基本操作

方法 描述
enqueue(o) 将对象 o 插入队尾
dequeue() 移除并返回队头元素（若队列为空则报错）

基于数组的实现

核心思路

用容量为 N 的数组 Q 存储元素，同时维护两个索引变量：

变量 含义
f (front) 指向队头元素的下标
r (rear) 指向下一个可用空位的下标

初始状态：f = r = 0

空队列条件：f == r

队列元素个数：(N - f + r) mod N

2.2.6 栈 vs 队列 对比

特性 栈（Stack） 队列（Queue）
原则 LIFO（后进先出） FIFO（先进先出）
插入 push — 从栈顶插入 enqueue — 从队尾插入
删除 pop — 从栈顶删除 dequeue — 从队头删除
典型应用 函数调用、递归、括号匹配 视频缓冲、打印队列、订票系统

2.2.7 扩展补充

其他常见栈的应用场景

  1. 括号匹配：编译器用栈检查 {}、[]、() 是否配对
  2. 表达式求值：中缀转后缀表达式（逆波兰表达式）
  3. 浏览器历史：后退功能本质上是一个栈
  4. 撤销操作（Undo）：文本编辑器的撤销功能
  5. 深度优先搜索（DFS）：图与树的遍历算法

2.3 列表

列表的定位

栈和队列只能在序列的两端进行更新操作，而列表（List）在保持线性顺序的同时，允许在序列中间进行访问和更新。

2.3.1 基于索引的列表（Index-based Lists）

1. 索引（Index / Rank）的定义

设线性序列 S 含有 n 个元素。每个元素 e 可用 [0,n−1] 范围内的整数唯一标识。

索引（rank）= 该元素之前的元素个数

  • 第一个元素索引为 0
  • 最后一个元素索引为 n−1

2. 关键区别：列表索引 ≠ 数组下标

特性 数组单元下标 列表中的索引
性质 静态（固定） 动态
是否变化 不变 随插入/删除而改变

举例：在列表开头插入一个新元素，其后所有元素的索引都 +1。 （这一定义与 Java 中的 ArrayList 一致。）

3. 基于索引列表的核心方法

方法 功能 错误条件
get(r) 返回索引为 r 的元素 r<0 或 r>n−1
set(r, e) 用 e 替换索引 r 处的元素，并返回旧元素 r<0 或 r>n−1
add(r, e) 插入新元素 e 使其索引为 r r<0 或 r>n
remove(r) 删除索引 r 处的元素 r<0 或 r>n−1

⚠️ 注意 add 的边界是 r>n （允许在末尾追加），其余三个方法都是 r>n−1

4. 数组实现

  • 用数组 A 实现， A[i] 存储索引为 i 的元素（的引用）。
  • 选取足够大的容量 N ，用实例变量维护实际元素个数 n （满足 n<N ）。
  • get(r) 实现极简：直接返回 A[r] 。

2.3.2 Algorithm ：add 与 remove 的实现

add(r, e) —— 插入

思路：从后往前，把索引 ≥r 的元素整体向后（上）移一位，再把 e 放入位置 r 。

remove(r) —— 删除

思路：从前往后，把索引 ≥r+1 的元素整体向前（下）移一位，覆盖被删位置，返回被删元素。

核心要点：元素移动（Shifting）

数组实现中最耗时的部分就是为保持单元连续而进行的元素移动：

  • 插入索引 r ：索引 ≥r 的所有元素上移 1 位。
  • 删除索引 r ：索引 ≥r+1 的所有元素下移 1 位。

移动的目的：始终维持「索引为 i 的元素恰好存放在 $A[i] $」这一规则。

复杂度直观分析

操作 时间复杂度 原因
get / set O(1) 直接按下标访问
add / remove O(n)（最坏） 需要移动元素；在开头操作最慢，末尾最快

2.3.3 基于数组的索引列表（Array-based Index List）

各操作的时间复杂度

方法 时间复杂度 说明
get(r) O(1) 直接按索引访问
set(r, e) O(1) 直接按索引修改
add(r, e) O(n) 最坏情况需移动大量元素
remove(r) O(n) 最坏情况需移动大量元素
  • 空间复杂度为 O(N)，其中 N 是数组的大小。

插入与删除的代价分析

add(r, e) 的最坏情况发生在 r = 0 时，此时已有的全部 n 个元素都要向后移动一位，因此为 Θ(n)。同理，remove(r) 在 r = 0 时需要移动 n−1 个元素。如果假设每个索引被传入的概率相等，平均每次操作要移动约 n/2 个元素，平均时间仍为 Θ(n)。

更精确地说，add 和 remove 实际运行时间为 O(n − r + 1)：只有 rank ≥ r 的元素才需要被移动。

关键性质：操作的"不对称性"

  • 在末尾操作很快：add(n, e)、remove(n−1) 只需 O(1) 时间（末尾附近常数个位置内的操作同样是常数时间）。
  • 在开头操作很慢：在列表头部插入/删除要移动几乎所有元素，需 Θ(n)。

改进思路

  1. 循环数组：放弃"列表索引 i 的元素一定存储在数组索引 i"这一规则，可使索引 0 处和末尾的插入删除都达到 O(1)（即队列中用过的技巧）。
  2. 可扩展表（extendable table）：可使末尾的插入/删除达到常数摊还时间（amortized O(1)），这正是 Java 中 ArrayList 的默认实现方式。

2.3.4 链表（Linked List）

核心思想：用"位置"代替"索引"

不再用索引引用元素，而是把每个元素存在一个 node（节点） 对象里，节点之间用指针相互引用。抽象出的概念叫 position（位置），它把"节点"这一直觉概念形式化。

链表被看作一个元素容器，每个元素存储在一个节点位置上，这些位置按线性顺序排列。

位置（Position）的关键特性

  • 位置是相对定义的：位置 p 总是在某个位置 q “之后”、某个位置 s “之前”（除非 p 是首/尾）。
  • 位置具有稳定性：即使元素 e 的 rank 在列表中发生变化，位置 p 也不变——除非显式删除该元素。
  • 替换或交换 p 处的元素也不改变位置本身。

Position 支持的方法：element() —— 返回该位置存储的元素。

链表的访问方法

方法 描述
first() 返回首元素的位置（空表则报错）
last() 返回末元素的位置（空表则报错）
before(p) 返回 p 前一个元素的位置（p 为首则报错）
after(p) 返回 p 后一个元素的位置（p 为尾则报错）

注意：这些方法用相对位置移动，但没有直接暴露指针/链接。

链表的更新方法

方法 描述
insertBefore(p, e) 在位置 p 之前插入新元素 e
insertAfter(p, e) 在位置 p 之后插入新元素 e
remove(p) 删除位置 p 处的元素

单链表 vs 双链表

借助节点对象，链表的多种操作（包括各处的插入/删除）都能在 O(1) 时间完成。

  • 单链表（Singly Linked）：节点只存一个 next 链接，只能从头到尾单向遍历。
  • 双链表（Doubly Linked）：节点同时存 next 和 prev 两个链接，可双向遍历。能从任一节点确定前后节点，大大简化实现。

哨兵节点（Sentinel / Dummy Nodes）

为简化更新和查找，在列表两端各加一个不存储元素的特殊节点：

  • header（头哨兵）：位于真正头节点之前 —— 有有效的 next，prev 为 null。
  • trailer（尾哨兵）：位于真正尾节点之后 —— 有有效的 prev，next 为 null。

它们的存在让我们不必特殊处理首尾插入删除的边界情况。链表对象本身只需存储这两个哨兵 + 一个 size 计数器（统计元素数，不含哨兵）。

应用举例：文本编辑器内嵌"位置插入/删除"的概念，光标（cursor） 就代表正在编辑的字符列表中的当前位置。

两种实现对比小结

维度 数组实现 链表实现
按索引随机访问 O(1)（优势） 慢（需遍历）
头部插入/删除 Θ(n)（慢） O(1)（优势）
末尾插入/删除 O(1) / 摊还 O(1) O(1)
引用元素的方式 索引 位置 / 节点
空间 O(N)（可能有空余） 每节点额外存指针

一句话总结：数组适合频繁随机访问的场景，链表适合频繁在任意位置插入/删除的场景。

2.3.5 带哨兵的双向链表结构

Figure 2.3.1 展示了带哨兵的双向链表：header 和 trailer 标记列表两端。空列表的特殊情形就是两个哨兵互相指向对方。

实现上的关键点：直接让链表的节点本身实现 position 概念——每个节点定义 element() 方法返回所存元素，于是节点即位置。

插入算法 insertAfter(p, e)

在位置 p 之后插入元素 e：创建新节点 v 存放 e，把 v 链入列表，并更新 v 两个新邻居的 next/prev 引用。

注意操作顺序：必须先用 p.next 取到旧后继（第 4、5 行），再修改 p.next（第 6 行），否则会丢失对旧后继的引用。

insertBefore、insertFirst、insertLast 的算法与此类似。

删除算法 remove(p)

核心思路：让 p 的两个邻居互相指向对方（把 p “链接出去”，link out）。p 被链出后没有任何节点再指向它，垃圾回收器即可回收其空间。

哨兵的妙用：因为有 header/trailer，即使 p 是列表中第一个、最后一个或唯一一个真实位置，这段算法依然成立，无需特殊处理边界情况。

双向链表性能

采用基于节点的实现后，链表的所有方法都能做到 O(1)：

方法 时间复杂度
first() O(1)
last() O(1)
before(p) O(1)
after(p) O(1)
insertBefore(p, e) O(1)
insertAfter(p, e) O(1)
remove(p) O(1)
  • 空间复杂度为 O(n)。

2.3.6 数组列表 vs 链表：综合对比

1. 按索引/秩访问

数组胜。链表要确定元素 e 的 rank，只能从存 e 的节点沿指针一路数到头或尾，因此基于索引的操作在链表上需 O(n)；数组直接定位是 O(1)。

2. 基于位置的更新

链表胜。链表能在列表"中间"以常数时间插入/删除；数组为保持元素在数组中连续，同样操作需 O(n)（要移动元素）。

3. 空间

  • 数组：O(N)，N 是数组大小（除非用可扩展数组）。
  • 双向链表：O(n)，n 是实际元素个数。
  • 当 n 远小于 N 时，链表的渐近空间更优；但链表有更大的常数因子开销（每个节点要额外存指针），而数组无需链接来维持顺序。

总结表

维度 数组实现 双向链表实现
索引/秩访问 O(1) ✓ O(n)
中间插入/删除 O(n) O(1) ✓
空间 O(N) O(n)（n≪N 时更省，但常数大）

结论：两种实现各有优劣，没有绝对的好坏。 选哪种取决于实际要执行的操作类型以及可用的内存空间——频繁随机访问选数组，频繁任意位置增删选链表。

2.4 树（Trees）

2.4.1 树的基本概念

树是一种分层存储元素的数据结构。除了顶部元素外，每个元素都有一个父节点（parent）**和零个或多个**子节点（children）。

绘制约定：

  • 通常用椭圆或矩形表示元素，用直线连接父子节点。
  • 顶部元素称为根（root），画在最高处，其余元素向下连接——与现实中的植物树正好相反。

树的形式化定义

树 T 是一组以父子关系存储元素的节点（nodes），满足以下性质：

  1. T 有一个特殊节点 r，称为根，它没有父节点。
  2. T 中每个不同于 r 的节点 v 都有唯一的父节点 u。

注意：按此定义，树不能为空（至少含有根节点）。本书约定树总是有根，以简化算法讨论。

核心术语

术语 含义
孩子（child） 若 u 是 v 的父节点，则 v 是 u 的孩子
兄弟（siblings） 拥有相同父节点的两个节点
外部节点 / 叶子（external / leaf） 没有孩子的节点
内部节点（internal） 有一个或多个孩子的节点
祖先（ancestor） 节点本身、其父节点，或其父节点的祖先
后代（descendant） 若 u 是 v 的祖先，则 v 是 u 的后代
子树（subtree） 以节点 v 为根的子树，由 v 的所有后代（含 v 本身）构成

有序树（Ordered Tree）

若每个节点的孩子之间存在线性次序（可识别为第一个、第二个、第三个……），则该树是有序的。有序树通常通过按正确顺序列出兄弟节点来表达这种次序关系。

二叉树（Binary Tree）

二叉树是一种有序树，其中每个节点至多有两个孩子。

  • 真二叉树（proper）：每个内部节点都恰好有两个孩子；否则为非真（improper）二叉树。
  • 每个孩子被标记为左孩子（left child）**或**右孩子（right child），且左孩子排在右孩子之前。
  • 以左/右孩子为根的子树分别称为左子树和右子树。

一张图理清层级关系

2.4.2 树的抽象数据类型（Tree ADT）

树在抽象层面将元素存储在位置（positions）**上，这些位置即树的**节点（nodes）。"位置"与"节点"两词可互换使用。每个位置对象都支持 element() 方法（返回该位置的元素）。节点位置的真正威力来自下列方法。

1. 访问方法（Accessor methods）

方法 说明
root() 返回树的根
parent(v) 返回节点 v 的父节点；若 v 是根则报错
children(v) 返回包含 v 所有孩子的集合

若树 T 有序，children(v) 按顺序返回；若 v 是外部节点，则返回空集。

2. 查询方法（Query methods）

方法 说明
isInternal(v) 测试 v 是否为内部节点
isExternal(v) 测试 v 是否为外部节点
isRoot(v) 测试 v 是否为根

3. 通用方法（Generic methods）

方法 说明
size() 返回树中节点数量
elements() 返回所有节点存储的元素集合
positions() 返回所有节点的集合
swapElements(v, w) 交换节点 v 与 w 存储的元素
replaceElement(v, e) 用 e 替换 v 的元素，并返回被替换的元素

此处不定义专门的更新方法，而是把更新操作留待与具体应用结合时再定义。

4. 运行时间假设

为分析基于树的算法，对各方法的运行时间作如下假设：

方法 时间复杂度
root()、parent(v) O(1)
isInternal(v)、isExternal(v)、isRoot(v) $O(1) $
children(v) O(cv) ， cv 为 v 的孩子数
swapElements(v, w)、replaceElement(v, e) O(1)
elements()、positions() O(n) ， n 为节点总数

2.4.3深度（Depth）

设 v 是树 T 的节点，v 的深度是 v 的祖先数量（不含 v 自身）。

递归定义：

  • 若 v 是根，则深度为 0；
  • 否则，v 的深度 = 1 + 父节点的深度。

算法：depth

运行时间： O(1+dv) ，其中 dv 为 v 的深度（对每个祖先执行一次常数时间的递归）。

  • 最坏情况下为 O(n) （某些节点深度可能接近 n ）；
  • 但用参数 dv 刻画更精确，因为 dv 往往远小于 n 。

2.4.4 高度（Height）

树 T 的高度 = T 中外部节点的最大深度。

此定义虽正确，但若对每个节点都套用 depth 算法，会得到 O(n2) 的低效算法。

更好的做法是用节点高度的递归定义：

  • 若 v 是外部节点，则高度为 0；
  • 否则， v 的高度 = 1 + 其孩子中的最大高度。

树 T 的高度 = 根节点的高度。

深度 vs. 高度 对比记忆

深度（Depth） 高度（Height）
方向 向上数到根 向下数到叶子
起点 单个节点 单个节点
基准值 根的深度 = 0 外部节点的高度 = 0
递归 1 + 父节点深度 1 + 孩子的最大高度
整棵树 —— = 根的高度

直观记法：深度向上看祖先，高度向下看子孙。 同一节点的深度和高度通常不同；只有"链状"退化树才可能相等。

高度算法（height）

基于高度的递归定义，算法 height(T, v) 高效计算以 v 为根的子树的高度。整棵树的高度通过调用 height(T, T.root()) 得到。

算法：height

运行时间分析（摊还论证）

从根开始调用时，该算法最终会在每个节点上恰好被调用一次。

  • 在节点 v 上，children(v) 耗时 O(cv) ；
  • for 循环执行 cv 次，每次为 O(1) 加上对孩子的递归调用；
  • 因此每个节点的非递归部分耗时 O(1+cv) ；
  • 总运行时间为： O(∑v∈T(1+cv))

2.4.5 树的遍历（Traversal）

遍历是系统化地访问（“visit”）树中所有节点的方式。两种基本遍历方案：前序遍历（preorder） 与后序遍历（postorder）。

前序遍历（Preorder）

规则：先访问根，再递归遍历各孩子的子树。若树有序，则按孩子顺序遍历子树。 "访问"的具体动作取决于应用（可以是计数，也可以是复杂计算）。

算法 ：preorder

初始调用：preorder(T, T.root())。

特点与应用

前序遍历会产生一种线性次序，其中父节点总是排在孩子之前。

阶段性小结：树算法的 O(n)范式

算法 每个节点耗时 关键依据 总时间
depth(T, v) O(1) 沿祖先链 $O(1 + d_v) $
height(T, v) O(1+cv) 定理 2.4.1 O(n)
preorder(T, v) $O(1 + c_v) $ 定理 2.4.1 $O(n) $

记忆要点：只要算法对每个节点做一次"常数 + 孩子数"的工作，凭借 ∑cv=n−1 ，整体一定是线性 O(n) 。

后序遍历（Postorder）

后序遍历可看作前序遍历的"对立面"：先递归遍历各孩子的子树，最后才访问根。若树有序，仍按指定顺序对孩子做递归调用。

算法：postorder

运行时间与适用场景

  • 分析与前序遍历相同：非递归部分总时间正比于访问各节点孩子的时间，假定每个节点访问为 O(1)O(1) O(1)，则整体 O(n)O(n) O(n)（线性时间）。
  • 适用场景：当计算某节点 v 的性质，必须先算出 v 所有孩子的同一性质时（自底向上计算），后序遍历最合适。

前序 vs. 后序 对比

前序（Preorder） 后序（Postorder）
访问根的时机 递归之前 递归之后
方向 自顶向下 自底向上
典型用途 父先于子的线性序（如生成目录） 子结果先于父（如求高度、表达式求值）

2.4.6 二叉树（Binary Tree）ADT

真二叉树是每个内部节点恰好有两个孩子的有序树。约定：除非另有说明，二叉树都假定为真。

这一约定不失一般性：

  • 任意非真二叉树都可转换为真二叉树；
  • 即便不转换，也可把缺失的外部节点视为 NULL 占位节点（仍计为节点），从而当作真二叉树处理。

三个附加访问方法

方法 说明
leftChild(v) 返回 v 的左孩子；若 v 是外部节点则报错
rightChild(v) 返回 v 的右孩子；若 v 是外部节点则报错
sibling(v) 返回 v 的兄弟节点；若 v 是根则报错

处理非真二叉树时还需额外错误条件（例如某内部节点可能缺左孩子或右孩子）。此处不定义更新方法，留待具体需求时再设计。

二叉树的性质

层（Level）

把树 T 中处于相同深度 dd d 的所有节点集合称为 T 的第 d 层（level d）。

层 dd d 最多节点数
0（根） 1

一般 d 2d

量 真二叉树（n 节点，高 h）
第 d 层最多节点 2d

2.4.7 二叉树的遍历

二叉树遍历的运行时间假设

除前面对一般树方法的假设外，二叉树额外假设：

  • children(v) 耗时 O(1)（每个节点要么 0 个、要么 2 个孩子）；
  • leftChild(v)、rightChild(v)、sibling(v) 各耗时 O(1)。

由于任意二叉树也可看作一般树，前面的通用遍历都适用，但针对二叉树可简化伪代码。

二叉树的三种递归遍历

1. 前序（binaryPreorder）—— 访问在递归之前

2. 后序（binaryPostorder）—— 访问在递归之后

3. 中序（inorder）—— 二叉树特有，访问在两次递归之间

中序遍历可非正式地理解为**“从左到右”**访问节点。

应用：对算术表达式树做中序遍历，得到与标准表达式书写一致的次序（如 3 + 1 × 3 / 9 - 5 + 2 ...），不过缺少括号。

三种遍历的差别只在"访问根"插入的位置：

遍历 访问根的位置 二叉树次序
前序 左右递归之前 根 → 左 → 右
中序 左右递归之间 左 → 根 → 右
后序 左右递归之后 左 → 右 → 根

2.4.8 欧拉环游（Euler Tour）

把上述遍历统一为一个框架——放宽"每个节点恰好访问一次"的要求，得到欧拉环游遍历。优点是能更容易表达更一般的算法。

直观定义

欧拉环游可看作绕树 T 的一次"行走"：从根出发走向左孩子，把树的边视为"墙"，始终靠左行走。每个节点 vv v 会被遇到三次：

  1. 左侧（on the left）：在 v 左子树环游之前
  2. 下方（from below）：在 v 两棵子树环游之间
  3. 右侧（on the right）：在 v 右子树环游之后

若 v 是外部节点，这三次"访问"实际同时发生。

算法：eulerTour

三种遍历都是欧拉环游的特例

遍历 等价于欧拉环游中"访问"动作发生在
前序 左侧
中序 下方
后序 右侧

运行时间

假定访问节点为 O(1)，每次环游在每个节点上花费常数时间，整体对 n 节点树为 O(n)。

2.4.9 二叉树的链式结构（Linked Structure）

实现二叉树 T 的自然方式是用链式结构：每个节点 vv v 用一个对象表示，该对象包含若干引用。

单个节点的结构

每个节点对象含 4 个字段：

字段 指向
element v 存储的元素
parent v 的父节点
left v 的左孩子
right v 的右孩子

NULL 引用约定

  • 若 v 是根，则 parent 引用为 NULL；
  • 若 v 是外部节点，则其孩子引用为 NULL；
  • 为节省空间，可允许内部节点指向"空外部节点"的引用直接为 NULL（即不实际创建空外部节点对象）。

性能

  • size()、isEmpty()、swapElements(v, w)、replaceElement(v, e) 均为 O(1)；
  • positions() 可用中序遍历实现，elements() 类似，二者均为 O(n)；
  • 空间：每个节点对应一个常数大小的对象，故总空间为 O(n)。

2.4.10 一般树的链式结构

可把二叉树的链式结构推广到一般树。关键区别：一般树节点 vv v 的孩子数没有上限，因此用一个容器（如列表或数组）存储孩子，而非两个固定的实例变量。

单个节点的结构

字段 指向
element v 存储的元素
parent v 的父节点
children 一个容器（列表/数组），存放指向各孩子的引用

一般树链式实现的运行时间

一般树链式实现的性能与二叉树链式实现相似，主要区别在于：用高效容器（列表/数组）存储每个节点的孩子，而非直接指向恰好两个孩子的链接。

设 cv 为节点 v 的孩子数：

操作 时间复杂度
size、isEmpty O(1)
positions、elements O(n)
swapElements、replaceElement O(1)
root、parent O(1)
children(v) O(cv)
isInternal、isExternal、isRoot O(1)

链式实现要点对比

二叉树链式结构 一般树链式结构
孩子存储 固定 left、right 两个引用 容器（列表/数组）存任意数量孩子
节点字段 element, parent, left, right element, parent, children(容器)
children(v) O(1) $O(c_v) $
positions() 实现 中序遍历，O(n) 遍历，O(n)
