12.4 希尔排序（壳排序）

希尔排序（Shell Sort）是插入排序的一种高效改进版本，也常被称为缩小增量排序。

它的核心思想很直观：先让数据大幅度跳跃，变得基本有序，最后再进行一次精排。 这解决了简单插入排序一次只能移动一位的低效问题。

12.4.1 核心原理

希尔排序通过引入增量的概念，将整个序列分割成若干个子序列，分别进行插入排序。待整个序列“基本有序”后，再对全体记录进行一次插入排序（此时增量通常为1）。

简单来说，它做了两件事：

  1. 分组：设定一个间隔（增量），将相隔这个距离的元素归为一组。
  2. 组内排序：对每一组内的元素进行插入排序。
  3. 缩小增量：不断缩小这个间隔，重复上述过程，直到间隔为1。

12.4.2 时间复杂度

希尔排序的效率与增量序列的选择密切相关。

  • 最坏情况：取决于增量序列。使用原始的希尔增量（每次除以2），最坏为 O(n²)。
  • 最好情况：当数组基本有序时，可接近 O(n)。
  • 平均复杂度：使用某些高效增量序列（如 Hibbard），可降至 O(n log² n) 级别。

12.4.3 关键特性与比较

  • 稳定性：不稳定。因为分组跳跃式移动时，相等元素的相对位置可能改变。
  • 适用性：不允许使用外部排序的中等规模数据很有效。代码简单，易于实现。
  • 与插入排序对比：它解决了简单插入排序在近似逆序数组上的性能瓶颈，核心优势在于快速减少逆序对。

简单总结就是：希尔排序 = 分组预排 + 最终精排。增量序列的选择是影响它效率的关键。

12.4.4交错式插入排序算法

希尔排序中的“交错式插入排序”，是指不是逐个处理子序列，而是交替扫描，一次性完成所有子序列的排序。

为了理解它，我们可以和另一种策略“逐个处理”对比：

  • 逐个处理（独立排序）
    先把第一个子序列完整排好，再排第二个，以此类推。比如有子序列A、B、C，就是A→A→A……排完→B→B→B……排完→C。
  • 交错式处理（希尔排序的做法）
    从整个数组的某个位置开始遍历，遇到哪个子序列的元素，就立即对它进行插入排序。过程像是在所有子序列之间来回跳跃。

为什么希尔排序实际采用交错式？

原因很直观：缓存友好，遍历顺序和数组在内存中的物理顺序一致。

你可以看到，循环变量 i 是连续从 gap 递增到 n-1 的，这保证了数组是从前到后顺序访问的，能充分利用CPU缓存和现代硬件的预取机制。

具体过程解析

假设数组 [8, 5, 3, 7, 1, 6, 4, 2]，初始增量 gap = 3。它被分为3个逻辑子序列：

  • 子序列1：索引 0, 3, 6 → 值 [8, 7, 4]
  • 子序列2：索引 1, 4, 7 → 值 [5, 1, 2]
  • 子序列3：索引 2, 5 → 值 [3, 6]

交错式插入排序的执行流程如下：

  1. i = 3，元素 7（属子序列1）。与前一个元素 arr[0]=8 比较并插入。
  2. i = 4，元素 1（属子序列2）。与 arr[1]=5 比较并插入。
  3. i = 5，元素 6（属子序列3）。与 arr[2]=3 比较并插入。
  4. i = 6，元素 4（属子序列1）。与子序列1中已部分排序的元素（索引3的7、索引0的8）比较并插入。
  5. i = 7，元素 2（属子序列2）。与子序列2中已部分排序的元素（索引4的1、索引1的5）比较并插入。

整个过程在数组上只进行了一次从前向后的扫描，就同时完成了所有子序列的排序。这就是“交错”的含义。

12.4.5 为什么排序最终要回到间隔为1

最终必须回到间隔为1，是为了保证算法正确性，完成最终的精确排序。

1. 正确性层面：只有间隔1才能保证全局有序

希尔排序在前几轮用大间隔（如5、3、2）做的“分组排序”，其实只是粗略调整，它们有一个根本的局限性：

间隔大于1的排序，只能保证各组内的元素有序，无法保证整个数组全局有序。

  • 比如以间隔2排序后，能保证 a[0] ≤ a[2] ≤ a[4]... 和 a[1] ≤ a[3] ≤ a[5]...。
  • 但你依然可能出现 a[0]（偶数组成员）比 a[1]（奇数组成员）大的情况。
  • 也就是说，以任何大于1的间隔排序，都只完成了局部有序。

只有当间隔为1时，排序的范围才覆盖了整个数组，它执行的就是标准的插入排序，能比较和调整相邻元素，从而消除所有逆序对，达成真正的“全局有序”。

这一步是不可跳过的，否则算法结束后，数组可能只是“基本有序”，而非“完全有序”。

2. 效率层面：此时已基本有序，插入排序接近O(n)

为了效率的巨大提升。 中间那些大间隔的排序，正是为了让最后这次间隔为1的排序变得极其廉价。

  • 原始插入排序的缺点：元素一次只能挪一个位置。如果一个最小的数在末尾，它需要很多次比较和移动才能到前面。
  • 希尔排序的功劳：大间隔的预排序，已经把大、小元素基本放到了正确的“大区域”。最小的数早就被大跳跃地送到了前端。
  • 最后的间隔1排序：此时数组里逆序对已经非常少。对于基本有序的数组，插入排序的效率极高，非常接近O(n)。很多元素根本不需要移动，比较几次就直接跳过。

总结：用前期大间隔的O(n log² n)开销，消灭绝大部分逆序对，为最后这次理论上O(n²)、实际接近O(n)的精准收尾工作铺平道路。 没有这最后一步，排序就是错的；但没有前面那些步骤，最后一步就会慢如蜗牛。

12.7 基数排序

基数排序是一种非比较型的整数排序算法。它的核心思想是：将整数按位数切割成不同的数字，然后从最低位开始，依次对每一位进行稳定的排序（通常用计数排序），最终得到完全有序的序列。

12.7.1 核心原理：多关键字排序

以最常见的最低位优先法为例，过程分三步：

  1. 找最大数：确定数组中最大数的位数，决定需要几轮排序。
  2. 逐位排序：从个位、十位、百位……一直到最高位，每一轮都对当前位进行稳定排序。
  3. 稳定积累：因为排序是稳定的，高位的顺序不会打乱低位已排好的结果，最终高位排序会让整个数组有序。

图解过程

以数组 [170, 45, 75, 90, 802, 24, 2, 66] 为例：

第一轮（个位）
按个位数字放入 0-9 号桶，结果为：
[170, 90, 802, 2, 24, 45, 75, 66]

第二轮（十位）
在上轮结果上按十位排序，结果为：
[802, 2, 24, 45, 66, 170, 75, 90]

第三轮（百位）
按百位排序，最终有序：
[2, 24, 45, 66, 75, 90, 170, 802]

算法特性

  • 时间复杂度：O(d × (n + k))，n是数据量，d是最大位数，k是基数（如十进制为10）。当d较小时，接近 O(n)。
  • 空间复杂度：O(n + k)，需要额外的桶空间。
  • 稳定性：稳定，因为逐位排序必须依赖稳定性。
  • 适用场景：适用于整数或能转为整数的字符串排序，且数据范围不能过大。

需要注意的局限

  • 数据格式受限：如果对float排序，设计“按位分割”会非常麻烦。
  • 额外的空间：不是原地排序。
  • 并非总是最优：如果数据重复度高或最大位数 d 非常大，效率会下降，这时可能不如快速排序等比较型算法。

12.7.2 处理负数排序

方法一：正负分治（最常用）

将数组拆分成负数和非负数两部分，分别排序后再合并。

步骤：

  1. 拆分：把负数和非负数分成两个数组。
  2. 取绝对值：将所有负数取绝对值（变正数）。
  3. 分别排序：对两个数组各自做标准的基数排序（都已是非负整数）。
  4. 反转并还原：负数部分排序后逆序，再加回负号；非负数部分保持原序。
  5. 合并：将处理后的负数数组和非负数数组合并。

方法二：偏移量映射

给所有数加上一个偏移量，把负数映射到非负范围，排序后再减回来。

核心思路：

  1. 找到数组的最小值 min_val（比如 -170）。
  2. 计算偏移量 offset = -min_val（即 170）。
  3. 所有元素加上偏移量，全部变成非负整数：[-170+170, -45+170, 75+170, ...] → [0, 125, 245, ...]。
  4. 对映射后的数组做标准基数排序。
  5. 排序完成后，所有元素减去偏移量，还原成原始值。

优点：一趟完成，不用拆数组。
缺点：如果最小值很小（比如 -10^9）而数据量不大，加了偏移后数字跨度巨大，基数排序的轮数和空间消耗会增加。

实际选择建议

方法 适用场景
正负分治 通用性好，负数和非负数数量相当，实现直观
偏移量映射 数据范围不太大，想避免拆分数组的麻烦
