12.4 希尔排序（壳排序）

希尔排序（Shell Sort）是插入排序的一种高效改进版本，也常被称为缩小增量排序。

它的核心思想很直观：先让数据大幅度跳跃，变得基本有序，最后再进行一次精排。 这解决了简单插入排序一次只能移动一位的低效问题。

12.4.1 核心原理

希尔排序通过引入增量的概念，将整个序列分割成若干个子序列，分别进行插入排序。待整个序列“基本有序”后，再对全体记录进行一次插入排序（此时增量通常为1）。

简单来说，它做了两件事：

  1. 分组：设定一个间隔（增量），将相隔这个距离的元素归为一组。
  2. 组内排序：对每一组内的元素进行插入排序。
  3. 缩小增量：不断缩小这个间隔，重复上述过程，直到间隔为1。

12.4.2 时间复杂度

希尔排序的效率与增量序列的选择密切相关。

  • 最坏情况：取决于增量序列。使用原始的希尔增量（每次除以2），最坏为 O(n²)。
  • 最好情况：当数组基本有序时，可接近 O(n)。
  • 平均复杂度：使用某些高效增量序列（如 Hibbard），可降至 O(n log² n) 级别。

12.4.3 关键特性与比较

  • 稳定性：不稳定。因为分组跳跃式移动时，相等元素的相对位置可能改变。
  • 适用性：不允许使用外部排序的中等规模数据很有效。代码简单，易于实现。
  • 与插入排序对比：它解决了简单插入排序在近似逆序数组上的性能瓶颈，核心优势在于快速减少逆序对。

简单总结就是：希尔排序 = 分组预排 + 最终精排。增量序列的选择是影响它效率的关键。

12.4.4交错式插入排序算法

希尔排序中的“交错式插入排序”，是指不是逐个处理子序列，而是交替扫描，一次性完成所有子序列的排序。

为了理解它，我们可以和另一种策略“逐个处理”对比：

  • 逐个处理（独立排序）
    先把第一个子序列完整排好，再排第二个，以此类推。比如有子序列A、B、C，就是A→A→A……排完→B→B→B……排完→C。
  • 交错式处理（希尔排序的做法）
    从整个数组的某个位置开始遍历，遇到哪个子序列的元素，就立即对它进行插入排序。过程像是在所有子序列之间来回跳跃。

为什么希尔排序实际采用交错式？

原因很直观：缓存友好，遍历顺序和数组在内存中的物理顺序一致。

具体过程解析

假设数组 [8, 5, 3, 7, 1, 6, 4, 2]，初始增量 gap = 3。它被分为3个逻辑子序列：

  • 子序列1：索引 0, 3, 6 → 值 [8, 7, 4]
  • 子序列2：索引 1, 4, 7 → 值 [5, 1, 2]
  • 子序列3：索引 2, 5 → 值 [3, 6]

交错式插入排序的执行流程如下：

  1. i = 3，元素 7（属子序列1）。与前一个元素 arr[0]=8 比较并插入。
  2. i = 4，元素 1（属子序列2）。与 arr[1]=5 比较并插入。
  3. i = 5，元素 6（属子序列3）。与 arr[2]=3 比较并插入。
  4. i = 6，元素 4（属子序列1）。与子序列1中已部分排序的元素（索引3的7、索引0的8）比较并插入。
  5. i = 7，元素 2（属子序列2）。与子序列2中已部分排序的元素（索引4的1、索引1的5）比较并插入。

整个过程在数组上只进行了一次从前向后的扫描，就同时完成了所有子序列的排序。这就是“交错”的含义。

12.4.5 为什么排序最终要回到间隔为1

最终必须回到间隔为1，是为了保证算法正确性，完成最终的精确排序。

1. 正确性层面：只有间隔1才能保证全局有序

希尔排序在前几轮用大间隔（如5、3、2）做的“分组排序”，其实只是粗略调整，它们有一个根本的局限性：

间隔大于1的排序，只能保证各组内的元素有序，无法保证整个数组全局有序。

  • 比如以间隔2排序后，能保证 a[0] ≤ a[2] ≤ a[4]... 和 a[1] ≤ a[3] ≤ a[5]...。
  • 但你依然可能出现 a[0]（偶数组成员）比 a[1]（奇数组成员）大的情况。
  • 也就是说，以任何大于1的间隔排序，都只完成了局部有序。

只有当间隔为1时，排序的范围才覆盖了整个数组，它执行的就是标准的插入排序，能比较和调整相邻元素，从而消除所有逆序对，达成真正的“全局有序”。

这一步是不可跳过的，否则算法结束后，数组可能只是“基本有序”，而非“完全有序”。

2. 效率层面：此时已基本有序，插入排序接近O(n)

为了效率的巨大提升。 中间那些大间隔的排序，正是为了让最后这次间隔为1的排序变得极其廉价。

  • 原始插入排序的缺点：元素一次只能挪一个位置。如果一个最小的数在末尾，它需要很多次比较和移动才能到前面。
  • 希尔排序的功劳：大间隔的预排序，已经把大、小元素基本放到了正确的“大区域”。最小的数早就被大跳跃地送到了前端。
  • 最后的间隔1排序：此时数组里逆序对已经非常少。对于基本有序的数组，插入排序的效率极高，非常接近O(n)。很多元素根本不需要移动，比较几次就直接跳过。

总结：用前期大间隔的O(n log² n)开销，消灭绝大部分逆序对，为最后这次理论上O(n²)、实际接近O(n)的精准收尾工作铺平道路。 没有这最后一步，排序就是错的；但没有前面那些步骤，最后一步就会慢如蜗牛。

12.7 基数排序

基数排序是一种非比较型的整数排序算法。它的核心思想是：将整数按位数切割成不同的数字，然后从最低位开始，依次对每一位进行稳定的排序（通常用计数排序），最终得到完全有序的序列。

12.7.1 核心原理：多关键字排序

以最常见的最低位优先法为例，过程分三步：

  1. 找最大数：确定数组中最大数的位数，决定需要几轮排序。
  2. 逐位排序：从个位、十位、百位……一直到最高位，每一轮都对当前位进行稳定排序。
  3. 稳定积累：因为排序是稳定的，高位的顺序不会打乱低位已排好的结果，最终高位排序会让整个数组有序。

图解过程

以数组 [170, 45, 75, 90, 802, 24, 2, 66] 为例：

第一轮（个位）
按个位数字放入 0-9 号桶，结果为：
[170, 90, 802, 2, 24, 45, 75, 66]

第二轮（十位）
在上轮结果上按十位排序，结果为：
[802, 2, 24, 45, 66, 170, 75, 90]

第三轮（百位）
按百位排序，最终有序：
[2, 24, 45, 66, 75, 90, 170, 802]

算法特性

  • 时间复杂度：O(d × (n + k))，n是数据量，d是最大位数，k是基数（如十进制为10）。当d较小时，接近 O(n)。
  • 空间复杂度：O(n + k)，需要额外的桶空间。
  • 稳定性：稳定，因为逐位排序必须依赖稳定性。
  • 适用场景：适用于整数或能转为整数的字符串排序，且数据范围不能过大。

需要注意的局限

  • 数据格式受限：如果对float排序，设计“按位分割”会非常麻烦。
  • 额外的空间：不是原地排序。
  • 并非总是最优：如果数据重复度高或最大位数 d 非常大，效率会下降，这时可能不如快速排序等比较型算法。

12.7.2 处理负数排序

方法一：正负分治（最常用）

将数组拆分成负数和非负数两部分，分别排序后再合并。

步骤：

  1. 拆分：把负数和非负数分成两个数组。
  2. 取绝对值：将所有负数取绝对值（变正数）。
  3. 分别排序：对两个数组各自做标准的基数排序（都已是非负整数）。
  4. 反转并还原：负数部分排序后逆序，再加回负号；非负数部分保持原序。
  5. 合并：将处理后的负数数组和非负数数组合并。

方法二：偏移量映射

给所有数加上一个偏移量，把负数映射到非负范围，排序后再减回来。

核心思路：

  1. 找到数组的最小值 min_val（比如 -170）。
  2. 计算偏移量 offset = -min_val（即 170）。
  3. 所有元素加上偏移量，全部变成非负整数：[-170+170, -45+170, 75+170, ...] → [0, 125, 245, ...]。
  4. 对映射后的数组做标准基数排序。
  5. 排序完成后，所有元素减去偏移量，还原成原始值。

优点：一趟完成，不用拆数组。
缺点：如果最小值很小（比如 -10^9）而数据量不大，加了偏移后数字跨度巨大，基数排序的轮数和空间消耗会增加。

实际选择建议

方法 适用场景
正负分治 通用性好，负数和非负数数量相当，实现直观
偏移量映射 数据范围不太大，想避免拆分数组的麻烦

12.8.2 逐个剖析与选型建议

1. 选择排序（不常用）

  • 原理：每轮找未排序部分的最小值，放到已排序部分的末尾。
  • 评价：无论数据怎样，都要进行约 n²/2 次比较。数据移动次数最少，为 O(n)。
  • 场景：当数据移动成本远高于比较成本时可考虑，否则几乎不用。

2. 插入排序（小规模数据好用）

  • 原理：将无序数据插入到已排好序的序列中。
  • 核心优势：对近乎有序数据效率极高，可达 O(n)。且是稳定排序。
  • 场景：数据量小，或数据基本有序时。常作为快速排序、归并排序在递归到小规模时的优化。

3. 希尔排序（实用的改进插入排序）

  • 原理：它先对相隔一定增量（gap）的元素进行插入排序，使数组变得“大致有序”，然后逐步减小增量，最终进行标准的插入排序。
  • 核心优势：利用了插入排序在部分有序时高效的特性，打破了 O(n²) 的壁垒。实现简单，效率不错。
  • 场景：嵌入式系统等对代码量有要求，且不要求稳定性的中等规模数据排序。

4. 快速排序（通用大将）

  • 原理：分治法。选基准值，将数组划分为比基准小和大的两部分，再递归排序。
  • 核心优势：实际应用中速度最快的通用排序算法之一，因为其内存访问模式对缓存友好。
  • 核心劣势：不稳定。在最坏情况下会退化到 O(n²)（如每次选到最小/大值作基准）。可通过随机选基准来避免。
  • 场景：绝大多数通用场景的首选，也是很多语言标准库的默认排序基础（如C++的std::sort）。

5. 归并排序（稳定之王）

  • 原理：分治法。将数组完全拆分为单元素，然后两两有序合并。
  • 核心优势：无论数据如何，都保证 O(n log n) 的时间复杂度，是稳定的外排序算法首选。
  • 核心劣势：需要 O(n) 的额外内存空间。
  • 场景：需要稳定排序，或处理**超大数据集（外排序）**时。Java语言对对象数组的排序就使用了归并排序（历史版本）。

6. 堆排序（空间苛刻时的选择）

  • 原理：将数组构建成最大堆，反复取出堆顶元素（最大值）放到数组末尾。
  • 核心优势：同样是 O(n log n)，但只需 O(1) 的额外空间，这点比归并和快排都好。
  • 核心劣势：对缓存不友好，实际速度通常慢于快排。不稳定。
  • 场景：在内存极其受限，又必须保证 O(n log n) 时间复杂度时。

7. 基数排序（特殊场景专用）

  • 原理：非比较排序。对数字或字符串的每一位进行分配和收集。
  • 核心优势：可以突破比较排序的理论下界 O(n log n)，达到近似线性时间。
  • 核心限制：仅适用于可分解为独立“位”或“字符”的数据。非常占内存，且对数据格式敏感。
  • 场景：对大量整数或固定格式字符串的排序，且数据量很大、范围已知时。

12.8.3 算法选型

  1. 看数据类型
    • 是整数或固定格式字符串，且范围不大？ → 可考虑 基数排序。
    • 是通用的可比较对象？ → 继续往下看。
  2. 看稳定性需求
    • 必须保持相等元素的原始顺序？ → 归并排序 或 插入排序（数据量小）。
    • 不需要稳定？ → 继续往下看。
  3. 看内存与规模
    • 内存极其受限，数据量却很大？ → 堆排序。
    • 数据量很小或基本有序？ → 插入排序。
    • 数据量中等，不想写复杂代码？ → 希尔排序。
    • 以上都不是，追求通用和最佳平均性能？ → 快速排序。

12.9 冒泡排序

冒泡排序是一种最基础的交换排序算法。它的核心思想就像水里的气泡往上冒一样，通过依次比较相邻的两个元素，将较大的数往后“冒”，较小的数往前“浮”。

12.9.1 核心原理

它重复地走访要排序的数列，一次比较两个相邻元素。如果它们的顺序错误（比如希望升序，但前面的比后面的大），就交换它们。这个过程会重复进行，直到没有需要交换的元素为止。

主要有两个要点：

  • 相邻比较：只比较紧挨着的两个元素。
  • 逐轮归位：每一轮遍历，都会把当前未排序部分的最大值（或最小值）推到最后面，就像气泡浮出水面。

总的来说，冒泡排序因为效率问题很少用于生产环境，但它非常适合用来入门算法思想。

12.9.2 图解步骤（升序为例）

假设有数组 [5, 1, 4, 2, 8]，第一轮会这样操作：

  1. 比较 5 和 1，5>1，交换 → [1, 5, 4, 2, 8]
  2. 比较 5 和 4，5>4，交换 → [1, 4, 5, 2, 8]
  3. 比较 5 和 2，5>2，交换 → [1, 4, 2, 5, 8]
  4. 比较 5 和 8，5<8，不交换 → 数组不变

第一轮结束，最大的数字 8 已“冒”到最后。

后续几轮会忽略已归位的元素，继续重复这个过程：

  • 第二轮比较前4个元素，最终 5 就位，数组变为 [1, 4, 2, 5, 8]。
  • 第三轮比较前3个元素，4 就位，数组变为 [1, 2, 4, 5, 8]。
  • 第四轮比较前2个元素，2 就位，排序完成。

12.9.4 性能分析

  • 时间复杂度
    • 最坏/平均：数据完全或部分无序时，需要双重循环，复杂度为 O(n²)。
    • 最好：数据本身有序，只遍历一轮就结束，复杂度为 O(n)。
  • 空间复杂度：O(1)，只在原数组上交换，不需要额外空间。
  • 稳定性：稳定。当相邻元素相等时，不会发生交换，它们的相对位置得以保留。

12.9.5 优缺点总结

  • 优点：原理简单，代码容易实现；是稳定排序；空间开销小。
  • 缺点：时间复杂度高，处理海量数据时效率极低。

12.10 快速选择(Quickselect)

快速选择是一种从无序数组中找出第k小（或第k大）元素的算法，可以看作是快速排序的变种。它的核心优势是平均时间复杂度为 O(n)，远优于直接排序的 O(n log n)。

核心原理

它借用了快速排序的分区思想，但每次只递归一侧：

  1. 从数组中随机选一个基准元素。
  2. 将数组分为三部分：小于基准的放左边、等于基准的放中间、大于基准的放右边。
  3. 判断第k小的元素落在哪：
    • 如果 k ≤ 左部分的长度，就递归处理左部分。
    • 如果 k 在左部分和中间部分长度之和的范围内，那么答案就是基准值本身。
    • 否则，问题就变成在右部分找第 (k - 左长度 - 中长度) 小的元素，递归处理右部分。

与快速排序的关键区别

  • 快速排序：每次分区后，左右两侧都要递归处理，类似二叉树遍历所有节点。
  • 快速选择：每次分区后，只进入包含目标元素的那一侧递归，类似只走二叉树的某一条路径。所以成本从 O(n log n) 降到了 O(n)。

时间与空间复杂度

  • 平均时间复杂度：O(n)。每次递归处理的数据量大致减半，总工作量是 n + n/2 + n/4 + …，极限收敛于 2n。
  • 最坏时间复杂度：O(n²)。当每次选的基准都极不走运（例如总选到最小元素），导致每次只排除一个元素时会发生。不过，使用随机化选择基准可以规避绝大多数最坏情况。
  • 空间复杂度：取决于实现，递归栈深度平均 O(log n)，尾递归优化可做到 O(1)。

一个直观的图示

假设从 [3, 7, 8, 5, 2, 1, 9, 4] 中找第3小的元素：

  1. 选 5 为基准，分区后为 [3, 2, 1, 4] | 5 | [7, 8, 9]，左边有4个元素。
  2. 要找第3小的，3 < 4，进入左边 [3, 2, 1, 4] 继续找第3小。
  3. 选 3 为基准，分区后为 [2, 1] | 3 | [4]，左边有2个元素。
  4. 3 > 2，所以答案在右边 [4]，并变为找第 (3-2-1)=0 小，也就是第一个元素，最终答案是 4。

应用场景

  • 寻找Top K问题（不只是找一个，而是找前K个，可与堆排序等方法权衡选择）。
  • 数据库中求中位数或百分位数。
  • 各类统计和数据分析中需要极高效率的线性选择操作。

12.11 桶排序

桶排序是一种分布式排序算法，核心思想不是靠两两比较，而是把数据分到几个有序的“桶”里，再分别排序，最后按桶的顺序倒出来。

核心原理

  • 设置桶：先确定要几个桶，每个桶覆盖一个数据区间。
  • 分桶：遍历所有数据，判断它属于哪个区间，就放进对应的桶里。
  • 桶内排序：每个桶里的数据用别的排序算法排好（常用插入排序）。
  • 合并：按桶的先后顺序，依次取出所有元素，整体就有序了。

示例

假设有数据：[0.12, 0.61, 0.29, 0.84, 0.45]

  • 分桶（10个桶，区间[0, 0.1)，[0.1, 0.2)…）：
    • 0.12 放桶1，0.61放桶6，0.29放桶2，以此类推。
  • 桶内排序：
    • 桶1 [0.12]，桶2 [0.29, 0.45]，桶6 [0.61]，桶8 [0.84]，其余空桶。
  • 合并输出：
    • 依次倒出所有桶的元素，结果为：0.12, 0.29, 0.45, 0.61, 0.84。

时间复杂度

它的效率高度依赖数据分布：

  • 最好/平均情况：数据均匀分布时，只需线性分桶加少量内部排序，O(n + k)，约等于线性时间 O(n)。
  • 最坏情况：数据全挤进一个桶里，退化成一个普通的排序算法，例如 O(n²) 如果桶内用插入排序。
  • 空间复杂度：O(n + k)，需要额外空间存放桶和所有数据。

核心要点

  • 适用于外部排序：比如海量数据无法一次装入内存，可以先分桶存成小文件。
  • 可对数据要求高：数据必须能轻松划分区间，并且最好分布得比较均匀。它不能像快排那样对任何数据都表现稳定。
  • 可以是稳定排序：只要桶内排序用的也是稳定算法，桶排序就是稳定的。
