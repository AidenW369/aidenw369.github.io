12.1 Do-While循环

do-while 循环是 C 语言里的一种循环结构,它的特点是先执行循环体,再判断条件。这意味着无论条件是否成立,循环体至少会执行一次。

基本语法

执行流程是:先运行一遍 do 后面的代码块,然后检查 while 里的条件。如果条件为真(非零),就跳回去再执行一遍;如果为假(零),就退出循环。

与 while 循环的区别

这是最容易混淆的地方,关键差别在于判断条件的时机:

while 循环是"先判断,后执行"。如果一开始条件就不成立,循环体一次都不会运行。

do-while 循环是"先执行,后判断"。循环体至少会执行一次,哪怕条件从一开始就是假的。

12.2.2 矩阵乘法（二维数组应用）

问题背景

矩阵可用二维数组表示，矩阵运算（如乘法）可基于此定义。示例为 4×2 矩阵 与 2×3 矩阵 相乘，结果为 4×3 矩阵。

矩阵乘法规则

  • 矩阵1（M1）：行数 M1_ROWS=4，列数 M1_COLS=2
  • 矩阵2（M2）：行数 M2_ROWS = M1_COLS（必须相等才能相乘），列数 M2_COLS=3
  • 结果矩阵 M3：M1_ROWS × M2_COLS（即 4×3）

  1. 数组存储数据：无论是一维（电阻值）还是二维（矩阵），都用数组承载工程数据
  2. 分步计算：先完成中间量计算（总电阻/点积），再用中间量计算最终结果
  3. 循环遍历：通过 for 循环对数组元素逐一处理，循环次数与数组维度（NUM_RES 或矩阵行列数）绑定
  4. 结果存入新数组：避免覆盖原始输入数据，便于后续打印和复用

什么是"宏"（Macro）

在编程中，"宏"是指一段可以被命名并重复使用的代码模板——你定义一次，之后每次"调用"这个名字时，它会被自动展开（替换）成实际的代码。

为什么叫"宏"（Macro）

“宏"这个名字来自英语 macro，是 macro-instruction（宏指令）的简称，词根来自希腊语 makros（μακρός），意思是"大的、长的”。

这个命名思路其实很直观：

  • 一条"宏指令"代表着用一个简短的名字，去代表一大段（更长、更复杂）的指令序列。
  • 你写一个很短的"调用"，但它实际展开后是一长串代码——就像把"小"的东西替换成"大"的东西。

这个术语最早出现在汇编语言编程的时代（20世纪50年代）。当时程序员发现，很多重复的指令序列（比如保存寄存器、调用某个常用过程）总是反复出现，于是汇编器引入了"宏汇编"（macro assembler）功能：程序员可以定义一个宏，给一段较长的指令序列起个简短的名字，之后只需写这个名字，汇编器就会自动把它"展开"成完整的、更长（更"宏大"）的指令序列。

这个概念后来被C语言的预处理器继承下来，#define 本质上就是这种"宏汇编"思想在高级语言中的体现：用一个简短的标识符，代表一段更长的代码。

12.6 模块化编译

在 C 语言里,Modular compilation(模块化编译,也常被称为"分离编译" / separate compilation)指的是把一个程序拆分成多个独立的源文件,各自单独编译成目标文件(object file),最后再链接(link)成一个可执行文件的开发方式。

核心思想

C 程序不必写在一个巨大的 .c 文件里。你可以把功能拆开:

  • 一个 .c 源文件 = 一个编译单元(translation unit)
  • 每个源文件可以被单独编译成 .o(或 Windows 上的 .obj)目标文件
  • 链接器把所有目标文件拼起来,解析彼此之间的函数和变量引用,生成最终程序

这是模块化编译的关键机制。main.c 编译时并不知道 add 的具体实现,它只需要通过头文件知道 add 的声明(签名),编译器就能生成调用代码,留一个"待填的符号"。等到链接阶段,链接器才把这个符号对应到 math_utils.o 里的真正实现上。

所以头文件 .h 放声明,源文件 .c 放定义,这种"接口与实现分离"正是模块化的体现。

为什么要这么做

主要好处包括:增量编译——只改了一个 .c 文件时,只需重新编译那一个,其它目标文件可以复用,大型项目能省下大量编译时间(配合 make / CMake 自动管理依赖);代码组织——按功能模块划分文件,结构清晰、易于维护;复用与协作——编译好的目标文件或库(.a 静态库、.so 动态库)可以被多个项目共享,多人也能分工开发不同模块;封装——通过 static 关键字可以把函数或变量限制在单个编译单元内,隐藏实现细节。

需要注意的几个点

链接阶段最常见的两类错误就来自这里:undefined reference(声明了但找不到实现,通常是漏链接某个 .o 或库)和multiple definition(同一个符号被定义了多次,常因为把变量定义写进了头文件)。头文件里一般用 #ifndef 这样的 include guard 防止重复包含。

12.8 二进制文件I/O（Binary File I/O）

C语言提供两种文件操作模式：文本模式（text mode）和二进制模式（binary mode）。二进制文件I/O是指直接以原始字节（raw bytes）形式读写数据，不做任何转换。

文本模式 vs 二进制模式

特性 文本模式 二进制模式
数据存储 经过转换（如换行符转换） 原始字节，不做转换
适用场景 文本文件（.txt等） 图片、音频、结构体、数组等
打开方式 "r", "w" "rb", "wb"

在Windows系统中，文本模式会自动将 \n 转换为 \r\n，而二进制模式不会做这种转换，保证数据原样读写。

注意事项

  1. 结构体对齐（padding）：不同编译器/平台可能在结构体内插入填充字节，导致二进制文件不可移植。
  2. 字节序（endianness）：在不同架构（大端/小端）间传输二进制文件时，多字节数据（如int）可能需要转换。
  3. 始终检查返回值：fopen 返回 NULL 表示打开失败；fread/fwrite 的返回值应与预期个数比较，以检测错误。
  4. 务必关闭文件：使用 fclose 释放资源，避免数据未刷新到磁盘。

main函数的两个特殊参数

  • argc (argument count)：表示命令行参数的个数，包括程序名本身。

  • argv

    (argument vector)：是一个字符串数组（字符指针数组），存储了每个参数的内容。

    • argv[0] 是程序的名称（或路径）
    • argv[1] 到 argv[argc-1] 是用户传入的实际参数
    • argv[argc] 总是 NULL
