6.2 映射/字典(Map)

6.2.1 核心概念

Map（映射） 又称 Dictionary（字典），是哈希表数据结构的核心思想：允许用户给元素分配键（key），之后通过键来查找或删除元素。

  • 形象比喻：键就像贴在文件夹上的标签，值就是文件夹本身。带标签的文件夹被放入"文件柜"（map）中，之后可凭标签取回或移除。
  • 支持的基本操作：基于键的插入、删除、查找。

6.2.2 Map 的定义

Map 存储一组 键值对 (k, v)，称为 items（项）：

  • k = key（键）：由应用或用户分配的标识符
  • v = value（值）：与键关联的任意数据元素

举例：在存储学生记录的 map 中，键可以是学生 ID，值是姓名、地址、成绩等。

键的唯一性：

情况 说明
键唯一（常见） 键可视为该对象在内存中的"地址"，这类 map 也称 associative store（关联存储）
允许重复键 称为 multimap（多重映射）

6.2.3 Map 的三个基本方法

设 map 为 M：

方法 功能
get(k) 若 M 中存在键为 k 的项，返回其值；否则返回特殊元素 NULL
put(k, v) 插入键 k、值 v 的项；若 k 已存在，则用 v 替换原值
remove(k) 删除并返回键为 k 的项；若不存在则返回 NULL

关键术语：

  • Sentinel（哨兵）：当 get/remove 失败时返回的特殊元素 NULL。查找一个不存在的键不算错误，因此用哨兵而非抛异常。

辅助方法：size()、isEmpty()，以及列出所有项 / 值 / 键等（但上述三个才是核心）。

应用场景：互联网路由器、编译器的符号表（程序中每个名字作为键，关联到变量、函数或类）。

6.2.4 Lookup Table（查找表）—— 一种简单实现

适用条件：键的取值范围是整数 [0, N−1]，且 N 较小。

实现思路：分配一个大小为 N 的数组 A，每个单元是一个"桶（bucket）"，存放一个键值对（或指针）。键值对 (k, v) 直接放在 A[k] 中，凭键 k 一次数组索引即可取到对应项。

操作实现（初始化时所有单元设为 NULL）：

操作 实现
put(k, v) 将 (k, v) 赋给 A[k]
get(k) 返回 A[k]
remove(k) 返回 A[k]，再把 A[k] 设为 NULL

6.2.5 查找表的性能分析

时间性能（优点）：

  • 每个基本方法最坏情况下都是 O(1)
  • 时间上是最优的

空间与限制（缺点）：

缺点 说明
空间占用 总内存为 Θ(N)，N 称为该实现的 capacity（容量）
浪费空间 当实际项数 n 远小于 N 时（N 相对 n 很大），大量空间被浪费
键的限制 要求键必须是 [0, N−1] 范围内的唯一整数，实际中常常不满足

结论 / 引出后续：
我们希望找到一种机制，既能克服上述缺点（节省空间、放宽键的限制），又能保持简单快速的操作性能——这正是后续**哈希表（hash table）**要解决的问题。

6.3 哈希函数

6.3.1 核心概念

当键（key）不再是 [0, N−1] 范围内的唯一整数，但我们仍想用类似查找表的方式存储键值对时，就需要一个哈希函数 h，把每个键 k 映射到 [0, N−1] 范围内的整数（N 是底层数组容量）。这样就能把字符串等对象当作数字来处理。

工作流程：用哈希值 h(k) 作为数组 A 的下标（而不是键 k 本身），把键值对 (k, v) 存入桶 A[h(k)]。

6.3.2 冲突（Collisions）

由于映射可能不是单射，会出现 h(k) = h(l) 但 k ≠ l 的情况，这称为在该哈希值处发生冲突。

判断哈希函数"好"的标准：

  • 尽量减少冲突——理想情况下函数表现得像"完全随机"，因为真正的随机函数能自动最小化任意哈希值上的期望冲突数；
  • 计算快速、易于实现。

6.3.3 键的两种标准视角

任何键本质上都可表示为二进制串，惯例上按两种方式看待：

  1. 整数元组：k = (x₁, x₂, …, x_d)，每个 xᵢ ∈ [0, M−1]。适合字符串、变量名等（顺序有意义）。
  2. 单个非负整数（可能很大）。适合定长 IP 地址等。

某些方案会混用两者：先把元组映射成整数，再用另一个函数进一步映射。

6.3.4 各类哈希函数对比

下面按"元组类"和"整数类"分别整理：

（A）针对元组键的哈希函数

1. 求和 / 异或（Summing components）

​ h(k)=∑i=1dxi或h(k)=⊕i=1dxi

  • 求和可取模 p 使结果落入 [0, p−1]。
  • 异或（XOR）优点：无进位问题、CPU 内置且快。
  • 异或缺点：一个数与自身异或为 0，元组中有重复分量时要小心。

对称性导致冲突的问题：单纯求和或异或忽略了分量的顺序。

例："temp01" 与 "temp10" 冲突；"stop"、"tops"、"pots"、"spot" 四个词互相冲突。
改进方向：让每个位置下标 i 在哈希中起作用。

2. 多项式求值（Polynomial-evaluation）

选取非零常数 a ≠ 1：

​ h(k)=x1ad−1+x2ad−2+⋯+xd−1a+xd

可用 Horner 法则改写，便于循环计算（d−1 次加法 + d−1 次乘法）：

​ h(k)=xd+a(xd−1+a(xd−2+⋯+a(x2+ax1)⋯))

  • 本质是以 a 为自变量、以各分量为系数的 (d−1) 次多项式。
  • 直觉：乘以 a 为新分量"腾出空间"，同时保留之前分量的特征。
  • 溢出时可忽略，或假设所有运算取模某素数 p。
  • 关键设计在于选 a：a 既要有高阶位来"移位"running sum，又要有低阶位让新项能被纳入。

英文单词的特殊常数值：实验表明 33、37、39、41 适合英文字符串。在 5 万多个英文单词的测试中，这几个值各自产生的冲突均少于 7 次。为追求速度，长字符串有时只对部分字符（如每 8 个取一个）应用多项式哈希。

3. 表查找哈希（Tabulation-based hashing）

适用于固定 d 的元组键，不需加法或乘法，适合小型设备。

做法：建立 d 张大小为 M 的表 T₁, …, T_d，每个 Tᵢ[j] 是 [0, N−1] 内独立均匀随机数：

​ h(k)=T1[x1]⊕T2[x2]⊕⋯⊕Td[xd]

  • 通常假设 N ≤ M^d（否则可直接用键作下标）。
  • 由于表值随机，函数本身较随机：两个不同键碰撞概率约为 1/N（接近完美随机函数）。
  • 只用 XOR，无需乘加，在某些机器上更快。

（B）针对整数键的哈希函数

1. 模除（Modular division）——最简单：

​ h(k)=kmodN

  • N 应取素数，以"打散"键的分布、减少模式重复造成的冲突。

例：键 {200, 205, 210, …, 600} 映射到大小 100 的桶数组时每个哈希值与 3 个其他键冲突；映射到大小 101 则无冲突。

  • 若键在远大于 N 的范围内均匀随机分布，碰撞概率至多 1/N。
  • 局限：即使 N 为素数且键均匀分布，若键不随机（如存在 iN + j 形式的重复模式），所有键仍会撞到同一哈希值 j。

2. 随机线性哈希（Random linear）——缓解重复模式：

​ h(k)=(ak+b)modN

  • N 为素数，0 < a < N，0 ≤ b < N，a、b 为独立均匀随机整数。
  • 目标是把任意两个不同键的碰撞概率压到 1/N（第 6.6 节有证明）。

3. 随机多项式哈希（Random polynomial）——保证多键碰撞概率也接近随机函数：

​ h(k)=ad+k(ad−1+k(ad−2+⋯+k(a2+ka1)⋯))modN

  • N 为素数，各 aᵢ 是 [0, N−1] 内独立均匀随机整数，且 {a₁, …, a_{d−1}} 中至少一个非零。
  • 可证明任意 2 ≤ c ≤ d 个不同键碰撞于同一哈希值的概率为 1/N^{c−1}。

6.3.5 总结要点

类型 函数 适用 / 特点
元组 求和 / XOR 简单但忽略顺序，易冲突
元组 多项式求值 考虑位置信息，需选好常数 a（33/37/39/41）
元组 表查找 仅用 XOR，无乘加，碰撞概率 ≈1/N
整数 模除 最简单，N 取素数；惧怕非随机模式
整数 随机线性 碰撞概率 ≈1/N
整数 随机多项式 c 键碰撞概率 ≈1/N^{c−1}

6.4 哈希冲突处理与再哈希

6.4.1 哈希冲突

哈希表的核心思想是：用查找表 A 和哈希函数 h，把每个键值对(k,v) 存进桶 A[h(k)]。

但当两个不同的键 k1≠k2 满足 h(k1)=h(k2) 时，就发生了冲突。冲突使得我们无法直接把新项放进 A[h(k)] ，也让 get(k) 操作变复杂。因此需要一套一致的冲突解决策略。

主要有两大类策略：分离链接（Separate Chaining） 和 开放定址（Open Addressing）。

6.4.2 分离链接（Separate Chaining）

基本思想

让每个桶 A[i] 存一个指向集合 Si 的引用， Si 用链表存放所有被映射到该桶的项。

  • Si 本身可看作一个"迷你 map"，只存满足 h(k)=i 的项 (k,v) 。
  • 对涉及键 k 的所有操作，都委托给 A[h(k)] ] 处的迷你链表 map 去处理。

三个核心操作

get(k) — 查找键 kk k 的值

put(k, v) — 插入/更新

remove(k) — 删除键 kk k 的项

各操作的代价（在链表上）

  • 插入：放在链表头部， O(1) 。
  • 查找：顺序遍历链表，直到找到目标键或到达末尾。
  • 删除：先找到项，再额外做删除。

分离链接的性能分析：负载因子（Load Factor）

假设哈希函数 h 把键独立、均匀地映射到 [0,N−1] 范围内。

设随机变量 X = 映射到某个桶 i 的项数，则其期望为：

​ E(X)=nN

其中 n 是 map 中的项数， N 是表的容量（因为 A 中每个位置被选中的概率相等）。

负载因子（load factor） 就是 n/N ，即"项数 ÷ 容量"。

关键结论：若负载因子为 O(1) ，则用分离链接处理冲突时，哈希表操作的期望时间为 O(1) 。

6.4.3 开放定址（Open Addressing）

动机

分离链接很好用，但有一个缺点：需要辅助数据结构（每个桶的链表）。

开放定址则把每项直接存进桶里，每桶至多一项，不使用辅助结构，只用 A 本身。

  • 优点：省空间。
  • 代价：处理冲突的逻辑更复杂。

线性探测（Linear Probing）

最简单的开放定址策略。当要插入 (k,v) 到桶 A[i] （ i=h(k) ）但该桶已被占用时：

  1. 尝试 A[(i+1)modN]
  2. 若仍被占用，尝试 A[(i+2)modN]
  3. 依此类推，直到找到一个空桶放入新项。

查找 get(k) 也要相应改变：从 A[h(k)] 开始，连续检查后续桶，直到

  • 找到键等于 k 的项（查找成功），或
  • 遇到一个空桶（查找失败）。

示例

哈希函数 h(k)=kmod11 ，要插入 key = 15 的元素：

  • h(15)=15mod11=4 ，但位置 4、5、6、7 都已被占用（13 在 2，26 在 4，5 在 5，37 在 6，16 在 7，21 在 10）。
  • 于是连续探测：4 → 5 → 6 → 7 → 8，探测 4 次后才在位置 8 找到空槽放入。

6.4.4 线性探测的三个操作

get(k) — 查找

从 i=h(k) 开始，沿桶向后扫描，遇空桶即停（查找失败）。

put(k, v) — 插入/更新

同样向后探测：若途中遇到相同键则替换值；若遇到空桶则放入新项。

remove(k) — 删除（含 Shift）

删除后不能简单留空，否则会切断探测链。本教材采用**移位（Shift）**法来修复：

Shift(i) — 修复"空洞"

删除后会在位置 ii i 形成一个"洞"。Shift 向后检查每个非空项，看它的理想位置 j=h(key) 是否落在区间 (i,i+s] 内：

  • 若不在该区间（说明这个项是被探测推到后面来的，可以前移），就把它移来填洞，洞随之后移；
  • 若在该区间（说明它本就该待在这），则跳过它，扩大检查范围 s 。

替代方案：墓碑标记（Deactivated Item）

另一种处理删除的方式是用一个特殊的**“失活项（deactivated item）”** 占住该桶，而不真正搬移数据。此时需要修改算法：

  • get / remove 查找时跳过失活项，继续探测，直到找到目标项或空桶；
  • put 插入时遇到失活项可以停下并直接复用该桶放入新项。

6.4.5 线性探测的性能分析（Chernoff 界）

分析设定

存 n 个项，表大小 nN=2n ，即负载因子 1/2 。负载因子更低时结论照样成立；但若远高于 1/2 ，线性探测性能会显著退化。

Chernoff 界（工具）

设 X1,…,Xn 为相互独立的指示随机变量， Xi i 以概率 pi>0 取 1，否则取 0；令 X= X=∑Xi ，$\mu=E(X)=\sum p_i $。则对任意 δ>0 ：

​ Pr(X>(1+δ)μ)<[eδ(1+δ)(1+δ)]μ

推导主线

设 X = 查找/更新某键时的探测次数； Xi 为指示变量（ i=h(k) ) 时为 1）； Yi = 从位置 i 起连续非空格的长度。由线性探测机制和 h 的随机性：

​ X=∑i=0N−1Xi(Yi+1)⇒E(X)=1+12nE(∑i=0N−1Yi)

于是只要能给 ∑Yi 的期望定界即可。

关键技巧（"收费"思想）：对一段长度为 k 的极大连续非空序列 S ，落入其中的查找最坏情况下要走到 S 末尾——落在第 1 格浪费 k 次，第 2 格 k−1 次……总代价至多 k2 。即把所有落进 S 的查找代价都"记账"到 S 上：

​ ∑i=0N−1Yi≤∑i=0N−1∑k=12nk2Zi,k

其中 Zi,k 是"存在长度为 k 的极大非空序列"的指示变量。

用 Chernoff 界给 Z 定界：设 Zk 为映射到某段 k 个格子的项数，则 $\Pr(Z_{i,k}=1)\le\Pr(Z_k\ge k) 。因负载因子1/2， E(Z_k)=k/2 $，套用 Chernoff（取 δ 使 (1+δ)(k/2)=k ）：

​ Pr(Zk≥k)=Pr(Zk≥2(k/2))≤(e/4)k/2<2−k/4

合并所有部分：

​ E(X)≤1+∑k=1∞k22−k/4=O(1)

结论：只要负载因子不超过 1/2，线性探测下查找/更新的期望运行时间为 O(1)。

6.4.6 其他开放定址策略

二次探测（Quadratic Probing）

依次尝试 A[(i+f(j))modN] ，其中 f(j)=j2 ， j=0,1,2,… ，直到找到空桶。

  • 优点：避开了线性探测那种连续聚集模式；
  • 缺点：同样使删除复杂；
  • 二次聚集（secondary clustering）：当负载因子接近 1 时，被占用的格子会按固定模式"弹跳"散布。若 N 不取素数，可能即便有空桶也找不到；即便 N 是素数，当表至少半满时也可能找不到空槽。

双重哈希（Double Hashing）

引入第二个哈希函数 h′ 。冲突时依次尝试 A[(i+f(j))modN] ，其中 f(j)=j⋅h′(k) ，$j=1,2,3,\dots $

  • h′ 不允许取 0；常用 h′(k)=q−(kmodq) ， q 为小于 N 的素数； N 也应取素数；
  • 若 h 和 f 视作随机函数，可证明查找期望时间为 O(1) ；
  • 优点：避免了线性探测和二次探测各自的聚集问题。

开放定址的权衡（Trade-offs）

开放定址比分离链接省空间，但不一定更快。实验与理论分析表明：

  • 负载因子接近 1 时，分离链接与其它方法相当或更快；
  • 负载因子小于 1/2 时，开放定址通常更快（省去了一次额外的指针跳转）。

6.4.7 再哈希（Rehashing）

为什么需要

负载因子 n/N 直接决定冲突概率和操作性能。在固定（有界）负载因子下，分离链接的 get/put/remove 期望时间为 O(⌈n/N⌉)=O(1) 。因此应始终把负载因子保持在一个明显小于 1 的小常数之下。

怎么做

当插入会使负载因子超过设定上限（如 1/2 或 3/4）时：

  1. 扩大桶数组 A；
  2. 换用与新容量匹配的新哈希函数；
  3. 用新哈希函数把所有已有元素重新插入新数组。

这一"扩容 + 重建"过程就是再哈希。

代价

仿照可扩展数组的做法，每次再哈希到约两倍大小的数组，则每次插入分摊到的再哈希额外代价为 O(1)（摊还分析）。

容量 8、负载因子 7/8 的表，再哈希到容量 16、负载因子 7/16 的表。所有项按新哈希函数 h′ 重新定位——例如键 7 在旧表中因 $h(7)=3 $放在桶 3，在新表中因 h′(7)=8 放到桶 8。

6.4.8 全章核心要点速览

主题 关键结论
分离链接 桶存链表；实现简单，需辅助结构
线性探测 直接存数组，省空间；删除需 Shift 或墓碑；易一次聚集
二次探测 缓解一次聚集；但有二次聚集， N 须素数且半满前才保证找到空槽
双重探测 用 h′ 决定步长，聚集最少； h′≠0 、 N 取素数
性能命门 全看负载因子 n/N ；线性探测 ≤1/2 时期望 O(1)
再哈希 超过阈值就扩容+重建；翻倍扩容 ⇒ 分摊 O(1)
