结构体

7.1 数据分组：结构体

在C语言中，struct（结构体） 是用来将不同类型的数据组合成一个自定义类型的方式。这正是“数据分组”的核心概念。

与其用多个独立、无关联的变量，不如将它们打包成一个逻辑整体。

7.1.1 为什么需要结构体

假设你要存储一个学生的信息：名字、年龄、成绩。
不使用结构体的话，数据是分散的：

如果有两个学生，变量名就会非常混乱（name1, name2, age1…），函数传递也非常麻烦。

结构体把这些相关数据捆绑成一个新的类型。

补充

C 的 struct 只是数据的容器；
Java 的 object 是数据 + 行为 + 保护机制的完整封装。

如果学过 Java 再来学 C，可以把 struct 理解为： “一个只有字段、没有方法、没有访问控制的裸对象”。

7.5 结构体使用独立的文件

在C语言中，Separate files for structs（将结构体定义分离到独立文件）是一种代码组织方式，目的是提高代码的可维护性、可读性和复用性。

核心概念

C语言通常将代码分为两类文件：

文件类型 扩展名 作用
头文件 .h 声明结构体、函数原型、宏等
源文件 .c 实现具体的函数逻辑

7.5.1 示例结构

假设我们有一个 Person 结构体，文件组织如下：

1. person.h — 头文件（定义结构体）

负责定义结构体模板，并声明相关函数。

2. person.c — 源文件（实现函数）

包含头文件，并实现函数的逻辑。

3. main.c — 主文件（使用结构体）

只需包含头文件就能使用。

关键要点

#ifndef 头文件守卫（Include Guard）

防止同一个头文件被多次包含，避免重复定义错误。

#include "person.h" vs #include <stdio.h>

  • "person.h" — 双引号，表示自定义的本地头文件
  • <stdio.h> — 尖括号，表示系统/标准库头文件

重要性

优点 说明
模块化 每个结构体和相关功能独立成模块
复用性 其他 .c 文件只需 #include 即可使用
可维护性 修改某个结构体不影响整个项目
编译效率 只重新编译修改过的文件
团队协作 不同成员可以负责不同模块

编译方式

需要将所有 .c 文件一起编译，头文件会自动通过 #include 被引入。
