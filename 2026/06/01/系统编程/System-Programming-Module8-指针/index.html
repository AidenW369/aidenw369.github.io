8.1 为什么使用指针

8.1.1 什么是指针？

指针是一个变量，它存储的不是普通数据，而是另一个变量的内存地址。

可以这样理解：如果变量是一栋房子，那么指针就是这栋房子的门牌号。

指针的基本语法

操作 语法 含义
声明指针 int *p; p 是一个指向 int 的指针
取地址 p = &x; 将 x 的地址赋给 p
解引用 *p 访问 p 所指向地址上的值

注意事项

使用指针时要特别小心以下几类常见错误：

  • 野指针：指针未初始化就使用，int *p; *p = 10; ❌
  • 空指针解引用：int *p = NULL; *p = 10; ❌
  • 内存泄漏：malloc 之后忘记 free ❌
  • 悬空指针：指针指向的内存已被释放，仍继续使用 ❌

8.1.3 野指针（未初始化指针）

空指针指未初始化的指针：int *p; *p = 10;

发生了什么？

声明 int *p 时，系统只分配了存放地址的空间，但没有给它赋任何值。此时 p 里存的是内存中的随机垃圾值，比如 0x7fff4a2b。

执行 *p = 10 就是往这个不知道是什么的地址写入数据，可能会：

  • 覆盖其他变量的数据，导致程序行为异常
  • 覆盖操作系统保护的内存区域，导致程序直接崩溃（Segmentation Fault）
  • 在某些情况下"看起来没问题"，但埋下隐患，最难排查

正确做法：声明后立即初始化

8.1.4 空指针解引用

发生了什么？

NULL 本质上是地址 0（即 0x00000000）。操作系统故意将地址 0 附近的内存设为不可访问的"禁区"，任何程序试图读写这块区域，都会被立即终止。

程序会立刻崩溃，报 Segmentation Fault（段错误）。

虽然崩溃让人烦恼，但其实比野指针更安全——至少错误是立即可见的，而不是悄悄破坏数据。

两者的对比

未初始化指针 空指针
指向哪里 随机垃圾地址 固定的地址 0
解引用后果 不确定，可能崩溃或静默破坏数据 必然立即崩溃
危险程度 ⚠️ 更危险（行为不可预测） 相对可控（必然崩溃）
排查难度 极难（bug 可能随机出现） 容易（必然复现）

一句话总结

  • 野指针：拿着一张不知道写着哪里的藏宝图去挖宝，可能挖到别人家的地基
  • 空指针：拿着一张明确写着"此路不通"的地图还硬要进去，门卫直接把你赶走

所以写指针时，始终让指针指向一个合法的内存地址，或者在不用时将其置为 NULL 以便排查错误。

8.3 malloc 和 free函数

malloc 和 free 是C语言中用于动态内存管理的核心函数，它们允许程序在运行时按需分配和释放内存。

8.3.1 malloc（Memory Allocation）

malloc 用于在**堆（heap）**上动态分配指定字节数的内存，返回一个指向该内存块的 void * 指针。

  • 参数：需要分配的字节数
  • 返回值：成功时返回指向分配内存的指针，失败时返回 NULL

8.3.2 free

free 用于释放之前由 malloc（或 calloc、realloc）分配的内存，归还给系统。

关键规则：

  • 只能释放动态分配的内存
  • 不能重复释放同一块内存
  • 释放后建议将指针设为 NULL

特性 静态数组 malloc 动态分配

常见注意事项

8.7 realloc函数

realloc 是 C 标准库中用于重新分配内存的函数，它用来重新调整之前分配的内存块的大小。

8.7.1 函数原型

参数说明

  • ptr：指向之前通过 malloc、calloc 或 realloc 分配的内存块的指针
    • 如果为 NULL，realloc 的行为等同于 malloc(new_size)
  • new_size：需要的新内存大小（以字节为单位）
    • 如果为 0，行为是实现定义的（通常等同于 free(ptr)，但不绝对）

返回值

  • 成功时，返回指向重新分配的内存块的指针（可能与原指针相同，也可能不同）
  • 失败时，返回 NULL，且原内存块保持不变

工作原理

  • 若当前位置有足够的连续空间，直接在原地扩展，返回原指针

  • 若没有，重新分配一块更大的内存，将原数据复制过去，释放原内存，返回新指针

  • 若是缩小，多余部分被截断

作用

对已经通过 malloc、calloc 或 realloc 分配的内存块，调整其大小（扩大或缩小）。

8.7.2 典型用法

8.7.3 常见注意事项

1.不要直接赋值给原指针

2. 扩大的新空间未初始化（不像 calloc，新增部分是垃圾值）

3. 原指针可能失效：realloc 成功后，不要再使用旧的 ptr，因为内存可能已被移动并释放

4. realloc(NULL, size) == malloc(size)，这是合法的用法

8.12 内存泄漏

**内存泄露（Memory Leak）**是指程序动态分配了一块内存，但在使用完毕后没有释放它，导致这块内存无法被程序或操作系统重新使用。

产生原因

在C语言中，内存管理是手动的。使用 malloc()、calloc()、realloc() 分配的堆内存，必须由程序员显式调用 free() 来释放。如果忘记释放，就会发生内存泄露。

场景 说明
忘记调用 free() 最基本的泄露原因
指针被覆盖 p = malloc(...); p = malloc(...); 第一块内存地址丢失
提前 return 在释放内存前就返回了函数
异常/错误路径 只在正常路径释放，错误路径忘记释放
循环引用 链表等数据结构节点未逐一释放

如何避免

  1. 配对原则：malloc 和 free 成对出现
  2. 释放后置空：free(p); p = NULL;，防止悬空指针
  3. 统一出口：函数只有一个返回点，确保资源在返回前被释放
  4. 使用工具检测：可以检测程序运行时的内存泄露
