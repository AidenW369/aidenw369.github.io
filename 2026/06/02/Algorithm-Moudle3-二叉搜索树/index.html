二叉搜索树

3.1 二叉空间分割（BSP）

3.1.1 问题背景

在虚拟环境中，对某个对象 x 进行参考检查（reference check）的朴素方法是：将 x 与环境中的每一个其他对象逐一比较。

  • 对单个对象 x：需要 O(n) 次比较
  • 对所有 n 个对象：总复杂度为 O(n²)

缺点： 没有利用"距离 x 很远的对象群组可以整体忽略"这一特性，导致大量无效比较，效率低下。

3.1.2 解决方案：二叉空间分割（BSP）

被早期 3D 游戏（如 Doom）广泛采用。

核心思想

用一个平面 P 将空间中的对象划分为两组（左侧 / 右侧），然后递归地对每组继续细分，直到每个子组的对象数量足够小，可以单独处理。

构建过程

查询过程

  1. 先判断目标对象在平面 P 的哪一侧
  2. 递归地在同侧子树中继续定位
  3. 快速排除另一侧的大量无关对象

3.1.3 与二叉搜索树（BST）的关系

特性 二叉搜索树（BST） BSP 树
结构 二叉树 二叉树
决策方式 每节点左/右判断 每节点左/右判断
存储内容 数值/键 空间对象
应用场景 一般搜索 三维虚拟环境

本质： BSP 树是二叉搜索树在三维空间中的应用形态。

优势

  • 将朴素的 O(n²) 复杂度大幅降低
  • 能够快速整组排除远离目标的对象
  • 是三维游戏/虚拟环境中空间索引的经典方案

3.2.2 二分搜索算法分析

一、核心观察

  • 每次递归调用执行常数次操作，故总运行时间 ∝ 递归调用次数
  • 每次递归后，候选元素数量 = high − low + 1
  • 每次递归后，候选数量至少减半

二、候选数量减半的证明

设 mid = ⌊(low + high) / 2⌋，每次递归后剩余候选数为以下两种情况之一：

情况 表达式 上界
搜索左半部分 (mid − 1) − low + 1 = ⌊(low+high)/2⌋ − low ≤ (high−low+1)/2
搜索右半部分 high − (mid+1) + 1 = high − ⌊(low+high)/2⌋ ≤ (high−low+1)/2

两种情况候选数均 ≤ (high − low + 1) / 2，即每次至少减半 ✓

b 为常数（每层递归的固定开销）

第 i 次调用后，候选数 ≤ n / 2ⁱ

四、最坏情况分析（未找到目标）

递归终止条件：候选数 < 1，即：

n2m<1⇒m>log⁡n

∴m=⌊log⁡n⌋+1

结论：BinarySearch(A, k, 1, n) 的时间复杂度为 O(log n)

五、空间复杂度与适用场景

维度 结论
空间复杂度 Θ(n)（需存储 n 个对象，最优）
适用场景 静态集合 S（无插入/删除需求）
不适用场景 动态集合（插入/删除为 O(n)，效率差）
动态场景性能瓶颈原因

插入新元素时，需将数组 A 中所有大于插入键的元素整体后移，以维持有序性 → O(n) 开销

3.2.3 二叉搜索树

二叉搜索树（BST）是一种二叉树 T，其中每个内部节点 v 存储一个键值对 (k, e)，满足：

位置 条件
v 的左子树中的所有键 ≤ k
v 的右子树中的所有键 ≥ k

外部节点（叶子节点）不存储元素，可以是 NULL 或 NULL_NODE 对象。

核心性质

  • 中序遍历（Inorder Traversal） 访问 BST 中所有元素时，结果为非递减顺序
  • 支持高效的查找、插入、删除操作（相比普通二叉树）

二、时间复杂度分析

基本分析

  • 算法对遍历路径上的每个节点执行 常数次 基本操作，即每个节点耗时 O(1)
  • 每一步都从当前节点移动到其子节点，路径从根节点出发，逐层向下
  • 路径上节点数不超过 h+1 （ h 为树的高度）

​ 总时间复杂度 = O(h)

其中 h 为二叉搜索树 T 的高度。

三、树高 h 的分析

最坏情况

树高 h 最大可达 n （退化为链表），即：

​ hmax=n

最优情况

​ hmin=⌈log(n+1)⌉

期望情况

  • 随机构造的二叉搜索树，树高以高概率为 O(log⁡n)
