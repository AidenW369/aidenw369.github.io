5.2 优先队列

5.2.1 基本概念

键（Key）

  • 定义：分配给集合中每个元素的属性对象，用于标识、排序或加权该元素
  • 键由用户或应用程序赋予元素

优先队列（Priority Queue）

  • 一种容器，每个元素在插入时携带一个关联的键
  • 名称来源：键决定了元素被取出的"优先级"

5.2.2 全序关系（Total Order）

为了能够比较键的优先级，比较规则 ≤ 必须满足全序关系的三个性质：

性质 描述
自反性 Reflexive k≤k
反对称性 Antisymmetric 若 k1≤k2 且 k2≤k1 ，则 k1=k2
传递性 Transitive 若 k1≤k2 且 k2≤k3 ，则 k1≤k3

满足以上三条性质的比较规则，永远不会产生矛盾，可定义出线性顺序。

因此，最小键 kmin 是满足 kmin≤k （对集合中所有其他键 k ）的键，是良定义的。

5.2.3 优先队列的方法

方法 描述
insert(k, e) 将键为 k、元素为 e 的项插入优先队列 P
removeMin() 返回并移除 P 中键最小的元素
min() 返回但不移除 P 中键最小的元素
size() 返回 P 中元素的数量

5.3 PQ-排序、选择排序与插入排序

5.3.1 PQ-Sort：用优先队列排序

PQ-Sort 是什么

PQ-Sort 就是 “Priority Queue Sort” 的缩写，直译"用优先队列来排序"。

它本身不是一个具体的排序算法，而是一个排序"框架/套路"（书里叫 scheme）。它只规定了"借助一个优先队列分两步完成排序"这个大思路，但不规定优先队列内部怎么实现。

为什么叫 PQ-Sort（优先队列排序）

因为它的整个排序过程完全依赖一个优先队列（Priority Queue，简称 PQ）来驱动。名字直接点明了它的核心工具：

排序的"动力"全部来自优先队列那个"每次都能吐出最小元素"的特性——离开了优先队列，这个方法就不存在了。所以叫它"优先队列排序"。

也正因为它只是个框架、把"优先队列怎么实现"留空，所以书里强调它更像"排序方案"而不是"排序算法"。换不同的优先队列实现，就变成选择排序 / 插入排序 / 堆排序。

核心思想：借助一个优先队列 Q （或 P ）对包含 n 个元素的集合 C 进行排序。整个过程分为两个阶段：

  1. 第一阶段（入队）：通过 n 次 insert 操作，把 C 中的元素全部放入初始为空的优先队列 P 。
  2. 第二阶段（出队）：通过 n 次 removeMin 操作，按非递减顺序从 P 中取出元素，依次放回 C 。

关键认识：PQ-Sort 更像是一种排序"方案/范式（scheme）"，而非具体算法，因为它没有规定 P 内部如何实现。算法本身对任何 P 都正确，但运行时间完全取决于 insert 与 removeMin 的实现方式。选择排序、插入排序、堆排序都属于这一范式。

5.3.2 选择排序（Selection-Sort）- 用无序列表实现 P

实现方式：把元素以键值对 (k,e) 存入一个无序列表 S （数组或双向链表均可，不影响性能）。

操作 做法 时间复杂度
insert 直接添加到列表末尾 O(1)
removeMin 必须扫描整个列表找最小元素 Θ(n) （即使最好情况也是 Ω(n) ）

两阶段分析：

  • 第一阶段： n 次 O(1) 插入 → 总共 O(n) 。
  • 第二阶段：每次 removeMin 的耗时正比于当前队列规模。规模从 n 递减到 1：

​ n+(n−1)+⋯+2+1=∑i=1ni=n(n+1)2

  • 因此第二阶段（即整个算法的瓶颈）为 O(n2) 。

为什么叫"选择"排序：瓶颈在于第二阶段反复"选择"出最小元素。

5.3.3 插入排序（Insertion-Sort）- 用有序列表实现 P

实现方式：列表 S 始终按键有序存储，因此第一个元素永远是键最小的。

操作 做法 时间复杂度
removeMin 直接移除首元素 O(1)
insert 需扫描 S 找到正确插入位置 O(n) （最坏情况）

两阶段分析：

  • 第二阶段： n 次 O(1) 的 removeMin → O(n) 。
  • 第一阶段（成为新的瓶颈）：第 i 次插入最坏耗时 O(i) ，从 O(1) 增至 O(n) ，总和仍为 $O\left(\sum_{i=1}^{n} i\right) = O(n^2) $。

为什么叫"插入"排序：瓶颈在于第一阶段反复把新元素"插入"到有序列表的合适位置。

5.3.4 两种排序的对比（重点）

选择排序 插入排序
P 的实现 无序列表 有序列表
insert O(1) O(n)
removeMin O(n) O(1)
瓶颈阶段 第二阶段（出队/选择） 第一阶段（入队/插入）
总体时间 O(n2) O(n2)

关键差异：

  • 选择排序始终是 Ω(n2) ：每步都必须扫描整个序列找最小值，与输入无关。
  • 插入排序随输入而变：如果输入序列 S 已经有序或接近有序，按算法 5.3.3 实现时可达到 O(n)

5.4 堆

5.4.1 基本概念

堆是一种用二叉树实现优先队列的高效数据结构，使 insert(k, e) 和 removeMin() 都能在对数时间内完成。其核心思想是放弃用列表存储键值，改用二叉树存储。

堆是一棵二叉树 T，键存储在内部节点，外部节点不存储数据，仅作为占位符。堆必须满足两条性质：

1. 堆序性质（Heap-Order Property）— 关系性质

对树中除根以外的每个节点 v，v 的键 ≥ 其父节点的键。

推论：

  • 从根到任一外部节点的路径上，键是非递减的
  • 最小键总是位于根节点

2. 完全二叉树性质（Complete Binary Tree Property）— 结构性质

高度为 h 的二叉树是"完全的"，当：第 0,1,2,…,h−1 层都填满（第 i 层有 2i 个节点），且第 h−1 层的所有内部节点都靠左排列。

最后节点（Last Node）：树中最右、最深的内部节点

5.4.2 堆的高度

存储 n 个键的堆，高度为：

h=⌈log⁡(n+1)⌉

证明思路（夹逼）：

  • 内部节点数最少： 1+2+4+⋯+2h−2+1=2h−1
  • 内部节点数最多： 1+2+4+⋯+2h−1=2h−1
  • 由 2h−1≤n≤2h−1 ，取对数得 h=⌈log⁡(n+1)⌉

这保证了只要操作时间正比于高度，操作就是对数时间的。

5.4.3 用数组实现堆

对每个节点 v 定义编号 p(v)：

  • 根： p(v)=1
  • 左孩子： p(v)=2p(u)
  • 右孩子： p(v)=2p(u)+1

由于堆是完全二叉树，n 个内部节点恰好存入数组 A 的前 n 个单元，无需显式存储外部节点。最小元素始终在 A[0]（或 A[1]），最后节点位置即 w=n。

由此可用简单算术模拟 parent、leftChild、rightChild 等操作。

5.4.4 插入操作 insert(k, e)

步骤 1：放置新节点 — 将 (k,e) 放到最后节点之后的位置 p（保持完全二叉树性质）。

步骤 2：上滤（Up-Heap Bubbling） — 此时可能违反堆序性质：

  • 比较 p 与其父节点 q 的键
  • 若 kp≥kq ：满足，结束
  • 若 kp<kq ：交换 p 与 q，继续向上重复，直到不再违反

最坏情况：一直上滤到根，交换次数等于树高 $ ⌈log(n+1)⌉$。

5.4.5 删除最小元素 removeMin()

不能直接删根（会留下两棵断开的子树）。

步骤 1：替换 — 把最后节点 p 的条目复制到根 r，然后删除最后节点（保持完全二叉树性质）。

步骤 2：下滤（Down-Heap Bubbling） — 此时可能违反堆序性质，从根开始：

  • 若 p 无右孩子，c = 左孩子
  • 否则 c = 两孩子中键较小的那个
  • 若 kp≤kc ：满足，结束
  • 若 kp>kc ：交换 p 与 c，向下继续

关键：必须选较小的孩子交换，这样提升上去的键既小于原父键、也不大于另一孩子的键，才能局部恢复堆序。

最坏情况：一直下滤到底层，交换次数等于树高 ⌈log⁡(n+1)⌉ 。

5.5 堆排序

5.5.1 堆排序的基本思想

堆排序源自 PQ-Sort 排序方案：用一个优先队列 P 来对列表 S 排序。当用堆来实现优先队列时：

  • 第一阶段（建堆）：执行 n 次 insert，每次操作耗时 O(log k)，k 是当时堆中元素个数。
  • 第二阶段（取出）：执行 n 次 removeMin，每次同样耗时 O(log k)。
  • 因为始终有 k ≤ n，所以每次操作最坏情况下为 O(log n)。
  • 每个阶段耗时 O(n log n)，整体算法即为 O(n log n)。

定理 5.5.1：堆排序可在 O(n log n) 时间内完成对 n 个可比较元素列表 S 的排序。

相比选择排序、插入排序的 O(n²)，O(n log n) 是显著的改进。

5.5.2 原地堆排序（In-place Heap-sort）

当 S 用数组实现时，可利用 S 自身的一部分来存储堆，从而省去外部堆结构，把空间需求降低一个常数因子。规则如下：

  1. 采用最大值比较规则（对应大顶堆，最大元素在顶部）。
  2. 任意时刻，数组 S 最左侧的 i 个元素表示堆，右侧剩余部分存放尚未进堆的元素。
  3. 第一阶段：从空堆开始，堆与列表的边界从左向右移动，每次取右侧无序部分的第一个元素并入堆。
  4. 第二阶段：反复从堆中取出最大元素，边界从右向左移动一步，将取出的元素放入边界右侧刚空出的位置。

为什么是"原地"：除列表本身外只用常数级额外空间——不是把元素搬出再搬回，而是直接在数组内重排。其实际优势是能最高效地利用计算机主存。

5.5.3 自底向上建堆（Bottom-up Heap Construction）

核心结论

用 n 次连续 insert 建堆需 O(n log n)。但若所有键事先已知，存在另一种自底向上的建堆方法，仅需 O(n) 时间。

  • 它可替代堆排序第一阶段的 n 次插入；但第二阶段仍是 O(n log n)。

假设与结构

为简化分析，设 n = 2^(h+1) − 1，即堆是每层都填满的完全二叉树，高度 h = log(n+1) − 1，整个过程共 h+1 = log(n+1) 个阶段。

各阶段

  • 第一阶段：构造 (n+1)/2 个"基本堆"，各存 1 个元素。
  • 第二阶段：合并成 (n+1)/4 个堆，各存 3 个元素——把成对的基本堆合并并加入一个新元素，新元素先放根部，必要时与子节点交换以维持堆序。
  • 第三阶段：合并成 (n+1)/8 个堆，各存 7 个元素——成对合并 3 元素堆并加新元素，通过**下移冒泡（down-heap bubbling）**维持堆序。
  • 一般第 i 阶段（2 ≤ i ≤ h）：形成 (n+1)/2^i 个堆，各存 2^i − 1 个元素，由成对的（2^(i−1) − 1）元素堆合并并加新元素，新元素自根部下移冒泡。
  • 最后一阶段：合并出最终堆，存全部 n 个元素，由两个各存 (n−1)/2 元素的堆合并并加新元素构成。

5.5.4 复杂度分析：为什么是 O(n)

直觉：自底向上比逐个插入更快——它在每个节点做一次下移操作而非上移操作。由于树中靠近底部的节点远多于靠近顶部的节点，所有向下路径之和较小，且这个总和是线性的。

定理：在 O(1) 时间内可比较两个键的前提下，n 个元素的自底向上建堆需 O(n) 时间。

证明思路一（按高度求和）

主要代价来自各内部节点的下移步骤：

  • 一半节点无子节点，无需下移；
  • 1/4 的节点子树高度为 1，1/8 的节点子树高度为 2，以此类推。

总运行时间正比于：

​ ⋅n4+2⋅n8+3⋅n16+⋯+i⋅n2i+1+⋯1⋅4n+2⋅8n+3⋅16n+⋯

可改写为 (∑i=1log⁡ni2j) 。

证明思路二（按边计数，更直观）

  • 对每个顶点 v，下移操作最坏耗时等于从 v 到某外部节点的路径长度。

  • 取候选路径 π_v：从内部节点 v 出发，先到右子节点，再一路向左下走到外部节点（即 v 的"中序后继"外部节点）。

  • 总时间被 ∑v∥πv∥ 所界定。

  • 关键

    ：所有内部节点的 π_v 路径

    互不共享边（edge-disjoint）

    ，因此总路径长度不超过树的总边数，即 O(n)。

    • 右倾边 e 只能属于其父节点的路径 π_v；
    • 左倾边按其向左下延伸所到达的外部节点划分，每个内部节点只占用通向自己中序后继的那组左倾边，而各内部节点中序后继互不相同，故不会共享同一左倾边。

结论：自底向上建堆为 O(n)。

5.5.5 要点速记

方法 建堆时间 整体排序
逐个 insert 建堆 O(n log n) O(n log n)
自底向上建堆 O(n) 仍 O(n log n)（第二阶段不变）
  • 堆排序整体复杂度 O(n log n)，优于 O(n²) 的选择/插入排序。
  • 原地堆排序：用数组自身存堆，额外空间 O(1)。
  • 自底向上建堆能把"建堆"这一步从 O(n log n) 优化到 O(n)，但取出阶段无法优化，故整体仍为 O(n log n)。

5.6 优先队列的扩展

5.6.1 辅助方法（Supporting Methods）

除了优先队列的两个基本方法外，还可以增加 size()、isEmpty() 等辅助方法，以及下面两个：

方法 说明
minElement() 返回（但不移除）P 中具有最小键的元素
minKey() 返回（但不移除）P 中的最小键

要点：

  • 两个方法在优先队列为空时都返回错误条件。
  • 若用有序列表或堆实现，这两个操作均可在 O(1) 时间内完成。

5.6.2 比较器（Comparators）

核心思想： 用一个外部的"比较器"对象来定义键的比较规则，而不是依赖键本身。

为什么需要：

  • 让优先队列的比较方式参数化，实现最通用、可复用的设计。
  • 键本身的默认比较规则可能不符合用户需求（尤其是多维数据）。
  • 优先队列 P 在构造时被赋予一个比较器；当 P 需要比较两个键时，就调用该比较器执行比较。
  • 还可在比较器"过时"后给 P 换上新的比较器。

比较器提供的方法（每个方法接收两个键并比较，键不可比时报错）：

方法 说明
isLess(a, b) 当且仅当 a < b 时为真
isLessOrEqualTo(a, b) 当且仅当 a ≤ b 时为真
isEqualTo(a, b) 当且仅当 a = b 时为真
isGreater(a, b) 当且仅当 a > b 时为真
isGreaterOrEqualTo(a, b) 当且仅当 a ≥ b 时为真
isComparable(a) 当且仅当 a 可被比较时为真

5.6.3 定位器（Locators）

定义： 定位器是一种维护"元素 ↔ 其在容器中当前位置"之间关联的机制。即使元素在容器中移动位置，定位器仍"粘附"在该元素上。

类比（衣帽寄存票）：

  • 把外套交给衣帽间 → 拿到一张寄存票（即"定位器"）。
  • 外套相对其他外套的位置会变化（有外套被增删），但寄存票始终能取回你的外套。
  • 关键：定位器跟随它的元素，即使位置改变也不变。

用途： 插入元素时可获得一个定位器，之后用它引用该元素（例如指定把这个元素移除）。

定位器 ℓ 支持的方法：

方法 说明
element() 返回与 ℓ 关联项的元素
key() 返回与 ℓ 关联项的键

5.6.4 在优先队列中使用定位器

优势： 定位器附着在插入优先队列的项上，可以与具体实现无关地访问该项。这一点很重要——因为优先队列中**没有"索引"或"节点"**的概念，访问是基于键的。

基于定位器的优先队列方法（扩展 P）：

方法 说明
min() 返回 P 中最小键项的定位器
insert(k, e) 插入元素 e、键 k 的新项，并返回其定位器
remove(ℓ) 从 P 中移除定位器 ℓ 对应的项
replaceElement(ℓ, e) 用 e 替换 ℓ 项的元素，并返回原元素
replaceKey(ℓ, k) 用 k 替换 ℓ 项的键，并返回原键

性能要点：

  • 基于定位器的访问：O(1)。
  • 基于键的访问：需在整个列表或堆中搜索，最坏情况 O(n)。
  • 可将 replaceKey 限制为只增/只减键，定义 increaseKey / decreaseKey，借助斐波那契堆等结构可达摊还 O(1)。

5.6.5 不同实现的运行时间对比

n = 执行某方法时优先队列中的元素个数

方法 无序列表 有序列表 堆
key, replaceElement O(1) O(1) O(1)
minElement, min, minKey O(n) O(1) O(1)
insert O(1) O(n) O(log n)
removeMin O(n) O(1) O(log n)
remove O(1) O(1) O(log n)
replaceKey O(1) O(n) O(log n)

对比小结：

  • 无序列表：插入快（O(1)），但找最小/删最小慢（O(n)）。
  • 有序列表：取最小/删最小快（O(1)），但插入慢（O(n)）。
  • 堆：各操作较为均衡，均在 O(log n) 或更优，适合需要兼顾插入与删除的场景。
