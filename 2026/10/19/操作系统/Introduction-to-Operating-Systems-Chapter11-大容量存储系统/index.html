大容量存储系统

一、大容量存储结构概述

现代计算机的二级存储主要是 HDD（机械硬盘） 和 NVM（非易失性存储设备）。

1. 机械硬盘 HDD

物理结构（Moving-head Disk Mechanism）

  • 盘片 platter：表面有磁性涂层，绕主轴 spindle 旋转
  • 磁道 track：盘面上的同心圆
  • 扇区 sector：磁道上划分出的小段，是基本存储单位
  • 柱面 cylinder：所有盘片上同一半径的磁道组成的集合
  • 读写磁头 read-write head：装在磁臂 arm上，所有磁臂由磁臂组件 arm assembly带动一起移动
  • 转速约每秒 60–250 转
  • 磁头碰撞 head crash：磁头接触盘面，会造成损坏

性能参数

  • 传输速率：数据在驱动器和计算机之间流动的速率。理论值约 6 Gb/s，实际约 1 Gb/s
  • 定位时间（随机访问时间） = 寻道时间（磁臂移到目标柱面）+ 旋转延迟（目标扇区转到磁头下）
  • 寻道时间为 3–12 ms，台式机常见 9 ms
  • 旋转一圈的时间 = 60 / RPM，平均旋转延迟 = 一圈时间的 ½

核心公式

  • 平均访问时间 = 平均寻道时间 + 平均旋转延迟
  • 平均 I/O 时间 = 平均访问时间 + (传输量 / 传输速率) + 控制器开销

例题：7200 RPM，平均寻道 5 ms，传输率 1 Gb/s，控制器开销 0.1 ms，传输 4 KB 块

  • 旋转一圈：60/7200 = 8.33 ms，平均延迟 = 4.17 ms
  • 传输时间：4 KB = 32 Kb，32 Kb ÷ 1 Gb/s ≈ 0.031 ms
  • 合计：5 + 4.17 + 0.1 + 0.031 ≈ 9.301 ms

💡 可以看出，HDD 的时间主要花在寻道和旋转上，真正传输数据的时间几乎可以忽略。

历史：1956 年 IBM Model 350 是第一个商用磁盘，有 50 张 24 英寸盘片，存 5M 个字符，访问时间不到 1 秒。

2. 非易失性存储设备 NVM

  • 形态像磁盘的叫 SSD（固态硬盘）。其他形式还有 U 盘、主板贴片存储、手机存储等
  • 优点：没有机械部件，所以没有寻道时间和旋转延迟，速度快，可靠性可能更高
  • 缺点：每 MB 更贵，容量较小，寿命可能较短
  • 传统总线可能跟不上它的速度，所以直接连 PCI 总线（即 NVMe）

NAND 闪存的特点（难点）

  • 以页 page 为单位读写，但不能原地覆盖写
  • 写之前必须先擦除，而擦除以更大的块 block 为单位进行
  • 擦除次数有限，约 10 万次
  • 寿命用 DWPD（每日全盘写入次数） 衡量。例如 1 TB、5 DWPD 的盘，保修期内每天可写 5 TB

NAND 闪存控制器算法

机制 作用
FTL 闪存转换层 维护逻辑块到物理页的映射，并记录哪些页有效
垃圾回收 GC 回收无效页占用的空间
超额配置 Overprovisioning 预留一部分空间给 GC 作为工作区
磨损均衡 Wear leveling 让写入均匀分布到所有单元，延长寿命

因为不能覆盖写，一个块里会同时有有效页和无效页混在一起（见示意图），这就是需要 GC 的原因。

3. 易失性存储：RAM 盘

  • 用 DRAM 模拟块设备，可以格式化成文件系统，作为高速临时存储
  • 严格说不算二级存储，因为断电数据会丢失
  • 与缓存的区别：缓存由 OS 或硬件管理，RAM 盘由用户控制
  • 例子：Linux 的 /dev/ram、tmpfs（/tmp），macOS 的 diskutil

4. 磁带 Magnetic Tape

  • 早期的二级存储介质，非易失，容量大
  • 随机访问比 HDD 慢约 1000 倍，比 SSD 慢约 10 万倍
  • 定位要几分钟，但定位后顺序读写速度和 HDD 相当
  • 主要用于备份、存放不常用的数据、在系统之间传输数据
  • 例子：LTO-6、SDLT

5. 磁盘结构与地址映射

  • 磁盘被看作一个一维逻辑块数组，逻辑块是最小的传输单位
  • 映射顺序：0 号扇区是最外层柱面第一个磁道的第一个扇区。先走完这个磁道，再走同柱面的其他磁道，然后从外向内依次走完各柱面
  • 难点：有坏扇区；而且外圈磁道的扇区数比内圈多，每道扇区数不固定

6. 磁盘连接

  • 常见总线：ATA、SATA（最常见）、eSATA、SAS、USB、FC（光纤通道）
  • 控制器 / HBA：主机端有主机控制器，设备端有设备控制器
  • 数据通过 DMA 在设备和内存之间传输

二、HDD 调度（重点 ⭐）

目标：缩短访问时间，提高磁盘带宽。寻道时间大致与寻道距离成正比。

  • 磁盘带宽 = 传输的总字节数 ÷（从第一个请求到最后一个传输完成的总时间）
  • 只有存在请求队列时，调度才有意义
  • 现在调度多由磁盘控制器完成，OS 只需提供 LBA

统一例题：柱面 0–199，队列为 98, 183, 37, 122, 14, 124, 65, 67，磁头在 53

算法 思想 访问顺序 总移动量
FCFS 按到达顺序服务 53→98→183→37→122→14→124→65→67 640
SSTF 每次选离当前位置最近的请求 53→65→67→37→14→98→122→124→183 236
SCAN（电梯算法） 磁头先移到一端，再反向扫描，沿途服务请求 53→37→14→0→65→67→98→122→124→183 208
C-SCAN 只在一个方向服务，到头后直接回到起点，返程不服务 53→65→…→183→199→0→14→37 146+199+37 = 382（含返程）

各算法的要点：

  • FCFS：公平，但磁头来回大幅摆动，效率低
  • SSTF：效率较好，但可能造成饥饿（远处的请求一直得不到服务）
  • SCAN：缺点是刚扫过的区域要等很久才会被再次访问。磁头掉头后，另一端积累的请求最多、等得最久
  • C-SCAN：把柱面看成一个环形列表，等待时间比 SCAN 更均匀

如何选择算法

  • SSTF 常用，也很直观

  • 负载重的系统用 SCAN 或 C-SCAN 更好

  • Linux deadline 调度器

    （防止饥饿）：

    • 读写队列分开，读优先，因为进程更容易因读而阻塞
    • 共 4 个队列：读、写各一个 LBA 排序队列（相当于 C-SCAN），读、写各一个 FCFS 队列
    • 请求按批次发出。每批结束后检查 FCFS 队列中是否有请求超过设定时限（默认 500 ms）。如果有，下一批就选包含该请求的 LBA 队列

  • RHEL 7 中还有 NOOP 和 CFQ（完全公平队列）

三、NVM 调度

  • 没有磁头和旋转延迟，一般用 NOOP（不排序），但会合并相邻的 LBA 请求
  • NVM 擅长随机 I/O，HDD 擅长顺序 I/O
  • 两者吞吐量可能接近，但 IOPS 差别很大：NVM 是几十万级，HDD 只有几百
  • 写放大：一次写入可能引发 GC，带来多次额外读写，会削弱 NVM 的性能优势

四、错误检测与纠正

  • 错误检测：发现错误（如位翻转），可以停止操作
    • 奇偶校验位：一种校验和（checksum）
    • CRC 循环冗余校验：用哈希函数检测多位错误，常用于网络
  • ECC 纠错码：不仅能检测，还能纠正部分错误
    • 软错误：可以纠正；硬错误：能检测但无法纠正

五、存储设备管理

  1. 低级格式化（物理格式化）：把磁盘划分成扇区。每个扇区包含头部、数据（通常 512 B）和 ECC

  2. 分区：把磁盘划分为一组或多组柱面，每组作为一个逻辑盘

  3. 逻辑格式化

    ：建立文件系统

    • 磁盘 I/O 以块为单位，文件 I/O 以簇为单位
  • 根分区存放 OS，开机时挂载。挂载时会检查文件系统一致性
  • 原始磁盘访问 raw disk：数据库等应用绕过 OS，自己管理块
  • 启动过程（Windows）：ROM/固件中的 bootstrap → MBR（引导代码 + 分区表）→ 找到引导分区 → bootstrap loader 加载内核
  • 扇区备用 sector sparing：用备用扇区替换坏块

六、交换空间管理

  • 内存不够时，把整个进程（交换）或页面（分页）移到二级存储
  • 要点：可以有多个交换空间来分散 I/O 负载；最好使用专用设备；可以放在原始分区（更快）或文件系统中的文件（便于增加）
  • Linux 数据结构：交换区被分成多个页槽 page slot，对应一个 swap map 计数数组
    • 0 表示空闲；n 表示有 n 个进程映射了该页（例如共享页为 3）

七、存储连接方式

方式 特点
主机连接 通过本地 I/O 端口和总线（USB、Thunderbolt），高端系统用 FC 光纤通道
NAS 网络附加存储 通过网络（LAN/WAN）访问文件系统，协议有 NFS、CIFS，基于 RPC 和 TCP/UDP；iSCSI 则是通过 IP 网络访问块设备
云存储 通过 Internet/WAN 访问远程数据中心，基于 API（因为延迟高、故障场景多），例如 Dropbox、S3、OneDrive、iCloud
存储阵列 带控制器的磁盘阵列，提供 RAID、热备、快照、克隆、精简配置、复制、去重等功能
SAN 存储区域网 多主机与多存储阵列通过 FC 交换机或 InfiniBand 组成的专用网络互连，用 LUN masking 分配存储，灵活且易于扩展

💡 NAS 与 SAN 的区别：NAS 走普通网络，提供的是文件；SAN 是专用存储网络，提供的是块。

八、RAID 结构（重点 ⭐）

RAID：廉价冗余磁盘阵列，用冗余提高可靠性，用条带化提高性能。

  • MTTF：平均故障时间
  • MTTR：平均修复时间，即另一块盘再坏就会丢数据的暴露窗口
  • 镜像例题：MTTF = 100,000 h，MTTR = 10 h，则平均数据丢失时间 = 100,000² / (2×10) = 5×10⁸ h ≈ 57,000 年
  • 常配合 NVRAM 提高写性能

RAID 级别

级别 方式 特点
RAID 0 非冗余条带化 性能最高，没有容错
RAID 1 镜像 每块盘都有副本，开销是 100%
RAID 4 块交错奇偶校验 有一块专用校验盘，它会成为瓶颈
RAID 5 块交错分布式奇偶校验 校验信息分散到各盘，最常用
RAID 6 P + Q 冗余 可以承受两块盘同时故障
多维 RAID 6 行和列都做 P/Q 校验 用于大规模阵列

RAID 0+1 与 RAID 1+0

  • 0+1（镜像的条带）：先条带化，再整体镜像。坏一块盘，整条条带失效
  • 1+0（条带的镜像）：先两两镜像，再条带化。坏一块盘，只影响这一对镜像，可靠性更高 ✅

其他特性

  • 快照：文件系统在某个时间点的视图
  • 复制：在不同站点之间自动复制写操作，用于容灾，分同步和异步两种
  • 热备盘：盘坏时自动顶替并重建数据，可以减少 MTTR

九、扩展

ZFS

  • RAID 只能应对磁盘故障，不能检测数据损坏
  • ZFS 对所有数据和元数据计算校验和。校验和存放在指向该对象的指针里（父块保存子块的校验和），所以能检测并纠正损坏
  • 存储池 pool：取消了传统的卷和分区，多个文件系统共享一个池，像 malloc() / free() 那样按需申请和释放空间
  • 对比：传统方式是每个 FS 对应一个卷再对应若干盘；ZFS 是所有 FS 共享一个存储池

对象存储

  • 用于超大规模场景。对象只是数据容器，没有目录结构，面向程序而不是用户
  • 典型流程：创建对象并得到对象 ID → 用 ID 访问 → 用 ID 删除
  • 代表系统：HDFS、Ceph。通过在 N 个节点上存 N 个副本来保护数据，可水平扩展，按内容寻址，适合非结构化数据
