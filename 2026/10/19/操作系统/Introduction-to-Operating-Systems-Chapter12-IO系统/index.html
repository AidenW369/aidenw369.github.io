I/O系统

一、概述

  • I/O 管理是操作系统设计的重要组成部分。I/O 设备种类繁多，控制方法各不相同，而且新设备不断出现。
  • 设备通过**端口（port）、总线（bus）和设备控制器（controller）**连接到计算机。
  • **设备驱动程序（device driver）*封装了设备细节，向 I/O 子系统提供*统一的访问接口。
  • 本章目标：
    1. 了解 OS I/O 子系统的结构
    2. 理解 I/O 硬件的原理与复杂性
    3. 分析 I/O 软硬件的性能问题

二、I/O 硬件

1. 设备分类

  • 存储类：磁盘、磁带
  • 传输类：网卡、调制解调器
  • 人机交互类：键盘、鼠标、显示器

2. 基本连接概念

概念 含义
端口 Port 设备的连接点
总线 Bus 共享的通信线路，可以是菊花链或共享直接访问
控制器 Controller 操作端口、总线或设备的电子部件，可能集成在主板上，也可能是独立电路板（host adapter，内含处理器、微码、私有内存等）

常见总线与接口

  • PCIe 总线：PC 和服务器的主干总线
  • 扩展总线（expansion bus）：连接较慢的设备（键盘、USB 等）
  • SAS（Serial-attached SCSI）：常用的磁盘接口
  • Fibre Channel (FC)：复杂控制器，通常是插在总线上的独立板卡（HBA）

3. 典型 PC 总线结构（图解）

要点：CPU 经桥接/内存控制器接入 PCIe 主干，高速设备（显卡、磁盘控制器）直接挂在 PCIe 上，低速设备经扩展总线接入。

4. 设备寄存器

设备驱动通过读写控制器的寄存器来控制设备：

寄存器 作用
data-in 主机从中读取输入数据
data-out 主机向其写入输出数据
status 设备状态（忙、出错、数据就绪等）
control 主机写入命令，改变设备模式

寄存器一般为 1–4 字节，也可能是 FIFO 缓冲区。

5. 设备寻址的两种方式

  1. 直接 I/O 指令（如 x86 的 in/out），使用独立的 I/O 端口地址空间
  2. 内存映射 I/O（Memory-mapped I/O）：设备寄存器映射到处理器地址空间，用普通访存指令操作。特别适合需要大地址空间的设备（如显卡）

6. PC 设备 I/O 端口地址（部分）

地址范围（十六进制） 设备
000–00F DMA 控制器
020–021 中断控制器
040–043 定时器
200–20F 游戏控制器
2F8–2FF 串口（副）
320–32F 硬盘控制器
378–37F 并口
3D0–3DF 图形控制器
3F0–3F7 软驱控制器
3F8–3FF 串口（主）

三、轮询（Polling）

每传输一个字节的握手过程：

  1. 主机反复读取状态寄存器的 busy 位，直到其为 0（忙等待）
  2. 主机设置读/写位；如果是写操作，把数据放入 data-out 寄存器
  3. 主机设置 command-ready 位
  4. 控制器看到命令后设置 busy 位，执行传输
  5. 传输完成后，控制器清除 busy、error、command-ready 位

评价

  • ✅ 设备快时合理，一次轮询只需约 3 条指令（读状态、与运算取位、条件跳转）
  • ❌ 设备慢时，CPU 在忙等待中浪费大量时间
  • ⚠️ 如果 CPU 切去做别的事，可能错过时机，导致数据被覆盖或丢失

四、中断（Interrupts）

1. 基本机制

  • CPU 有一条中断请求线，由 I/O 设备触发
  • CPU 每执行完一条指令就检查一次中断线
  • **中断处理程序（interrupt handler）**负责处理中断
  • 中断向量（interrupt vector）：根据中断号分派到对应的处理程序
  • 中断开始和结束时需要上下文切换
  • 中断有优先级
  • 可屏蔽中断可以被忽略或延迟；不可屏蔽中断不能
  • 中断链（interrupt chaining）：多个设备共用一个中断号时，依次调用各处理程序

2. 中断驱动的 I/O 周期（7 步）

  1. CPU 中的设备驱动发起 I/O
  2. I/O 控制器开始执行 I/O
  3. 输入就绪、输出完成或出错时，控制器产生中断信号
  4. CPU 在指令间检测到中断，把控制权转给中断处理程序
  5. 中断处理程序处理数据，然后从中断返回
  6. CPU 恢复执行被中断的任务
  7. 回到第 1 步，循环往复

3. 中断机制的其他用途

  • 异常：终止进程，或因硬件错误使系统崩溃
  • 缺页（page fault）：访存错误时触发
  • 系统调用：通过**陷阱（trap）**进入内核执行请求
  • 多 CPU 系统可以并发处理中断（前提是 OS 支持）
  • 中断用于时间敏感的处理，发生频繁，所以必须很快

4. Intel Pentium 事件向量表

向量号 含义
0 除法错误
1 调试异常
2 空中断
3 断点
4 INTO 检测到溢出
5 越界异常
6 非法操作码
7 设备不可用
8 双重故障
9 协处理器段越界（保留）
10 无效 TSS

记忆：0–31 是不可屏蔽的异常和保留项，32–255 是可屏蔽的设备中断。

5. 中断延迟（Latency）

  • 即使是单用户系统，每秒也要处理数百次中断；服务器每秒可达数十万次。

  • 实例：一台"安静的" macOS 桌面在

    10 秒内产生了约 23,000 次中断

    （22,998 次）。

    • 延迟 < 10 µs 的有 16,243 次，< 20 µs 的有 5,312 次
    • 全部中断的延迟都在 100 µs 以内

  • 结论：中断管理的效率对系统性能至关重要。

五、直接内存访问（DMA）

1. 目的

避免**程序控制 I/O（PIO，每次 CPU 搬一个字节）**在大量数据传输时的低效。

2. 原理

  • 需要专门的 DMA 控制器

  • 数据在 I/O 设备和内存之间直接传输，绕过 CPU

  • OS 在内存中写入一个

    DMA 命令块

    ，包含：

    • 源地址和目的地址
    • 读/写模式
    • 传输字节数

  • OS 把命令块的位置告诉 DMA 控制器

  • 总线主控（bus mastering）：DMA 控制器从 CPU 手中获取总线控制权

  • 周期窃取（cycle stealing）：会占用 CPU 的部分总线周期，但整体仍然高效得多

  • 传输完成后，发中断通知 CPU

  • DVMA：能识别虚拟地址的 DMA，效率更高

3. DMA 传输六步

步骤 内容
1 设备驱动被告知：把 drive2 的数据传到内存地址 x 处的缓冲区
2 设备驱动通知驱动器控制器：传输 c 个字节到地址 x
3 驱动器控制器发起 DMA 传输
4 DMA 控制器把字节传到缓冲区 x，内存地址递增，c 递减，直到 c = 0
5 c = 0 时，DMA 中断 CPU，通知传输完成
6 （CPU 处理中断，传输结束）

关键：整个传输过程中 CPU 只在**开始（下命令）和结束（处理中断）**时参与。

4. 三种 I/O 控制方式对比

方式 CPU 参与程度 适用场景
轮询 全程忙等待 快速设备、少量数据
中断 每个数据单元一次中断 慢速、字符设备
DMA 仅在开始和结束时参与 大块数据传输（磁盘）

六、应用程序 I/O 接口

1. 分层抽象

  • I/O 系统调用把设备行为封装成通用类别
  • 设备驱动层向内核屏蔽各控制器的差异
  • 使用已实现协议的新设备无需额外工作
  • 每种 OS 有自己的 I/O 子系统结构和驱动框架

2. 内核 I/O 结构（图解）

设备驱动是软件和硬件之间的边界：每类控制器对应一个驱动，上层统一由 I/O 子系统管理。

3. I/O 设备特性

维度 取值 例子
数据传输模式 字符 / 块 终端 / 磁盘
访问方式 顺序 / 随机 调制解调器 / CD-ROM
传输调度 同步 / 异步 磁带 / 键盘
共享性 独占 / 可共享 磁带 / 键盘
设备速度 延迟、寻道时间、传输率、操作间隔 —
I/O 方向 只读 / 只写 / 读写 CD-ROM / 图形控制器 / 磁盘

4. OS 对设备的大致分组

  • 块 I/O
  • 字符（流）I/O
  • 内存映射文件访问
  • 网络套接字

后门接口：Unix 的 ioctl() 可以直接向设备控制寄存器发送任意位，向数据寄存器发送数据，用于处理设备特有的功能。

设备编号：UNIX/Linux 用 （主设备号 major，次设备号 minor） 标识设备，主设备号表示类型（对应驱动），次设备号表示实例。例如 ls -l /dev/sda* 显示的主设备号为 8，次设备号为 0–4。

七、各类设备接口

1. 块设备（如磁盘）

  • 命令：read、write、seek
  • 访问方式：原始 I/O（raw）、直接 I/O、经由文件系统访问
  • 支持内存映射文件：文件映射到虚拟内存，通过请求分页调入
  • 通常使用 DMA

2. 字符设备（如键盘、鼠标、串口）

  • 命令：get()、put()
  • 上层库可以提供行编辑等功能

3. 网络设备

  • 与块设备和字符设备差别较大，有自己的接口
  • Linux、Unix、Windows 等都提供 socket 接口
  • 把网络协议和网络操作分离
  • 提供 select()，用于检测哪些套接字有数据
  • 进程间通信方式多样：管道、FIFO、流、队列、邮箱

4. 时钟与定时器

  • 提供当前时间、已用时间，以及定时器功能
  • 普通分辨率约为 1/60 秒，部分系统提供更高精度
  • 可编程间隔定时器：用于计时和产生周期性中断
  • 在 UNIX 中，时钟等特殊功能通过 ioctl() 处理

八、阻塞、非阻塞与异步 I/O

类型 行为 特点
阻塞（Blocking） 进程挂起，直到 I/O 完成 简单易懂，但有时不能满足需求
非阻塞（Nonblocking） 调用立即返回已有的数据和读写字节数 用于用户界面、缓冲 I/O；可用多线程实现；常用 select() 判断数据就绪后再 read()/write()
异步（Asynchronous） 进程继续运行，I/O 在后台执行，完成后由 I/O 子系统通知进程 编程难度高

两种 I/O 方法（图解）

  • (a) 同步：请求进程在用户态一直等待，直到硬件传输完成、经中断处理返回。
  • (b) 异步：请求进程发起 I/O 后立即返回用户态继续执行；硬件传输完成后再通知进程。

非阻塞和异步的区别：非阻塞调用立即返回当前能拿到的数据；异步调用立即返回，但要求完整完成传输，完成时再通知。

九、向量 I/O（Vectored I/O）

  • 一次系统调用完成多个 I/O 操作
  • 例如 Unix 的 readv()（课件写作 readve），接受一个由多个缓冲区组成的向量，从中写出或读入
  • 这种 scatter-gather（分散-聚集）方式优于多次单独调用：
    • 减少上下文切换
    • 减少系统调用开销
  • 部分实现保证原子性，避免多线程同时修改数据时出现不一致

十、内核 I/O 子系统

1. 调度（Scheduling）

  • 通过每个设备的请求队列对 I/O 请求排序
  • 有些 OS 追求公平性
  • 有些实现服务质量（QoS，如 IPQOS）

2. 缓冲（Buffering）

在设备之间传输数据时，把数据暂存在内存中。三个目的：

  1. 应对速度不匹配（如调制解调器比磁盘慢得多）
  2. 应对传输大小不匹配（如网络包的分片与重组）
  3. 维护"复制语义"（copy semantics）：保证写入设备的是系统调用时刻的数据版本，即使应用随后修改了自己的缓冲区

双缓冲（Double buffering）

  • 数据有内核和用户两份拷贝
  • 两个缓冲区轮流使用：一个已满、正在处理，另一个未满、正在填充
  • 某些情况下可以用**写时复制（copy-on-write）**提高效率

十一、设备状态表（Device-status Table）

内核为每个设备维护一个设备状态表，记录设备类型、地址和状态（空闲/忙）。设备忙时，新的请求挂在该设备的等待队列上。

图示：

设备 状态 等待队列
keyboard idle —
laser printer busy → 请求（address 38546, length 1372）
mouse idle —
disk unit 1 idle —
disk unit 2 busy → 请求1：读文件 xxx（address 43046, length 20000）→ 请求2：写文件 yyy（address 03458, length 500）

要点：每个设备一条请求链表，OS 的 I/O 调度就是对这些队列中的请求重新排序。

十三、内核 I/O 子系统（续）

1. 缓存（Caching）

  • 用更快的设备保存数据的副本
  • 缓存里的永远只是副本，原数据在别处
  • 是提升性能的关键
  • 有时与缓冲结合使用（同一块内存既当缓冲又当缓存）

缓冲 vs 缓存

  • 缓冲区里可能是数据唯一的一份（正在传输中）
  • 缓存里一定是另一处数据的副本

2. 假脱机（Spooling）

  • 为设备暂存输出
  • 适用于一次只能服务一个请求的设备，典型例子是打印机
  • 各进程的输出先写入磁盘上的 spool 文件，再按顺序逐个送到打印机，从而避免多个进程的输出交织在一起

3. 设备预留（Device Reservation）

  • 为进程提供对设备的独占访问
  • 通过系统调用进行分配和释放
  • ⚠️ 需要警惕死锁

十四、错误处理（Error Handling）

  • OS 能从以下错误中恢复：磁盘读错误、设备不可用、暂时性写失败
    • 常用方法：重试读或写操作
  • 更高级的系统（如 Solaris FMA、AIX）：
    • 跟踪错误发生频率
    • 当可重试错误越来越频繁时，停止使用该设备
  • 大多数系统在 I/O 请求失败时返回错误号或错误码
  • 系统错误日志记录问题报告

十五、I/O 保护（I/O Protection）

  • 用户进程可能无意或故意通过非法 I/O 指令破坏系统正常运行
  • 保护措施：
    1. 所有 I/O 指令都是特权指令
    2. I/O 必须通过系统调用完成
    3. 内存映射 I/O 区域和 I/O 端口地址也必须受到保护（防止用户程序直接访问）

用系统调用执行 I/O（图解，3 步）

  1. 陷入内核（trap to kernel）：用户程序执行 system call n
  2. 执行 I/O（perform I/O）：内核按系统调用号分派到 n，调用 read
  3. 返回调用线程（return to calling thread）

十六、内核数据结构

  • 内核为 I/O 组件保存状态信息：打开文件表、网络连接、字符设备状态等
  • 用大量复杂的数据结构跟踪缓冲区、内存分配和**”脏"块（dirty blocks）**
  • 有些系统采用面向对象 + 消息传递来实现 I/O：
    • Windows 使用消息传递
    • 携带 I/O 信息的消息从用户态传入内核
    • 消息在流经设备驱动、再返回进程的过程中被逐步修改
    • 优点：结构清晰、模块化、易扩展
    • 缺点：相比共享数据结构，开销更大

UNIX I/O 内核结构（图解）

要点：

  • 文件描述符 → 进程打开文件表 → 系统范围打开文件表
  • 每条记录都含有一组函数指针（read、write、select、ioctl、close），体现了面向对象的多态：文件和 socket 共用同一套接口，具体实现不同
  • 文件记录指向活动 inode 表，socket 记录指向网络信息表

十七、电源管理（Power Management）

1. 背景

  • 严格来说不完全属于 I/O，但大部分与 I/O 相关
  • 设备耗电、发热、需要散热，OS 可以帮助优化
  • 云计算：在服务器之间迁移虚拟机，可以把整台服务器腾空后关机
  • 移动计算：电源管理是 OS 的一等公民

2. Android 的电源管理

① 组件级电源管理

  • 理解组件之间的关系，构建表示物理设备拓扑的设备树
    • 例：system bus → I/O subsystem → {flash, USB storage}
  • 设备驱动跟踪设备状态（是否在使用）
  • 组件不用时 → 关闭该组件
  • 整个树分支都不用时 → 关闭整个分支

② 唤醒锁（Wake locks）

  • 与普通锁类似，但持有时阻止设备进入睡眠

③ 电源坍缩（Power collapse）

  • 让设备进入极深度睡眠，耗电极低
  • 只保留响应外部刺激的能力（按键、来电）

3. ACPI

现代系统使用 ACPI（高级配置与电源接口） 固件，提供可由内核调用的例程，负责设备发现、管理、错误处理和电源管理。

十八、内核 I/O 子系统功能总结

I/O 子系统为应用程序和内核其他部分协调一系列服务：

  1. 文件和设备的命名空间管理
  2. 文件和设备的访问控制
  3. 操作控制（例如调制解调器不能 seek()）
  4. 文件系统空间分配
  5. 设备分配
  6. 缓冲、缓存、假脱机
  7. I/O 调度
  8. 设备状态监控、错误处理、故障恢复
  9. 设备驱动配置和初始化
  10. I/O 设备电源管理

I/O 子系统上层通过设备驱动提供的统一接口访问设备。

十九、将 I/O 请求转换为硬件操作

以进程从磁盘读文件为例：

  1. 确定存放文件的设备
  2. 把文件名转换为设备表示
  3. 物理读取磁盘数据到缓冲区
  4. 让请求进程可以使用这些数据
  5. 把控制权返回给进程

I/O 请求的生命周期（图解）

向下（发出请求）：

层次 动作
用户态 请求 I/O → 发起系统调用
内核 I/O 子系统 判断能否直接满足请求（如数据已在缓存中）？ • 能 → 把数据放入返回值或进程空间，直接返回 • 不能 → 把请求发给设备驱动，必要时阻塞进程
设备驱动 处理请求，向控制器发命令，配置控制器，阻塞直到中断
设备控制器 执行命令，监控设备

向上（完成返回）：

层次 动作
设备控制器 I/O 完成，产生中断
中断处理程序 接收中断；如果是输入，把数据存入驱动缓冲区；发信号唤醒设备驱动
设备驱动 确定哪个 I/O 完成，把状态变化通知 I/O 子系统
内核 I/O 子系统 把数据放入返回值或进程空间
用户态 从系统调用返回，输入数据可用或输出已完成

关键：命中缓存时走捷径直接返回，不命中才一路走到硬件。

二十、STREAMS

1. 定义

  • STREAM：Unix System V 及之后系统中，用户进程与设备之间的全双工通信通道

2. 组成

  • STREAM head（流头）：与用户进程交互
  • driver end（驱动端）：与设备交互
  • 中间有零个或多个 STREAM 模块

3. 工作方式

  • 每个模块包含一个读队列和一个写队列
  • 队列之间通过消息传递通信
  • 可选的流量控制：标示队列可用或繁忙
  • 内部是异步的；用户进程与流头之间是同步的

4. 结构（图解）

数据向下走写队列，向上走读队列。模块可以动态压入或弹出，实现协议的灵活组合。

二十一、性能（Performance）

1. I/O 是影响系统性能的主要因素

  • CPU 要执行设备驱动和内核 I/O 代码
  • 中断引起的上下文切换
  • 数据拷贝
  • 网络流量的压力尤其大

2. 计算机间通信示例（图解）

发送端：

  1. 键盘输入一个字符 → 产生中断 → 保存状态（state save）
  2. 内核接收中断 → 中断处理程序 → 设备驱动
  3. 上下文切换 → 用户进程收到字符
  4. 用户进程调用 send 发送字符 → 系统调用经设备驱动到网卡
  5. 从系统调用返回（又一次上下文切换）

网络传输：数据包经网络发送

接收端：

  1. 网卡产生中断 → 保存状态
  2. 中断处理程序 → 设备驱动
  3. 上下文切换到网络守护进程（network daemon）
  4. 再次上下文切换到用户进程，收到数据包

结论：仅传送一个字符，就涉及多次中断、状态保存和上下文切换，开销巨大。

3. 提升性能的方法

  1. 减少上下文切换次数
  2. 减少数据拷贝
  3. 减少中断：使用大块传输、智能控制器、轮询
  4. 使用 DMA
  5. 使用更智能的硬件设备
  6. 平衡 CPU、内存、总线和 I/O 性能，获得最高吞吐量
  7. 把用户态进程或守护进程移入内核线程

4. 设备功能的实现层次演进（图解）

新算法可以在以下层次中实现，从上到下依次为：

越往下（越接近硬件）：

  • ⬆ 开发时间（代际）越长
  • ⬆ 效率越高
  • ⬆ 开发成本越高
  • ⬆ 抽象程度越高

越往上（越接近应用）：

  • ⬆ 灵活性越高

规律：新算法通常先在应用层实现（便于调试），成熟后逐步下移到内核、驱动乃至硬件，以换取效率。

5. 存储与网络延迟（图解）

类别 介质 延迟量级 容量量级
内存 Load/Store CPU 缓存 ~1–10 ns < 10 GB
DRAM DIMM ~几十 ns ~10 GB 级
DIMM NVM（非易失内存条） ~100 ns ~100 GB 级
存储 Read/Write PCIe/NVMe NVM ~几 µs ~TB 级
PCIe/NVMe SSD ~几十 µs 数 TB
SAS SSD ~100 µs 数 TB
SAS HDD ~10 ms 数 TB
网络延迟 — ~1–100+ µs —

结论：

  • 延迟跨越 ns → µs → ms 多个数量级，容量越大的介质通常越慢
  • 网络延迟（µs 级）已经接近甚至低于 SSD，远低于 HDD，这也是分布式存储可行的原因
  • NVM 新型介质正在模糊内存和存储的界限

🔑 本部分核心考点速记

  1. 设备状态表：每个设备一条请求队列
  2. 缓冲 vs 缓存 vs 假脱机：缓冲区可能存唯一副本；缓存一定是副本；假脱机为独占设备（打印机）排队输出
  3. 设备预留：独占访问，注意死锁
  4. I/O 保护：所有 I/O 指令都是特权指令，必须通过系统调用
  5. UNIX 打开文件表：通过函数指针实现文件和 socket 的统一接口
  6. Android 电源管理：设备树、wake lock、power collapse；ACPI
  7. I/O 请求生命周期：先查能否直接满足，否则依次经驱动、控制器、中断返回
  8. STREAMS：流头、模块、驱动端；每个模块有读写两个队列；内部异步，与用户同步
  9. 性能杀手：上下文切换、数据拷贝、中断
  10. 功能层次：越靠近硬件越高效但越不灵活
