文件系统接口

一、本章概览

主要内容：文件概念、访问方法、磁盘与目录结构、保护、内存映射文件

学习目标：

  • 理解文件系统的功能
  • 了解文件系统提供的接口
  • 讨论设计上的权衡：访问方法、文件共享、文件锁、目录结构
  • 探讨文件系统的保护机制

二、文件概念（File Concept）

文件是一段连续的逻辑地址空间，内容由创建者定义。

文件类型：

  • 数据文件：数值型、字符型、二进制型
  • 程序文件
  • 常见的有文本文件、源文件、可执行文件

1. 文件属性（File Attributes）

属性 说明
名称 Name 唯一以人类可读形式保存的信息
标识符 Identifier 文件系统内部的唯一编号
类型 Type 供支持多种文件类型的系统使用
位置 Location 指向文件在设备上位置的指针
大小 Size 文件当前大小
保护 Protection 控制谁可以读、写、执行
时间、日期、用户标识 用于保护、安全和使用监控
  • 文件的属性信息保存在目录结构中，目录结构存放在磁盘上
  • 部分系统支持扩展属性，例如文件校验和（checksum）

📌 示例：Mac OS X 的文件信息窗口（以 11.tex 为例）可以直接看到这些属性：

  • 类型（Kind）：TeX Document
  • 大小：111,389 字节（磁盘占用 115 KB）
  • 位置（Where）：/Users/greg/Dropbox/osc9e/tex
  • 创建时间、修改时间、最后打开时间
  • 默认打开程序：texmaker
  • 权限：greg 读写，staff 只读，everyone 无权限

2. 文件操作（File Operations）

  • Create 创建
  • Write 写：在写指针位置写入
  • Read 读：在读指针位置读取
  • Seek 在文件内重新定位
  • Delete 删除
  • Truncate 截断
  • Open(Fi)：在磁盘上的目录结构中查找 Fi 的条目，并把条目内容调入内存
  • Close(Fi)：把内存中 Fi 的条目内容写回磁盘上的目录结构

3. 打开文件的管理（Open Files）

管理已打开的文件需要以下信息：

  • 打开文件表（Open-file table）：记录所有已打开的文件
  • 文件指针（File pointer）：上次读写的位置，每个进程各有一个
  • 文件打开计数（File-open count）：记录文件被打开的次数，最后一个进程关闭时，才把它从打开文件表中删除
  • 文件的磁盘位置：缓存数据访问信息
  • 访问权限：每个进程的访问模式

4. 文件锁（File Locking）

  • 由部分操作系统或文件系统提供，作用类似读者-写者锁
  • 共享锁（Shared lock）≈ 读锁，多个进程可同时持有
  • 排他锁（Exclusive lock）≈ 写锁
  • 两种机制：
    • 强制锁（Mandatory）：系统根据持有和请求的锁，直接拒绝访问
    • 建议锁（Advisory）：进程可以查询锁状态，自行决定怎么做

📌 Java API 示例要点：

  • 通过 RandomAccessFile 获取 FileChannel
  • ch.lock(起始位置, 长度, 是否共享)：参数 false 表示排他锁，true 表示共享锁
  • 示例对文件前半部分加排他锁后修改数据，对后半部分加共享锁后读取数据
  • 用完调用 release() 释放，并在 finally 块中确保锁一定被释放

5. 文件类型：名称与扩展名

文件类型 常见扩展名 功能
可执行文件 exe, com, bin 或无 可直接运行的机器语言程序
目标文件 obj, o 已编译、未链接的机器语言
源代码 c, cc, java, pas, asm, a 各种语言的源代码
批处理 bat, sh 给命令解释器的命令
文本 txt, doc 文本数据、文档
文字处理 wp, tex, rtf, doc 各种文字处理格式
库文件 lib, a, so, dll 供程序员使用的例程库
打印/查看 ps, pdf, jpg 用于打印或查看的 ASCII 或二进制文件
归档 arc, zip, tar 多个相关文件打包成一个，有时会压缩
多媒体 mpeg, mov, rm, mp3, avi 包含音频或音视频的二进制文件

6. 文件结构（File Structure）

  • 无结构：字或字节的序列
  • 简单记录结构：按行组织，记录可以是定长或变长
  • 复杂结构：格式化文档、可重定位装入文件
  • 复杂结构可以用无结构方式模拟，方法是插入适当的控制字符
  • 结构由谁决定：操作系统，或者应用程序

三、访问方法（Access Methods）

前提：文件由定长的逻辑记录组成。

1. 顺序访问（Sequential Access）

操作：read next、write next、reset（回到开头）

  • 在最后一次写之后不能再读（rewrite）
  • 模型：有一个当前位置指针，读写操作让指针向后移动，rewind 让它回到开头
  • 典型应用：磁带，编辑器、编译器的处理过程

2. 直接访问（Direct Access）

操作：read n、write n、position to n、read next、write next、rewrite n

  • n 是相对块号
  • 好处：相对块号让操作系统可以自行决定文件放在磁盘的什么位置

3. 在直接访问文件上模拟顺序访问

用一个当前位置变量 cp 就能实现：

顺序访问操作 直接访问实现
reset cp = 0;
read next read cp; cp = cp + 1;
write next write cp; cp = cp + 1;

⚠️ 反过来，在顺序访问上模拟直接访问的效率很低。

4. 其他访问方法：索引方法

  • 构建在基本方法之上，通常需要为文件建立索引

  • 索引放在内存中，可以快速定位数据。例子：UPC 商品条码加上商品数据记录

  • 如果索引太大，可以建立多级索引：内存中的索引指向磁盘上的索引

  • IBM ISAM

    （索引顺序访问方法）：

    • 一个小的主索引，指向二级索引所在的磁盘块
    • 文件按某个关键字排序
    • 全部由操作系统完成

  • VMS 操作系统也提供索引文件和相对文件

📌 索引文件与相对文件示例：

  • 索引文件：按姓氏排序（Adams、Arthur、Asher……Smith），每项记录一个逻辑记录号
  • 相对文件：存放实际记录，例如 smith, john | 社保号 | 年龄
  • 查找过程：先在索引文件中找到 “Smith”，取出逻辑记录号，再直接定位到相对文件中的那条记录

四、目录结构（Directory Structure）

  • 目录是包含所有文件信息的节点集合
  • 每个目录节点指向一个文件（F1、F2、F3……Fn）
  • 目录结构和文件本身都存放在磁盘上

五、磁盘结构（Disk Structure）

1. 基本概念

  • 一个磁盘可以划分为多个分区（partition），分区也叫 minidisk 或 slice
  • 磁盘或分区可以用 RAID 保护，防止故障导致数据丢失
  • 磁盘或分区有两种用法：
    • 裸用（raw）：不建文件系统，直接使用
    • 格式化：在上面建立文件系统
  • 包含文件系统的实体叫做卷（volume）
  • 每个卷在设备目录或卷目录表（volume table of contents）中记录该文件系统的信息
  • 除了通用文件系统，同一个操作系统中常常还有很多专用文件系统

2. 典型的文件系统组织

📌 图示说明了分区与磁盘不必一一对应：

  • 一盘多区：disk 1 被分成 partition A 和 partition B，每个分区各有自己的目录（directory）和文件（files）
  • 一区多盘：partition C 横跨 disk 2 和 disk 3，只有一个目录

结论：每个分区（卷）都由目录 + 文件两部分组成。

3. 文件系统的类型（以 Solaris 为例）

文件系统 用途
tmpfs 基于内存的易失性文件系统，用于快速的临时 I/O
objfs 访问内核内存的接口，用于获取内核符号以便调试
ctfs 契约（contract）文件系统，用于管理守护进程
lofs 回环（loopback）文件系统，让一个文件系统可以代替另一个被访问
procfs 访问进程结构的内核接口
ufs、zfs 通用文件系统

六、目录结构（Directory Structure）

1. 目录的定义

  • 目录是包含所有文件信息的节点集合，每个节点指向一个文件（F1、F2……Fn）
  • 目录结构和文件都存放在磁盘上

2. 目录上的操作

  • 查找文件
  • 创建文件
  • 删除文件
  • 列出目录内容
  • 重命名文件
  • 遍历文件系统

3. 目录组织的目标

目标 含义
效率 Efficiency 能快速定位文件
命名 Naming 方便用户：两个用户的不同文件可以同名；同一个文件可以有多个名字
分组 Grouping 按属性对文件进行逻辑分组，例如所有 Java 程序、所有游戏

下面几种目录结构，就是围绕这三个目标逐步改进的。

4. 单级目录（Single-Level Directory）

  • 所有用户共用一个目录
  • 图示：一个目录中平铺着 cat、bo、a、test、data、mail、cont、hex、records，每项直接指向一个文件
  • 缺点：
    • 命名问题：所有文件必须名字不同，用户一多就容易冲突
    • 分组问题：无法对文件分类

5. 两级目录（Two-Level Directory）

  • 每个用户有自己独立的目录
  • 结构：
    • 第一级是主文件目录（MFD，master file directory），列出 user 1 到 user 4
    • 第二级是用户文件目录（UFD，user file directory），存放每个用户自己的文件
  • 图示中，user 1、user 2、user 3、user 4 都有名为 a 的文件，互不冲突
  • 特点：
    • 引入了路径名（如 user1/a）
    • 不同用户的文件可以同名 ✅
    • 查找效率高 ✅
    • 没有分组能力 ❌（每个用户内部仍是平铺的）

6. 树形目录（Tree-Structured Directories）

  • 在两级目录的基础上推广到任意多层

  • 图示：root 下有 spell、bin、programs；spell 下有 stat、mail、dist；mail 下又有 prog、copy、prt、exp；prog 下还有 list、obj、spell……

  • 优点：

    • 查找高效
    • 有分组能力，可以用子目录分类 ✅
    • 不同目录下的文件可以同名（如 bin/find 和 programs/p/find）

  • 引入了

    当前目录

    （工作目录）的概念，以及：

    • 绝对路径：从根开始，如 /spell/mail/prog
    • 相对路径：从当前目录开始

  • 局限：一个文件只能属于一个目录，无法共享

7. 无环图目录（Acyclic-Graph Directories）

  • 允许共享子目录和文件：同一个文件或子目录可以出现在多个目录中
  • 图示：root 下有 dict 和 spell
    • dict/count 和 spell/count 指向同一个文件
    • dict/w 和 spell/words 指向同一个子目录（里面有 list、rade、w7）
    • dict/all 也指向该子目录中 list 的同一个文件

带来的问题：

  1. 别名问题（aliasing）：同一个文件有两个不同的名字，遍历或统计时可能重复处理
  2. 悬空指针（dangling pointer）：如果 dict 删除了 w/list，其他指向它的指针就悬空了

解决方法：

方法 说明
反向指针（Backpointers） 记录所有指向该文件的指针，删除时一并删掉；但变长记录不好处理，可以用菊花链（daisy chain）组织反向指针
引用计数（Entry-hold-count） 记录有多少个目录项指向该文件，计数为 0 时才真正删除

新的目录项类型：链接（Link）

  • 链接就是现有文件的另一个名字（一个指针）
  • 解析链接（resolve the link）：沿着指针找到实际的文件

8. 通用图目录（General Graph Directory）

  • 允许目录之间形成环
  • 图示：root 下有 avi、tc、jim
    • avi/book 指向一个子目录（含 avi、count），而这个子目录中的 avi 又指回 avi/book 所在的目录，形成了环
    • jim/book 也指向同一个子目录

存在环会带来的问题：遍历时可能陷入死循环；引用计数可能永远不为 0，导致无法回收空间。

如何保证没有环：

  1. 只允许链接到文件，不允许链接到子目录
  2. 垃圾回收（Garbage collection）：遍历整个文件系统，标记所有可访问的对象，回收没被标记的
  3. 每次添加新链接时运行环检测算法，判断是否允许添加

9. 当前目录（Current Directory）

  • 可以把某个目录指定为

    当前（工作）目录

    • 例：cd /spell/mail/prog 切换目录
    • 例：type list 直接访问当前目录下的 list 文件

  • 创建和删除文件都在当前目录中进行

  • 示例：当前目录是 /mail 时，执行 mkdir <dir-name>，会在 mail 下新建一个子目录。图中 mail 下的子项为 prog、copy、prt、exp、count

  • ⚠️ 删除 “mail” 意味着删除以 mail 为根的整棵子树

📊 五种目录结构对比

结构 允许重名 分组 共享 主要问题
单级 ❌ ❌ — 命名冲突、无法分组
两级 ✅（不同用户之间） ❌ ❌ 无法分组
树形 ✅ ✅ ❌ 无法共享
无环图 ✅ ✅ ✅ 别名、悬空指针
通用图 ✅ ✅ ✅ 环导致遍历死循环、回收困难

七、保护（Protection）

1. 基本要求

文件的拥有者或创建者应该能控制：

  • 能做什么
  • 由谁来做

访问类型：读（Read）、写（Write）、执行（Execute）、追加（Append）、删除（Delete）、列目录（List）

2. Unix 中的访问列表和用户组

访问模式：读（r）、写（w）、执行（x）

三类用户，每类用 3 位二进制 RWX 表示：

用户类别 数值 RWX 含义
a) 拥有者 owner 7 1 1 1 读、写、执行
b) 用户组 group 6 1 1 0 读、写
c) 其他人 public 1 0 0 1 仅执行

使用步骤：

  1. 请管理员创建一个组（名字唯一），比如 G，并把一些用户加进去
  2. 为文件（如 game）或子目录设置合适的权限：

三位数字依次对应 owner、group、public

  1. 把组关联到文件：

💡 换算技巧：r = 4，w = 2，x = 1，相加即可。例如 rw- = 4+2 = 6，r-x = 4+1 = 5。

3. UNIX 目录列表示例

权限字符串的读法：第 1 位是类型（d 表示目录，- 表示普通文件），后面 9 位每 3 位一组，依次是 owner、group、others。

权限 所属组 名称 解读
-rw-rw-r-- staff intro.ps 文件；拥有者和组可读写，其他人只读（664）
drwx------ staff private/ 目录；只有拥有者能访问（700）
drwxrwxr-x staff doc/ 目录；拥有者和组完全权限，其他人可读和进入（775）
drwxrwx--- student student-proj/ 目录；拥有者和 student 组完全权限，其他人无权限（770）
-rw-r--r-- staff program.c 源文件；拥有者读写，其他人只读（644）
-rwxr-xr-x staff program 可执行文件；所有人可执行，只有拥有者能修改（755）
drwx--x--x faculty lib/ 目录；其他人只能进入，不能列出内容（711）
drwx------ staff mail/ 目录；私有（700）
drwxrwxrwx staff test/ 目录；所有人完全权限（777）

其他列依次为：链接数、拥有者（pbg）、所属组、大小（字节）、修改日期。

4. Windows 7 的访问控制列表（ACL）管理

  • 在文件属性的"安全"（Security）选项卡中管理，示例文件为 ListPanel.java
  • 用户和组列表包括：SYSTEM、Gregory G. Gagne、Guest、FileAdmins、Administrators
  • 可以为每个用户或组分别设置权限，每项都有"允许"和"拒绝"两列
  • 权限类型：完全控制、修改、读取和执行、读取、写入、特殊权限
  • 图示中，Guest 的所有权限都被设为拒绝
  • 点"高级"可以设置特殊权限和更细的选项

📊 Unix 与 Windows 保护机制对比

方面 Unix Windows
方式 拥有者、组、其他人三类 + rwx 位 访问控制列表（ACL）
粒度 较粗，只分三类用户 较细，可针对任意用户或组
设置方式 chmod、chgrp 命令 图形界面（属性 → 安全）
拒绝规则 没有显式的"拒绝" 有显式的"拒绝"，可覆盖允许

八、复习要点速记

  1. 分区与磁盘不必一一对应：一盘多区或一区多盘都可以；包含文件系统的实体叫卷
  2. 目录组织的三个目标：效率、命名、分组
  3. 单级 → 两级 → 树形 → 无环图 → 通用图，依次解决：命名冲突 → 分组 → 共享
  4. 无环图的问题是别名和悬空指针，解决方法是反向指针或引用计数
  5. 通用图防环：只链接文件、垃圾回收、添加链接时检测环
  6. 删除一个目录会删除整棵子树
  7. Unix 权限：owner / group / public，r=4、w=2、x=1，例如 chmod 761
  8. Windows 用 ACL，可以对每个用户分别设置允许或拒绝
