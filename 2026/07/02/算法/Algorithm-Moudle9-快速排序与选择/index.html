快速排序与选择

9.1 快速排序与选择导论

9.1.1 引入场景：成绩直方图

  • 课程管理系统（如 zyBooks）需要对学生成绩做统计：平均分、最小值、最大值等。

  • 一个典型计算是

    分桶 / 直方图统计（bucketing / histogramming）：

    • n 名学生，每人一个整数分数，取值在某个范围内（如 0–100）。
    • 按分数排序后，即可统计每个分数出现的人数，画出直方图。
    • 教师据此确定各等级（A/B/C…）的分数线。

  • 图 9.1.1 就是一个算法课总分的直方图示例（横轴为分数区间，纵轴为人数，峰值出现在 80 附近，25 人）。

9.1.2核心观察：这是一类"特殊"的排序问题

  • 直方图统计本质上是排序问题，但不是最一般的排序：
    • 排序的 键是给定范围内的整数，而非任意可比较对象。
  • 已知结论（第 8.4 节）：基于比较的排序有 Ω(n log n) 的下界。
  • 关键问题：能否利用"键是小范围整数"这一额外信息，突破比较排序的下界？
  • 答案：可以。当键是整数且范围较小时，可在 O(n) 时间完成排序（本章将介绍的桶排序 / 基数排序等非比较排序）。

9.1.3 第二个主题：选择（Selection）与中位数

  • 中位数定义：n 个分数中的某个值，使得比它大的元素至多 n/2 个，比它小的元素也至多 n/2 个。
  • 朴素做法：先排序再取中间元素 → O(n log n)。
  • 更好的目标：不排序，直接在 O(n) 时间找到中位数。
  • 本章结论：即使元素只有一个"两两比较"的规则（定义了全序），也能在 O(n) 时间内找到第 k 小的元素（对任意 k）。
    • 取 k = n/2 即得中位数 → 中位数可 O(n) 求出。

9.1.4 要点速记

问题 前提条件 可达时间复杂度
一般比较排序 只能两两比较 Θ(n log n)（下界）
整数键排序（直方图/分桶） 键为小范围整数 O(n)
选择第 k 小 / 中位数 仅需全序比较规则 O(n)

9.2 桶排序与基数排序

9.2.1 背景：为什么能突破 Ω(n log n)

  • 基于比较的排序，最坏情况下必须 Ω(n log n)。
  • 若对输入做特殊假设（如键是有限范围内的整数），就可以不用比较，从而做到更快。
  • 本节讨论的对象：键-元素对（key-element pair） 组成的序列。

9.2.2 桶排序（Bucket-sort）

前提假设

序列 S 有 n 个元素，键为整数且落在 [0, N−1]（N ≥ 2）。

核心思想

不做比较，而是把键直接当作数组下标：

  • 建立桶数组 B[0..N−1]，每个 B[k] 是一个链表；
  • 键为 k 的元素放进 B[k]；
  • 最后按 B[0], B[1], …, B[N−1] 的顺序依次取出，即为有序序列。

伪代码（Algorithm 9.2.1）

复杂度

项目 结果
第一个循环 O(n)
第二个循环 O(n + N)（要遍历所有 N 个桶）
总时间 O(n + N)
空间 O(n + N)（S 占 O(n)，B 占 N）

适用条件：N 相对 n 较小时高效，例如 N = O(n) 或 N = O(n log n) → 此时可达 O(n)。N 相对 n 越大，性能越差。

注意：桶排序天然支持重复键（同键元素都进同一个桶的链表）。

9.2.3 稳定性（Stability）

定义

对序列 S = ((k₀,e₀), …, (kₙ₋₁,eₙ₋₁))，若任意两项满足 kᵢ = kⱼ 且 (kᵢ,eᵢ) 在排序前排在 (kⱼ,eⱼ) 之前（i < j），排序后仍保持这个先后关系，则该排序算法是稳定的。

意义：许多应用需要保留相同键元素的原始相对顺序。

让桶排序稳定

上面的"非正式"伪代码不保证稳定，但稳定性并非方法本身的缺陷 —— 只要在执行时始终从 S 和每个 B[i] 的头部（第一个元素）取出，就能得到稳定版本，且仍保持 O(n + N) 时间。

9.2.4 基数排序（Radix-sort）

字典序（lexicographical order）

键为二元组 (k, l)，k、l ∈ [0, N−1]。定义 (k₁,l₁) < (k₂,l₂) 当且仅当：

  • k₁ < k₂，或
  • k₁ = k₂ 且 l₁ < l₂。

（可自然推广到 d 元组。）

算法

对序列做两次稳定桶排序，一次按一个分量。关键问题：先排哪个分量？

例 9.2.1 的结论

以 S = ((3,3),(1,5),(2,5),(1,2),(2,3),(1,7),(3,2),(2,2)) 为例：

  • 先按第一分量、再按第二分量 → 结果不是字典序（被后一次排序打乱了第一分量的顺序）。
  • 先按第二分量、再按第一分量 → 结果 正是字典序：
    ((1,2),(1,5),(1,7),(2,2),(2,3),(2,5),(3,2),(3,3))

为什么正确（直觉）

第二遍按第一分量排序时，第一分量相同的元素因为算法稳定，会保持它们在上一遍（按第二分量已排好）中的相对顺序 → 恰好就是字典序要求的次序。

口诀：从最次要（最低位）的分量开始排，逐步排到最重要（最高位）的分量。

定理 9.2.1

设 S 含 n 个键-元素对，键为 d 元组 (k₁, …, k_d)，每个 kᵢ ∈ [0, N−1]（N ≥ 2）。
则基数排序可在 O(d(n + N)) 时间内把 S 按字典序排好。

9.3 选择问题（Selection）

9.3.1 问题定义

  • 顺序统计量（order statistics）：按元素在全序中的**秩（rank）**来查询元素，如最小、最大、中位数。
  • 选择问题：在 n 个无序、可比较的元素中，找第 k 小的元素（k ∈ [1, n]）。
  • 平凡解法：先排序再取下标 k−1 → O(n log n)。
  • 核心问题：能否对任意 k（包括中位数 k = ⌈n/2⌉）做到 O(n)？→ 答案是可以。

9.3.2 prune-and-search（剪枝—搜索）

通用技术思路：

  1. 每轮剪掉输入中**一部分（一个常数比例）**的元素；
  2. 对剩下的更小规模子问题递归求解；
  3. 规模缩到常数时用暴力法解决；
  4. 有时可以写成迭代形式（无需递归），反复剪枝直到能暴力求解。

9.3.3 随机化快速选择（Randomized quick-select）

算法 9.3.1

要点：

  • 结构类似随机化快速排序，但只递归一个子序列（不是两个）→ 递归树退化成一条路径。
  • 注意 G 分支的新参数 k′ = k − |L| − |E|。
  • 复杂度：期望 O(n)（与输入分布假设无关，只依赖算法自身的随机性）；最坏 O(n²)。

期望时间分析（关键推理链）

  1. 工具：期望的线性性 E(X+Y) = E(X) + E(Y)，E(cX) = cE(X)。
  2. 定义"好枢轴"：划分后 |L|、|G| 均 ≤ 3n/4；否则为"坏枢轴"。
    • 位于中间一半位置的枢轴即为好枢轴 → P(好) = 1/2。
  3. 设 g(n) = 连续调用多少次（含当前）才碰到一次好调用。 t(n) ≤ b·n·g(n) + t(3n/4)
  4. g(n) 相当于"抛硬币直到出现正面"的次数 → E(g(n)) = 2。
  5. 令 T(n) = E(t(n))： T(n) ≤ T(3n/4) + 2bn
  6. 迭代展开： T(n) ≤ 2bn · Σ_{i=0}^{⌈log_{4/3} n⌉} (3/4)^i 这是公比 < 1 的几何级数，其和为常数 → T(n) = O(n)。

定理 9.3.1：随机化 quick-select 的期望运行时间为 O(n)。

9.3.4 确定性选择（Deterministic selection / 中位数的中位数）

核心思想

改变选枢轴的方式，使其确定性地"足够居中"：

  1. 把 S 分成 ⌈n/5⌉ 组，每组 5 个（最后一组可能不足）；
  2. 每组排序，取出各组中位数（baby median）；
  3. 对这 ⌈n/5⌉ 个 baby medians 递归调用本算法，求它们的中位数；
  4. 用这个"中位数的中位数"作枢轴，其余同 quick-select。

算法 9.3.2（结构）

分析

两次递归调用：

递归 规模
① baby medians g = ⌈n/5⌉
② L 或 G ≤ 7n/10 + 2

为什么第二次递归规模 ≤ 7n/10 + 2？

  • x 是 g 个 baby medians 的中位数 → 有 ⌈g/2⌉ 组，其组内至少一半元素 ≤ x。
  • 每个这样的（满 5 个的）组贡献至少 3 个 ≤ x 的元素；扣掉可能不满的 S_g： 3(⌈g/2⌉ − 1) + 1 = 3⌈(1/2)·⌈n/5⌉⌉ − 2 ≥ 3n/10 − 2
  • 对称地，≥ x 的元素数量也至少这么多。
  • 因此被剪掉的至少 3n/10 − 2 个，剩下 ≤ n − (3n/10 − 2) = 7n/10 + 2。

递推式：

T(n) ≤ T(n/5 + 1) + T(7n/10 + 2) + bn

代入法求解（猜 T(n) ≤ cn）：

T(n) ≤ cn/5 + c + 7cn/10 + 2c + bn = 9cn/10 + bn + 3c

取 c = 11b：T(n) ≤ 9cn/10 + cn/11 + 3c，只要
cn/11 + 3c ≤ cn/10，即 n ≥ 330，就有 T(n) ≤ cn。

定理 9.3.2：确定性选择算法运行时间为 O(n)（最坏情况）。

9.3.5 对比与实践结论

随机化 quick-select 确定性选择
枢轴 随机 中位数的中位数
递归调用数 1 2
时间 期望 O(n)，最坏 O(n²) 最坏 O(n)
常数因子 小 很大（c = 11b 级别）

实践建议：确定性算法的常数太大，实际中通常用随机化 quick-select 更高效；确定性版本的价值在于理论上保证最坏情况也能达到 O(n)。

9.3.6易错点提醒

  • k 的更新：递归到 G 时必须用 k − |L| − |E|，直接传 k 是常见 bug。
  • 三路划分 (L, E, G) 而非两路，是为了正确处理重复元素（否则重复元素多时可能死循环）。
  • 分组大小取 5 是关键：取 3 会使 T(n) ≤ T(n/3) + T(2n/3) + bn，两项系数和 = 1，无法得到线性时间。
  • 截图（Analysis of deterministic selection）中"the above value is also a lower bound on the number of elements of S less than or equal to x"应为 greater than or equal to（原文疑似笔误），对称论证给出的是 ≥ x 的元素数下界。

9.4 加权中位数（Weighted Medians）

9.4.1 问题背景（直观理解）

一群人要过河，每人有年龄（互不相同、可公开）和体重（不愿公开）。船一次只能承载约总重量 W 的一半。于是我们希望宣布一个年龄阈值 x：比 x 年轻的先上船，其余的坐第二班。

要求：

  • 年龄小于 x 的人总重量 ≤ W/2
  • 年龄大于 x 的人总重量 ≤ W/2

即：按"值"（年龄）排序，但按"权重"（体重）来切分。

9.4.2 形式化定义

给定集合 X = {x₁, …, xₙ}，n 个互异元素，来自某个全序集；每个 xᵢ 有正权重 wᵢ，总权重

​ W=∑i=1nwi

求元素 x_m ∈ X 满足：

​ $$\sum_{x_i < x_m} w_i \le \frac{W}{2}
\qquad\text{且}\qquad
\sum_{x_i > x_m} w_i \le \frac{W}{2}$$

注意点

  • 两个和式都不包含 x_m 自身的权重 w_m。
  • 等价刻画（关键！）：最小的满足下式的 x_m 就是一个加权中位数：

​ ∑xi≤xmwi>W2

也就是"按值升序做权重前缀和，第一次超过 W/2 的那个元素"。

  • 若所有 wᵢ 相等，则退化为普通中位数。

9.4.3 解法一：基于排序 —— O(n log n)

思路：按值（不是按权重）排序，从头扫描并累加权重，一旦累计和超过 W/2 就返回当前元素。

text

  • 正确性：直接来自上面的"最小前缀和 > W/2"的刻画，扫描过程正是逐步构建"小于加权中位数的元素集合"。
  • 复杂度：扫描是 O(n)，瓶颈在排序，总计 O(n log n)（因为只假设元素来自全序集，只能比较排序）。

9.4.4 解法二：剪枝-搜索（Prune-and-Search）—— O(n)

核心思想（类似二分查找）：用线性时间选择算法（DeterministicSelect，9.3.2）找到不考虑权重的中位数 y，然后判断 y 相对于加权中位数是偏大还是偏小，丢掉一半元素后递归。

设

  • w₁ = 严格小于 y 的元素权重和
  • w₂ = 小于等于 y 的元素权重和（= w₁ + w_y）

判断规则（阈值参数记为 W，初始调用传入总权重的一半 W/2）：

情况 含义 递归做法
w₁ > W y 太大 在"小于 y 的元素"上递归，阈值仍为 W
w₂ < W y 太小 在"大于 y 的元素"上递归，阈值改为 W − w₂
否则 y 就是答案 return y

两个易错点

  1. 向右递归时阈值要减去 w₂：被丢掉的那部分权重不会再出现在新集合里，必须从"目标重量"中扣除，否则阈值失去意义。向左递归时被丢掉的是右侧元素，不影响前缀和，故 W 不变。
  2. 每轮只需 O(n)：选择是 O(n)，算 w₁、w₂ 也只是一次扫描。

9.4.5 复杂度分析

递推式（n = 1 时为常数）：

​ T(n)≤T(⌈n/2⌉)+bn,b>0

定理 9.4.1：加权中位数问题可在 O(n) 时间内解决。

归纳证明 T(n) ≤ cn：n < 4 时取 c 足够大；n ≥ 4 时

​ T(n)≤T(⌈n/2⌉)+bn≤T(n/2+1)+bn≤cn/2+c+bn≤cn

只要取 c ≥ 4b（此时 bn ≤ cn/4，且由 n ≥ 4 得 c ≤ cn/4）。

9.4.6 对比小结

方法 关键工具 时间
排序 + 前缀和扫描 比较排序 O(n log n)
剪枝-搜索 线性时间选择 + 递归剪半 O(n)

一句话记忆：加权中位数 = “权重前缀和首次越过 W/2 的元素”；把二分查找的思路套在线性时间选择上，就能从 O(n log n) 降到 O(n)。
