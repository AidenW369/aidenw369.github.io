并归排序和快速排序

8.1 归并排序与快速排序简介

8.1.1 排序问题（Sorting Problem）

  • 定义：给定 n 个可比较（comparable）的元素，把它们按顺序排列。
  • 高效排序算法应用广泛，其中一个典型场景就是搜索引擎的底层技术。

8.1.2 应用背景：倒排文件（Inverted File）

1. 什么是倒排文件

  • 一张查找表（lookup table），把「词」映射到「包含该词的文档」。
  • 索引项 = 关键词；每个关键词对应一个文档列表。
  • 作用：用户查某个关键词时，直接查表即可迅速返回相关文档。

2. 原始数据形态

  • 爬虫抓到的只是一堆文档，并不是现成的查找表。

  • 第一步：扫描每篇文档 d，对其中出现的每个关键词 k 输出一个

    键值对 (k, d)。

    • k = 关键词，d = 文档标识符
    • 这一步很容易，只需顺序扫描文档内容。

3. 从 (k, d) 对到倒排文件 —— 排序登场

  • 目标：把同一关键词 k 的所有文档聚集到一起。
  • 方法：以关键词为键，对所有 (k, d) 对排序
    • 排序后，相同 k 的键值对自然相邻。
    • 再顺序扫描一遍这个有序列表，即可直接构建出每个关键词的文档列表。

4. 实际工程中的改进：字典序（lexicographic）排序

  • 主键：关键词 k
  • 次键：文档 d 的相关性 / 排名分数（relevance / ranking score）
  • 效果：同一关键词下的文档在排序结果中已经按分数高低排好，直接可用于返回排名结果。
  • 结论：快速的排序算法对搜索引擎至关重要，尤其是面对超大规模输入数据时。

8.1.3 本章的两个排序算法

算法 适用场景
归并排序 Merge-sort 极大规模数据集；数据存放在硬盘或网络存储上时特别合适
快速排序 Quick-sort 中等偏大、能**装入内存（RAM）**的数据集，效率很高

8.1.4 配图说明

  • 章节配图为 G. Sundback 的「可分离式扣件」美国专利图（专利号 1,219,881，1917 年），即拉链的专利图（公有领域图片）。
  • 寓意：拉链把两排齿交错合并成一条 —— 正好对应归并排序中 merge（归并） 两个有序序列的过程，是很形象的比喻。

8.2 归并排序

8.2.1 分治范式（Divide-and-Conquer）

三个步骤：

  1. Divide（分）：若输入规模小于某个阈值（如 10 个元素），直接用简单方法求解并返回；否则把输入划分成两个或多个互不相交的子集。
  2. Recur（治/递归）：对各子集对应的子问题递归求解。
  3. Conquer（合）：把各子问题的解"合并"成原问题的解。

对应到示意图：顶部 Split list equally → 两棵子树 S₁、S₂ 递归 → 底部 Merge 汇合。

8.2.2 归并排序的三步

设输入序列 S 有 n 个元素（可用数组或链表表示）：

步骤 内容
Divide 若 n ≤ 1，S 已有序，直接返回。否则拆成 S₁（前 ⌈n/2⌉ 个）和 S₂（后 ⌊n/2⌋ 个）
Recur 递归排序 S₁ 和 S₂
Conquer 把有序的 S₁、S₂ 归并成一个有序序列放回 S

归并排序树 T：

  • 每个节点 = 一次递归调用，节点 v 关联它处理的那段序列
  • v 的两个孩子 = 处理 S₁、S₂ 的递归调用
  • 外部节点（叶子）= 单个元素，不再递归

8.2.3 merge 算法（数组版，下标从 1 开始）

输入：有序数组 S₁（长 n₁）、S₂（长 n₂），空数组 S（容量 ≥ n₁+n₂）
输出：S 为 S₁、S₂ 元素的有序合并

要点

  • 核心思想：反复从两个数组的当前最小元素中取较小者，追加到输出数组末尾；一方耗尽后把另一方剩余全部拷过去。
  • 下标技巧：i+j-1 正好是已输出元素个数 +1，即 S 的下一个写入位置。
  • ≤ 保证稳定性（相等时优先取 S₁ 的元素）。

优点/代价

  • 三个 while 都是对输入数组的顺序扫描，对磁盘等外部存储的顺序访问非常友好，适合大数据集。
  • 代价：必须使用额外的输出数组 S，不能原地复用输入空间。

链表版：思路相同——比较两个链表的表头，摘下较小的接到输出链表尾部；一方为空则把另一方剩余整段接上（图 8.2.2 的 (a)~(i) 展示了 S₁=24,45,63,85 与 S₂=17,31,50,96 逐步合并为 17,24,31,45,50,63,85,96 的过程）。

8.2.4 复杂度分析

1. merge 的时间

  • 三个 while 循环，循环体内操作均为 O(1)。
  • 关键观察：每次迭代恰好向 S 输出一个元素，且该元素不再被考虑。
  • 因此总迭代次数 = n₁ + n₂。

定理 8.2.1：归并两个有序数组 S₁、S₂ 需 O(n₁ + n₂) 时间。

2. 归并排序树的分析（设 n 为 2 的幂）

  • 高度：深度为 i 的节点存储长度 n/2ⁱ 的子序列；当 i = log n 时子序列长度为 1（叶子）。故树高为 log n。
  • 节点耗时：“在节点 v 处花的时间” = divide + conquer 的时间（不含递归调用等待时间）。divide 与 merge 都是线性的，故深度 i 的节点耗时 O(n/2ⁱ)。
  • 每层耗时：深度 i 恰有 2ⁱ 个节点 ⇒ 该层总时间 O(2ⁱ · n/2ⁱ) = O(n)。
  • 总时间：共 log n + 1 层，每层 O(n) ⇒ O(n log n)。

定理 8.2.2：对 n 个元素做归并排序的运行时间为 O(n log n)。

定理 8.2.3（n 不是 2 的幂时）：归并排序树的高度为 ⌈log n⌉。（证明留作练习 8.5.1；一般情形的完整分析见练习 8.5.2）

8.2.5 递推方程（另一种证明）

设 t(n) 为规模 n 的最坏情况运行时间：

​ t(n)={bn=1 或 n=0t(⌈n/2⌉)+t(⌊n/2⌋)+cn否则(b,c>0)

这种"函数出现在等号两边"的刻画称为递推方程（recurrence equation）；我们真正想要的是不含 t 自身的**闭式（closed-form）**表达。

设 n 是 2 的幂，简化为：t(n) = b（n=1）；t(n) = 2t(n/2) + cn（否则）。

反复展开：

  • t(n) = 2(2t(n/2²) + cn/2) + cn = 2²t(n/2²) + 2cn
  • t(n) = 2³t(n/2³) + 3cn
  • t(n) = 2⁴t(n/2⁴) + 4cn
  • 归纳出通式：t(n) = 2ⁱ·t(n/2ⁱ) + i·cn

何时停止：当 n/2ⁱ = 1，即 2ⁱ = n，即 i = log n。代入：

​ t(n)=2log⁡nt(1)+(log⁡n)cn=n⋅b+cnlog⁡n

⇒ t(n) 是 O(n log n)，与树形分析结论一致。

8.2.6 自底向上（非递归）归并排序

  • 不用递归，而是逐层向上执行归并：
    1. 先把相邻元素两两归并成长度 2 的有序段（run）；
    2. 再把长度 2 的段两两归并成长度 4；
    3. 再合成长度 8……直到整个数组有序。
  • 时间仍是 O(n log n)，但实践中略快：省去了递归调用开销和每层临时内存的开销。
  • 空间处理：使用第二个数组存放归并结果，每轮迭代后交换输入/输出数组的角色（"乒乓"式），使空间开销保持合理。

8.3 快速排序

8.3.1 算法思想：分治法

对序列 S 排序，分三步：

步骤 内容
1. Divide（分） 若 S 至少有 2 个元素，选一个枢轴（pivot） x（常规做法：取 S 的最后一个元素）。把 S 的元素全部取出，分成三个子序列： • L：所有 <<x 的元素 • E：所有 =x 的元素 • G：所有 >x 的元素 （若元素互不相同，E 中只有枢轴一个元素）
2. Recur（治） 递归排序 L 和 G（E 无需排序）
3. Conquer（合） 按 L→E→G 的顺序简单拼接回 S

💡 与归并排序对比：快排的"重活"在**划分（divide）**阶段，合并只是拼接；归并排序恰好相反。
递归过程可用二叉递归树表示，称为 quick-sort tree。

8.3.2 运行时间分析

1. 分析框架

  • 每个节点 v 的时间正比于其输入规模 s(v)（divide 与 conquer 都是线性时间）。
  • 因为 E 至少含 1 个元素（枢轴），所以 v 的子节点输入规模之和 ≤s(v)−1——枢轴不再向下传递。
  • 记 si = 深度 i 处所有节点的输入规模之和：
    • s0=n
    • s1≤n−1
    • s2≤n−2
    • 一般地：$\boxed{s_i \le n - i} $

2. 最坏情况： O(n2)

树高最坏为 n−1。

  • 触发条件：n 个互异元素且序列已排好序 → 取最后一个（最大）元素作枢轴 → ∣L∣=n−1, ∣E∣=1, ∣G∣=0，每层只减少一个元素。
  • 总时间：
    O(∑i=0n−1si)=O(∑i=0n−1(n−i))=O(∑i=1ni)=O(n2)
  • ⚠️ 悖论：排序"最该轻松"的输入（已有序）反而是最坏情况。

3. 最好情况： O(nlog⁡n)

  • 当 L 与 G 每次大小大致相等时达到。
  • 每层"省掉"的枢轴数：根 1 个、第 1 层 2 个、第 2 层 22 个……
    si=n−(1+2+22+⋯+2i−1)=n−(2i−1)
  • 树高 O(log⁡n) → 总时间 O(nlog⁡n) 。

4. 平均情况

直觉：枢轴大概率把序列分得比较均匀 → 平均时间接近最好情况 O(nlog⁡n) 。

8.2.3 随机化快速排序（Randomized Quick-Sort）

动机

若"假设枢轴总能均分序列"，等于预设了输入分布（实际中"近乎有序"的输入很常见）。解决办法：不假设输入，而是随机化算法本身。

新规则

枢轴 = 从输入序列中随机均匀选取的元素。

Theorem 8.3.1

随机化快排在规模为 nn n 的序列上的期望运行时间为 O(nlog⁡n) 。

证明要点：

  1. 概率事实：公平硬币期望投掷 2k 次才能出现 k 次正面。
  2. 定义"好"调用：设本次调用输入规模为 m，若枢轴使 ∣L∣,∣G∣ 都落在 [m/4, 3m/4]，称这次调用是"好"的。
  3. 有 m/2 个枢轴候选能让调用变"好" → 好调用的概率 = 1/2（等价于抛硬币出正面）。
  4. 一次好调用使子问题规模 $\le \tfrac{3}{4}s(v) = s(v)/(4/3) $ → 只需 log4/3⁡n 次好调用即可到达叶子。
  5. 由概率事实，期望需 2log4/3⁡n 次调用 → 根到外部节点的期望路径长 = O(log⁡n) 。
  6. 每层时间 O(n) ⟹ 期望总时间 O(nlog⁡n) 。

注意：这里的期望是对算法自身的随机选择取的，与输入分布无关。进一步还可证明其运行时间以高概率为 O(nlog⁡n) 。

8.2.4 原地快速排序（In-Place Quick-Sort）

定义

in-place：除待排序对象本身外，只使用少量额外内存。（归并排序难以做到；快排和堆排序可以。）

实现要点

  • 不显式创建 L, E, G，而是通过元素交换修改原数组。
  • 子序列用下标区间 [a,b] 隐式表示。
  • 划分：两个指针 l（向右扫）、r（向左扫），交换逆序的元素对；两指针交错时划分完成，然后对两个子区间递归。
  • 没有显式的 combine 步骤——拼接是隐含的。

8.4 比较排序的下界

8.4.1 问题背景

  • 已学的 merge-sort、quick-sort、heap-sort，最坏或期望时间均为 O(n log n)。
  • 自然的疑问：能否比 O(n log n) 更快？
  • 结论：只要算法的基本操作是"两元素比较"，就不可能更快——比较排序的最坏情况下界是 Ω(n log n)。

8.4.2 模型：决策树（decision tree）

设待排序列 S = (x₁, …, xₙ)，不妨假设元素互异（求下界，这不算限制）。

决策树元素 含义
内部节点 v 一次比较 “xᵢ < xⱼ?”
两条出边 “yes” / “no” 两种结果
根到外部节点的路径 某个输入排列所触发的完整比较序列
树高 最坏情况下的比较次数（≈ 最坏运行时间）

要点：

  • 只统计比较次数，忽略内部计算，这对求下界已足够。
  • 算法本身并不"知道"这棵树；树只是用来刻画所有可能的比较序列。

8.4.3 关键观察：每个外部节点最多对应一个排列

反证思路：

  1. 若两个不同排列 P₁、P₂ 落在同一外部节点，则存在一对元素 xᵢ、xⱼ，它们在 P₁ 与 P₂ 中的先后顺序相反。
  2. 该外部节点的输出是固定的一种排列，xᵢ、xⱼ 只能有一种先后。
  3. 于是 P₁、P₂ 中必有一个被输出成错误顺序 → 与"算法正确"矛盾。

∴ 每个外部节点恰好对应一个排列；不同排列必须落到不同外部节点。

8.4.4 定理 8.4.1 及证明

定理：任何比较排序算法对 n 个元素排序，最坏情况运行时间为 Ω(n log n)。

证明链条：

  1. 运行时间 ≥ 决策树高度 h。
  2. n 个元素共有 n! 个排列，每个排列对应一个不同的外部节点 → 树至少有 n! 个外部节点。
  3. 二叉树若有 n! 个外部节点，则高度至少 log(n!)（定理 2.4.2）。
  4. 放缩 n!：在 n·(n−1)···2·1 中，至少有 n/2 个因子 ≥ n/2，故

​ log⁡(n!)≥log((n2)n/2)=n2log⁡n2

  1. 而 (n/2)·log(n/2) = Ω(n log n)。

8.4.5 边界与延伸

  • 该下界只对基于比较的算法成立。
  • 第 9.1 节将给出非比较型排序（如桶排序/基数排序），在特定场景下可达到 o(n log n)。
