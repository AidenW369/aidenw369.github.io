操作系统导论

一、操作系统是什么

定义困境：操作系统没有公认的严格定义。两种常见说法：

说法 含义
“厂商发货时打包的所有东西” 近似描述，但各系统差异极大
“始终运行在计算机上的那一个程序” 指内核（kernel）

除内核外的软件分为两类：

  • 系统程序：随 OS 一起发布，但不属于内核
  • 应用程序：与 OS 无关的所有程序
  • 中间件（middleware）：现代通用/移动 OS 还包含的一层软件框架，为开发者提供数据库、多媒体、图形等附加服务

本质角色：OS 是用户与硬件之间的中介。三大目标：

  1. 执行用户程序、方便用户解决问题
  2. 让系统易于使用
  3. 高效利用硬件资源

二、计算机系统的四层结构（对应"抽象视图"图）

  • 硬件：提供基本计算资源
  • 操作系统：在各应用与用户之间协调、控制硬件的使用
  • 应用程序：定义如何用系统资源解决具体问题
  • 用户：不只是人，也可以是机器或其他计算机

注意图中箭头都是双向的，且应用程序与 OS 之间有多条通路——多个程序并发地向 OS 请求服务。

三、"OS 做什么"取决于立场

场景 关注点
普通用户 方便、易用、性能好；不关心资源利用率
共享主机（大型机/小型机） 必须让所有用户都满意 → OS 是资源分配器 + 控制程序
工作站等专用系统 有专属资源，但常使用服务器的共享资源
移动设备（手机、平板） 资源匮乏，为可用性与续航优化；触屏、语音等交互方式
嵌入式（汽车、家电） 几乎无用户界面，基本无人干预运行

历史来由：当军用的固定用途计算机转向通用用途后，产生了资源管理和程序控制的需求，OS 由此诞生。如今从烤面包机到航天器、游戏机、工业控制系统都有 OS。

四、计算机系统组成（硬件层）

对应"Computer System Organization"图：

  • 一个或多个 CPU 与各类设备控制器（磁盘控制器、USB 控制器、图形适配器…）通过公共的**系统总线（bus）*相连，共享访问*内存
  • CPU 与设备并发执行，彼此竞争内存周期

设备控制器要点：

  • 每个控制器负责一类特定设备，并拥有本地缓冲区（local buffer）
  • 每类控制器都有对应的 OS 设备驱动程序来管理
  • 数据流向：I/O 设备 ↔ 控制器本地缓冲区 ↔（由 CPU 搬运）↔ 主存
  • 控制器完成操作后，通过产生中断通知 CPU

五、中断（Interrupt）★ 核心机制

操作系统是中断驱动（interrupt-driven）的。

1. 基本流程

  • 中断通过**中断向量（interrupt vector）*把控制权转交给*中断服务例程；中断向量表中存放着所有服务例程的地址
  • 中断体系结构必须保存被中断指令的地址，以便返回

2. 中断处理时 OS 做的事

  • 保存 CPU 状态：保存寄存器和程序计数器（PC）
  • 判定发生了哪种类型的中断
  • 由各自独立的代码段决定该类型中断应采取的动作

3. 陷阱 / 异常（trap / exception）

软件产生的中断，来源有两类：

  • 程序错误（如除零、非法访问）
  • 用户主动请求（如系统调用）

4. 中断驱动 I/O 周期（7 步，对应流程图）

步 动作
1 设备驱动程序发起 I/O
2 请求送到 I/O 控制器
3 控制器启动 I/O 操作
4 输入就绪 / 输出完成 / 出错 → 产生中断信号
5 CPU（在指令之间检查中断）接收中断，把控制转给中断处理程序
6 中断处理程序处理数据，然后从中断返回
7 CPU 恢复执行被中断的任务

关键细节：CPU 是在每条指令执行完之后、下一条指令开始前检查有无中断。

5. 中断时间线

从时间线图可读出：CPU 大部分时间跑用户程序，I/O 设备并行地传输数据；只有在"传输完成 → 中断发出 → 中断处理"这一小段，CPU 才短暂切去做 I/O 中断处理，随后回到用户程序。这直观体现了CPU 与 I/O 的并发。

六、I/O 结构：两种处理方式

同步（阻塞） 异步（非阻塞）
控制返回时机 I/O 完成后才返回用户程序 立即返回，不等待完成
实现 wait 指令让 CPU 空转直到下次中断；或用 wait 循环（会争用内存访问） 通过系统调用请求 OS，让用户在需要时再等待 I/O 完成
并发度 同一时刻最多一个 I/O 请求未完成，无法并行 I/O 可同时处理多个 I/O 请求
所需数据结构 — 设备状态表：每个设备一个表项，记录类型、地址、状态；OS 通过索引该表查询设备状态、并修改表项以关联中断

七、系统启动（Computer Startup）

  1. 加电或重启时加载引导程序（bootstrap program）
  2. 它通常存放在 ROM / EPROM 中，即所谓固件（firmware）
  3. 初始化系统的各个方面（寄存器、设备控制器、内存内容等）
  4. 加载 OS 内核并启动其执行

八、本章目标回顾（自检清单）

  • 能描述计算机系统的总体组织，以及中断在其中的作用
  • 能说清现代多处理器系统的组成部件
  • 能说明用户态 → 内核态的转换过程
  • 知道 OS 在不同计算环境（服务器、移动、嵌入式、分布式）中的差异
  • 能举出自由/开源操作系统的例子（如 GNU/Linux、BSD 系列）

九、存储结构（Storage Structure）

1. 主存 vs 辅存

主存 Main Memory 辅存 Secondary Storage
CPU 能否直接访问 ✅ 唯一能被 CPU 直接访问的大容量存储 ❌ 必须先调入主存
访问方式 随机访问（random access） 视介质而定
易失性 通常易失（volatile，断电丢失） 非易失（nonvolatile）
典型实现 DRAM（动态随机访问存储器） HDD、NVM
定位 — 主存的扩展，提供大容量持久存储

💡 扩展：CPU 只能直接寻址主存和寄存器，这是"程序必须装入内存才能执行"这一根本约束的来源，也是后面内存管理、虚拟内存章节存在的理由。

2. 两类辅存介质

HDD（硬盘驱动器）

  • 刚性金属或玻璃盘片，表面覆盖磁性记录материал
  • 盘面逻辑上划分为磁道（track），磁道再细分为扇区（sector）
  • 磁盘控制器决定设备与计算机之间的逻辑交互

NVM（非易失性存储器，如 SSD/闪存）

  • 比硬盘快，且非易失
  • 技术路线多样；随着容量和性能提升、价格下降而日益普及
  • 无机械运动部件 → 无寻道时间

3. 存储单位复习

术语 定义
bit（位） 最基本单位，取值 0 或 1
byte（字节） 8 bit；多数计算机上最小的方便存储块（有移动字节的指令，但没有移动单个位的指令）
word（字） 某体系结构的本地数据单元，由一个或多个字节组成。64 位寄存器 + 64 位寻址的机器通常是 64 位（8 字节）字
  • 计算机以本地字长执行大量操作，而非一次一个字节
  • 容量换算：1 KB = 1,024 B，MB = 1024²，GB = 1024³，TB = 1024⁴，PB = 1024⁵
  • ⚠️ 两个例外：
    • 厂商常按 10 的幂取整（1 MB ≈ 100 万字节，1 GB ≈ 10 亿字节）→ 这就是"买的 1TB 硬盘只有 931GB"的原因
    • 网络速率用 bit 计量（因为网络逐位传输），如 100 Mbps ≈ 12.5 MB/s

十、存储层次结构（Storage Hierarchy）★

1. 层次金字塔（对应 Storage-Device Hierarchy 图）

三条排序原则贯穿始终：速度、成本、易失性。

2. 各级存储特性对照（重要数据感觉）

级别 1 寄存器 2 高速缓存 3 主存 4 SSD 5 磁盘
典型容量 < 1 KB < 16 MB < 64 GB < 1 TB < 10 TB
实现技术 多端口 CMOS 定制存储 片上/片外 CMOS SRAM CMOS SRAM* 闪存 磁盘
访问时间(ns) 0.25–0.5 0.5–25 80–250 25,000–50,000 5,000,000
带宽(MB/s) 20,000–100,000 5,000–10,000 1,000–5,000 500 20–150
由谁管理 编译器 硬件 操作系统 操作系统 操作系统
后备存储 cache 主存 磁盘 磁盘 磁盘/磁带

最该记住的一行是"由谁管理"：寄存器分配是编译器的事，Cache 由硬件自动完成对软件透明，而从主存往下全部由操作系统负责——这正好界定了本课程的管辖范围。

另外注意访问时间跨越了7 个数量级（0.25 ns → 5 ms），这就是为什么缓存与并发如此重要：一次磁盘访问，CPU 可以执行上千万条指令。

层次间的数据移动可以是显式的，也可以是隐式的（如寄存器由程序显式装载，Cache 填充则隐式发生）。

3. 缓存（Caching）——贯穿全机的通用原理

在硬件、操作系统、软件的许多层次上都会执行。

工作流程：

  1. 把正在使用的信息从较慢存储临时复制到较快存储
  2. 访问时先查 cache
  3. 命中 → 直接使用（快）
  4. 未命中 → 把数据复制进 cache，再从 cache 使用

设计要点：

  • Cache 必然小于被缓存的存储 → 缓存管理是重要设计问题
  • 两个核心参数：缓存大小 与 替换策略
  • 主存本身可以看作辅存的 cache（同理：TLB 是页表的 cache，浏览器缓存是网页的 cache）

4. 缓存一致性问题（Migration of “A”）

数据 A 从磁盘迁移到寄存器要经过：磁盘 → 主存 → cache → 硬件寄存器，于是同一份数据在多处存在副本。

环境 问题与解决
多任务 必须保证用到的是最新值，无论它此刻在层次的哪一层
多处理器 必须由硬件提供缓存一致性（cache coherency），使所有 CPU 的 cache 中都是最新值
分布式 情况更复杂，同一数据可能存在多个副本（解决方案见第 19 章）

十一、现代计算机如何工作（von Neumann 体系）

对应 “How a Modern Computer Works” 图：

  • CPU（可有 N 个）内含执行线程与 cache，与内存之间有两条主线：指令执行周期、数据移动
  • 设备（可有 M 个）与 CPU 之间三条线：I/O 请求（CPU→设备）、数据、中断（设备→CPU）
  • 设备与内存之间还有一条直连箭头：DMA

DMA（直接内存访问）

  • 用于能以接近内存速度传输的高速 I/O 设备
  • 设备控制器把整块数据从缓冲区直接传到主存，无需 CPU 干预
  • 中断次数：每块产生一个中断，而不是每字节一个中断

💡 扩展：这是"用中断次数换 CPU 时间"的经典优化。若无 DMA，1 MB 数据要触发 100 万次中断，CPU 将被中断处理淹没。DMA 期间 CPU 可执行其他任务，只在传输完成时被打断一次。

设备驱动程序

每个设备控制器都有对应驱动，在控制器与内核之间提供统一接口——这正是"OS 隐藏硬件特性"的具体落地。

十二、操作系统的运行（Operating-System Operations）

启动链条

内核是中断驱动的（硬件 + 软件两类）

类型 来源 例子
硬件中断 某个设备发出 键盘输入、磁盘传输完成
软件中断（异常/陷阱） ① 软件错误 除零
② 请求 OS 服务 系统调用（system call）

其他需要 OS 应对的进程问题：死循环、进程互相修改或修改操作系统。
→ 这三类威胁分别引出了后面的 定时器、双模式、内存保护 三大机制。

十三、多道程序与多任务

1. 多道程序设计 Multiprogramming（批处理）

动因：单个用户/单个作业无法始终让 CPU 和 I/O 设备都忙碌（跑 I/O 时 CPU 空转）。

机制：

  • 组织多个作业（代码+数据），使 CPU 总有事可做
  • 系统中全部作业的一个子集保存在内存里
  • 通过**作业调度（job scheduling）**选出一个来运行
  • 该作业需要等待（如等 I/O）时，OS 切换到另一个作业

目标：最大化 CPU 利用率（吞吐量）。

2. 多任务 / 分时 Multitasking (Timesharing)

批处理的逻辑延伸：CPU 切换作业足够频繁，使用户能在程序运行时与之交互 → 交互式计算。

要点：

  • 响应时间应 < 1 秒
  • 每个用户至少有一个程序在内存中执行 → 这就是进程（process）
  • 多个作业同时就绪 → 需要 CPU 调度
  • 进程装不下内存 → 交换（swapping）：换入换出以运行
  • 虚拟内存：允许执行并未完全装入内存的进程

目标：最小化响应时间（用户体验）。

3. 多道程序系统的内存布局

内存中同时驻留 OS 与多个进程 → 引出保护需求：谁来阻止 process 2 去改写 OS 或 process 3？答案见下节。

十四、双模式操作与定时器（保护的两大基石）★

1. 双模式操作 Dual-mode Operation

目的：让 OS 能保护自身和其他系统组件。

  • 两种模式：用户态（user mode） 与 内核态（kernel mode）
  • 由**硬件提供模式位（mode bit）**来区分当前执行的是用户代码还是内核代码
    • 用户运行 → mode bit = 1（user）
    • 内核代码执行 → mode bit = 0（kernel）

如何保证用户不能自己把模式位设成内核？

  • 只有系统调用能把模式改为内核态，调用返回时重置为用户态
  • 部分指令被指定为特权指令（privileged instruction），只能在内核态执行（如设置定时器、I/O 指令、修改模式位、加载内存管理寄存器）

2. 用户态→内核态的转换（对应流程图）

关键：入口只有一个（trap），且由硬件把模式位置 0，用户程序无法绕过。

3. 定时器 Timer

目的：防止死循环，或某进程霸占资源不放。

机制：

  1. 设置定时器，在一段时间后中断计算机
  2. 维护一个计数器，由物理时钟递减
  3. 由 OS 设置该计数器（特权指令）
  4. 计数器归零时产生中断
  5. 在调度进程前先设好 → 超出分配时限就重获控制权或终止程序

💡 扩展：定时器是抢占式调度（preemptive scheduling）能够存在的硬件前提。没有定时器，OS 一旦把 CPU 交给用户程序就再也拿不回来——这正是早期协作式多任务系统（如 Win 3.x）容易被单个程序卡死的原因。

十五、OS 的五大资源管理职责

1. 进程管理 Process Management

核心概念辨析：

程序 Program 进程 Process
性质 被动实体（passive） 主动实体（active）
形态 磁盘上的文件 执行中的程序，系统内的工作单元
  • 进程需要资源完成任务：CPU、内存、I/O、文件，以及初始化数据
  • 进程终止时须回收所有可重用资源
  • 单线程进程：一个 PC（程序计数器）指示下一条指令位置，顺序执行至完成
  • 多线程进程：每个线程一个 PC
  • 系统中通常有许多进程（用户的 + OS 的）在一个或多个 CPU 上并发运行
  • 并发通过在进程/线程间多路复用 CPU 实现

OS 的进程管理活动（5 条）：

  1. 创建与删除用户进程和系统进程
  2. 挂起与恢复进程
  3. 提供进程同步机制
  4. 提供进程通信机制
  5. 提供死锁处理机制

2. 内存管理 Memory Management

前提：要执行程序，其指令（全部或部分）必须在内存中；所需数据（全部或部分）也必须在内存中。

内存管理决定什么内容在内存中、何时在，以优化 CPU 利用率和对用户的响应。

活动：

  • 跟踪内存哪些部分正被使用、被谁使用
  • 决定把哪些进程（或其部分）和数据换入换出
  • 按需分配与回收内存空间

3. 文件系统管理 File-System Management

  • OS 提供统一的、逻辑的信息存储视图
  • 把物理属性抽象为逻辑存储单位——文件
  • 每种介质由设备控制（磁盘驱动器、磁带机等），属性各异：访问速度、容量、数据传输率、访问方法（顺序 or 随机）
  • 文件通常组织成目录；多数系统有访问控制决定谁能访问什么

活动：创建/删除文件与目录；提供操作文件目录的原语；把文件映射到辅存；把文件备份到稳定（非易失）介质。

4. 大容量存储管理 Mass-Storage Management

  • 磁盘用于存放装不下主存的数据、或需长期保存的数据
  • 整机运行速度取决于磁盘子系统及其算法 → 管理至关重要

活动：挂载/卸载、空闲空间管理、存储分配、磁盘调度、分区、保护。

5. I/O 子系统

OS 的目的之一是向用户隐藏硬件设备的特殊性。I/O 子系统负责：

  • I/O 的内存管理，包含三个易混概念：
术语 含义
缓冲 buffering 数据传输过程中临时存储
缓存 caching 把部分数据存于更快存储以提升性能
假脱机 spooling 一个作业的输出与其他作业的输入相重叠
  • 通用设备驱动接口
  • 针对特定硬件的驱动程序

十六、保护与安全

保护 Protection 安全 Security
定义 控制进程或用户对 OS 所定义资源的访问的任何机制 防御系统免受内部与外部攻击
面向 内部（机制层面） 内外部威胁

用户标识体系：

  • 用户 ID（user ID / security ID）：包含名字和关联的数字，每用户一个
  • 用户 ID 与该用户的所有文件和进程关联，用于访问控制

  • 权限提升（privilege escalation）：允许用户切换到拥有更多权限的有效 ID（如 Unix 的 setuid、sudo）

十九、计算机系统体系结构（Computer System Architecture）

1. 总体格局

  • 多数系统使用单个通用处理器
  • 多数系统同时还有专用处理器（如磁盘控制器上的微处理器、GPU、键盘控制器）
  • 多处理器系统的使用与重要性正在增长

2. 多处理器系统（Multiprocessor Systems）

别名：并行系统（parallel systems）、紧耦合系统（tightly-coupled systems）

三大优势：

优势 含义 注意
提高吞吐量 Increased throughput 处理器多 → 单位时间完成更多工作 ⚠️ N 个处理器不等于 N 倍加速，协调开销和共享资源竞争会带来损耗
规模经济 Economy of scale 共享外设、存储、电源、机箱，比 N 台独立机器便宜 —
提高可靠性 Increased reliability 一个处理器故障不导致系统停机，只是变慢 关键词：优雅降级（graceful degradation）、容错（fault tolerance）

两种类型：

非对称多处理 AMP 对称多处理 SMP
分工 每个处理器被指派特定任务 每个处理器执行所有任务
结构 主-从关系（boss/worker） 各处理器地位平等
现状 早期方案 现代主流

3. SMP 体系结构（图解）

要点：每个处理器自带寄存器和私有 cache，但共享主存。
→ 这正是前面讲的**缓存一致性（cache coherency）**必须由硬件保证的原因：两个 cache 里可能各有一份同名数据的副本。

4. 双核 / 多核设计（Multicore）

关键区别：

  • 多芯片（multi-chip）：多个物理处理器芯片
  • 多核（multicore）：单个芯片内包含多个计算核心
  • 系统可以包含所有芯片；机箱可容纳多个独立系统（刀片服务器）

💡 扩展：为什么多核胜过多芯片？

  1. 片内通信远快于片间通信，功耗也低得多
  2. 共享 L2/L3 使核间数据交换不必绕到主存
  3. 从 OS 视角，N 核 = N 个可调度的 CPU，调度器不必区分它们是不是同一块芯片——但为了性能，现代调度器实际上是关心的（亲和性 affinity）

5. NUMA（非一致内存访问）

  • 每个 CPU 挂载自己的本地内存，通过互连网络访问其他 CPU 的内存
  • 访问本地内存快，访问远程内存慢 → 所以叫"非一致"
  • 优点：随 CPU 数增加可扩展，避免了 SMP 中共享总线成为瓶颈
  • 代价：OS 必须感知拓扑，尽量把进程调度到其内存所在的节点上（NUMA-aware 调度与内存分配）

从主板视角看：一块主板就是一台完整计算机（处理器插槽 + DRAM 插槽 + PCIe 总线插槽 + 各类 I/O 与电源接口）。即使最低端的通用 CPU 也含多个核心；有的主板含多个处理器插槽；更高级的计算机允许多块系统板，从而构成 NUMA 系统。

6. 三层并行结构总结（易混，务必分清）

层级 名称 共享什么 耦合度
芯片内 多核 multicore L2/L3 cache + 内存 最紧
单机内 SMP / 多芯片 主存（共享总线） 紧
单机内 NUMA 内存（但有远近之分） 较紧
多机 集群 cluster 存储（经 SAN） 松
多机 分布式系统 仅靠消息通信 最松

二十、集群系统（Clustered Systems）

定义：类似多处理器系统，但是多个独立的系统协同工作。

核心特征：

  • 通常通过存储区域网络（SAN）共享存储
  • 提供高可用（high-availability）服务，能在故障后继续存活

两种模式：

非对称集群 Asymmetric 对称集群 Symmetric
结构 一台机器处于**热备（hot-standby）**状态 多个节点都运行应用，并互相监控
备机状态 平时不干活，只等主机故障 都在干活
资源利用 低（一半机器闲置） 高

高性能计算（HPC）集群：

  • 应用程序必须专门为并行化编写才能利用集群（不是把单机程序丢上去就快了）
  • 部分集群带分布式锁管理器（DLM），避免多节点对共享数据的冲突操作

6. 实时嵌入式系统（Real-Time Embedded Systems）

  • 是最普遍的一种计算机形态（数量上远超 PC 和服务器）
  • 差异极大：专用、功能受限的 OS，或实时 OS

实时 OS 的定义特征：

  • 具有明确定义的固定时间约束
  • 处理必须在约束内完成
  • 只有满足时间约束，操作才算正确 ← 这是与普通 OS 最本质的区别

💡 扩展：普通 OS 追求"平均快"（吞吐量、平均响应时间），实时 OS 追求"最坏情况可预测"。一个平均 1 ms、偶尔 500 ms 的系统在桌面上很优秀，在汽车安全气囊控制器上是致命缺陷。

  • 软实时（soft real-time）：错过截止期只是质量下降（视频播放丢帧）

二十二、自由与开源操作系统

1. 基本概念

  • 以源代码形式提供的操作系统，而非只有二进制的闭源专有形式
  • 是对拷贝保护与数字版权管理（DRM）运动的一种反制
  • 由**自由软件基金会（FSF）**发起，其 **GNU 通用公共许可证（GPL）**采用 “copyleft” 机制

2. ⚠️ 重要辨析：Free ≠ Open Source

自由软件（free software）与开源软件（open-source software）是由不同群体倡导的两种不同理念。

自由软件（FSF） 开源软件（OSI）
出发点 伦理/自由：用户应有运行、研究、修改、分发的自由 实用/工程：开放源码能产生更好的软件
关键词 copyleft、GPL、“free as in freedom” 协作开发、宽松许可（MIT/BSD/Apache）

（延伸阅读：gnu.org 的 “Open Source Misses the Point”）

💡 copyleft 的巧妙之处：它反用版权法——利用版权授予许可，但要求衍生作品必须以同样条款发布，从而让自由"传染"下去。这正是 Linux 内核（GPLv2）的法律基础。

3. 例子与实践工具

  • 例子：**GNU/Linux、BSD UNIX（含 Mac OS X 的核心）**等
  • 可用 VMM 运行客户机 OS 进行探索：
    • VMware Player（Windows 上免费）
    • VirtualBox（多平台，开源且免费）

4. 为什么现在是学 OS 的最好时代（教材观点归纳）

三条理由：

  1. 源码可得 —— Linux、BSD UNIX、Solaris、部分 macOS 都同时提供源码和二进制形式。过去只能靠文档或观察行为回答的问题，现在可以直接查看代码来回答，实现"由内而外"地研究 OS
  2. 历史系统也开源了 —— 不再有商业价值的 OS 被开放源码，让我们能研究在 CPU、内存、存储资源都稀缺的年代系统是如何运作的
  3. 虚拟化成为主流且常常免费 —— 学生可在一个核心系统上运行数百个 OS 而无需专用硬件（VMware 免费 player + 大量免费"虚拟设备"；VirtualBox 跨平台开源 VMM）

结果：从学生到 OS 开发者的门槛大幅降低——只需一些知识、努力和网络连接，学生甚至能创建一个新的 OS 发行版。以前获取源码困难甚至不可能，如今唯一的限制只是兴趣、时间和磁盘空间。

二十三、内核数据结构（Kernel Data Structures）

总原则：许多内核数据结构与标准编程数据结构相似——OS 并不需要发明新数据结构，而是在极端约束下（无法动态分配失败、需在中断上下文使用、需极致性能）复用经典结构。

1. 链表（三种）

类型 结构 特点
单链表 Singly linked 每节点一个 next 指针，末节点指向 null 只能单向遍历
双链表 Doubly linked 每节点有 prev 和 next，首节点 prev = null，末节点 next = null 可双向遍历，删除节点 O(1)
循环链表 Circular 末节点指回首节点，无 null 适合轮转遍历（如轮转调度队列）

共同代价：查找是 O(n) 顺序遍历。
用途：链表常作为更复杂结构（栈、队列）的底层实现。

2. 二叉搜索树（Binary Search Tree）

规则：left ≤ right（左子树 ≤ 节点 ≤ 右子树）

普通二叉搜索树 O(n)（最坏情况退化成链表）
平衡二叉搜索树 O(lg n)

💡 扩展：Linux 内核大量使用**红黑树（red-black tree）**这一平衡 BST，头文件 <linux/rbtree.h>。例如 CFS 完全公平调度器就用红黑树按虚拟运行时间组织可运行进程，取最左节点即为下一个要跑的进程。

3. 哈希表 / 哈希映射（Hash Map）

  • 哈希函数把 key 映射到表中的位置，从而创建哈希映射
  • 平均查找 O(1) —— 这是它相对链表和树的最大优势
  • 代价：需处理冲突；Linux 中环形缓冲区见 <linux/kfifo.h>

4. 位图（Bitmap）

定义：由 n 个二进制位组成的串，表示 n 个项目的状态。

  • 空间效率极高：n 个对象的状态只需 n bit
  • 典型用途：磁盘空闲块管理、内存帧分配表、进程 ID 分配
  • 例：001011101 表示第 0、1、3、5 号资源空闲，第 2、4、6、7、8 号被占用

头文件 数据结构

<linux/kfifo.h> FIFO 队列 / 环形缓冲区
