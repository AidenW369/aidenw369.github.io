Linux 系统

1. Linux 的历史（Linux History）

Linux 是基于 UNIX 标准的自由、开源操作系统，1991 年由 Linus Torvalds 开发，主要目标是 UNIX 兼容性。Linux 内核具有独立实现，并通过全球开发者协作不断发展。

版本 主要特点（按课件）
0.01（1991） 支持 80386、Minix 文件系统，缺少网络支持
1.0（1994） TCP/IP、BSD socket、以太网、SCSI、增强文件系统
1.2（1995） 最后一个仅面向 PC 的内核版本
2.0（1996） 多体系结构、64 位 Alpha、SMP、内核线程和模块支持
2.4 / 2.6 增强 SMP、日志文件系统、内核抢占、64 位内存支持
3.0 时代 虚拟化、内存管理、页面回写等改进；课件同时讨论 CFS
  • 早期版本曾采用奇数开发版本、偶数生产版本的命名惯例，并非现代通用规则。
  • Linux 系统包含 GNU 系统库与工具、BSD 网络工具以及 X Window System 等组件。
  • FHS（File System Hierarchy Standard）规定配置文件、库、系统二进制文件和运行时数据的目录布局。
  • 发行版（Distribution）是内核、应用、安装和管理工具的集合，例如 Slackware、Red Hat、Debian。
  • GPL（GNU General Public License）：Linux 内核不是公有领域软件；允许商业销售，但分发受 GPL 约束的程序或衍生作品时须遵守相应源码提供等义务。

2. 设计原则（Design Principles）

Linux 是多用户（Multiuser）、多任务（Multitasking）系统，主要设计目标为速度、效率、标准化。遵循 UNIX 文件系统语义和网络模型，支持 POSIX、Pthreads 及部分实时进程控制接口。课件指出其编程接口主要遵循 SVR4 UNIX 语义。

2.1 Linux 系统的组成（Components of a Linux System）

组成 功能
Kernel（内核） 管理进程、内存、设备等操作系统抽象；在内核态执行
System Libraries（系统库） 提供应用与内核交互的标准函数，实现无需内核特权的功能
System Utilities（系统工具） 完成专门的系统管理任务

截图上层包含系统管理程序、用户进程、用户实用程序和编译器；中间为系统共享库；下层为 Linux 内核和可加载内核模块。内核代码和数据结构位于共同的内核地址空间，可加载模块属于内核的一部分，而非独立的用户态层。

3. 内核模块（Kernel Modules）

内核模块是可独立编译、加载、卸载的内核代码，常用于设备驱动、文件系统和网络协议。通过模块化可以保持基础内核精简，并按需求扩展功能。

模块支持组成 功能
Module-management system 管理模块代码占用的内核内存及模块可引用的符号
Module loader / unloader 加载、卸载模块
Driver-registration system 将新驱动注册到内核动态表中
Conflict-resolution mechanism 管理硬件资源预留，避免多个驱动冲突

驱动注册表包括设备驱动、文件系统、网络协议和二进制格式。驱动在访问硬件前申请资源，资源已被占用时可拒绝申请，避免自动探测干扰已有驱动。课件还介绍了按需加载及不再使用时卸载模块的机制。

4. 进程管理（Process Management）

UNIX 将创建进程与运行新程序分离：fork() 创建新进程，exec() 替换当前进程的程序映像（不创建新进程）。Linux 将进程属性分为 Identity、Environment、Context 三类。

4.1 进程身份（Process Identity）

属性 含义
PID 进程标识，用于发送信号、等待或操作进程
Credentials UID、GID 等凭证，决定访问权限
Personality 调整部分系统调用语义，用于兼容其他 UNIX 风格
Namespace 课件主要指文件系统视图，可拥有不同根目录和挂载集合

4.2 进程环境（Process Environment）

由父进程继承的环境包含两个以空指针结束的向量：参数向量（argument vector，argv）与环境向量（environment vector，envp）。后者采用 NAME=VALUE 格式，使系统行为可按进程配置，而不必全局修改。

4.3 进程上下文（Process Context）

进程运行时不断变化的状态，包括调度上下文（暂停和恢复所需信息）、资源统计信息、文件表（文件描述符 fd 是索引）、文件系统上下文（根目录、当前目录）、信号处理表及虚拟内存上下文。

4.4 进程与线程（Processes and Threads）

Linux 使用统一的内部任务（Task）表示进程与线程。fork() 创建独立任务上下文；clone() 创建有独立身份的新任务，并通过标志指定共享资源。线程通常共享地址空间等资源，但仍具有各自的执行上下文。

clone 标志 共享内容
CLONE_FS 文件系统上下文（根目录、当前目录等）
CLONE_VM 虚拟地址空间
CLONE_SIGHAND 信号处理函数表
CLONE_FILES 打开的文件描述符表

注意：fork() 的地址空间逻辑独立，但可通过写时复制暂时共享物理页；不能简单理解为立即复制所有物理内存。

5. 调度（Scheduling）

调度负责在不同任务间分配 CPU 时间，既涉及用户进程，也涉及内核任务。课件介绍早期 O(1) 抢占式优先级调度器及 Linux 2.6 系列中的 CFS（Completely Fair Scheduler，完全公平调度器）。

5.1 CFS 公平调度

设有 N 个权重相同的可运行任务，则理想 CPU 时间份额为：

[ s_i=\frac{1}{N} ]

设目标延迟（Target Latency）为 T，则理想运行时间为：

[ t_i=\frac{T}{N} ]

若任务权重不同，设第 i 个任务权重为 w_i，则：

[ s_i=\frac{w_i}{\sum_{j=1}^{N}w_j} ][ t_i=T\cdot\frac{w_i}{\sum_{j=1}^{N}w_j} ]

nice 值越小，权重越大，获得的 CPU 时间比例越高。目标延迟指希望所有可运行任务至少运行一次的时间区间。

例：目标延迟为 10 ms，2 个等权重任务各运行 5 ms；10 个等权重任务各运行 1 ms。

[ t_i=\frac{10,\mathrm{ms}}{2}=5,\mathrm{ms} ][ t_i=\frac{10,\mathrm{ms}}{10}=1,\mathrm{ms} ]

Minimum Granularity（最小调度粒度）避免每次运行时间过短、上下文切换开销过大，因此实际调度可能偏离理想公平模型。以上为课件中的简化模型。

5.2 内核同步（Kernel Synchronization）

进入内核态的两种途径：进程主动请求系统服务（系统调用）或隐式触发异常（如缺页）；硬件中断触发内核中断处理程序。内核同步用于保护临界区（Critical Section）及共享数据结构。

  1. 内核抢占控制：课件中早期不可抢占内核收到时钟中断后设置 need_resched，待系统调用结束、返回用户态前执行调度。可抢占内核可在安全点抢占，但临界区仍需要保护。
  2. 中断控制：在必要的临界区禁用本 CPU 的相关中断，防止本 CPU 中断处理程序并发访问共享数据；不能阻止其他 CPU 访问。
单处理器（课件简化模型） 多处理器
禁止内核抢占 获取自旋锁
执行临界区 执行临界区
恢复内核抢占 释放自旋锁

Linux 提供 Spinlock（自旋锁）、Semaphore（信号量）及读写版本。自旋锁适合短临界区，等待者忙等；信号量可使等待任务睡眠。若临界区与中断共享数据，还需相应中断保护。

5.3 中断上半部与下半部

为避免长时间关闭中断，中断处理分为 Top Half（上半部，处理紧急工作）和 Bottom Half（下半部，延后处理非紧急工作）。课件的模型中，下半部执行时允许硬件中断，并可按需禁止选定的下半部。

优先级（高到低） 执行层次
1（最高） Top-half interrupt handlers
2 Bottom-half interrupt handlers
3 Kernel-system service routines
4（最低） User-mode programs

在课件的简化保护模型中，高层可以打断低层，同层或低层不能打断高层。用户进程可在时间共享调度中被抢占。实际内核的中断、抢占和下半部机制更复杂。

5.4 对称多处理（SMP）

Linux 2.0 首次支持 SMP，多个进程或线程可以在不同处理器并行运行。早期以单个内核自旋锁限制内核态并行，后来逐渐采用多个细粒度锁，并增强处理器亲和性（Processor Affinity）和负载均衡（Load Balancing）。

6. 内存管理（Memory Management）

Linux 管理物理页、连续页组、小块内存及虚拟地址空间。

6.1 物理内存区域（Memory Zones）

课件正文称四种 zone，但截图仅列出传统 32 位 x86 的三个区域，以下按截图整理（非现代所有架构的固定划分）。

区域 物理地址范围 用途
ZONE_DMA 小于 16 MB 受地址限制的 DMA 设备
ZONE_NORMAL 16–896 MB 常规、可直接映射的内存
ZONE_HIGHMEM 896 MB 以上 不能全部永久直接映射的高端内存

6.2 伙伴系统（Buddy System）

物理页分配器采用 Buddy Heap 算法，管理连续物理页。大小为 2 的幂次个页的内存块称为一个 order 对应的块：

[ B_k=2^k\times P ]

其中 P 为页大小，k 为 order。申请小块时，若没有合适的空闲块，就将更大的块二等分；释放时，若对应的伙伴也空闲，则合并并继续尝试向上合并。

以截图为例，16 KB 分成两个 8 KB，再将其中一个 8 KB 分成两个 4 KB：

[ 16,\mathrm{KB}=8,\mathrm{KB}+8,\mathrm{KB} ][ 8,\mathrm{KB}=4,\mathrm{KB}+4,\mathrm{KB} ]

若申请 4 KB，最终可分配一个 4 KB 块，保留另外一个 4 KB 和一个 8 KB。两个对应的空闲 4 KB 伙伴可合并为 8 KB，再在满足伙伴条件时合并为 16 KB。不是任意相邻空闲块都能合并。

优点：快速拆分与合并，便于提供连续物理页；缺点：按幂次分配可能造成内部碎片。

6.3 Slab 分配器（Slab Allocator）

Slab 用于高效分配频繁创建和销毁的内核对象。结构为 Cache → Slab → Object：一个 cache 管理特定类型或大小的对象，包含一个或多个 slab；每个 slab 由一个或多个连续物理页构成，并划分为对象槽位。截图分别展示 3 KB 对象与 7 KB 对象对应的缓存。

Buddy System Slab Allocator
面向物理页或连续页组 面向内核对象
按 2 的幂次拆分和合并 按对象大小组织与复用
为上层分配器提供页 从页分配器获取内存

内核还可通过静态预留或动态分配获取内存。Page Cache（页缓存）保存文件内容页，为本地、网络文件 I/O 提供缓存，并与虚拟内存系统结合。

6.4 虚拟内存（Virtual Memory）

虚拟内存管理器维护进程可见的地址空间，并按需建立、加载或换出页面。

视图 内容
Logical View 由互不重叠、连续且页对齐的虚拟内存区域（VMA）组成
Physical View 由硬件使用的进程页表描述虚拟页到物理页的映射

虚拟内存区域由后备存储（Backing Store，如文件或 demand-zero 匿名内存）和写入行为（共享或 Copy-on-Write）描述。

  • exec()：替换旧地址空间，加载程序并建立新的区域。
  • fork()：复制 VMA 描述符及页表，初始阶段父子进程共享相应物理页，增加引用计数；对私有可写页采用 COW，在写入时按需复制。

6.5 换页与交换（Swapping and Paging）

Pageout Policy 决定换出哪些页、何时换出；Paging Mechanism 执行实际的数据传输。课件介绍 swap device 或 swap file、位图记录交换空间使用状态，以及 next-fit 算法尝试分配连续块。

6.6 内核虚拟内存

课件模型中，每个进程虚拟地址空间预留体系结构相关的内核区域，用户态不能直接访问。其中包括直接映射区域及可动态改变映射的区域。具体映射范围因体系结构与内核配置而异。

6.7 ELF 程序加载与内存布局

ELF（Executable and Linkable Format）是可执行与可链接格式。Linux 在 exec() 时通过相应加载器读取 ELF 头部，将可加载内容映射到虚拟地址空间，实际页面可在访问触发缺页时按需加载。课件也提到历史上的 a.out 格式。

从高地址到低地址 作用
Kernel virtual memory 内核虚拟内存，用户态不可直接访问
Stack 栈，保存调用帧、局部变量等，图中向低地址增长
Memory-mapped region 映射文件、共享库及匿名区域等
Run-time data（Heap） 动态分配内存，传统 brk 堆向高地址增长
Uninitialized data（BSS） 未初始化或零初始化的静态/全局数据
Initialized data（Data） 已初始化的静态/全局数据
Program text（Text） 程序机器指令
Forbidden region 不可访问区域，用于防止非法访问等

brk 指针表示传统堆的末端；实际布局可能受 ASLR、体系结构及分配器影响。

6.8 静态链接与动态链接

静态链接 动态链接
所需库代码直接包含在可执行文件中 运行时映射所需共享库
不同程序可能重复保存库代码 可共享库的只读代码页，节约内存和磁盘空间
不依赖相应的运行时共享库 依赖动态链接器及所需共享库

Linux 在用户态执行动态链接：启动时映射动态链接器，确定所需库、映射共享库并解析符号。共享库通常使用 PIC（Position-Independent Code，位置无关代码）。

7. 文件系统（File Systems）

7.1 虚拟文件系统 VFS

VFS（Virtual File System）向用户提供统一的 UNIX 层次目录及访问接口，屏蔽底层文件系统差异。

VFS 对象 含义
inode 表示单个文件的元数据对象
file 表示打开的文件实例
superblock 表示整个文件系统
dentry 表示目录项，用于名字与 inode 的关联

通过 file_operations 等操作集合实现 open()、read()、write()、mmap() 等统一接口。

7.2 ext2 / ext3 与块分配

课件以 ext3 为当时的标准磁盘文件系统，介绍其与 ext2、BSD FFS 的关系，并提及 ext4 的 extents（区段）特性。该描述属于历史背景。

FFS 使用较大块并划分片段（Fragments）；课件中的 ext3 采用较小的分配单位而不使用 FFS 式片段，支持的块大小依架构等条件而定。

图中灰色为已使用块，白色为空闲块，蓝色带点为选中的块，箭头为位图搜索路径。细线表示 bit 边界，粗线表示 byte 边界。

分散分配 连续分配
从不同位置选择空闲块 优先选择相邻空闲块
文件块可能分散 逻辑相邻块尽量物理相邻
可能增加磁盘寻道和 I/O 请求 有利于合并 I/O，减少机械磁盘寻道

课件介绍通过块组中的空闲位图查找全空闲字节，尝试一次分配至少 8 个连续块。一个字节包含 8 个 bit，每个 bit 对应一个块。

7.3 日志机制（Journaling）

ext3 将需要记录的文件系统更新组织成事务，先写入日志并提交，再写回实际文件系统位置。崩溃后重放已提交但尚未写回的事务，通常不需要传统方式的全面一致性扫描。日志还可能将部分随机写转为顺序写。具体记录数据还是元数据取决于日志模式。

7.4 proc 文件系统

/proc 是虚拟文件系统，其内容主要由内核根据访问请求动态生成，而非普通磁盘持久化数据。课件描述其通过 inode 标识所需操作，收集信息、格式化并放入进程读取缓冲区。

8. 输入与输出（Input and Output）

课件区分 Page Cache（缓存文件数据，与虚拟内存统一）和 Buffer Cache（按磁盘块组织，课件用于描述元数据缓存等）。这一划分按课件历史模型理解。

8.1 设备分类与驱动结构

设备类型 访问方式 典型路径
Block Device 固定大小块、支持随机访问 文件系统/块设备文件 → I/O 调度器 → 块设备驱动
Character Device 不要求固定块随机访问 字符设备文件 → 字符设备驱动
Network Device 通过网络子系统收发数据包 Socket → 协议驱动 → 网络设备驱动

截图还显示 SCSI manager / SCSI device driver，以及终端设备的 TTY driver / Line discipline。

8.2 块设备与 I/O 调度

块缓冲用于活动 I/O 和缓存已完成 I/O，Request Manager 管理缓冲区与驱动之间的读写。课件介绍 Linux 2.6 时代 CFQ（Completely Fair Queueing）：按进程维护队列，以 C-SCAN 与轮转方式组织请求，课件示例每次处理一个进程的四个块。CFQ 是历史调度器，不应理解为现代内核默认值。

8.3 字符设备与线路规程

字符设备驱动注册文件 I/O 操作，内核通常直接转发读写请求。终端设备是例外，TTY Line Discipline（线路规程）连接终端数据流与进程的标准输入/输出，并处理前后台进程相关的终端访问。课件还列举 PPP、SLIP 等网络线路规程。

9. 进程间通信（Interprocess Communication）

IPC 机制 特点
Signal（信号） 通知事件发生；传统普通信号主要传递事件而非大量数据
Semaphore（信号量） 同步与资源协调；System V 支持多个信号量操作的原子执行
Pipe（管道） 一端写入、另一端读取，可由子进程继承通信通道
Shared Memory（共享内存） 多个进程映射同一内存区域，数据通信速度快，但需额外同步

内核内部还通过调度状态和 wait_queue 等机制实现等待和唤醒。

10. 网络结构（Network Structure）

Linux 网络内核的三层结构：Socket Interface（套接字接口）→ Protocol Drivers（协议驱动）→ Network Device Drivers（网络设备驱动）。支持 Internet 协议族、IP 路由、TCP、UDP、ICMP，并通过防火墙规则链过滤数据包。课件还列举 AppleTalk、IPX 等历史协议。

11. 安全性（Security）

PAM（Pluggable Authentication Modules，可插拔认证模块）为系统组件提供统一的用户认证机制。

访问控制以 UID、GID 为基础，保护掩码分别规定所有者（Owner）、所属组（Group）和其他用户（Others）的读取 r、写入 w、执行 x 权限。

课件介绍 Saved UID（保存的用户 ID），允许进程在许可条件下放弃并恢复有效 UID；Capabilities（能力机制）将特权细分，使进程只获得所需权限；还可选择性传递单个打开文件的访问能力，而无需授予接收进程其他权限。
