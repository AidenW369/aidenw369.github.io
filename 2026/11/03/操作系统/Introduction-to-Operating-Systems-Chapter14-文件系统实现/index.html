文件系统实现

一、本章大纲与目标

大纲：文件系统结构 → 文件系统操作 → 目录实现 → 分配方法 → 空闲空间管理 → 效率与性能 → 恢复 → 实例（WAFL）

学习目标：

  • 理解本地文件系统和目录结构的实现细节
  • 掌握各种块分配算法、空闲块算法及其权衡
  • 了解文件系统的效率、性能和故障恢复
  • 以 WAFL 为例分析一个具体的文件系统

注：本次材料只覆盖到分配方法，空闲空间管理及之后的内容还没有涉及。

二、文件系统结构

1. 基本概念

  • 文件是逻辑存储单位，由一组相关的信息组成。
  • 文件系统存放在**二级存储（磁盘）*上。它向用户提供访问存储的接口，并负责把*逻辑地址映射到物理地址。
  • 磁盘的两个关键特性：可以原地重写，也支持随机访问。
  • I/O 以块为单位传输，一个块由若干扇区组成，扇区通常为 512 字节。
  • **FCB（文件控制块）**是保存文件信息的存储结构。
  • 设备驱动程序负责控制物理设备。

2. 分层文件系统（自上而下）

层次 职责 典型输入 / 输出
逻辑文件系统 管理元数据；维护 FCB（UNIX 中即 inode）；负责目录管理和保护 把文件名转换成文件号、文件句柄和位置
文件组织模块 理解文件、逻辑地址和物理块；管理空闲空间和磁盘分配 把逻辑块号转换成物理块号
基本文件系统 向设备驱动发出通用命令；管理内存缓冲区和缓存（分配、释放、替换） 例如"读取第 123 块"
I/O 控制 由设备驱动程序和中断处理程序组成，负责管理 I/O 设备 输入"读 1 号驱动器、72 号柱面、2 号磁道、10 号扇区，到内存 1060"，输出硬件相关的低级命令
  • **缓冲区（buffer）**存放正在传输中的数据，**缓存（cache）**存放经常使用的数据。
  • 分层的优点是降低复杂度、减少冗余；缺点是增加开销，可能降低性能。
  • 各逻辑层可以由 OS 设计者用任意方式实现。

3. 常见文件系统

  • CD-ROM：ISO 9660
  • Unix：UFS、FFS
  • Windows：FAT、FAT32、NTFS
  • Linux：超过 130 种，主流是 ext3 和 ext4，此外还有分布式文件系统
  • 较新的：ZFS、GoogleFS、Oracle ASM、FUSE

三、文件系统操作：磁盘上和内存中的结构

1. 磁盘上的结构

结构 内容 备注
引导控制块 (boot control block) 从该卷引导 OS 所需的信息 仅在卷上装有 OS 时需要，通常位于卷的第一个块
卷控制块 (volume control block) 总块数、空闲块数、块大小、空闲块指针或数组 UFS 中叫 superblock，NTFS 中叫 master file table
目录结构 组织文件：文件名加 inode 号 NTFS 中同样存放在 master file table
FCB 每个文件一个，记录文件的详细信息 见下文

2. 文件控制块（FCB）

每个文件都有一个 FCB，通常包含 inode 号、权限、大小和日期。典型字段如下：

  • 文件权限
  • 文件日期（创建、访问、写入）
  • 文件所有者、组、ACL
  • 文件大小
  • 文件数据块，或指向数据块的指针

3. 内存中的结构

  • 挂载表 (mount table)：记录已挂载的文件系统、挂载点和文件系统类型。
  • 系统级打开文件表 (system-wide open-file table)：保存每个已打开文件的 FCB 副本及其他信息。
  • 进程级打开文件表 (per-process open-file table)：保存指向系统级表中对应项的指针，以及其他信息（如当前读写位置、访问模式）。

4. 打开和读取文件的过程（图 12-3）

(a) open(file name)

  1. 用户进程调用 open(文件名)。
  2. 内核在目录结构中查找文件名。常用的目录可能已缓存在内存中，否则从磁盘读入。
  3. 找到后，从磁盘读入该文件的 FCB，放入系统级打开文件表。
  4. 在进程级打开文件表中新建一项，指向系统级表，并向用户返回索引（UNIX 中叫文件描述符，Windows 中叫文件句柄）。

(b) read(index)

  1. 用户以 read(index) 发起读请求。
  2. 用 index 找到进程级打开文件表中的项。
  3. 由该项找到系统级打开文件表中的 FCB。
  4. 根据 FCB 中的块信息定位并读取磁盘上的数据块。

关键点：open 之后，后续读写都不需要再查目录，直接通过 index 访问。

四、目录实现

方式 原理 优点 缺点
线性列表 文件名加指向数据块的指针 编程简单 查找需要线性时间，执行慢。可以用链表按字母排序，或改用 B+ 树
哈希表 线性列表加哈希结构 大大缩短目录查找时间 存在冲突（两个文件名哈希到同一位置）。只适合定长表项，否则需要用链式溢出法

五、分配方法（重点）

分配方法指如何为文件分配磁盘块，主要有：连续分配、链接分配（及其变体 FAT）、索引分配。

1. 连续分配 (Contiguous Allocation)

原理：每个文件占用一组连续的块，目录中只需记录起始块号和长度。

优点：

  • 大多数情况下性能最好，顺序访问和随机访问都很快。
  • 实现简单。

缺点：

  • 很难为新文件找到足够大的连续空间。
  • 创建文件时必须预先知道文件大小。
  • 会产生外部碎片，需要紧缩（compaction）：可以离线进行（需要停机），也可以在线进行。

地址映射（块大小为 512 字节）：

例题（使用图中目录）：

file start length
count 0 2
tr 14 3
mail 19 6
list 28 4
f 6 2

访问 mail 文件的逻辑地址 LA = 1300：
1300 / 512 → Q = 2，R = 276
物理块 = 19 + 2 = 21，块内偏移 = 276

2. 基于区段的系统 (Extent-Based Systems)

  • 这是改进的连续分配，例如 Veritas 文件系统。
  • 以区段 (extent) 为单位分配磁盘块。一个区段是一段连续的磁盘块。
  • 一个文件由一个或多个区段组成，从而缓解了连续分配需要大块连续空间的问题。

3. 链接分配 (Linked Allocation)

原理：每个文件是一个块的链表，块可以散布在磁盘任何位置。每个块中存有指向下一块的指针，文件以 nil 指针结束。目录中记录起始块和结束块。

示例（图中文件 jeep，start = 9，end = 25）：

优点：

  • 没有外部碎片，也不需要紧缩。
  • 文件可以动态增长：需要新块时调用空闲空间管理系统即可。

缺点：

  • 只适合顺序访问。定位某一块需要沿链逐个读取，涉及多次 I/O 和磁盘寻道。
  • 可靠性差：一个指针损坏，后面的整条链都会丢失。
  • 每个块都要拿出一部分空间存放指针。
  • 可以把若干块组成簇 (cluster) 来提高效率，但这会增加内部碎片。

地址映射（块大小 512 字节，其中 1 字节存放指针，数据区只有 511 字节）：

例题：访问 jeep 的 LA = 1300
1300 / 511 → Q = 2，R = 278
沿链 9 → 16 → 1，第 Q = 2 块是物理块 1；块内偏移 = 278 + 1 = 279

4. FAT（文件分配表）

原理：

  • 卷的开头存放一张表，按块号索引。
  • 表中每项记录该块的"下一块"块号，相当于把链接分配的指针集中放进一张表；文件尾用特殊值（如 −1）标记。
  • 目录项中只需记录文件的起始块号。

示例（图中文件 test，起始块为 217）：

特点：

  • 本质上和链表相同，但 FAT 可以缓存到内存，查链时不用逐块读磁盘，因此速度更快，随机访问也得到改善。
  • 分配新块很简单：在 FAT 中找到值为 0（空闲）的项，再接到链尾即可。

5. 索引分配 (Indexed Allocation)

原理：每个文件有自己的索引块，即一张指针数组，第 i 项指向文件的第 i 个数据块。目录中记录索引块的块号。

示例（图中文件 jeep，索引块为 19）：

特点：

  • 支持直接（随机）访问，并且没有外部碎片。
  • 代价是每个文件都要占用一个索引块。小文件也是如此，所以未用的 −1 项会造成浪费。

补充（材料中未给出，来自教材常规内容）：映射方式为 LA / 512 → Q, R，Q 是索引表中的下标，R 是块内偏移。大文件可以使用链接式索引块、多级索引，或 UNIX inode 那样的组合方案。

6. 分配方法对比总结

方法 目录中记录 顺序访问 随机访问 外部碎片 主要问题
连续 起始块、长度 快 快 有 难找空间，需预知文件大小，需紧缩
区段 区段列表 快 较快 较少 区段大小难以选择
链接 起始块、结束块 可以 慢 无 可靠性差，指针占空间，寻道多
FAT 起始块 可以 较快（FAT 已缓存时） 无 FAT 表本身占空间，未缓存时需额外寻道
索引 索引块号 可以 快 无 索引块有开销，小文件浪费

六、分配方法的性能比较

核心结论：哪种分配方法最好，取决于文件的访问方式。

方法 顺序访问 随机访问 说明
连续分配 好 好 两种访问方式都很快
链接分配 好 差 随机访问需要沿链逐块查找
索引分配 好 较好 实现更复杂；访问一个数据块，可能先要读 2 个索引块（如二级索引），再读数据块

常见策略与优化：

  • 创建文件时声明访问类型，系统据此选择连续分配或链接分配。
  • 聚簇 (clustering)：把若干块合成一组分配，可以提高吞吐量，减少 CPU 开销。

NVM（非易失性存储，如 SSD）的特殊性：

  • NVM 没有磁头，因此需要不同的算法和优化。
  • 如果沿用为 HDD 设计的旧算法，会白白耗费大量 CPU 周期去避免根本不存在的磁头移动。
  • 优化目标是减少 CPU 周期，缩短 I/O 的整体路径。

七、空闲空间管理（重点）

文件系统维护一个空闲空间表 (free-space list)，记录哪些块或簇可用。为简便起见，下文统称"块"。

1. 位向量 / 位图 (Bit Vector / Bit Map)

原理：n 个块对应 n 个位。

查找第一个空闲块的块号：

  • 值全为 0 的字说明整字都被占用，可以整字跳过。
  • 许多 CPU 有专门的指令，能直接返回字中第一个 “1” 位的偏移，所以速度很快。

例：每字 32 位，前 2 个字全为 0，第 3 个字中第一个 1 位于偏移 5（从 0 开始计）。
块号 = 32 × 2 + 5 = 69

缺点：位图本身需要额外空间

例题：
块大小 = 4KB = 2¹² 字节
磁盘大小 = 2⁴⁰ 字节（1TB）
n = 2⁴⁰ / 2¹² = 2²⁸ 位 = 2²⁵ 字节 = 32MB
如果以 4 块为一簇，位数变为 2²⁶ 位，即 8MB

优点：容易找到连续的空闲块，适合连续分配的文件。

2. 链表 (Linked Free Space List)

原理：把所有空闲块用指针串成一条链，内存中只保存链表头。

图中示例（空闲块链）：

特点：

  • 优点是不浪费空间，因为指针就存放在空闲块自身里。
  • 只要另外记录了空闲块总数，就不需要遍历整条链。一般只从链头取块即可。
  • 缺点是不易获得连续空间。

3. 分组 (Grouping)

对链表的改进：

  • 在第一个空闲块中存放接下来 n−1 个空闲块的地址，最后一项指向下一个同样存放空闲块地址的块。
  • 这样一次读取就能拿到大量空闲块的地址，比普通链表快得多。

4. 计数 (Counting)

  • 依据：空间经常是连续分配和释放的，例如连续分配、区段分配或聚簇的情况。
  • 做法：只记录第一个空闲块的地址以及其后连续空闲块的个数。
  • 空闲表的每一项形如 （起始地址，个数），表因此变得很短。

5. 空间图 (Space Maps，ZFS 使用)

背景：在超大文件系统中，位图这类完整的数据结构无法装进内存，元数据 I/O 可能多达数千次。

做法：

  1. 把设备空间划分为若干 metaslab，一个卷可以有数百个 metaslab。
  2. 每个 metaslab 有一个对应的空间图。
  3. 空间图使用计数算法，但记录写到日志文件，而不是直接写入文件系统结构。日志按时间顺序、以计数格式记下所有块的分配和释放。
  4. 当某个 metaslab 有活动时：
    • 把它的空间图载入内存，组织成按偏移索引的平衡树；
    • 把日志重放 (replay) 到这棵树中；
    • 把相邻的连续空闲块合并成一项。

6. TRIM：回收未使用的块

设备 特点 释放块的处理
HDD 可以原地覆盖 只需空闲表。块被释放后不做特殊处理，数据还留着，只是没有文件指向它，直到被覆盖
NVM 不能原地覆盖，写之前必须先擦除；擦除以大块（由多个页组成）为单位，而且很慢 沿用 HDD 的做法效果很差

TRIM 机制：文件系统通知 NVM 设备某个页已经空闲。设备据此可以做垃圾回收；如果整个块都空闲了，就可以提前擦除这个块。

7. 空闲空间管理方法对比

方法 空间开销 找连续空间 分配速度 典型用途
位图 需要额外空间（1TB 磁盘约 32MB） 容易 快（有硬件指令支持） 通用
链表 无额外浪费 困难 取一块很快，遍历很慢 简单系统
分组 小 较难 快（一次获得多个地址） 链表的改进
计数 很小（空闲块连续时） 容易 快 连续分配、区段分配
空间图 小（基于日志） 容易 快 ZFS 等超大文件系统

八、效率与性能

1. 影响效率的因素

  • 磁盘分配算法和目录算法
  • 文件目录项中保存的数据类型（如是否记录"最后访问时间"，记录的话每次读都要写回）
  • 元数据结构是预分配还是按需分配
  • 数据结构是定长还是变长

2. 提高性能的手段

  • 把数据和元数据放在一起，减少寻道。
  • 缓冲区缓存 (buffer cache)：在主存中划出一块区域，存放常用的磁盘块。
  • 同步写与异步写：
同步写 异步写
缓冲 / 缓存 不经过缓冲 可以缓冲
何时返回确认 数据写到磁盘后才确认 写入缓存后立即返回
速度 慢 快，也更常见
适用场景 应用要求或 OS 需要时（如元数据） 一般场景
  • 顺序访问的优化：
    • free-behind：请求下一页时，立即从缓冲区中移除上一页，因为顺序访问不会再用到它。
    • read-ahead（预读）：读取请求页时，把后面的若干页一并读入。
  • 读往往比写慢：异步写只需写到缓存就能返回，而读如果缓存不命中，就必须等待磁盘。

3. 页缓存与统一缓冲缓存

  • 页缓存 (page cache)：用虚拟内存技术和地址缓存页，而不是磁盘块。
    • 内存映射 I/O 使用页缓存。
    • 普通文件系统 I/O（read()/write()）使用缓冲区（磁盘）缓存。

没有统一缓冲缓存时：

问题是双重缓存 (double caching)：内存映射的数据在页缓存和缓冲区缓存中各存一份，既浪费内存，又可能不一致。

使用统一缓冲缓存时：

  • 内存映射页和普通文件 I/O 共用同一个页缓存，避免了双重缓存。
  • 带来的新问题：各类缓存谁优先？采用什么替换算法？

九、恢复 (Recovery)

1. 一致性检查 (Consistency Checking)

  • 把目录结构中的数据与磁盘上的数据块进行比较，尝试修复不一致（如 UNIX 的 fsck）。
  • 缺点：速度慢，而且有时会失败。

2. 备份与恢复

  • 用系统程序把磁盘数据备份到其他存储设备，如磁带、其他磁盘或光盘。
  • 丢失文件或磁盘损坏时，从备份中恢复。

3. 日志结构文件系统 / 日志文件系统 (Log Structured / Journaling)

流程：

  1. 每次元数据更新都作为一个事务 (transaction) 记录下来。
  2. 事务顺序写入日志（日志有时放在单独的设备或磁盘区域）。写入日志即视为已提交。
  3. 此时文件系统结构本身可能还没更新。
  4. 日志中的事务被异步地应用到文件系统结构上。
  5. 文件系统结构修改完成后，该事务从日志中删除。
  6. 如果系统崩溃，日志中剩余的事务在恢复时必须全部执行完。

优点：

  • 崩溃后恢复更快，不需要像 fsck 那样扫描整个磁盘。
  • 消除了元数据不一致的可能。
  • 日志是顺序写，速度快。

十、实例：WAFL 文件系统

1. 概述

  • 全称 Write-Anywhere File Layout（任意位置写文件布局）。
  • 用于 Network Appliance 公司的 “Filer”，即分布式文件系统专用设备。
  • 提供 NFS、CIFS、http、ftp 等服务。
  • 针对随机 I/O 和写操作做了优化，用 NVRAM 作为写缓存。
  • 与 Berkeley Fast File System 类似，但做了大量修改。

2. 文件布局

  • 所有元数据都存放在文件中：inode 本身组成一个 inode 文件，空闲块图和空闲 inode 图也都是文件。
  • 因此元数据块可以写到任意位置，这正是 “write anywhere” 的含义。只有根 inode 的位置是固定的。

3. 快照 (Snapshots)

阶段 状态
(a) 快照前 root inode 指向块 A、B、C、D、E
(b) 刚做完快照，块还没有变化 复制一份 root inode 作为新快照，两者指向同一组块，几乎不占额外空间
© 块 D 被修改为 D′ 后 新数据写到新位置 D′，root inode 改为指向 D′；快照仍然指向旧的 D
  • 本质是写时复制 (copy-on-write)：只有被修改的块才产生新副本，未修改的块由当前文件系统和快照共享。
  • 快照创建得快，占用空间少，可以保留多个历史版本。

十一、实例：Apple 文件系统（APFS）

1. 背景

  • Apple 于 2017 年发布 APFS，用来替代用了约 30 年的 HFS+。
  • HFS+ 为不断加入新功能被反复扩展，变得越来越复杂，继续添加功能也越来越难。因此 Apple 选择从零开始重新设计，直接基于当前的技术和方法，只提供真正需要的功能。
  • 目标是运行在所有 Apple 设备上，从 Apple Watch、iPhone 到 Mac（watchOS、iOS、tvOS、macOS）。

2. 主要特性

  • 64 位指针
  • 文件和目录的克隆 (clones)
  • 快照
  • 空间共享 (space sharing)
  • 快速目录大小统计 (fast directory sizing)
  • 原子安全保存 (atomic safe-save)
  • 写时复制 (copy-on-write) 设计
  • 加密（单密钥和多密钥）
  • I/O 合并 (I/O coalescing)
  • 同时支持 NVM 和 HDD

3. 新概念解释

概念 含义
空间共享 与 ZFS 类似：存储被组织为一个或多个大的空闲空间，称为容器 (container)，各文件系统从中按需取用空间，因此 APFS 卷可以动态增大或缩小
快速目录大小统计 能够快速计算和更新已用空间
原子安全保存 把文件、文件包或目录的重命名作为单个原子操作完成。只能通过 API 调用，不能通过文件系统命令使用
I/O 合并 针对 NVM 的优化：把多个小写操作合并成一次大写操作，以提高写性能

4. 其他

  • APFS 本身不实现 RAID，软件 RAID 依赖 Apple 现有的 RAID 卷机制。
  • 兼容 HFS+，现有系统可以方便地转换过来。

十二、补充与回顾

1. 链接分配的块结构（补充第五节）

这就是映射时用 LA / 511、块内偏移取 R + 1 的原因：前 1 字节是指针，数据从偏移 1 开始。

2. 内存中文件系统结构（补充第三节）

  • 除了挂载表、系统级打开文件表和进程级打开文件表之外，还有缓冲区，用来存放从二级存储读入的数据块。
  • open 返回一个文件句柄，供后续操作使用。
  • read 读出的数据最终被复制到用户进程指定的内存地址。

十三、易错点与考点提示

  1. 位图中 1 表示空闲，0 表示占用（本教材的约定，有的教材正好相反，需要留意）。
  2. 位图空间计算：位数 = 磁盘大小 / 块大小；换成字节还要再除以 8。2²⁸ 位 = 2²⁵ 字节 = 32MB。
  3. 块号计算公式：每字位数 × 全 0 字的个数 + 第一个 1 位的偏移。
  4. 链表与位图：链表不浪费空间，但难以获得连续空间；位图容易获得连续空间，但需要额外空间。
  5. 分组与计数的区别：分组是在一个块里存放 n−1 个空闲块的地址；计数存放的是**（起始地址，连续个数）**。
  6. TRIM 只对 NVM 有意义：HDD 可以原地覆盖，不需要 TRIM。
  7. 统一缓冲缓存解决的是"双重缓存"问题。
  8. 日志文件系统中，事务写入日志即视为提交，而不是写入文件系统结构后才提交；崩溃后要重做日志中剩余的事务。
  9. WAFL 快照的原理是写时复制：复制根 inode，被修改的块写到新位置。
  10. 同步写要等数据落盘后才确认；异步写更快也更常见；读往往比写慢。
