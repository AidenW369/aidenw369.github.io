系统内部机制

一、本章目标

  • 深入理解文件系统的细节和实现
  • 了解系统引导（booting）和文件共享
  • 以 NFS 为例理解远程文件系统

二、文件系统的基本组织

层次关系：存储设备 → 分区（partition）→ 卷（volume）→ 文件系统

  • 一台通用计算机可以有多个存储设备
  • 设备可以划分成多个分区，分区里存放卷
  • 一个卷可以跨多个分区（甚至跨多个设备）
  • 每个卷通常会格式化成一个文件系统，可选的文件系统类型往往有几十种

图示说明（典型存储设备组织）：

卷 分区 所在设备 说明
volume 1 partition A storage device 1 一个设备上分两个分区
volume 2 partition B storage device 1 每个分区各自有目录和文件
volume 3 partition C + D storage device 2 + 3 一个卷跨两个设备，共用一套目录

Solaris 示例（截图）： 同一台机器上同时挂着很多种文件系统，说明"文件系统类型多样"：

  • 磁盘型：ufs（/、/var、/opt）、zfs（/export/home、/var/mail 等）
  • 内存型：tmpfs（/tmp、/var/run）
  • 特殊/伪文件系统：proc（/proc 进程信息）、devfs/dev（设备）、ctfs（contract）、mntfs（挂载表）、objfs、lofs（回环挂载）、fd（文件描述符）

三、分区与挂载（Partitions and Mounting）

分区的两种形态：

  • cooked（熟分区）：卷中包含文件系统
  • raw（裸分区）：只是一串块，没有文件系统（如交换区、数据库直接使用）

引导相关：

  • 引导块（boot block） 可以指向引导卷，或指向引导加载程序（boot loader）所在的一组块，这些代码足够从文件系统中加载内核
  • 也可以是多系统引导管理程序（multi-OS booting）
  • 根分区（root partition） 存放操作系统，在引导时挂载；其他分区可存放别的 OS、别的文件系统，或者是裸分区

挂载：

  • 其他分区可以在**挂载点（mount point）**自动或手动挂载，挂载点就是访问该文件系统的位置
  • 挂载时会检查一致性：
    1. 元数据是否都正确？
    2. 不正确 → 修复后再试
    3. 正确 → 加入挂载表（mount table），允许访问

图示（File Systems and Mounting）：

  • (a) 现有的 Unix 目录树：/ → users → bill、fred → help
  • (b) 一个未挂载的文件系统：根下有 sue、jane → prog、doc
  • 把 (b) 挂载到 /users 后，/users 原来的内容（bill、fred）被遮住，路径变成 /users/sue、/users/jane/prog……
  • ⚠️ 要点：挂载点原有的子树在挂载期间不可见，卸载后才恢复

四、文件共享（File Sharing）

  • 让多个用户 / 多个系统访问同一批文件
  • 必须实现准确的权限 / 保护机制
  • 大多数系统有 所有者（owner） 和 组成员（group） 的概念
  • 难点：需要在不同系统之间也能套用这些身份和权限

五、虚拟文件系统（VFS）

核心思想：用面向对象的方式实现文件系统

  • 同一套系统调用接口（API）可以用于各种类型的文件系统
  • 把通用操作和具体实现分开
  • 底层实现可以是任意本地文件系统，也可以是网络文件系统
  • 实现 vnode：其中保存 inode（本地）或网络文件的细节（远程）
  • 然后把操作**分派（dispatch）**给对应文件系统的实现例程

图示（VFS 分层）：

👉 程序面对的是 VFS 接口，而不是某种具体的文件系统。

Linux VFS 实现：4 种对象类型

对象 含义
inode 单个文件
file 一个打开的文件
superblock 整个文件系统
dentry 单个目录项
  • VFS 为这些对象规定一组必须实现的操作
  • 每个对象有一个指向函数表的指针，函数表里是实现各操作的例程地址（类似 C 里的"虚函数表"）
  • 例：open() 打开、close() 关闭、read() 读、write() 写、mmap() 内存映射

六、远程文件系统（Remote File Systems）

通过网络共享文件的三种方法：

  1. 手动传输：如 ftp，每个文件单独传
  2. 分布式文件系统（DFS）：远程目录直接在本地机器上可见
  3. 万维网（WWW）：本质是第 1 种的变体，用浏览器查找并上传/下载；匿名访问不需要认证

1. 客户端-服务器模型

  • 服务器：通过网络协议提供文件系统访问
  • 客户端：用协议访问远程文件系统
  • 问题：靠网络 ID 识别对方可能被伪造；加密又开销大
  • 以 NFS 为例的流程：
    1. 客户端和服务器的用户认证信息必须一致（如 UserID）
    2. 挂载远程文件系统后，文件操作代表用户经网络发给服务器
    3. 服务器检查权限，返回文件句柄（file handle）
    4. 之后的读写都使用这个句柄，直到文件关闭

2. 分布式信息系统（分布式命名服务）

为远程计算提供统一的信息访问：

  • DNS：主机名 → 网络地址
  • NIS：用户名、密码、UserID、组信息
  • CIFS（微软）：网络信息 + 用户认证 → 建立网络登录，服务器据此允许/拒绝访问
  • Active Directory：微软的分布式命名服务，使用源自 Kerberos 的网络认证协议
  • 业界趋势：LDAP（轻量目录访问协议）作为安全的分布式命名机制

七、一致性语义（Consistency Semantics）

  • 评价共享文件系统的重要标准
  • 规定：多个用户同时访问共享文件时怎样工作；一个用户的修改什么时候被别人看到
  • 与进程同步算法直接相关，但在网络上保证原子性开销很大（参见 AFS）
  • 文件会话（file session）：从 open 到 close 之间的一系列访问
UNIX 语义 会话语义（AFS/OpenAFS）
写入何时可见 立即对其他打开该文件的用户可见 会话期间不可见，close 时才可见
副本 只有一个物理映像，互斥访问 可以有多个副本，各自独立修改
其他特点 可共享当前 I/O 位置指针；竞争会导致进程延迟 性能更好，但同时修改时可能出现覆盖

八、Sun 网络文件系统（NFS）

1. 基本概念

  • 既是实现也是规范，用于在 LAN（或 WAN）上访问远程文件
  • 最初是 SunOS 的一部分，现已是行业标准
  • 可用 UDP/IP（不可靠数据报）或 TCP/IP，跑在以太网或其他网络上

2. 设计特点

  • 把互联的工作站看作一组独立的机器，各有独立文件系统，在此基础上透明地共享
  • 远程目录挂载到本地某个目录上，看起来就像本地文件系统的一棵子树，并替换掉该本地目录下原来的子树
  • 挂载操作不透明：必须提供远程目录所在的主机名
  • 挂载后访问是透明的：像访问本地文件一样
  • 在访问权限允许的前提下，任何文件系统（或其中的目录）都可以挂载到任何本地目录上
  • 面向异构环境（不同机器、操作系统、网络架构），规范与这些无关
    • 实现手段：在 XDR（外部数据表示） 协议之上的 RPC 原语
  • 规范把挂载机制和远程文件访问服务分开

3. 挂载示例（截图）

  • 三个独立的文件系统：
    • U：/usr/local
    • S1：/usr/shared/dir1
    • S2：/usr/dir2
  • (a) 普通挂载：把 S1 的 /usr/shared 挂到 U 的 /usr/local 上 → 在 U 上可以通过 /usr/local/dir1 访问 S1 的 dir1
  • (b) 级联挂载（cascading mounts）：再把 S2 的 /usr/dir2 挂到 U 的 /usr/local/dir1 上 → /usr/local/dir1 现在显示的是 S2 的内容，S1 原来的 dir1 被遮住

4. NFS 挂载协议（Mount Protocol）

  • 在客户端和服务器之间建立初始逻辑连接

  • 挂载请求包括：要挂载的远程目录名 + 存放它的服务器名

  • 请求映射为相应的 RPC，转发给服务器上的挂载服务器（mount server）

  • 导出列表（export list）：服务器允许挂载哪些本地文件系统，以及允许哪些机器挂载

  • 请求符合导出列表 → 服务器返回

    文件句柄

    （后续访问的钥匙）

    • 文件句柄 = 文件系统标识符 + inode 号（用于定位被挂载的目录）

  • ⚠️ 挂载只改变客户端用户的视图，不影响服务器端

5. NFS 协议（远程文件操作）

提供一组 RPC，支持：

  • 在目录中查找文件
  • 读取一组目录项
  • 操作链接和目录
  • 访问文件属性
  • 读写文件

关键特性：

  • 服务器无状态（stateless）：每个请求都要带上完整参数（NFS v4 例外：有状态，但较新、用得少，差别很大）
  • 修改的数据必须先提交到服务器磁盘，才把结果返回给客户端 → 失去了缓存的部分优势，但崩溃后安全
  • NFS 协议不提供并发控制机制（需要另外加锁）

6. NFS 架构三层

  1. UNIX 文件系统接口：基于 open、read、write、close 调用和文件描述符

  2. VFS 层

    ：区分本地文件和远程文件；本地文件再按文件系统类型区分

    • 本地请求 → 调用对应文件系统的操作
    • 远程请求 → 调用 NFS 协议例程

  3. NFS 服务层：最底层，实现 NFS 协议

图示（NFS 架构示意）：

👉 请求路径：系统调用 → 客户端 VFS → NFS 客户端 → RPC/XDR → 网络 → 服务器 RPC/XDR → NFS 服务器 → 服务器 VFS → 本地 UNIX 文件系统 → 磁盘

7. 路径名转换（Path-Name Translation）

  • 把路径拆成一个个分量，对每一对（分量名, 目录 vnode） 分别发一次 NFS

    • 例：/usr/local/dir1/a 要逐级查找多次

  • 为了加速：客户端有目录名查找缓存，保存远程目录名对应的 vnode

  • （逐级查找的原因：路径中途可能跨越挂载点，包括级联挂载）

8. 远程操作（Remote Operations）

  • 普通 UNIX 系统调用与 NFS RPC 几乎一一对应（open 和 close 除外，因为服务器无状态）
  • 遵循远程服务模式，但为了性能使用了缓冲和缓存：
    • 文件块缓存：打开文件时，内核向服务器确认是要重新获取还是重新验证缓存的属性；只有缓存属性是最新的时候才使用缓存的文件块
    • 文件属性缓存：服务器发来新属性时就更新
    • 延迟写：在服务器确认数据已写入磁盘之前，客户端不释放延迟写的块

九、复习要点速记

  1. 设备 → 分区 → 卷 → 文件系统；卷可以跨分区/跨设备
  2. cooked vs raw 分区；根分区在引导时挂载；挂载前做一致性检查，通过后加入挂载表
  3. 挂载会遮住挂载点原有内容
  4. VFS：统一 API + vnode + 函数表分派；Linux 四对象：inode / file / superblock / dentry
  5. 远程共享三种方式：FTP、DFS、WWW
  6. 命名服务：DNS、NIS、CIFS/AD（Kerberos）、LDAP
  7. 一致性语义：UNIX 语义（立即可见）vs 会话语义（close 后可见）
  8. NFS：RPC + XDR 实现异构；挂载协议与访问协议分离；导出列表 + 文件句柄（FS ID + inode 号）
  9. NFS 服务器无状态、同步写盘、无并发控制；open/close 不对应 RPC
  10. NFS 三层：UNIX 接口 → VFS → NFS 服务层；路径名逐分量 lookup，客户端有目录名缓存
