Hexo博客迁移到新电脑并与GitHub同步

Posted on 2026-11-19 In Notes

Hexo博客迁移到新电脑并与GitHub同步

概述

迁移 = 把博客源文件夹拷到新电脑 + 重装依赖 + 配好 SSH 密钥，之后照常 hexo d 即可。GitHub 仓库里只有生成好的网页，没有 Markdown 源文件，所以源文件必须从旧电脑拷过来。

本博客的配置要点：

项目 当前情况
博客目录 myHexoBlog
Hexo 版本 8.1.2
主题 NexT，放在 themes/next/ 文件夹（不是 npm 安装）
主题配置文件 themes/next/_config.yml
Markdown 渲染器 hexo-renderer-markdown-it + markdown-it-mathjax3（支持 LaTeX 公式）
部署仓库 git@github.com:AidenW369/aidenw369.github.io.git，分支 main

下文所有命令都在 Git Bash 里执行（安装 Git for Windows 后自带），这样命令和 Mac 终端基本一致。

第 1 步：拷贝博客文件夹

把整个 myHexoBlog 文件夹拷到 Windows 电脑（U 盘、网盘均可），建议放在 C:\Users\你的用户名\myHexoBlog。

文件/文件夹 是否要拷 说明
source/ 必须 所有文章
themes/ 必须 NexT 主题及其配置
scaffolds/ 必须 文章模板
_config.yml 必须 站点配置
package.json、package-lock.json 必须 依赖清单
常用命令.txt 建议 个人笔记
node_modules/ 不用 会重新安装，Mac 上的版本在 Windows 上不能用
public/、.deploy_git/、db.json 不用 会重新生成

不拷 node_modules 还能大大加快拷贝速度。.deploy_git 是隐藏文件夹，在 Mac 上默认看不到，按 Cmd + Shift + . 可以显示。

第 2 步：安装 Git、Node.js 和 Hexo

  1. Git for Windows：从 git-scm.com 下载安装，全部保持默认选项即可。装完后开始菜单里会有 Git Bash。
  2. Node.js：从 nodejs.org 下载 LTS 版安装，保持默认选项。

第 4 步：核对两个配置文件

配置文件是随文件夹拷过来的，一般已经正确，这里只是确认一下。

输出应当包含以下内容：

文件 配置项 正确的值
_config.yml theme next
_config.yml deploy.repo git@github.com:AidenW369/aidenw369.github.io.git
_config.yml deploy.branch main
_config.yml markdown.plugins - markdown-it-mathjax3
themes/next/_config.yml mathjax.enable（约第 571 行） false

mathjax.enable 必须是 false：公式已由 markdown-it-mathjax3 在生成网页时渲染，再开 NexT 自带的 MathJax 会重复处理，导致显示错乱。如果是 true，在 Git Bash 里执行（注意 Windows 版不写 Mac 上的 ''）：

也可以用记事本或 VS Code 打开文件手动修改。

第 5 步：配置 Git 身份和 SSH 密钥

每台电脑要有自己的 SSH 密钥，并把公钥添加到 GitHub，才能用 hexo d 推送。如果这台 Windows 以前已经配过密钥且仍在 GitHub 上，可以直接跳到本步最后的连接测试。

密钥位置：C:\Users\你的用户名\.ssh\。

文件 用途
id_ed25519.pub 公钥，添加到 GitHub
id_ed25519 私钥，只留在本机，不要发给任何人

公钥只有一行，以 ssh-ed25519 开头、邮箱结尾，比以前的 RSA 公钥（ssh-rsa 开头）短得多。这是算法不同导致的，安全性相同，而且是 GitHub 推荐的算法。

添加到 GitHub：右上角头像 → Settings → SSH and GPG keys → New SSH key，Title 填 Windows，Key 里粘贴，点 Add SSH key。

日常写文章

Mac 和 Windows 两台电脑都写博客时

hexo d 只会把生成的网页推到 GitHub，不会同步 Markdown 源文件。如果在一台电脑上发了文章，另一台没有这篇文章，下次在另一台部署时，线上的这篇文章就会被覆盖掉。

推荐做法：在 GitHub 新建一个私有仓库（如 hexo-source），专门存放源文件。

常见问题

现象 原因 解决办法
PowerShell 里提示 hexo.ps1 无法加载，因为在此系统上禁止运行脚本 Windows 默认的脚本执行策略 改用 Git Bash；或在 PowerShell 里执行 Set-ExecutionPolicy -Scope CurrentUser RemoteSigned
npm warn install-scripts ... not yet covered by allowScripts 新版 npm 默认不自动运行安装脚本 只是警告，先继续。如果 hexo g 报 highlight 相关的错误，执行 npm install-scripts approve hexo-util，再删掉 node_modules 重新 npm install
hexo d 提示 Permission denied (publickey) SSH 公钥没有添加到 GitHub 重做第 5 步，用 ssh -T git@github.com 验证
hexo d 提示 Deployer not found: git 缺少部署插件 npm install hexo-deployer-git --save
warning: LF will be replaced by CRLF Windows 和 Mac 的换行符不同 不影响使用，可以忽略
npm install 大量报错 Node 版本与 Hexo 不兼容 安装和 Mac 上一致的 Node 版本（Mac 上用 node -v 查看）
公式显示为原始的 $...$ 或显示两遍 渲染器冲突或 NexT 的 MathJax 没关 按第 3 步卸载冲突渲染器，按第 4 步把 mathjax.enable 设为 false
页面变成默认主题 themes/next 没拷过来，或 theme 不是 next 补拷 themes 文件夹，检查 _config.yml
