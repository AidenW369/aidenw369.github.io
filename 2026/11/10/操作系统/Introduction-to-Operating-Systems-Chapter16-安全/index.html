安全

一、安全问题概述

1. 基本概念

  • 安全的定义：系统资源在任何情况下都按预期被使用和访问。绝对安全无法实现。
  • 入侵者（Intruder / Cracker）：试图破坏安全的人
  • 威胁（Threat）：潜在的安全违规
  • 攻击（Attack）：实际的破坏尝试，可以是意外的或恶意的
  • 防范意外误用比防范恶意攻击容易

2. 安全违规的五类（重点）

类别 含义
破坏机密性 (Confidentiality) 未授权读取数据
破坏完整性 (Integrity) 未授权修改数据
破坏可用性 (Availability) 未授权销毁数据
窃取服务 (Theft of service) 未授权使用资源
拒绝服务 (DoS) 阻止合法用户使用

3. 安全违规的方法

  • 伪装 (Masquerading)：冒充授权用户以提升权限（破坏认证）
  • 重放攻击 (Replay)：原样或修改后重发截获的消息
  • 中间人攻击 (MITM)：攻击者处于通信链路中间，对双方分别冒充对方
  • 会话劫持 (Session hijacking)：截取已建立的会话，从而绕过认证
  • 权限提升 (Privilege escalation)：获得超出应有范围的访问权限

📊 图示（标准安全攻击）：

  • 正常：发送者 ↔ 接收者
  • 伪装：攻击者直接冒充发送者与接收者通信
  • 中间人：发送者 ↔ 攻击者 ↔ 接收者

4. 四层安全模型（重点）

安全必须在四个层次同时实施，系统安全取决于最薄弱的一环。

层次 攻击类型 防御方法
应用层 逻辑漏洞、设计缺陷、代码注入 沙箱、软件限制
操作系统 不安全的默认配置、平台漏洞 打补丁、重新配置、加固
网络 嗅探、欺骗、伪装 加密、认证、过滤
物理 控制台访问、基于硬件的攻击 警卫、保险库、设备数据加密
  • 人也是风险来源：钓鱼 (phishing)、社会工程学 (social engineering)
  • 目标：不追求绝对安全，而是让攻击者的代价足够高
  • 思考题：安全措施过多也会降低可用性

二、程序威胁（Program Threats）

1. 常见恶意软件 (Malware)

名称 特点
特洛伊木马 (Trojan Horse) 滥用其运行环境的代码；利用"用户编写的程序可被他人执行"的机制；隐蔽运行
间谍软件 (Spyware) 常随正常软件一起安装，弹广告、收集用户数据；高达80%的垃圾邮件来自被感染的系统
勒索软件 (Ransomware) 加密锁住数据，索要赎金
陷阱门 (Trap Door) 绕过正常安全流程的特定用户名/密码；可能藏在编译器中，极难发现
逻辑炸弹 (Logic Bomb) 满足特定条件（如某日期）才触发
  • 恶意软件都在试图违反最小权限原则 (Principle of Least Privilege)
  • 常见目标：留下远程访问工具 (RAT) 以便反复进入

2. 代码注入与缓冲区溢出（重点）

  • 代码注入：系统代码本身并不恶意，但存在漏洞，使攻击者能添加或修改可执行代码
  • 常见于 C/C++ 等允许通过指针直接操作内存的低级语言
  • 📊 示例程序：strcpy(buffer, argv[1]) 没有检查输入长度，若参数超过 256 字节就会溢出 → 代码审查 (code review) 有助于发现这类问题

📊 缓冲区溢出的四种结果（栈中自上而下：buffer → padding → 其他变量 → 返回地址）：

溢出程度 结果
仅覆盖 padding 无察觉
覆盖其他变量 逻辑被破坏 / 程序崩溃 (DoS)
覆盖返回地址并注入代码 代码注入，执行攻击者代码
  • 跳板 (Trampoline)：利用 NOP 等空操作指令区 + shellcode + 被改写为指向 shellcode 的返回地址
  • 攻击后果：获得进程所有者权限的 shell、开放网络端口、删除文件、下载程序等；有时可通过允许的连接绕过防火墙
  • 脚本小子 (script kiddies)：找漏洞和写攻击代码需要很高技术，但他人可以直接运行现成的工具
  • 防御：禁用栈执行，或在页表中加入**”不可执行"位**（NX，SPARC 与 x86 均支持），但仍然存在其他漏洞

3. 病毒 (Virus)

  • 嵌入在合法程序中的代码片段，能自我复制，用于感染其他计算机
  • 高度依赖 CPU 架构、操作系统和应用程序
  • 通常通过电子邮件或宏传播（课件示例：VB 宏在打开文档时格式化硬盘）
  • 病毒投放器 (dropper)：负责把病毒放进系统

病毒分类：

类型 说明
文件型 / 寄生型 附着于可执行文件
引导区型 / 内存型 感染引导扇区
宏病毒 藏在文档宏中
源代码型 修改源代码
多态 (Polymorphic) 每次变化以避免病毒特征码被识别
加密型 加密自身躲避检测
隐形 (Stealth) 修改系统以隐藏自身
隧道型 (Tunneling) 绕过杀毒软件
多分体 (Multipartite) 同时感染多个部位
装甲型 (Armored) 难以被分析

📊 引导区病毒流程：

  1. 把原引导扇区复制到未使用位置 X
  2. 用自身替换原引导块
  3. 系统启动时减少可用物理内存，藏在新上限之上
  4. 挂接磁盘读写中断，监控所有磁盘活动
  5. 之后：感染新插入的可写磁盘 / 阻止其他程序写引导扇区 / 内含逻辑炸弹在特定日期发作

4. 威胁现状

  • 攻击已从"科学实验"演变为有组织犯罪工具：针对特定公司、构建僵尸网络 (botnet) 发送垃圾邮件和 DDoS、键盘记录窃取密码和信用卡号
  • 为什么 Windows 是主要目标？ 用户最多；用户普遍以管理员身份运行；单一化 (monoculture) 有害

三、系统与网络威胁

1. 概述

  • 有些系统默认"开放"而不是默认安全 → 应减少攻击面 (attack surface)，但会更难用、更难管理
  • 网络威胁更难检测和防范：保护机制较弱、难以建立共享秘密、没有物理边界、难以确定连接方位置（通常只知道 IP 地址）

2. 蠕虫 (Worm)

  • 独立程序，使用 spawn 机制自我复制（与病毒的区别：病毒需寄生在宿主程序中）
  • 莫里斯蠕虫 (Internet worm, 1988)：
    • 利用 UNIX 远程访问功能及 finger、sendmail 的漏洞
    • 利用 rsh 信任关系免密码访问"友好"系统
    • 抓钩程序 (grappling hook)：99 行 C 代码，上传后再拉取主程序
    • 还会通过猜密码入侵本地其他用户账户
    • 若目标已被感染则放弃，但每第 7 次仍会再次感染（导致系统过载）

3. 端口扫描 (Port Scanning)

  • 自动尝试连接某个或某段 IP 上的一系列端口
  • 可识别正在运行的服务协议、操作系统及版本
  • 工具：nmap（扫描端口）、nessus（含协议、漏洞库）
  • 常从僵尸系统发起以降低可追溯性；可用于善意（安全审计）或恶意目的

4. 拒绝服务 (DoS / DDoS)

  • 使目标过载，无法完成正常工作
  • DDoS：从多个站点同时发起
  • 例：SYN 洪泛（大量半开 TCP 连接耗尽系统资源）
  • 难点：如何区分被攻击和真的很受欢迎？
  • 意外：学生写错 fork() 代码；故意：勒索、报复

四、密码学作为安全工具（重点）

1. 为什么需要密码学

  • 在单台计算机内部，操作系统能管理进程 ID 和通信端口，消息来源可信
  • 在网络上，不能依赖 IP 地址确认身份（可能有非法主机加入），必须依靠密码学
  • 密码学基于秘密（密钥），可实现：确认来源、仅特定接收者能接收、建立信任关系

2. 加密 (Encryption) —— 限制接收者

形式化定义：

  • 密钥集 K、明文集 M、密文集 C
  • 加密函数 E: K → (M → C)；解密函数 D: K → (C → M)
  • 都应高效可计算
  • 核心性质：只有持有 k 才能由密文 c 求出 m；且不能从密文推出 k

📊 不安全信道上的安全通信：发送方用 E_k(m) 得到密文 c，在不安全信道传输（攻击者可截获），接收方用 D_k© 还原 m；双方需事先进行密钥交换。

3. 对称加密 (Symmetric) —— 同一密钥加解密，k 必须保密

算法 要点
DES 美国政府制定，分组加密；密钥过短，已不安全
3DES 使用 2~3 个密钥执行 3 次，更安全
AES (2001, NIST) 密钥 128/192/256 位，分组 128 位
RC4 最常见的流密码（如无线传输）；密钥作为伪随机数发生器的输入生成无限密钥流；已知有漏洞

4. 非对称加密 (Asymmetric / 公钥加密)

  • 每个用户两把钥匙：公钥（公开，用于加密）+ 私钥（自己保存，用于解密）

  • 最常用：RSA

    • 原理：判断素数很容易，但分解大数的质因数没有高效算法

  • 数学形式：

    • N = p × q（p、q 为大素数，如各 512 位）
    • 加密：E(m) = m^ke mod N
    • 解密：D© = c^kd mod N
    • 其中 ke·kd mod (p−1)(q−1) = 1

RSA 例题（考试常考）：

  1. p = 7，q = 13 → N = 91，(p−1)(q−1) = 72
  2. 选 ke 与 72 互质且小于 72 → ke = 5
  3. 求 kd 使 5·kd mod 72 = 1 → kd = 29（5×29 = 145 = 2×72 + 1 ✓）
  4. 公钥 (5, 91)，私钥 (29, 91)
  5. 加密消息 69：69⁵ mod 91 = 62
  6. 解密：62²⁹ mod 91 = 69 ✓

验算提示：69² mod 91 = 29，69⁴ mod 91 = 29² mod 91 = 22，69⁵ mod 91 = 22×69 mod 91 = 1518 mod 91 = 62

5. 对称 vs 非对称

对称加密 非对称加密
基础 变换 (transformations) 数学函数
速度 快 计算开销大得多
用途 大量数据加密 一般不用于大量数据，常用于交换会话密钥、签名

五、认证 (Authentication) —— 限制发送者

1. 形式化定义

  • 与加密互补，还能证明消息未被修改
  • 密钥集 K、消息集 M、认证符集 A
  • 签名函数 S: K → (M → A)；验证函数 V: K → (M × A → {true, false})
  • 只有持有 k 才能生成能通过 V_k 验证的认证符；不能从认证符推出 k
  • 若 V_k(m, a) = true → m 未被修改，且发送方持有 k

2. 哈希函数 (Hash Function)

  • 从 m 生成小的、固定长度的消息摘要
  • 必须抗碰撞：找不到 m’ ≠ m 使 H(m) = H(m’)
  • 常见：MD5（128 位）、SHA-1（160 位）
  • ⚠️ 哈希本身不能当认证符：攻击者可改 m 并重新计算 H(m’) → 所以必须对 H(m) 再做认证

补充：MD5 和 SHA-1 现在均已被证明可构造碰撞，实际应用推荐 SHA-256 等 SHA-2/SHA-3 系列。

3. 消息认证码 (MAC)

  • 使用对称密钥生成加密校验和
  • 先哈希再认证 H(m)，即可安全认证长消息
  • 缺点：生成和验证用同一个 k，能验证的人也能伪造

4. 数字签名 (Digital Signature)

  • 基于非对称密钥，任何人都能验证
  • 无法从验证密钥 kv 推出签名密钥 ks → kv 是公钥，ks 是私钥
  • RSA 数字签名：与 RSA 加密密钥用法相反
    • 签名：S(m) = H(m)^ks mod N
    • 验证：a^kv mod N 是否等于 H(m)

5. 为什么认证不直接用加密？

  • 计算更少（RSA 签名除外）
  • 认证符通常比消息短
  • 有时只需要认证而不需要保密（如签名补丁）
  • 可作为不可否认性 (non-repudiation) 的基础

六、密钥分发与证书

1. 密钥分发

  • 对称密钥的传递是巨大挑战，有时用带外 (out-of-band) 方式
  • 非对称密钥会增多 → 存放在密钥环 (key ring) 上
  • 公钥分发同样需要小心 —— 中间人攻击

📊 对非对称加密的中间人攻击：

  1. 接收方发出公钥 ke，被攻击者截获
  2. 攻击者把自己的公钥 k_bad 冒充给发送方
  3. 发送方用 k_bad 加密 → 攻击者用自己的私钥解密，读取消息

→ 解决方法：数字证书

2. 数字证书 (Digital Certificate)

  • 证明某公钥属于谁：由可信第三方对公钥进行数字签名
  • 证书颁发机构 (CA)：其公钥内置在浏览器中
  • CA 之间可相互签名担保，形成信任链

七、密码学的实现

1. 在 OSI 模型的不同层实现

  • 传输层：SSL / TLS
  • 网络层：IPSec（用 IKE 交换密钥）→ VPN 的基础
  • 为什么不全放在最底层？ 某些功能需要更高层的信息，如用户认证、电子邮件投递

2. TLS 示例（重点）

  • 限制两台计算机只与彼此交换消息
  • 用于浏览器与 Web 服务器之间（如传输信用卡号）
  • 流程：
    1. 服务器通过证书验证身份，确保客户端连接的是正确的服务器
    2. 用非对称加密协商出一个会话密钥
    3. 之后的大量通信使用对称加密

核心思想：非对称加密解决密钥交换，对称加密负责高效传输数据

八、用户认证 (User Authentication)

1. 密码 (Password)

  • 保护系统依赖用户 ID，所以必须正确识别用户
  • 密码可看作密钥 (key) 或能力 (capability) 的特例
  • 管理措施：保密、定期更换、记录历史避免重复、使用难猜密码、记录无效尝试（但不记录密码本身）
  • 加密密码能防嗅探，但不能防肩窥 (shoulder surfing) 和键盘记录木马

2. 密码存储

  • 使用易计算、难求逆的单向算法，只存储加密后的结果，永不解密
  • 即使加密了也仍要保密（UNIX 的 /etc/shadow 仅超级用户可读）
  • 加盐 (salt)：使相同密码加密后得到不同值

3. 其他认证方式

  • 一次性密码 (OTP)：用户和系统基于种子同时计算；使用硬件令牌/钥匙扣；频繁变化
  • 生物识别：指纹、手掌扫描
  • 多因素认证 (MFA)：需要两个及以上因素，如 USB 加密狗 + 生物特征 + 密码

4. 强且易记的密码（课件补充）

  • 关键系统（如银行账户）必须使用强密码，且不要在多个系统重复使用
  • 技巧：取一句易记的话中每个单词的首字母，大小写混合并加入数字或标点
    • 例：“My girlfriend’s name is Katherine” → Mgn.isK!
  • 允许空格的系统可使用口令短语 (passphrase)：易记且难破解

九、实施安全防御

1. 核心理论：纵深防御 (Defense in Depth) —— 多层安全

2. 主要手段

  • 安全策略 (Security policy)：说明要保护什么
  • 漏洞评估 (Vulnerability assessment)：比较系统实际状态与安全策略
  • 入侵检测 (Intrusion detection)：
方法 原理 特点
基于特征 (Signature-based) 匹配已知恶意模式 无法发现新攻击
异常检测 (Anomaly) 发现与正常行为的偏差 可检测零日攻击，但误报多
  • 都存在误报 (false positive) 和漏报 (false negative) 问题
  • 病毒防护：扫描已知病毒特征；或在沙箱中运行
  • 审计、记账、日志
  • 安全上网习惯：只从可信来源下载等

十、防火墙 (Firewall)

1. 网络防火墙

  • 位于可信与不可信主机之间，限制两个安全域之间的访问
  • 弱点：
    • 隧道 (Tunneling)：将被禁止的协议封装在允许的协议中（如 telnet 藏在 HTTP 中）
    • 欺骗 (Spoofing)：规则通常基于主机名或 IP，可被伪造

2. 防火墙类型

类型 作用
个人防火墙 主机上的软件层，监控/限制进出流量
应用代理防火墙 理解应用层协议并加以控制（如 SMTP）
系统调用防火墙 监控重要系统调用并施加规则

3. DMZ（非军事区）📊

  • 防火墙将网络分为：Internet、公司内网、DMZ 三部分
  • 允许：公司内网 → Internet；Internet → DMZ；DMZ ↔ 内网（受限）
  • 禁止：Internet 直接访问公司内网
  • 对外服务器（Web、邮件）放在 DMZ，即使被攻破也不会直接危及内网

十一、计算机安全分级（美国国防部 TCSEC / “橘皮书”）

等级 含义
D 最低安全
C 通过审计提供自主保护；C1（同级用户协作保护）、C2（用户级访问控制）
B 具有 C 的全部特性，且每个对象有敏感度标签（强制访问控制）；B1、B2、B3
A 使用形式化设计与验证确保安全（最高级）

十二、安全防御措施总结（清单）

  1. 教育用户安全计算习惯（不接未知设备、不共享密码、警惕社会工程）
  2. 教育用户防钓鱼（不点不明链接/附件，通过电话等方式核实请求）
  3. 尽可能使用安全通信
  4. 物理保护硬件
  5. 最小化攻击面，关闭所有未用服务
  6. 尽可能安全地配置守护进程、特权程序和服务
  7. 使用现代软硬件
  8. 及时更新、打补丁
  9. 只运行可信来源的程序（如代码签名的程序）
  10. 启用日志与审计，定期审查或自动告警
  11. 安装并更新杀毒软件
  12. 使用强密码/口令短语，不要随处记录
  13. 使用入侵检测、防火墙等网络防护
  14. 对重要设施定期做漏洞评估和应急测试
  15. 加密存储设备及重要文件
  16. 制定并及时更新安全策略

十三、实例：Windows 安全

  • 安全基于用户账户，每个用户有唯一安全 ID (SID)
  • 登录后生成安全访问令牌 (access token)：包含用户 SID、所属组 SID、特权
  • 每个进程获得令牌副本，系统据此判断允许/拒绝访问
  • 使用主体 (subject) 模型：跟踪管理用户运行的每个程序的权限
  • 每个对象有安全描述符 (security descriptor)：所有者 ID、组 SID、自主访问控制列表 (DACL)、系统访问控制列表 (SACL)
  • 强制完整性控制 (Mandatory Integrity Control)：为每个对象和主体分配完整性标签
  • 对象分为容器对象（如目录）和非容器对象；默认情况下，容器内新建对象继承父对象权限
  • Windows 的安全挑战：默认设置较弱、自带服务多、安装的应用多

📌 考点速记

  • 五类安全违规：机密性、完整性、可用性、窃取服务、DoS
  • 四层安全：物理、网络、操作系统、应用 → 最弱一环决定安全
  • 病毒 vs 蠕虫：病毒寄生于程序；蠕虫是独立程序、自行传播
  • 加密限制接收者，认证限制发送者
  • 对称：快，密钥分发难（DES / 3DES / AES / RC4）；非对称：慢，用于密钥交换和签名（RSA）
  • RSA 例题：p=7, q=13 → (5,91)/(29,91)，69 → 62 → 69
  • 哈希不是认证符，需配合 MAC 或数字签名
  • MAC 用对称密钥；数字签名用私钥签、公钥验
  • TLS：证书验证服务器 → 非对称加密交换会话密钥 → 对称加密传数据
  • 加盐防止相同密码得到相同哈希值
  • 异常检测可发现零日攻击
  • DMZ 用来隔离对外服务
